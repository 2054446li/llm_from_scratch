# 合成训练数据与 SOP-Maze Eval 的 Reasoning 和 Requirement 难度分析

## 1. 分析目标

当前 Answer-first 合成数据完成训练后没有带来明显提升。本文验证一个核心假设：**合成训练样本是否比 Eval 样本简单，导致模型主要学习了已有的明确分支，却没有补足多分支搜索、优先级判断和跨字段推理能力。**

分析分为两部分：

1. Reasoning Content 长度：按 23 个 Eval subset 比较 Kimi 测试样本和对应训练样本。
2. Requirement 复杂度：比较 Eval Requirement 与映射到该 subset 的训练场景 Requirement。

## 2. 数据与统计口径

- 训练集：当前实际入库的 15,644 条 `status=ok` SFT。
- 训练场景：131 个物理场景，按 `target_subset` 映射到 Eval。
- Eval：`bench_json` 中 Kimi-K3 的完整 400 条结果。
- Eval 得分分组：172 条 1 分、215 条 0.2 分、13 条 0 分。
- 长度：使用 Python `len()` 统计 `reasoning_content` 或 `model_think` 的 Unicode 字符数。
- 训练 Reasoning：只统计最终进入 SFT 的 `ok` 记录。
- Requirement 训练均值：按实际训练行数加权，表示模型训练时真正看到的分布。
- Requirement 场景分布：不同物理场景等权，避免样本量较大的场景重复放大模板数量。

需要注意：`target_subset` 是机制或最近模式映射，不代表合成场景与 Eval 场景严格一一等价。

## 3. 总体结论

### 3.1 Reasoning Content

| 数据组 | 样本数 | 均值 | 中位数 |
|---|---:|---:|---:|
| Kimi Eval：1 分 | 172 | 5,667 | 3,447 |
| Kimi Eval：0.2 分 | 215 | 20,460 | 14,006 |
| Kimi Eval：0 分 | 13 | 15,403 | 10,355 |
| 合成训练 SFT：ok | 15,644 | 1,630 | 915 |

Reasoning 越长并不意味着答案越好。0.2 分样本的平均 Reasoning 是 1 分样本的 3.61 倍，说明测试集全量均值被失败时的反复搜索、犹豫和跑偏明显拉高。

更公平的比较应使用测试集 1 分样本，并控制训练集的 subset 配比：

- 训练 Reasoning 均值：1,630 字符。
- 按训练 subset 配比重加权后的测试 Kimi 1 分均值：3,855 字符。
- 训练均值仍然只有测试正确样本的 42%。
- 已覆盖的 17 个 subset 中，训练 Reasoning 均值全部低于测试全量均值。
- 有 1 分样本可比较的 16 个 subset 中，16/16 的训练均值更低，14/16 不足测试 1 分均值的一半。

因此，失败样本确实放大了表面差距，但排除这一因素后，训练样本的推理负担仍然系统性偏低。

### 3.2 Requirement

将 Eval Requirement 按训练集的 subset 和场景样本量重新加权后：

| Requirement 指标 | 训练 | 对应 Eval | 训练/Eval |
|---|---:|---:|---:|
| 字符数 | 5,989 | 6,701 | 89% |
| BFS 宽度代理 | 9.88 | 12.69 | 78% |
| DFS 深度代理 | 4.08 | 6.56 | 62% |
| Step 节点数 | 31.49 | 31.35 | 100% |
| 条件数量 | 50.69 | 62.27 | 81% |

训练 Requirement 并没有缺少 Step：Step 节点数与 Eval 基本相同。主要差距在于：

- 决策链更浅；
- 同一节点下需要竞争的候选分支更少；
- 条件组合与优先级冲突更少；
- Requirement 虽然写得较长，但更偏显式、平铺的规则列表。

## 6. 为什么 Requirement 差距不大，Reasoning 差距却很大

### 6.1 Requirement 测量规则库，Reasoning 测量单条样本的实际搜索

Requirement 类似程序代码，Input 类似测试用例。两份代码长度接近，不代表测试用例会执行相同数量的分支。

训练 Requirement 可以包含很多 Step，但某条训练 Input 可能直接给出唯一判定信号，只激活一个浅层分支。Eval Input 则可能同时出现旧状态、最新状态、客户自述、权威系统信号和多个业务诉求，需要排除候选分支并处理优先级。

### 6.2 BFS 和 DFS 的影响是组合性的，不是线性的

训练 BFS 为 Eval 的 78%，DFS 为 62%。搜索空间同时受宽度和深度影响，二者下降会组合放大。这里的 BFS/DFS 是代理指标，不能直接代入指数公式，但它们说明“少几层判断”和“每层少几个候选”可以让实际搜索轨迹缩短数倍。

### 6.3 Answer-first 生成降低了条件熵

当前流程先确定目标 Answer，再反向构造支持该 Answer 的 Input，并要求主线明确、答案唯一。生成模型知道目标答案，因此倾向于提供足够直接的证据。

这相当于：

> 已知答案以后，为该答案构造一份能够通过验证的证明。

而 Eval 是：

> 不知道答案，需要在完整规则空间中搜索、排除、解决冲突并得到答案。

即使加入支线干扰，只要提示继续要求“主线明显且答案唯一”，干扰通常也容易排除，不一定形成真正的分支竞争。

### 6.4 只保留 ok 造成可解性选择偏差

独立回推 Answer 与目标不一致的记录不会进入训练 SFT。Gemini Input 批次中，rejected Reasoning 的平均长度约 2,344 字符，而 ok 为约 1,366 字符，说明筛选确实更容易保留短而确定的样本。

这种筛选是保证标签一致性所必需的，但会同时过滤掉一部分真正困难、存在合理竞争分支的样本。

### 6.5 模型和推理档位也影响长度

Eval Kimi 来自 `k3sopmaze1-ckpt_-1`，训练 Reasoning 来自多个 Kimi 网关，并且主训练批次主要使用 Medium。已有 Max 公平小样本的平均 Reasoning 约为 3,020 字符，高于 Medium 的 1,630，说明推理档位和服务端停止策略解释了一部分差距。

不过 Max 仍明显短于测试 1 分样本，说明模型配置不是唯一原因，Input 的实际决策难度仍存在差距。

## 7. 其他分布问题

- 训练数据只覆盖 17/23 个 Eval subset，缺少 1、3、6、8、15、19。
- 训练量最大的 6 个 subset 占全部训练数据的 85.4%。
- subset 17 单独占 37.2%。
- 缺失的 subset 1、3、19 包含测试集中 Reasoning 很长、机制较特殊的任务。
- 同一 `target_subset` 下的一些合成场景仍是近邻映射，不能保证 hard gate 和输入信号与 Eval 完全一致。

因此，训练无明显提升不只是单条样本简单，也可能来自机制覆盖不足和训练配额严重失衡。

## 8. 下一轮合成建议

### 8.1 不要直接要求模型写更长的 Reasoning

测试 0.2 分样本比 1 分样本更长，证明长度本身不是质量目标。下一轮应提升可验证的决策难度，而不是设定最小 Reasoning 字数。

### 8.2 为每条 Input 记录实际激活难度

建议新增以下内部指标：

- 初始可能命中的分支数量；
- 必须排除的候选分支数量；
- 命中的决策链长度；
- 优先级冲突数量；
- 历史状态被新状态覆盖的次数；
- system、assistant、user 之间的证据冲突数量；
- 跨字段一致性约束数量；
- 最终 Answer 依赖的独立证据数量。

### 8.3 使用真正的困难构造

困难样本应包含：

- 两个表面可匹配、但只有一个满足优先级的分支；
- 旧权威状态与新权威状态冲突；
- 客户自述与系统事实冲突；
- 当前诉求与历史诉求不同；
- 多字段必须联合才能确定 Answer；
- 缺省规则与显式规则竞争；
- 必须回退或继续查询，不能直接选择最终分支。

所有困难样本仍必须保证答案唯一、可由规则复算。

### 8.4 做严格受控消融

固定以下条件，只改变 Input 难度：

- 相同 subset；
- 相同 Requirement；
- 相同模型和 endpoint；
- 相同 reasoning effort；
- 相同样本数量和 Answer 分布。

分别比较清晰 Input 与多分支 Input 的严格答案准确率、训练收益和 Reasoning 分布。这样才能判断训练无提升究竟来自样本过简单、覆盖不足，还是模型及训练配置。

## 9. 最终判断

当前证据支持以下结论：

1. 测试全量 Reasoning 的巨大长度部分来自 0.2 分和 0 分样本，不能全部解释为有效难度。
2. 即使只比较测试 1 分样本，并控制 subset 分布，训练 Reasoning 仍只有约 42%。
3. 训练 Requirement 的文字长度和 Step 数并未大幅减少，但 BFS、DFS 和条件复杂度更低。
4. Answer-first 反向构造与只保留一致样本，使训练 Input 更容易呈现唯一、直接的判定证据。
5. 因而当前训练数据更像“覆盖许多显式规则的简单执行样本”，而不是“需要在规则之间搜索和消歧的困难样本”。

这很可能是训练数据量较大但 Eval 没有明显提升的重要原因之一。
