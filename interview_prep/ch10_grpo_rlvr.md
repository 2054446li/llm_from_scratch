# ch10 — GRPO 与 RLVR

> 当前最热门的后训练算法，DeepSeek-R1 的核心，必背必懂。

---

## Q1 ⭐ GRPO 的核心思想？它相比 PPO 砍掉了什么？
**GRPO（Group Relative Policy Optimization）**：对同一个 prompt 采样一组（G 个）回复，用**组内奖励的均值和标准差**做归一化，得到每个回复的优势，**去掉了 Critic（Value 网络）**。

```
对 prompt x 采样 G 个回复 {y_1, ..., y_G}
每个回复奖励 r_i
组内归一化优势：Â_i = (r_i - mean(r)) / std(r)
```

**相比 PPO 砍掉的**：
- **Critic 网络**：PPO 需要一个与 Actor 同量级的 Value 网络估计 V(s)，GRPO 用组内均值当基线，直接省掉 Critic → **省一半显存 + 省 Critic 训练**。

**为什么能砍**：Critic 的作用是提供 baseline 降方差，GRPO 用"同 prompt 下多个回复的平均奖励"作为 baseline，同样能降方差，且无需额外网络。

## Q3 ⭐ GRPO 的 KL 为什么放在 loss 里？k1/k2/k3 估计器区别？
**位置区别**：
- PPO：KL 加在每步 reward 上（`R_t = r - β·KL_t`），影响优势估计。
- GRPO：KL 作为独立正则项加在 loss 上，不进入优势计算，更直接。

**k1/k2/k3 估计器**（估计 `KL(π_θ||π_ref)`）：
- **k1**：`log(π_θ/π_ref)`，无偏但方差大，可能为负。
- **k2**：`½(log(π_θ/π_ref))²`，低方差但有偏。
- **k3**：`(π_ref/π_θ) - 1 - log(π_ref/π_θ)`，**无偏且恒非负、低方差**，GRPO/PPO 默认使用。

**k3 为什么低方差？** 记 `r = π_ref/π_θ`，则 `k3 = k1 + (r - 1)`（其中 `k1 = -log r`）。多出的 `(r-1)` 是一个**控制变量（control variate）**：在 π_θ 下 `E[r] = Σπ_ref = 1`，所以 `E[r-1] = 0`——加上它**不改变期望（仍无偏）**。而 `(r-1)` 与 `-log r` **负相关**：某样本 r 偏大时，`-log r` 偏小、`(r-1)` 偏大，两者波动相互抵消，从而压低整体方差。此外 k3 对任意 `r>0` 恒有 `r-1-log r ≥ 0`（log 凸性，r=1 取等），单样本不会出现"负 KL"这种噪声值，取值范围受约束、极端值更少，方差自然更低、训练更稳。参见 [[13_unbiased_kl_estimate]]。

## Q4 ⭐🔥 RLVR（可验证奖励强化学习）是什么？为什么和 GRPO 是绝配？
**RLVR（RL with Verifiable Rewards）**：用**规则/程序验证**替代奖励模型——数学题验证答案是否正确，代码题运行单元测试，形式化证明用 Lean 检查。奖励是 0/1（或带格式奖励）。

**为什么和 GRPO 是绝配**：
1. **无需训练 RM**：省去 RM 训练和 reward hacking 问题。
2. **组内对比天然合理**：同一道数学题采样多个解，有对有错，组内归一化优��信号清晰。
3. **可扩展**：验证是自动的，可以大规模生成训练信号。

**局限**：只适用于**可验证领域**（数学、代码、逻辑），开放域（写作、对话）仍需 RM 或 RLAIF。

## Q5 ⭐🔥 DeepSeek-R1 的四段式训练流程？
1. **冷启动 SFT**：用少量高质量 CoT 数据 SFT，让模型有基本的推理格式（避免 R1-Zero 的可读性问题）。
2. **推理 RL（GRPO + RLVR）**：在数学/代码上用规则奖励做大规模 RL，激发推理能力。
3. **拒绝采样 + SFT**：用 RL 模型生成大量回复，用规则/RM 筛选高质量的，再做一轮 SFT（扩展到通用领域）。
4. **全场景 RL**：结合规则奖励（推理）和 RM（通用对齐），做最终对齐。

**R1-Zero**：跳过冷启动，纯 RL 从 base 模型直接训练。能涌现推理能力，但有**可读性差、语言混杂**问题（中英文混用），所以正式版 R1 加了冷启动 SFT。

## Q6 ⭐🔥 为什么 RL 提升 Maj@K 却不提升 Pass@K？这意味着什么？
- **Pass@K**：采样 K 次，至少一次正确的概率（衡量能力上界）。
- **Maj@K**：采样 K 次，多数投票正确的概率（衡量稳定性）。
- **现象**：RL 后 Maj@K 显著提升，但 Pass@K 提升有限甚至不变。
- **含义**：RL **主要是把 base 模型已有的正确答案的概率提高**（让正确答案更容易被采到），而**不是注入新能力**。能力上界由预训练决定，RL 是"能力激发/重分配"而非"能力创造"。这是理解 RL 作用边界的关键认知。

## Q7 🔥（进阶）Spurious Rewards 现象是什么？
- **现象**：在某些模型（如 Qwen2.5-Math）上，即使用**随机奖励或纯格式奖励**（与正确性弱相关甚至无关），RLVR 也能带来显著提升。
- **原因**：奖励只是"触发器"，激活了模型预训练中已有的潜在推理策略（如 code reasoning），而非真正教会新东西——再次印证"RL 激发不注入"。
- **关键 caveat**：**高度模型依赖**——同样的 spurious reward 在 Llama3/OLMo2 上不 work。所以看到某个 RLVR trick 的结果时，要问"这是通用的还是特定模型的？"
- **面试价值**：能说出这个，说明你读过 2025 的前沿争议，不是只会背 GRPO 公式。

## Q8 🔥（进阶）GRPO 在 agentic / 多轮场景为什么会坍缩？
- **现象**：从 base 用纯可验证奖励（Zero RL）做多轮工具推理时，GRPO 常出现**突然的 reward 崩溃**（catastrophic reward collapse），而 PPO 在同设定下更稳定。
- **一个尖锐的机制发现**：问题出在 GRPO 的 **std 归一化**——当一组 rollout 全部失败（all-fail group）时，z-score 归一化后的优势对奖励缩放不变，导致有界奖励变成无界的更新压力，退火也救不了。**去掉 std 归一化**就能把 0% 拉回基线水平。
- **机制拆解（为什么除 std 会炸）**：
  1. GRPO 优势 `Â_i = (r_i - mean(r)) / std(r)`，问题出在**除以 std**。
  2. **对奖励缩放不变**：奖励同乘常数 c，分子分母各出一个 c 约掉，`Â` 不变——优势只反映组内相对分布，与奖励绝对尺度无关。
  3. **难题 → std 趋近 0**：题越难，一组里对的越少（如 8 个里 1 个对），`std → 0`，于是 `Â = (r_i - mean)/std → ±∞`。奖励本身**有界**（0/1，差距≤1），除以趋 0 的 std 后梯度变**无界**，某个偶然答对的 rollout 得到爆炸性更新，一两次就把策略拽崩——这就是「有界奖励变无界更新压力」。降学习率（退火）救不了，因为病根在**分母**不在步长。
  4. **PPO 为何稳**：PPO 不做组内 std 归一化，用 GAE + value baseline，优势尺度绑在有界奖励上，不会因某组特别难而把分母除没。
- **联系**：这与 Dr.GRPO 指出的"std 归一化难度偏置"是同一根源（ch11 Q2），也是 DAPO"去 std 归一化"的动机。
- **面试价值**：回答"GRPO 和 PPO 谁更稳"时，能指出 GRPO 在长程/agentic 下的这个具体失效点，很加分。

---

## 一句话速记
- GRPO：组内均值当 baseline，砍掉 Critic，省一半显存。
- KL：放 loss 里，用 k3 无偏非负估计器。
- RLVR：规则验证替代 RM，与 GRPO 绝配，限可验证领域。
- R1：冷启动 SFT → 推理 RL → 拒绝采样 SFT → 全场景 RL。
- RL 提升 Maj@K 不提升 Pass@K：激发已有能力，不创造新能力。
- Spurious rewards：随机奖励也能提升（激发潜在策略），但高度模型依赖。
- GRPO 在 agentic 下易坍缩，根源是 std 归一化（all-fail 组无界压力）。
