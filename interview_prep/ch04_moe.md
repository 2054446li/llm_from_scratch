# ch04 — 混合专家 MoE

> MoE 是 DeepSeek-V2/V3/Qwen3 的核心架构，后训练工程师必须理解它对训练稳定性的影响。

---

## Q1 ⭐ MoE 的基本原理？为什么用 MoE？
**核心思想**：把 FFN 层替换为 N 个"专家"（独立 FFN），每个 token 只激活其中 K 个（稀疏激活）。

```
MoE(x) = Σ_{i∈TopK} gate_i(x) · Expert_i(x)
gate(x) = Softmax(x · W_gate)  # 路由分数
```

**为什么用**：
- **参数量 vs 计算量解耦**：总参数量大（多个专家），但每个 token 只过 K 个专家，**激活参数量**（实际计算量）远小于总参数量。
- 同等计算预算下，MoE 可以有更大的"知识容量"。
- DeepSeek-V3：671B 总参数，每 token 激活约 37B。

---

## Q2 ⭐ 负载均衡损失（Load Balance Loss）是什么？为什么需要它？
**问题**：路由器（gate）容易退化——总是把 token 发给少数几个专家（专家坍缩），其他专家得不到训练，浪费参数。

**解决**：加辅助损失，惩罚专家负载不均：
```
L_balance = α · N · Σ_i (f_i · P_i)
```
- `f_i`：专家 i 实际处理的 token 比例
- `P_i`：路由器给专家 i 的平均概率
- 两者乘积最小化 → 鼓励均匀分配

**DeepSeek 的改进**：引入**专家偏置（bias）**动态调整路由，替代辅助损失，减少对主任务 loss 的干扰（V3 采用）。

---

## Q3 🔥 Token Drop 是什么？对后训练有什么影响？
**背景**：每个专家有容量上限（capacity factor），超出的 token 被丢弃（token drop）。

**训练时**：可接受，随机性有正则效果。
**推理时**：不能丢 token，通常关闭 token drop 或用 expert choice 路由。
**后训练影响**：RL rollout 时若有 token drop，训练-推理不一致（训练时丢了 token，推理时没丢），会引入偏差。这是 MoE 模型做 RL 时需要特别注意的工程细节。

---

## Q4 🔥 DeepSeekMoE 的创新：共享专家 + 细粒度专家
**共享专家（Shared Expert）**：部分专家对所有 token 都激活（不参与路由），负责处理通用知识，减轻路由专家的负担。

**细粒度专家**：把每个大专家拆成多个小专家，增加路由灵活性（同等激活参数下，可以组合更多专家的知识）。

**GSPO 与 MoE 的关联**🔥：GSPO（Qwen3 采用）把重要性采样比从 token 级改为序列级，正是为了缓解 MoE 模型在长序列 RL 训练时 token-ratio 连乘导致的高方差，稳定 MoE 的 RL 训练。

---

## Q5 MoE 训练的主要挑战？
1. **通信开销**：All-to-All 通信（token 路由到不同设备上的专家），是 MoE 分布式训练的主要瓶颈。
2. **负载不均**：需要辅助损失或动态偏置。
3. **RL 训练稳定性**：token-ratio 连乘方差大（GSPO 解决）；token drop 导致训练-推理不一致。
4. **显存**：总参数量大，需要专家并行（EP）。

---

## 一句话速记
- MoE：稀疏激活，参数量与计算量解耦，同预算更大知识容量。
- 负载均衡损失：防专家坍缩，DeepSeek 用动态偏置替代辅助损失。
- Token drop：推理关闭，RL 时需保证训练-推理一致。
- GSPO：序列级 ratio，专为稳定 MoE 的 RL 训练设计。
