# ch16 — 横向对比与选型决策题（面试杀手题）

> 这是最能区分候选人的一类题。不考单点知识，考"什么时候用什么、为什么"。每道题给决策逻辑，不要死背结论。

---

## Q1 ⭐⭐ 什么时候用 SFT，什么时候用 RL？
**决策逻辑**：
| 场景 | 选择 | 理由 |
|------|------|------|
| 有大量高质量"标准答案"数据 | **SFT** | 直接模仿最省事，RL 是杀鸡用牛刀 |
| 只有"哪个更好"的偏好信号，无标准答案 | **RL / DPO** | 偏好信号适合排序优化，不适合 SFT |
| 有可验证的正确性（数学/代码） | **RL（RLVR）** | 规则奖励信号强，RL 能激发推理 |
| 要模型探索、超越示范数据 | **RL** | SFT 只能模仿，无法超越标注上界 |
| 要对齐风格/安全/帮助性 | **SFT 打底 + RL 精调** | 主流 pipeline |

**核心区分**：
- **SFT 是模仿**：学"标准答案长什么样"，上界是标注质量。
- **RL 是优化**：学"什么更好"，能探索标注外的更优解，但需要奖励信号。
- **标准答案**：SFT 一定要有明确的目标输出；RL 只需要"能判断好坏"（奖励/偏好）。

**实践顺序**：几乎总是 **先 SFT 冷启动**（教格式、教基础能力）**再 RL**（精调、激发探索）。纯 RL（R1-Zero）能 work 但有可读性问题。

---

## Q2 ⭐⭐ DPO vs PPO vs GRPO 三方对比？（最高频对比题）
| 维度 | PPO | GRPO | DPO |
|------|-----|------|-----|
| on/off-policy | on-policy | on-policy | **off-policy（离线）** |
| 需要 RM？ | 是（显式） | 否（RLVR）/是 | 否（隐式奖励） |
| 需要 Critic？ | **是** | **否**（组内基线） | 否 |
| 需要在线采样？ | 是 | 是 | **否** |
| 模型数量 | 4（Actor/Critic/RM/Ref） | 2-3（无 Critic） | 2（Policy/Ref） |
| 显存/资源 | 最重 | 中 | 最轻 |
| 能否探索 | 能 | 能 | **不能**（限于偏好数据） |
| 稳定性 | 调参难 | 中（熵坍缩问题） | 稳定 |
| 适用场景 | 通用 RLHF | 推理/可验证任务 | 资源受限、有偏好对 |

**一句话串**：
- **PPO → GRPO**：砍掉 Critic，用组内均值当 baseline，省一半显存。
- **PPO/GRPO → DPO**：把"RM+在线 RL"压成离线分类损失，无采样无 RM，但失去探索能力。
- **根本分野**：DPO 是 off-policy（只能学固定数据），PPO/GRPO 是 on-policy（能探索新回答）。

---

## Q3 ⭐ 为什么很多前沿实验室从 PPO 转向 DPO 又转向 GRPO？
- **PPO → DPO 的动机**：PPO 四模型显存重、调参难、RM 需要单独训练且易 reward hacking。DPO 简单稳定、资源省，**通用对齐**任务上够用。
- **DPO → GRPO 的动机**：DPO 是 off-policy，无法探索，在**推理任务**上天花板低（不能发现新解法）。GRPO + RLVR 能在线探索 + 用规则奖励激发推理，是 reasoning 模型的主流。
- **结论**：没有银弹。**通用对齐用 DPO（省事），推理任务用 GRPO+RLVR（能探索）**。

---

## Q4 ⭐ RLHF vs RLVR vs RLAIF 怎么选？
- **RLHF**：人类标注偏好 → RM → RL。质量高但标注贵、慢，有 reward hacking。用于**通用对齐**（帮助性、安全性）。
- **RLVR**：规则/程序验证当奖励。无标注、无 hacking，但**限可验证领域**（数学、代码、逻辑）。
- **RLAIF**：AI 标注偏好替代人类。可扩展、便宜，但 AI 偏好有系统性偏差（偏好冗长/奉承）。
- **决策**：可验证任务优先 RLVR；开放域对齐用 RLHF/RLAIF（预算紧用 RLAIF）。

---

## Q5 ⭐ 离线蒸馏 vs On-Policy Distillation vs RL 怎么选？
- **离线蒸馏**：学生学教师固定输出。最省，但有曝光偏差（学生推理时偏离教师轨迹无法恢复）。
- **OPD**：学生自己采样，教师在学生分布上给密集监督。信号密、无曝光偏差，但需要教师在线打分。
- **RL**：奖励稀疏但能探索超越教师。
- **决策**：有强教师且想高效传递能力 → OPD；无教师但有奖励信号 → RL；快速低成本 → 离线蒸馏。DeepSeek-V4 用"分域 RL 练强 + OPD 统一"结合两者。

---

## Q6 ⭐ KL 约束该不该加？放 reward 还是 loss？
- **该不该加**：通用 RLHF **必须加**（防 reward hacking、防偏离 SFT 太远）；**纯推理 RLVR 可以不加或弱加**——因为可验证奖励可靠，不怕 hacking，且长 CoT 推理本就需要模型大幅偏离 base（加 KL 反而限制推理能力发展）。
- **放哪**：PPO 放 reward（逐 token 减 KL）；GRPO 放 loss（独立正则项）。放 loss 更直接，不干扰优势估计。
- **估计器**：默认 k3（无偏、非负、低方差）。

---

## Q7 🔥 什么时候会遇到"RL 提升 Maj@K 不提升 Pass@K"？这限制了什么？
- **现象**：RL 后多数投票准确率(Maj@K)升，但采样上界(Pass@K)不升。
- **含义**：RL 主要**重分配概率**（让已有的正确答案更容易被采到），不创造新能力。
- **限制**：模型能力上界由**预训练**决定，RL/后训练只能激发不能注入。所以想要更强能力，根子在预训练数据和规模，而非后训练算法。

---

## Q8 🔥（进阶）为什么 RL 比 SFT 遗忘更少？
- **现象**：同等目标任务表现下，RL 比 SFT 造成的通用能力遗忘更少。
- **原因（主流假说）**：RL 用**近似 on-policy 数据**，mode-seeking，参数更新更保守，倾向保留原有"能力电路"；SFT 在 off-policy 数据上优化，更容易破坏已有电路。遗忘程度与"到 base 策略的 KL 距离"正相关。
- **实践启示**：想减少遗忘——混入原分布数据（replay）、用 on-policy 数据、迭代式 SFT、冻结关键参数。

# 二、后训练数据工程与流程决策（应用题，后训练岗差异化考点）

> 这部分不考算法公式，考"怎么做数据、怎么判断流程"。是后训练工程师区别于纯研究岗的核心能力，面试常以开放题形式出现。

---

## Q9 ⭐⭐ 如何判断 SFT 是否已经"做到头"（该停了）？
没有单一指标，要综合多个信号：
1. **验证集 loss 平台/回升**：训练 loss 还在降但**验证集 loss 不再降甚至回升** → 开始过拟合，该停。这是最直接的信号。
2. **下游任务饱和**：在目标 benchmark（如 IFEval 指令遵循、领域测试集）上表现不再提升，甚至因过拟合下降。
3. **通用能力开始退化**：监控"held-out 的通用能力"（多语言、常识、代码）——一旦明显下滑，说明 SFT 过头开始灾难性遗忘。
4. **输出多样性/熵下降过快**：SFT overtraining 会让熵过度坍缩，**损害后续 RLVR**（过训的 SFT 会加剧 RL 阶段熵坍缩，甚至导致 rank inversion）。所以为下游有 RL 的 pipeline，SFT 更要"见好就收"。
5. **epoch 经验值**：通常 1-3 epoch，超过后收益递减、风险上升。

**关键 mindset**：SFT 的目标是"教格式 + 激发能力打底"，不是把 loss 压到最低。**为下游 RL 服务的 SFT，宁可欠训一点，保留熵和探索空间。**

**追问：怎么区分"欠训"和"过训"？** 欠训：验证 loss 还在稳定下降、格式/指令遵循还不稳定。过训：验证 loss 回升、通用能力掉、输出趋于单一模板。

---

## Q10 ⭐⭐ 一条数据应该加入到哪个阶段（SFT / RM / RL）？决策树
按"这条数据带的是什么信号"来分：
```
这条数据有明确的"标准答案/示范回复"吗？
├─ 有，且高质量、要模型模仿其格式与内容  → SFT
│    （如：精标的指令-回复、CoT 示范、冷启动推理数据）
│
├─ 没有标准答案，但有"A 比 B 好"的成对比较 → RM 训练 / DPO
│    （如：人工或 AI 标注的 chosen/rejected 偏好对）
│
├─ 有客观可验证的正确性（答案/单测/编译）  → RLVR (GRPO)
│    （如：数学题带答案、代码题带测试用例）
│
└─ 只有标量奖励信号、需要在线探索           → PPO/GRPO
     （如：RM 打分驱动的在线 RL）
```
**更细的判断维度**：
- **信号类型**：示范(demonstration)→SFT；偏好(preference)→RM/DPO；可验证(verifiable)→RLVR；标量奖励→PPO。
- **数据质量**：最高质量的少量精标数据留给 SFT 冷启动（教模型"什么是好"）；规模化的、噪声可容忍的留给 RL/偏好。
- **难度**：太简单的题对 RL 无梯度（组内全对，优势=0，应过滤/进 SFT）；有对有错的中等难度题最适合 RLVR。
- **同一条 prompt 可跨阶段复用**：先在 SFT 用示范答案，再在 RL 阶段用它做 rollout（有答案可验证）。

---

## Q11 ⭐ 拒绝采样（Rejection Sampling）在后训练里怎么用？
- **做法**：用当前模型对 prompt 采样多条回复，用 RM/规则/验证器筛出高质量的，再拿这些高质量样本做 SFT。
- **为什么有效**：等于用"模型自己能力上限内的最好输出"来自我提升，是 on-policy 数据（比外部标注更贴合模型分布，遗忘少）。
- **R1 的用法**：R1 第三阶段就是用 RL 模型做拒绝采样 + SFT，把推理能力扩展到通用领域。
- **和 Best-of-N 的关系**：BoN 是推理时选最优；拒绝采样是把 BoN 的"选出的最优"回收成训练数据。

---

## Q12 ⭐ SFT 和 RL 的数据配比怎么定？
- **没有固定公式**，但有原则：
  - **SFT 数据要多样**（覆盖任务类型），防止偏科和遗忘；质量 > 数量（LIMA）。
  - **RL 数据要"可区分难度"**：太简单（全对）和太难（全错）的 prompt 对 GRPO 无梯度贡献，动态采样应过滤掉（DAPO 的做法）。
  - **领域配比影响能力此消彼长**：多领域一起 RL 会互相干扰（V4 用分域 RL + OPD 统一解决）。
- **混入原分布数据**：SFT/RL 阶段都建议混少量预训练或通用数据（replay），缓解遗忘。

---

## Q13 ⭐ 数据去污染（decontamination）是什么？为什么关键？
- **是什么**：确保训练数据（尤其合成/爬取的）不包含评测 benchmark 的原题，否则分数虚高、不反映真实能力。
- **做法**：n-gram 重叠检测、embedding 相似度匹配，剔除与测试集高度重合的样本。
- **为什么关键**：后训练大量用合成数据和网络数据，污染风险高；面试官问"你怎么保证评测可信"时，去污染是标准答案。

---

## Q14 🔥 合成数据（Synthetic Data）的构造与风险？
- **构造**：用强模型生成（distillation）、Self-Instruct（自举指令）、Evol-Instruct（逐步加难）、拒绝采样回收。
- **风险**：
  1. **分布坍缩/多样性下降**：反复用模型生成数据训模型，多样性递减（model collapse）。
  2. **继承教师偏差**：教师的错误和偏好（冗长、奉承）被放大。
  3. **污染**：合成数据可能无意中包含评测题。
- **缓解**：人工/规则过滤、多样性约束、去污染、混入真实数据。

---

## 一句话速记（数据工程）
- SFT 做到头的信号：验证 loss 回升 + 通用能力退化 + 熵坍缩过快；为下游 RL 宁可欠训。
- 数据分阶段：示范→SFT，偏好→RM/DPO，可验证→RLVR，标量奖励→PPO。
- 拒绝采样：采多条→筛最优→回收做 SFT（on-policy 自提升）。
- RL 数据过滤全对/全错组（无梯度）；去污染保证评测可信。

---

## 一句话速记（算法对比）
- SFT=模仿(要标准答案)，RL=优化(要奖励信号，能探索)。
- PPO→GRPO：砍 Critic；PPO/GRPO→DPO：离线化失探索。
- 推理任务 GRPO+RLVR，通用对齐 DPO/RLHF。
- 纯 RLVR 可不加 KL；RL 比 SFT 遗忘少（on-policy mode-seeking）。
- RL 提升 Maj@K 不提升 Pass@K：激发不注入，上界看预训练。
