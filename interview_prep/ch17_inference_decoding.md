# ch17 — 推理时解码策略（Inference-Time Decoding）

> 训练完成后，推理阶段的解码策略直接影响输出质量和计算成本。这是面试中越来越高频的话题，尤其是 reasoning 模型兴起后。

---

## Q1 ⭐ 贪心解码 vs 采样解码，各自适合什么场景？
| 策略 | 机制 | 适合场景 | 缺点 |
|------|------|----------|------|
| **贪心（Greedy）** | 每步选最高概率 token | 确定性任务（翻译、摘要、代码补全） | 容易陷入重复、次优局部解 |
| **温度采样（Temperature）** | 按 softmax(logits/T) 采样 | 创意写作、多样性需求 | T 太高→乱；T 太低→退化为贪心 |
| **Top-k** | 只从概率最高的 k 个 token 中采样 | 通用 | k 固定，不适应分布形状变化 |
| **Top-p（Nucleus）** | 从累积概率 ≥ p 的最小集合中采样 | 通用，比 top-k 更自适应 | p 需调参 |
| **Min-p** | 过滤掉概率 < p_min × max_prob 的 token | 推理任务，保留高置信 token | 较新，调参经验少 |

**核心直觉**：温度 T 控制"探索程度"——T→0 退化为贪心，T→∞ 退化为均匀随机。推理任务通常用低温（0.6-0.8）保证连贯性。

## Q2 ⭐⭐ Best-of-N（BoN）是什么？和 Beam Search 有什么区别？
**Best-of-N**：
- 独立采样 N 条完整回答，用 RM 或规则选最好的一条。
- 简单、并行友好，是 test-time scaling 的基础。
- 计算成本 O(N)，但每条独立，无法共享前缀计算。

**Beam Search**：
- 维护 k 条"候选序列"，每步扩展并保留得分最高的 k 条。
- 适合短序列、确定性任务（机器翻译）。
- 长序列上容易产生"重复、无聊"输出（beam search curse）。
- 不适合 LLM 开放生成：序列越长，beam 越容易收敛到相似路径。

**关键区别**：BoN 是"生成后选择"，Beam Search 是"生成中剪枝"。BoN 更适合 LLM + RM 的现代范式。

## Q3 ⭐⭐ Test-Time Scaling（推理时扩展）是什么？为什么重要？
**核心思想**：推理时投入更多计算（更多采样、更长思考链、更多验证步骤）来提升准确率，而不是只靠更大模型。

**主要形式**：
1. **Best-of-N**：采样 N 条，选最好的。Pass@1 随 N 增大而提升。
2. **多数投票（Majority Voting / Maj@K）**：采样 K 条，选出现最多的答案。
3. **Sequential Revision**：模型自我修正，多轮迭代。
4. **MCTS / Tree Search**：用树搜索探索推理路径（o1 类模型的核心）。
5. **长 CoT**：让模型在 `<think>` 中展开更长推理链再给答案。

**为什么重要**：
- 打破"只能靠更大模型"的范式，用计算换准确率。
- 对于难题（竞赛数学、代码），test-time scaling 效果显著。
- 是 o1/R1 类 reasoning 模型的核心设计哲学。

**局限**：
- 对"简单问题"收益递减（已经 Pass@1=1，多采样无意义）。
- 需要可靠的验证器（RM 或规则）来选最优答案，否则 BoN 无效。
- 延迟增加，不适合实时场景。

## Q4 ⭐ Pass@K vs Maj@K vs Pass@1 的关系？
- **Pass@1**：单次采样正确率。日常使用的标准指标。
- **Pass@K**：K 次采样中至少一次正确的概率。衡量模型"能力上界"。
- **Maj@K**：K 次采样中多数投票的正确率。衡量"可靠性"。

**关系**：
- Pass@K ≥ Maj@K ≥ Pass@1（通常）。
- RL 训练主要提升 Maj@K（重分配概率），Pass@K 基本不变（能力上界由预训练决定）。
- 如果 Pass@K 很高但 Pass@1 很低：模型"会但不稳"，适合用 BoN/投票提升。
- 如果 Pass@K 低：模型根本不会，再多采样也没用，需要训练。

## Q5 ⭐ 什么是 Speculative Decoding（推测解码）？
**动机**：LLM 自回归解码慢（每步都要跑完整大模型），能否加速？

**方法**：
1. 用小模型（draft model）快速生成 K 个 token 草稿。
2. 大模型（target model）并行验证这 K 个 token。
3. 接受与大模型分布一致的 token，拒绝不一致的，从拒绝点重新采样。

**关键性质**：
- **无损**：输出分布与大模型独立解码完全等价（数学上可证明）。
- **加速比**：取决于小模型与大模型的"对齐程度"，通常 2-4x。
- **适用场景**：大模型推理加速，尤其是 batch size=1 的实时场景。

**变体**：
- **Self-speculative**：用同一模型的早期层做 draft（层跳过）。
- **Medusa**：在模型顶部加多个并行 head 预测未来 token。

## Q6 ⭐ 什么是 Chain-of-Thought（CoT）？为什么有效？
**CoT**：让模型在给出最终答案前，先输出中间推理步骤。

**为什么有效**（主流解释）：
1. **分解复杂问题**：把多步推理拆成单步，每步更容易。
2. **利用模型自身知识**：中间步骤激活相关知识，减少"跳步"错误。
3. **自我纠错机会**：写出中间步骤后，模型可以"看到"前面的推理并修正。
4. **训练信号**：长 CoT 数据让模型学会"慢思考"模式。

**触发方式**：
- Zero-shot CoT："Let's think step by step."
- Few-shot CoT：提供带推理步骤的示例。
- 训练时强化：RLVR 奖励正确答案，模型自发学会用 CoT。

**局限**：
- 增加 token 数量，延迟和成本上升。
- 中间步骤可能"看起来合理但实际错误"（unfaithful CoT）。
- 对简单问题反而可能引入错误（overthinking）。

## Q7 🔥 Reasoning Model（o1/R1 类）的解码和普通模型有什么不同？
| 维度 | 普通模型 | Reasoning 模型 |
|------|----------|----------------|
| 解码策略 | 直接生成答案 | 先生成长 `<think>` 再给答案 |
| 推理链长度 | 短（几句话） | 长（几百到几千 token） |
| 训练目标 | 模仿标准答案 | RLVR 激励正确答案，CoT 自发涌现 |
| Test-time compute | 固定 | 可扩展（更难题→更长思考） |
| 温度 | 通常低 | 通常稍高（需要探索） |
| 验证 | 无 | 内置自我验证（"wait, let me reconsider"） |

**核心差异**：Reasoning 模型把"思考"显式化为 token 序列，让 test-time scaling 成为可能——更难的题可以"想更久"。

---

## Q8 🔥（进阶）为什么 Reasoning 模型会出现"过度思考"（Overthinking）？
- **现象**：模型对简单问题也生成极长推理链，浪费计算，有时反而出错。
- **原因**：RLVR 训练时，模型发现"更长的 CoT 在难题上有效"，泛化到了简单题。
- **解决方向**：
  1. 奖励函数加入长度惩罚（DAPO、DR-GRPO 等）。
  2. 训练时混入简单题的短回答示例。
  3. 推理时设置最大 thinking token 预算（budget forcing）。
- **权衡**：过度压缩思考链会损害难题性能，需要在长度和准确率间平衡。

---

## 一句话速记
- 贪心=确定性，采样=多样性，top-p 比 top-k 更自适应。
- BoN=生成后选，Beam Search=生成中剪枝；LLM 用 BoN。
- Test-time scaling：用计算换准确率，Pass@K 是上界，Maj@K 是可靠性。
- RL 提升 Maj@K 不提升 Pass@K：激发不注入。
- Speculative Decoding：小模型起草+大模型验证，无损加速 2-4x。
- CoT：显式中间步骤，分解复杂推理；Reasoning 模型把 CoT 训练成自发行为。
- Overthinking：RLVR 泛化过度，用长度惩罚+预算控制缓解。
