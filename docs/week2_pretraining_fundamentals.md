## 1. 预训练的基础原理

### 1.1 什么是预训练？

**定义**：在大规模无标签数据上，用自监督学习任务训练一个通用语言模型的过程。

**核心特点**：
- 无需人工标注
- 利用大量互联网文本
- 学习通用的语言表示
- 为下游任务提供初始化

### 1.2 预训练的学习目标

主要有三种范式：

1. **自回归建模（Autoregressive）**
   - 目标：预测下一个 token
   - 代表：GPT 系列
   - 适用：生成任务
   - $$L = -\sum_t \log P(x_t | x_1, \ldots, x_{t-1})$$

2. **自编码建模（Autoencoding）**
   - 目标：预测被掩盖的 token
   - 代表：BERT
   - 适用：理解任务
   - $$L = -\sum_{i \in \text{masked}} \log P(x_i | x_{\setminus i})$$

3. **序列到序列建模（Sequence-to-Sequence）**
   - 目标：编码-解码框架
   - 代表：T5、BART
   - 适用：通用任务
   - $$L = -\sum_t \log P(y_t | y_1, \ldots, y_{t-1}, x)$$

### 1.3 为什么预训练有效？

**理论基础**：

1. **语言统计**
   - 自然语言不是随机的，有深层结构
   - 预训练学习这些统计规律

2. **知识压缩**
   - 大规模数据中包含丰富的知识
   - 模型学习压缩和表示这些知识

3. **迁移学习**
   - 学到的表示对多个任务都有帮助
   - 无需从零开始

4. **缩放律**
   - 模型越大，数据越多，性能越好
   - 近似幂律关系

## 2. 因果语言建模（Causal Language Modeling）

### 2.1 核心思想

预测序列中的下一个 token，基于所有先前的 token。

$$P(x_{1:n}) = \prod_{t=1}^n P(x_t | x_{1:t-1})$$

### 2.2 与 RNN 的关键区别

| 特性 | RNN | Transformer（因果） |
|-----|-----|------------------|
| 依赖性 | 顺序 | 完全（通过因果掩码） |
| 计算 | 顺序（不可并行） | 并行 |
| 长距离依赖 | 困难（梯度消失） | 容易（直接路径） |
| 推理效率 | 低 | 高（KV 缓存） |

### 2.3 因果掩码的实现

在自注意力中应用掩码，防止 token 看到未来信息：

```
位置 1 可以看到：位置 1
位置 2 可以看到：位置 1, 2
位置 3 可以看到：位置 1, 2, 3
...
位置 n 可以看到：位置 1, ..., n
```

**数学表达**：

$$\text{Attention}(Q, K, V, \text{mask}) = \text{softmax}\left(\frac{QK^T}{\sqrt{d_k}} + \text{mask}\right) V$$

其中 mask 是一个 lower triangular 矩阵，上三角为 $-\infty$。

### 2.4 训练 vs 推理

**训练时**：
- 有因果掩码
- 可以并行处理整个序列
- 一次前向计算多个 token 的损失

**推理时**：
- 自回归生成
- 一次生成一个 token
- 使用 KV 缓存加速

## 3. Token 化策略

### 3.1 为什么需要 Token 化？

原始文本（字符级）太细粒度：
- 词表大（数万甚至更多）
- 噪声多
- 学习困难

Token 化在字符和词之间找到平衡。

### 3.2 主要 Token 化算法

**1. 字节对编码（BPE - Byte Pair Encoding）**

原理：
- 从字符集开始
- 迭代地合并频率最高的相邻对
- 重复直到词表大小达到预设大小

优点：
- 可以表示任何单词（无 UNK 符号）
- 词表大小可控
- 参数可调

缺点：
- 合并是贪心的
- 不总是最优

应用：GPT 系列

**2. WordPiece（Google）**

原理：
- 类似 BPE，但合并基于概率增益
- 选择使语言模型困惑度下降最多的合并

优点：
- 更优化的合并策略
- 对未见单词处理更好

应用：BERT

**3. SentencePiece（Google）**

原理：
- 不依赖空格分割
- 直接在字节序列上工作
- 语言无关

优点：
- 多语言友好
- 无需预处理
- 可训练 BPE 或 Unigram 两种

应用：XLNet、mBART、Qwen、LLaMA

### 3.3 词表大小的选择

| 词表大小 | 优点 | 缺点 |
|---------|-----|-----|
| 小（< 5K） | 参数少 | 平均 token 长，信息密度低 |
| 中（32K-50K） | 平衡 | 通用选择 |
| 大（100K+） | 平均 token 短，高效 | 参数多，训练困难 |

GPT-3：50257
LLaMA：32000
Qwen：151936（多语言优化）

### 3.4 多语言的 Token 化考量

**问题**：
- 不同语言的字频分布差异大
- 英文友好的 token 化对中文可能低效

**解决方案**：
1. **语言特定的 Token 化**
   - 为每种语言优化词表
   - 但增加复杂性

2. **多语言词表**
   - 单一词表包含多种语言
   - Qwen 使用 SentencePiece 处理

3. **混合方法**
   - 基础层用字节级编码
   - 上层用语言特定的合并

## 4. GPT 系列演进

### 4.1 GPT-1 (2018)

**背景**：
- Transformer 发表仅 1 年
- NLP 仍主要使用 LSTM

**创新**：
- 证明预训练 + 微调的有效性
- 单向 Transformer 用于生成

**规模**：
- 参数：117M
- 训练数据：约 5GB

**影响**：
- 开启预训练范式

### 4.2 GPT-2 (2019)

**关键发现**：
- **"数据规模至关重要"**
- 单纯扩大数据量就能显著改进性能

**改进**：
- 参数：1.5B
- 数据：40GB（WebText，新爬取的高质量互联网文本）
- 架构：优化的 Transformer

**关键贡献**：
- Few-shot 学习能力出现
- 对多任务的零样本迁移
- 生成文本质量显著提升

**重大发现**：
$$\text{Loss} \propto (N + D)^{-\alpha}$$
- 模型大小 N 和数据大小 D 都很重要

### 4.3 GPT-3 (2020)

**"少样本学习"的突破**

改进：
- 参数：175B（两个数量级增加！）
- 数据：约 300B tokens
- 上下文长度：2048 tokens
- 架构改进：使用 MHA、Flash Attention 前身的思想

**关键突破**：
- **In-context learning**：无需梯度更新，通过 prompt 改变行为
- **涌现能力**（Emergent Abilities）：新能力随规模增加而出现

**观察**：
```
Few-shot 性能随模型大小非线性改善
某些任务在特定规模时突然大幅提升
```

### 4.4 GPT-3.5 (2022-2023)

**与 GPT-3 的关键区别**：不仅仅是规模增加

**改进**：
1. **SFT（监督微调）**：使用高质量指令数据
2. **RLHF 对齐**：从人类反馈学习
3. **指令跟随能力**：显著改善

**ChatGPT 的成功**：
- 实际上更可能是 GPT-3.5 or 类似规模
- SFT + RLHF 的威力被充分展现
- 用户体验大幅提升

### 4.5 GPT-4 (2023)

**已知信息受限**，但我们知道的改进：

1. **模型规模**：更大（传言 1T+ 参数，但官方未公开）
2. **数据质量**：更高质量的训练数据
3. **多模态**：支持图像输入（重要突破）
4. **安全性**：更好的安全对齐
5. **推理能力**：多步推理能力增强
6. **可靠性**：一致性和准确性提升

### 4.6 缩放律（Scaling Laws）

**关键规律**：

$$L(N, D) = a \cdot N^{-\alpha} + b \cdot D^{-\beta} + c$$

其中：
- $N$ 是模型参数数
- $D$ 是数据量（tokens）
- $\alpha, \beta$ 通常都在 0.07-0.1 范围内

**启示**：
1. 模型和数据都需要扩展
2. 不存在"最优点"，继续扩大就能改进
3. 计算最优设置：$N:D \approx 1:20$（模型参数与训练 tokens 的比例）

## 5. 预训练数据与规模

### 5.1 数据来源

**Common sources**：
- 网页内容（Common Crawl）
- 书籍（Project Gutenberg、Google Books）
- 代码仓库（GitHub）
- 维基百科
- 学术论文（arXiv、Papers）

**数据量对比**：
| 模型 | 数据量 | 来源特点 |
|-----|------|--------|
| GPT-2 | 40GB | WebText（精选） |
| GPT-3 | 300B tokens | 多源混合 |
| Llama | 1.4T tokens | Common Crawl + Books |
| Qwen | 2.4T tokens | 多语言平衡 |
| DeepSeek | > 5T tokens | 多源高质量 |

### 5.2 数据质量控制

**质量评估**：
1. 文本长度分布
2. 去重（精确匹配和模糊匹配）
3. 去噪（移除垃圾、乱码）
4. 语言识别与分类
5. 敏感内容过滤

**重要发现**：
- 数据质量比数量更重要（某些情况下）
- 去重能显著改进模型性能
- 不同数据源的贡献不均

### 5.3 多语言数据的平衡

**问题**：
- 互联网数据主要是英文（>50%）
- 其他语言的高质量数据稀缺

**解决方案**：
1. **按语言特定的采样**
   - 英文采样率 < 网络占比
   - 稀有语言过采样

2. **质量加权**
   - 高质量源得到更高采样权重
   - 构建语言特定的质量分数

3. **多语言代码混合**
   - 学习语言间的转移关系
   - 帮助低资源语言

## 7. 总结与面试准备

### 7.1 关键知识点

| 概念 | 核心要点 | 面试重点 |
|-----|--------|--------|
| 预训练 | 自监督学习，规模优势 | 为什么有效 |
| 因果建模 | 自回归，next token prediction | 与 BERT 的区别 |
| Token 化 | BPE/SentencePiece，词表权衡 | 多语言考虑 |
| 缩放律 | 模型和数据都重要 | 如何优化 |
| GPT 演进 | 规模、数据、指令微调 | 关键突破点 |

### 7.2 常见面试题

**Q1: 为什么预训练-微调范式有效？**

框架：
- 预训练学习通用知识
- 微调适配任务特定知识
- 迁移学习理论支撑
- 实验证明（逐渐扩大规模）

**Q2: GPT-3 为什么能 Few-shot 学习？**

框架：
- 规模效应（175B 参数）
- 数据多样性（300B tokens，多任务）
- 因果建模的灵活性
- 上下文学习能力出现

**Q3: Token 化如何选择词表大小？**

框架：
- 权衡：平均序列长 vs 参数数量
- 典型选择：32K-50K
- 多语言时需要考虑语言特性
- 实验验证不同大小的效果

**Q4: 缩放律的实用意义？**

框架：
- 不存在"完美大小"
- 继续扩展就能改进
- 计算最优配置：N:D ≈ 1:20
- 指导资源分配

### 7.3 深度追问准备

- "数据和参数哪个更重要？"
  - 答：需要平衡。违反缩放律会浪费资源。
  
- "为什么不用 BERT 的双向建模而是单向的 GPT？"
  - 答：生成任务需要单向。BERT 用于理解，GPT 用于生成。

- "如何评估数据质量？"
  - 答：去重、多个质量指标、在模型上验证。
