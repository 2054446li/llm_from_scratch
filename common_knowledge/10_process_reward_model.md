# 过程奖励模型（PRM, Process Reward Model）

> 后训练 RL 深水区。理解它能讲清「为什么 DeepSeek-R1 放弃了过程监督」。前置：[[9_grpo]]。

## 概述

奖励模型给 LLM 的回答打分，按**打分粒度**分两类：

| | ORM（Outcome RM，结果奖励模型） | PRM（Process RM，过程奖励模型） |
|---|---|---|
| 打分位置 | 只在**整条回答末尾**打 1 个分 | 在**每个推理步骤末尾**各打 1 个分 |
| 信号密度 | 稀疏 | 密集 |
| 训练数据 | (问题, 完整答案, 对/错) | (问题, 部分解答, **每步**对/错) |
| 典型用途 | GRPO 结果监督、RLHF | GRPO 过程监督、复杂数学推理 |

PRM 的卖点：复杂数学题里，一个错误往往发生在中间某步，ORM 只告诉你「最终错了」却不知道**错在哪**；PRM 能定位到具体步骤，信号更细、更适合 credit assignment。

## PRM 怎么用在 GRPO 里

详见 [[9_grpo]]。要点：组内 G 条回答的**所有步骤分数拉平成一个大池子**，用该池子的 mean/std 统一归一化每一步：

$$\tilde{r}_i^{\,\mathrm{index}(j)} = \frac{r_i^{\,\mathrm{index}(j)} - \mathrm{mean}(\mathbf{R})}{\mathrm{std}(\mathbf{R})}$$

再把「某 token 之后所有步的归一化分」加起来当优势（reward-to-go）：

$$\hat{A}_{i,t} = \sum_{\mathrm{index}(j)\geq t} \tilde{r}_i^{\,\mathrm{index}(j)}$$

## 核心缺陷：把「正确性」误当「价值」★★

这是 PRM 最根本、也是面试最值得讲的问题。

两个概念必须解耦：

| 概念 | 含义 | 标准 PRM 学的是哪个 |
|---|---|---|
| **步级正确性** (correctness) | 这步本身在数学上对不对 | ✅ 这正是 PRM 的训练目标 |
| **步级价值** (value) | 这步对**最终解出题**的真实贡献 | ❌ PRM 不建模 |

**问题场景**：人类做题时，第一次尝试常常是错的，但这个错误探索（试错、反证、走死路再回头）**极可能为正确解带来关键思路**。这类步骤是「**正确性为负、但价值为正**」。

标准 PRM（如 PRM800K 标注方式）按「这步推理是否有效/正确」逐步打标 → 探索性错误步被打成 **negative** → PRM 学到的是「**像不像标准解法的一步**」，而非「**这步对通往答案有没有帮助**」。

> 一句话：**标准 PRM 会错误惩罚「有启发价值的错误探索」，因为它评判的是"当下对不对"，而非"未来能否成功"。**

## 更深一层：credit assignment 本身就难

「某一步错棋是否为后面的妙手埋了伏笔」——这是**反事实推理**，连人类标注员自己都判断不好。让人逐步打分，等于要人解决一个人都做不好的任务。这才是 PRM800K 即便精标仍有 **~20% 误标**的深层原因：不只是手滑，而是**任务定义本身模糊**。

## 理论解法：蒙特卡洛价值估计（Math-Shepherd）

用「**未来能否成功**」而非「**人类判断对错**」来定义步级奖励。代表作 **Math-Shepherd**（Wang et al., 2023b，正是 DeepSeekMath 过程监督引用的那篇）：

$$\text{score}(s) \approx P(\text{从步骤 } s \text{ 出发能走到正确答案}) = \frac{\text{从 } s \text{ 续写 } N \text{ 次中答对的次数}}{N}$$

做法：从某中间步出发，继续 rollout（采样补全）N 次，**统计最终答对的比例**作为这步的分。

**为什么这解决了上面的缺陷**：如果从那个「错误但有启发」的步骤出发，后续 rollout 成功率很高，它就会拿**高分**——因为蒙特卡洛估计衡量的是「**这步把模型带到了一个容易成功的状态**」，而不是「这步像不像标准解法」。这恰好就是直觉里想要的：**用未来追认当下的价值。**

### 但蒙特卡洛 PRM 也有代价

| 问题 | 说明 |
|---|---|
| **贵** | 每个中间步都要 rollout 多次，采样成本爆炸 |
| **噪声大** | rollout 次数有限 → 成功率估计方差高 |
| **信号稀疏** | 难题上几乎所有 rollout 都失败 → 全 0 → 学不到东西 |

## DeepSeek-R1 的工程抉择：放弃 PRM

DeepSeekMath 论文 5.2.3「未来方向」已埋伏笔——提到要研究「高效构建高质量 PRM」，暗示 PRM 不好搞。到 **DeepSeek-R1**，索性**放弃过程监督**，只用**规则化结果奖励**（最终答案对不对 + 格式对不对），让模型在 RL 中**自己涌现**反思、回溯、试错的长链推理（著名的 "aha moment"）。

哲学转变：

> 与其让 PRM 去逐步评判「这步对不对」（而它根本判不准探索价值），不如**只在最终结果给信号，让模型自己学会哪些"看似错误的探索"值得**。

即：**担心 PRM 扼杀有价值的探索 → 解法是干脆不让 PRM 在中间插手。** 结果奖励信号虽稀疏，但它不会错误惩罚探索，反而给了模型自由试错的空间。

## 类比记忆（下棋）

| 概念 | 类比 |
|---|---|
| ORM | 棋局结束才告诉你赢了还是输了 |
| PRM（correctness 式） | 每步都有个教练喊「这步是不是定式」——但他不懂弃子争先 |
| 错误但有启发的步 | 弃一个子，三步后绝杀（弃子本身"亏"，但价值极高） |
| 标准 PRM 的失误 | 教练在弃子那步喊「臭棋」，扼杀了胜着 |
| 蒙特卡洛 PRM | 从这步往后多下几盘，看赢率——弃子若常导向胜局，就给高分 |
| R1 弃用 PRM | 撤掉中间教练，只看终局胜负，让 AI 自己悟出弃子的妙处 |

## 一句话总结

PRM 比 ORM 信号更密、能定位错误，但**根本缺陷是把「步级正确性」当「步级价值」，会错误惩罚有启发的错误探索**。理论解法是蒙特卡洛 rollout 的未来成功率（Math-Shepherd），但贵且噪声大；DeepSeek-R1 的工程解法是**彻底弃用 PRM、改用规则化结果奖励**，让探索在 RL 中自然涌现。

## 面试题

**问：用一个神经网络模型（PRM）去给推理过程逐步打分，可能存在哪些问题？**

**参考回答**（层层递进，三个层次）：

**1. 数据层面：步骤级标注数据稀缺。**
训练一个 PRM 需要「问题 + 部分解答 + 每一步对错」的细粒度标注，而绝大多数现成数据集只有「问题 + 最终答案」的结果级标签。步骤级数据天然稀少，构造成本远高于结果级数据，这是训练 PRM 的第一道门槛。

**2. 标注层面：数据少 → 转向人工标注，但人也标不准。**
为补足数据，自然想到让人逐步标注（如 PRM800K）。但「判断某一步对最终解题的价值有多大」本质是**反事实推理**——要预判这步是否为后续埋下伏笔。这件事连人类专家都做不好，导致即便精标的数据集仍有约 20% 误标。问题不在标注员手滑，而在**任务定义本身就模糊**。

**3. 建模层面（最关键）：PRM 评判的是「正确性」，而非「价值」。**
标准 PRM 训练目标是判断「这一步在数学上对不对 / 像不像标准解法」，即**步级正确性 correctness**。但真正该奖励的是**步级价值 value**——这步对最终成功的贡献。二者会解耦：就像人做题时第一次尝试虽然错了，却可能为正确解带来关键思路（试错、反证、走死路再回头）。这类「正确性为负、价值为正」的探索步骤，会被标准 PRM 错误地打成负分，从而**扼杀有价值的探索**。

**4. 解法与代价：蒙特卡洛价值估计。**
要修正第 3 点，应改用「**未来能否成功**」定义奖励，而非「当下对不对」。即从某中间步出发多次 rollout，用**最终答对的比例**作为这步的分（Math-Shepherd）。这样「错误但有启发」的步骤——只要从它出发后续成功率高——就能拿高分。但代价是：① 每步都要采样多次，**成本爆炸**；② rollout 有限时**估计方差大**；③ 难题上几乎全失败 → **信号稀疏**。

**5. 升华（点出工程趋势）：**
正因 PRM 又难训、又难标、又容易奖错，**DeepSeek-R1 干脆放弃过程监督**，改用规则化结果奖励（答案对不对 + 格式对不对），让反思、回溯、试错等长链推理行为在 RL 中**自然涌现**。结果信号虽稀疏，但不会错误惩罚探索——这是对 PRM 困境最直接的回应。

> **一句话答题骨架**：数据稀缺 → 人工标注也标不准（反事实推理难）→ 模型只评正确性、忽略价值（错杀有启发的探索）→ 蒙特卡洛可救但贵且噪声大 → R1 索性弃用 PRM 改结果奖励。
