# MoE 负载均衡损失(Load Balance Loss)

> MoE 面试高频深水区。前置:[[7_mixture_of_experts]]。

## 为什么需要

Router 是自动学出来的,无约束时会"偷懒"——发现某几个专家好用就一直只发给它们。两个后果:

1. **路由坍缩(routing collapse)**:模型只用少数专家(如 64 选 5),其余专家从不被选中 → 永远训练不到 → 参数白白浪费。**(模型质量问题)**
2. **设备计算瓶颈**:专家分布在多卡上,热门专家若挤在同一张卡 → 该卡过载、其他卡空闲 → 整体被最慢的卡拖住。**(训练速度问题)**

DeepSeekMoE 用**两个 loss 各治一个病**:专家级 loss 治坍缩,设备级 loss 治设备过载。

## 专家级均衡损失(Expert-Level Balance Loss)

目标:让每个专家被选中的频率尽量均匀。

$$\mathcal{L}_{\text{ExpBal}} = \alpha_1 \sum_{i=1}^{N'} f_i P_i$$

$$f_i = \frac{N'}{K'T} \sum_{t=1}^{T} \mathbb{1}(\text{Token } t \text{ 选择 Expert } i), \qquad P_i = \frac{1}{T} \sum_{t=1}^{T} s_{i,t}$$

- **$f_i$**(实际接客频率):统计 T 个 token 里有多少个把专家 $i$ 选进 Top-K($\mathbb{1}(\cdot)$ 是指示函数,选了记 1),再用 $\frac{N'}{K'T}$ 归一化($N'$=专家数, $K'$=每 token 激活数, $T$=token 数)。完全均匀时 $f_i \approx 1$,被偏爱 $>1$,被冷落 $<1$。**离散、不可导。**
- **$P_i$**(平均路由概率):softmax 亲和度 $s_{i,t}$ 对所有 token 求平均,即 router 平均有多想派给专家 $i$。**连续、可导。**

### 关键:为什么是 $f_i P_i$ 相乘?(最难懂的点)

- $f_i$ 离散不可导,没法直接做梯度下降;$P_i$ 连续可导。
- 设计巧思:**用可导的 $P_i$ 当"梯度把手",用 $f_i$ 当"该惩罚多重的权重"。**
- 某专家又被频繁选中($f_i$ 大)、router 又偏爱它($P_i$ 大)→ 乘积大 → loss 大 → 梯度压低它的 $P_i$ → 流量摊向冷门专家 → 趋于均衡。

> 一句话:**惩罚"过热"专家。$f$ 标记谁过热,$P$ 提供可优化的梯度。**

## 设备级均衡损失(Device-Level Balance Loss)

为什么还要再来一个:**专家级约束太强会损害性能**——强行让本该冷门的专家也被均匀使用,违背"专业化"初衷。于是放松粒度:不要求每个专家均匀,只要求**每张卡的总负载均匀**。

把被路由专家分成 $D$ 组,每组放一张 GPU:$\mathcal{E}_1, \mathcal{E}_2, \ldots, \mathcal{E}_D$。

$$\mathcal{L}_{\text{DevBal}} = \alpha_2 \sum_{i=1}^{D} f_i' P_i'$$

$$f_i' = \frac{1}{|\mathcal{E}_i|} \sum_{j \in \mathcal{E}_i} f_j, \qquad P_i' = \sum_{j \in \mathcal{E}_i} P_j$$

其中 $f_i'$ 是第 $i$ 张卡上所有专家 $f_j$ 的平均,$P_i'$ 是其 $P_j$ 的总和。思路与专家级完全一样,只是把"单个专家"换成"一张卡上的一组专家"。粒度更粗 → 约束更松 → **允许卡内专家不均匀(保住专业化),只要卡间均衡(保住速度)。**

## 实践配比(论文的关键选择)

- **专家级因子 α₁:设小** → 只轻轻防路由坍缩,不过度干预(管太死会压制专业化、伤性能)。
- **设备级因子 α₂:设大** → 重点保证各卡计算均衡(直接决定训练速度,且不伤性能)。

## 类比记忆(专家=厨师,token=订单)

| 概念 | 类比 |
|---|---|
| 路由坍缩 | 所有订单都派给 1 号厨师,其他厨师闲到失业(没学会做菜) |
| f_i | 厨师 i 实际接了多少单(相对平均) |
| P_i | 派单系统平均多想派给厨师 i |
| 专家级 loss | 别让谁累死/闲死——但管太死,厨师没法专精某菜系 |
| 设备级 loss | 退一步:只要每个后厨(GPU)总工作量均衡,后厨内谁专精啥随意 |
| α₁小、α₂大 | 对单个厨师宽松(保专精),对后厨间严格(保出餐速度) |

## 一句话总结

专家级 loss 防"少数专家垄断"(轻管,怕伤专业化);设备级 loss 防"某张卡过载"(重管,直接关系速度)。两者都用 `f×P` 套路——**f 标记谁过热、P 提供可导梯度。**
