## Objective

本SOP旨在规范运营商宽带故障报修服务流程，确保：

1. **响应及时**：故障报修快速响应，减少用户等待时间
2. **诊断准确**：通过标准化排查流程，准确定位故障原因
3. **修复高效**：自助排障→远程检测→上门维修三级处理，提高修复效率
4. **服务闭环**：故障修复后回访确认，确保用户满意

**多方对话系统**：
- **用户** ↔ **客服**（故障报修、进度查询、结果确认）
- **客服** ↔ **远程检测系统**（光猫状态读取、线路质量检测）
- **客服** ↔ **工程师/装维**（派单、预约、现场维修）
- **客服** ↔ **回访系统**（满意度调查、工单关闭）

### Step 2: 自助排障

#### 2.1 无法上网排障

**【话术】无法上网自助排障**

```
客服："请先进行自助排障，按以下步骤操作：

1️⃣ 检查光猫电源
   - 查看光猫指示灯状态：
   - 电源灯：应常亮（不亮请检查电源线）
   - 光信号灯（PON）：应常亮绿色（闪红灯表示线路故障）
   - 网口灯（LAN）：应闪烁（表示有数据传输）

2️⃣ 检查光纤线路
   - 确认光纤线插紧，无松动
   - 检查光纤线无弯折、无破损（弯折半径需大于3cm）

3️⃣ 重启光猫
   - 拔掉光猫电源线
   - 等待30秒以上
   - 重新插上电源
   - 等待2-3分钟，观察指示灯状态

4️⃣ 检查路由器（如使用）
   - 尝试电脑/手机直连光猫测试
   - 排除路由器故障

请按步骤操作后告诉我结果，哪一步有问题？"
```

#### 2.2 网速慢排障

**【话术】网速慢自助排障**

```
客服："请问是最近变慢还是一直慢？
📱 有线测速还是无线WiFi？
📱 所有设备都慢还是某个设备慢？

请按以下步骤排查：

1️⃣ 测速对比
   - 访问 speedtest.cn 或运营商官方测速网站
   - 有线直连光猫测速（排除WiFi干扰）
   - 记录下载速度（MB/s）

2️⃣ 签约带宽对照
   ┌────────────┬──────────────┐
   │ 签约带宽   │ 正常下载速度 │
   ├────────────┼──────────────┤
   │ 100Mbps    │ 10-12MB/s    │
   │ 200Mbps    │ 20-25MB/s    │
   │ 300Mbps    │ 30-35MB/s    │
   │ 500Mbps    │ 50-60MB/s    │
   │ 1000Mbps   │ 100-120MB/s  │
   └────────────┴──────────────┘

3️⃣ 排查干扰因素
   - WiFi信道干扰（建议切换信道）
   - 高峰期网络拥堵（19:00-23:00）
   - 后台程序占用带宽
   - 网线老化（建议更换超五类/六类网线）

请测速后告诉我结果。"
```

#### 2.3 频繁掉线排障

**【话术】频繁掉线自助排障**

```
客服："请问：
📱 一天大概掉线几次？
📱 大概什么时间段？
📱 光猫指示灯在掉线时是否正常？

请按以下步骤排查：

1️⃣ 检查光猫散热
   - 摸摸光猫是否发烫
   - 如发烫请关机散热30分钟
   - 确保光猫周围通风，无遮挡

2️⃣ 检查线路接触
   - 重新插拔光纤接头
   - 检查网线接口是否松动
   - 观察线路有无弯折、挤压

3️⃣ 记录掉线规律
   - 是否固定时间段（如整点）
   - 是否与用电高峰相关
   - 是否使用特定应用时掉线

4️⃣ 路由器排查
   - 尝试直连光猫测试
   - 更换路由器测试

请先摸摸光猫是否发烫，如是请关机散热后再试。"
```

#### 2.4 自助排障结果处理

**【话术】排障结果处理**

```
【自助解决】
用户："重启好了，能上网了"
客服："太好了！问题已解决。
💡 建议：定期重启光猫（每周一次）可保持网络稳定。
💡 光猫长期运行可能缓存溢出，重启可清理缓存

请问还有其他可以帮您的吗？"

【仍未解决-光猫红灯】
用户："还是不行，光猫红灯"
客服："光猫红灯表示光信号异常，可能是光纤线路问题。我为您远程检测光猫状态..."
→ 进入Step 3 远程检测

【仍未解决-其他情况】
用户："还是上不了网，灯都正常"
客服："了解，我立即为您进行远程检测，查看光猫后台状态。"
→ 进入Step 3 远程检测

【用户无法操作】
用户："我不会弄这些"
客服："完全理解，立即为您安排工程师上门。工程师将在24小时内上门检测维修，您无需操作任何设备。"
→ 进入Step 4 上门维修
```

## Output Requirement

### 系统输出规范

| 输出类型 | 要求 | 字段示例 |
|----------|------|----------|
| 故障登记 | 工单号+故障类型+预计处理时间 | work_order, fault_type, eta |
| 排障指导 | 分步骤操作指引+示意图 | troubleshoot_steps, images |
| 远程检测结果 | 检测数据+故障判断+处理建议 | check_data, diagnosis, suggestion |
| 上门预约 | 工单号+时间+工程师信息 | work_order, appointment_time, engineer |
| 回访确认 | 满意度评价+工单关闭 | satisfaction, work_order_closed |

### 关键字段定义

```json
{
  "step": {
    "type": "enum",
    "values": ["1", "1.1", "1.2", "2", "2.1", "2.2", "2.3", "2.4", "3", "3.1", "3.2", "3.3", "4", "4.1", "4.2", "4.3", "5", "5.1", "5.2", "5.3"],
    "description": "对应的step编号"
  },
  "response": {
    "type": "string",
    "description": "必须严格使用sop中定义的原话"
  },
  "action": {
    "type": "enum",
    "values": ["moveon", "end", "escalate"],
    "description": "后续动作：moveon(继续话题)end(结束对话)escalate(升级处理)"
  },
  "work_order": {
    "type": "string",
    "description": "工单号，格式GDYYYYMMDDXXXX"
  },
  "fault_type": {
    "type": "enum",
    "values": ["no_internet", "slow_speed", "frequent_disconnect", "other"],
    "description": "故障类型"
  },
  "auth_status": {
    "type": "enum",
    "values": ["pending", "verified", "failed"],
    "description": "身份核验状态"
  }
}
```

### 约束条件

- 3-4字段required，`additionalProperties: false`
- `step`取enum精确到最细step
- `response`必须严格使用SOP中定义的原话，不可自由发挥
- `action`：`moveon`=继续话题，`end`=结束对话，`escalate`=升级处理
- `work_order`：故障报修需生成工单号，格式"GDYYYYMMDDXXXX"
- 涉及上门维修必须确认详细地址和预约时间
- 结束对话前必须询问"是否还有其他可以帮您"
