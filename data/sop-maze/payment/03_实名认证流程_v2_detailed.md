## Objective

本SOP旨在规范第三方支付平台实名认证业务流程，确保：

1. **合规安全**：严格遵守央行《非银行支付机构网络支付业务管理办法》等监管要求
2. **身份真实**：通过OCR识别、银行卡四要素验证、人脸活体检测等多重手段确保用户身份真实有效
3. **风险可控**：建立完善的风控拦截机制，防范身份冒用、欺诈等风险
4. **体验顺畅**：在保障安全的前提下，优化认证流程，提升用户认证成功率

**多方对话系统**：
- **用户** ↔ **平台系统**（OCR识别、银行卡验证、人脸检测）
- **用户** ↔ **人工客服**（认证失败处理、疑问解答、申诉处理）
- **系统** ↔ **人工审核**（OCR失败转人工、人脸检测失败转人工、风控复核）
- **平台** ↔ **银行/银联**（银行卡四要素验证、小额打款验证）
- **平台** ↔ **公安/权威数据源**（身份信息核验、证件真实性校验）

## Standard Operating Procedures

### 1. 入口识别

#### 1.1 用户身份类型判断

##### 1.1.1 认证类型对照表

| 认证类型 | 适用对象 | 认证内容 | 认证时效 | 限额权限 |
|----------|----------|----------|----------|----------|
| 个人L1基础 | 普通个人用户 | 身份证OCR识别 | 即时 | 单笔1000元/日累计5000元 |
| 个人L2标准 | 需要更高额度的个人用户 | L1+银行卡四要素+人脸活体 | 即时 | 单笔50000元/日累计200000元 |
| 个人L3高级 | 高净值个人用户 | L2+资产/职业证明 | 3-5工作日 | 单笔500000元/日累计1000000元 |
| 企业M1基础 | 个体户/小微企业 | 营业执照+法人身份 | 即时 | 单笔50000元/日累计200000元 |
| 企业M2标准 | 一般企业商户 | M1+对公账户验证 | 1-3工作日 | 单笔500000元/日累计2000000元 |
| 企业M3高级 | 大型企业/高风险行业 | M2+实地认证/资质审核 | 5-7工作日 | 单笔5000000元/日累计20000000元 |

##### 1.1.2 入口流程

      │              │               │              │

```

```

### 2. 个人实名认证

#### 2.1 身份证OCR识别

##### 2.1.1 OCR识别标准

| 项目 | 要求 | 校验规则 |
|------|------|----------|
| 支持证件 | 二代身份证/临时身份证/港澳台居住证/外国人永久居留证 | 自动识别证件类型 |
| 识别字段 | 姓名/性别/民族/出生日期/住址/身份证号/签发机关/有效期限 | 全字段提取 |
| 图像要求 | 分辨率≥300dpi，JPG/PNG/PDF格式，单张≤10MB | 自动质量检测 |
| 拍摄要求 | 四角完整/光线充足/无反光/无遮挡 | 实时拍摄引导 |
| 自动校验 | 身份证号18位校验(加权求和模11) | 实时校验 |
| 人脸比对 | 与公安库照片比对，相似度≥0.85 | 自动比对 |

##### 2.1.2 OCR识别流程

```
用户上传身份证 ──▶ 图像质量检测 ──▶ 文字识别提取 ──▶ 字段校验 ──▶ 人脸比对 ──▶ 结果返回
      │                │               │            │          │
      ▼                ▼               ▼            ▼          ▼
   正反面照片      清晰度/完整性    提取8个字段    18位校验   相似度≥0.85
```

**【话术】OCR引导话术**：

```
系统："请上传您的身份证正反面照片，要求四角完整、光线充足、文字清晰。您可以现场拍摄或从相册选择。"
用户：（上传照片）
系统："已收到您的身份证照片，正在进行识别..."
```

**【话术】OCR失败处理话术（关键新增）**：

```
系统："识别失败，请重新拍摄上传。注意避免反光和遮挡。"
用户："我已经拍了三次了还是不行，怎么办？"
系统："理解您的困扰。OCR识别失败可能是由于以下原因：1.光线过暗或过亮产生反光；2.身份证边缘未完全入镜；3.照片模糊。建议您：1.在自然光下拍摄，避免强光直射；2.将身份证平放在深色背景上；3.确保身份证四个角都在画面内。如果仍无法识别，我将为您转接人工审核。"
用户："我还是搞不定，转人工吧"
系统："好的，已为您转接人工审核。人工客服将在5分钟内联系您，请保持电话畅通。"
```

**【多方对话】OCR失败转人工审核**：

```
【系统提示】
系统："OCR自动识别失败，已转人工审核通道"

【人工客服介入】
客服："您好，我是实名认证专员，看到您的身份证OCR识别遇到了问题。我可以协助您通过人工方式完成认证。"
用户："太好了，我拍了好几次都识别不了"
客服："没关系，请问您方便现在进行视频认证吗？或者您可以将身份证照片发送至我们的安全认证邮箱，我们将在30分钟内完成人工核验。"
用户："视频认证吧"
客服："好的，请准备好您的身份证原件，我将通过视频方式为您完成认证。请确认您的网络畅通，我们马上开始。"
```

**【KCP】身份证OCR关键控制点**：
- 自动重试≤3次，仍失败必须转人工审核
- 身份证有效期必须大于30天（即将过期提醒）
- 年龄校验：≥16周岁可独立认证，<16周岁需监护人陪同
- 人脸比对相似度阈值≥0.85，低于阈值触发人工复核
- 证件图像必须加密存储，仅用于实名认证

#### 2.2 银行卡四要素验证

##### 2.2.1 四要素验证标准

| 验证要素 | 说明 | 错误提示 |
|----------|------|----------|
| 姓名 | 与身份证姓名一致 | "姓名与身份证不符" |
| 身份证号 | 18位有效身份证号 | "身份证号格式错误" |
| 银行卡号 | 本人名下借记卡 | "银行卡号无效或不支持" |
| 银行预留手机号 | 可接收验证码 | "银行预留手机号不符" |

##### 2.2.2 验证方式对比

| 验证方式 | 适用场景 | 时效 | 特点 |
|----------|----------|------|------|
| 实时接口验证 | 主流银行卡 | 即时 | 银联/网联通道实时返回 |
| 小额打款验证 | 接口验证失败时 | 1-3分钟 | 打款0.01-0.99元，用户回填金额 |
| 人工审核 | 特殊银行卡 | 1-3工作日 | 上传银行卡照片人工核验 |

**【话术】银行卡验证话术**：

```
系统："请输入您的银行卡号、银行预留手机号，我们将进行验证。"
用户："卡号6222021234567890123，手机号13800138000"
系统："正在验证...验证失败，您输入的银行预留手机号与银行记录不符。请核对银行预留手机号是否准确，或联系银行更新预留手机号后重试。"
用户："我换过手机号，还没去银行改"
系统："建议您先联系银行更新预留手机号，或使用其他银行卡进行验证。您也可以选择小额打款验证方式，我们将向您的银行卡打款0.01-0.99元，您回填金额即可完成验证。"
```

**【KCP】银行卡四要素关键控制点**：
- 验证失败必须提示具体错误字段，不得笼统提示"验证失败"
- 仅支持本人名下借记卡，信用卡不支持
- 全程加密传输，不存储CVN2和有效期
- 单日验证失败超过5次触发频率限制
- 银行卡不支持时建议更换主流银行（工/农/中/建/招）

#### 2.3 人脸活体检测

##### 2.3.1 活体检测标准

| 检测项目 | 要求 | 失败处理 |
|----------|------|----------|
| 活体动作 | 眨眼/摇头/张嘴/点头（随机组合） | 动作未完成提示重试 |
| 光线条件 | 光线充足，无逆光/过暗 | 提示调整光线 |
| 面部遮挡 | 无口罩/墨镜/帽子遮挡 | 提示摘除遮挡物 |
| 人脸比对 | 与身份证照片相似度≥0.85 | 低于阈值转人工 |
| 防攻击 | 检测照片/视频/面具攻击 | 攻击行为记录并拦截 |

##### 2.3.2 检测流程

```
发起检测 ──▶ 动作引导 ──▶ 实时采集 ──▶ 活体判断 ──▶ 人脸比对 ──▶ 结果返回
    │           │           │          │          │
    ▼           ▼           ▼          ▼          ▼
 随机动作    语音+文字    视频流      AI算法      公安库
 组合引导    双重提示    实时分析    判断真假    比对
```

**【话术】人脸检测引导话术**：

```
系统："请进行人脸识别，按照提示完成眨眼、摇头等动作。请将面部对准框内，保持光线充足。"
用户：（完成动作）
系统："检测通过！正在进行身份比对..."
```

**【话术】人脸检测失败话术**：

```
系统："检测失败，请确保光线充足、面部无遮挡，重试。"
用户："我试了三次都不行，是不是系统有问题？"
系统："抱歉给您带来不便。检测失败可能是由于：1.光线过暗或过亮；2.面部有遮挡（如眼镜反光）；3.动作未完成。建议您：1.面对光源但避免强光直射；2.暂时摘下眼镜；3.按照语音提示完成动作。您还有2次尝试机会。"
用户：（再次尝试仍失败）
系统："检测多次未通过，已为您转接人工审核。人工客服将通过视频方式为您完成认证，请保持电话畅通。"
```

**【KCP】人脸活体检测关键控制点**：
- 自动重试≤3次，仍失败必须转人工视频审核
- 必须采用随机动作组合，防止视频重放攻击
- 实时检测照片/视频/面具攻击，攻击行为记录风控
- 人脸比对相似度阈值≥0.85，低于阈值必须人工复核
- 检测视频加密存储，仅用于认证和纠纷处理

### 3. 企业商户认证

#### 3.1 营业执照OCR识别

##### 3.1.1 OCR识别标准

| 项目 | 要求 | 校验规则 |
|------|------|----------|
| 支持证件 | 营业执照正副本/电子营业执照 | 自动识别 |
| 识别字段 | 统一社会信用代码/企业名称/类型/住所/法定代表人/注册资本/成立日期/营业期限/经营范围 | 全字段提取 |
| 自动校验 | 统一社会信用代码18位校验 | 实时校验 |
| 企业状态 | 存续/在营状态校验 | 异常状态拦截 |
| 法人一致性 | 法人身份证与营业执照法人一致性校验 | 自动比对 |

**【话术】营业执照OCR话术**：

```
系统："请上传营业执照正本或副本照片，确保印章清晰可辨。支持纸质执照拍照或电子营业执照上传。"
用户：（上传执照）
系统："识别成功！企业名称：北京科技有限公司，统一社会信用代码：91110108XXXXXXXXXX，法定代表人：张三。请核对信息是否正确。"
用户："对的"
```

**【KCP】营业执照OCR关键控制点**：
- 企业状态必须为"存续"或"在营"，注销/吊销企业拦截
- 营业期限必须有效，过期执照需更新
- 法人信息必须与后续法人认证一致
- 经营范围涉及特殊行业需额外资质审核

**【KCP】对公账户验证关键控制点**：
- 账户名称必须与营业执照企业名称完全一致
- 打款金额随机生成，4位有效数字防止猜测
- 验证时效24小时，超时需重新发起
- 失败3次后锁定24小时
