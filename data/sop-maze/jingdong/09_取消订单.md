## 三、SOP-Maze 格式详细内容

### 3.1 Objective（任务目标）

| 项目 | 内容 |
|------|------|
| **角色** | 京东售后客服 |
| **任务** | 处理用户取消订单申请 |
| **目标** | 在确保合规的前提下，高效、准确地完成订单取消操作，保障用户权益，减少客诉 |
| **关键指标** | • 取消处理时效：待付款/待发货 ≤ 1小时；已发货拦截 ≤ 4小时<br>• 用户满意度 ≥ 90%<br>• 退款准确率 100% |

---

### 3.2 Standard Operating Procedures（标准操作流程）

#### 步骤 1：接收并确认用户申请

| 属性 | 内容 |
|------|------|
| **步骤编号** | S1 |
| **步骤名称** | 接收取消申请并核实身份 |
| **触发条件** | 用户通过客服热线/在线客服/APP提交取消订单请求 |
| **输入** | 用户账号、订单编号、取消原因 |
| **处理动作** | 1. 核实用户身份（订单归属验证）<br>2. 查询订单当前状态<br>3. 判断订单类型（自营/POP商家/全球购等） |
| **输出** | 订单状态信息、是否可取消标记 |
| **异常处理** | 身份验证失败 → 拒绝操作并引导用户核实信息 |

#### 步骤 2：判断订单状态分支

| 属性 | 内容 |
|------|------|
| **步骤编号** | S2 |
| **步骤名称** | 订单状态判断与分支处理 |
| **决策点** | 根据订单当前状态选择处理路径 |

**分支逻辑表：**

| 订单状态 | 处理路径 | 操作说明 |
|----------|----------|----------|
| 待付款 | 路径A：直接取消 | 系统自动或客服手动取消，立即生效 |
| 待发货 | 路径B：仓库拦截 | 通知仓库停止发货，确认后取消 |
| 已发货 | 路径C：物流拦截 | 申请物流拦截，根据结果处理 |
| 已签收 | 路径D：转退货 | 引导用户走退货退款流程 |
| 已完成 | 路径E：不可取消 | 说明规则，建议其他解决方式 |

#### 步骤 3A：待付款订单取消（路径A）

| 属性 | 内容 |
|------|------|
| **步骤编号** | S3A |
| **适用场景** | 订单状态为"待付款" |
| **处理动作** | 1. 执行取消操作<br>2. 系统自动释放库存<br>3. 触发退款流程（如有预授权） |
| **时效要求** | 即时处理，30分钟内完成退款（如有） |
| **系统操作** | 在客服系统中点击"取消订单"按钮 |

#### 步骤 3B：待发货订单取消（路径B）

| 属性 | 内容 |
|------|------|
| **步骤编号** | S3B |
| **适用场景** | 订单状态为"待发货"或"配货中" |
| **处理动作** | 1. 提交仓库拦截申请<br>2. 等待仓库确认（通常30分钟内）<br>3. 确认未发货后执行取消 |
| **时效要求** | 1小时内完成取消或告知用户结果 |
| **异常处理** | 仓库已出库 → 转为路径C（已发货处理） |

#### 步骤 3C：已发货订单拦截（路径C）

| 属性 | 内容 |
|------|------|
| **步骤编号** | S3C |
| **适用场景** | 订单已发货，物流运输中 |
| **处理动作** | 1. 提交物流拦截申请<br>2. 联系物流公司确认拦截可行性<br>3. 根据拦截结果处理 |

**拦截结果分支：**

| 拦截结果 | 后续处理 |
|----------|----------|
| 拦截成功 | 商品退回仓库 → 确认入库 → 触发退款 |
| 拦截失败 | 告知用户 → 建议拒收或走退货流程 |
| 已派送/签收 | 引导用户拒收或申请退货 |

#### 步骤 4：退款处理

| 属性 | 内容 |
|------|------|
| **步骤编号** | S4 |
| **步骤名称** | 退款执行与到账 |
| **处理动作** | 1. 确认取消/退货入库完成<br>2. 系统自动触发退款<br>3. 记录退款流水号 |

**退款时效表：**

| 支付方式 | 退款时效 | 说明 |
|----------|----------|------|
| 京东白条 | 实时 | 额度立即恢复 |
| 京东支付余额 | 实时 | 退回京东钱包 |
| 微信支付 | 1-3个工作日 | 原路退回微信零钱/银行卡 |
| 支付宝 | 1-3个工作日 | 原路退回支付宝余额/银行卡 |
| 银行卡直付 | 1-7个工作日 | 具体以银行处理为准 |
| 信用卡 | 3-15个工作日 | 以银行账单周期为准 |

#### 步骤 5：优惠券/京豆返还

| 属性 | 内容 |
|------|------|
| **步骤编号** | S5 |
| **步骤名称** | 优惠权益返还处理 |
| **处理动作** | 系统自动处理，客服需向用户说明规则 |

**返还规则表：**

| 权益类型 | 返还规则 | 时效 |
|----------|----------|------|
| 优惠券 | 取消成功后自动返还，仅限有效期内优惠券 | 实时 |
| 已过期的优惠券 | 不予返还 | - |
| 京豆 | 全额返还 | 实时 |
| 满减/满赠活动 | 按比例返还实际支付部分对应的优惠 | 实时 |
| 运费券 | 如已使用则不予返还 | - |
| 礼品卡/E卡 | 金额退回卡内 | 实时 |

#### 步骤 6：结果通知与闭环

| 属性 | 内容 |
|------|------|
| **步骤编号** | S6 |
| **步骤名称** | 通知用户并关闭工单 |
| **处理动作** | 1. 发送短信/APP推送通知<br>2. 客服确认用户知悉<br>3. 记录服务日志<br>4. 关闭客服工单 |
| **通知内容** | • 取消成功确认<br>• 退款金额与到账时间<br>• 优惠券返还情况<br>• 如有异常说明原因 |

## 四、关键知识点速查

### 4.1 取消时效规则

| 订单状态 | 取消时效 | 备注 |
|----------|----------|------|
| 待付款 | 30分钟内自动关闭或立即取消 | 用户可自行操作 |
| 待发货 | 1小时内处理完成 | 需仓库确认 |
| 已发货 | 4小时内反馈拦截结果 | 受物流影响 |

### 4.2 退款方式对照

- **原路退回**：退回原支付账户
- **京东钱包**：退回京东账户余额
- **白条恢复**：恢复白条可用额度

### 4.3 已发货订单处理优先级

1. 优先尝试物流拦截
2. 拦截失败建议用户拒收
3. 已签收引导走退货流程

### 4.4 优惠券返还要点

- 仅返还在有效期内的优惠券
- 已过期的优惠券不返还
- 满减活动按实际支付比例返还
- 京豆、礼品卡全额返还

## 五、常见问题FAQ

**Q1：用户问"为什么我的优惠券没有返还？"**
> A：首先核实优惠券是否在有效期内。已过期的优惠券系统不予返还。如确实在有效期内未返还，提交工单给技术核查。

**Q2：用户问"退款什么时候到账？"**
> A：根据支付方式告知：白条实时，微信/支付宝1-3个工作日，银行卡1-7个工作日。如超过时效未到账，提供退款流水号供用户查询。

**Q3：订单已发货但用户强烈要求取消怎么办？**
> A：立即申请物流拦截，同时告知用户拦截成功率受物流状态影响。如拦截失败，建议拒收或签收后退货。

**Q4：第三方商家订单取消如何处理？**
> A：POP商家订单需商家审核，24小时内商家未处理系统自动同意。如商家拒绝且理由不充分，客服可介入协调。

**Q5：拆单订单如何取消？**
> A：根据子订单状态分别处理。已发货子订单走拦截流程，未发货子订单可直接取消。
