## Objective

本SOP旨在规范饿了么跑腿（同城急送）服务的运营流程，确保：

1. **响应速度**：用户下单后快速匹配蜂鸟骑手，缩短等待时间
2. **服务品质**：保障物品安全、准时送达，提升用户体验
3. **服务多样**：支持帮我买、帮我送、帮我取等多种服务场景
4. **风险管控**：完善物品损坏/丢失处理、安全保障及异常应对机制
5. **运力保障**：依托蜂鸟众包+蜂鸟专送双运力体系，确保配送稳定

## Standard Operating Procedures

### 1. 下单发件

#### 1.1 服务类型选择

##### 1.1.1 服务类型定义

| 服务类型 | 说明 | 典型场景 | 预估时效 |
|----------|------|----------|----------|
| 帮我买 | 骑手代用户购买商品 | 代购餐饮、超市商品、药品、鲜花等 | 45-90分钟 |
| 帮我送 | 骑手将物品从A地送至B地 | 文件传递、礼品配送、商务急件、餐饮配送 | 30-60分钟 |
| 帮我取 | 骑手代为取回物品 | 取快递、取钥匙、取证件、取外卖 | 30-60分钟 |
| 专人直送 | 骑手取货后直接送达，无中转 | 高价值物品、紧急文件、生鲜蛋糕 | 20-40分钟 |

##### 1.1.2 下单流程

```
选择服务类型 ──▶ 填写取/送地址 ──▶ 描述物品/需求 ──▶ 选择配送时效 ──▶ 确认支付
      │              │                  │              │              │
      ▼              ▼                  ▼              ▼              ▼
  帮我买/      精确到门牌号       物品类型/价值    普通/特快/     预估费用确认
  帮我送/      联系人及电话       特殊要求说明     专人直送       支付方式选择
  帮我取
```

**【话术】下单引导话术**：

**用户选择帮我买服务**：
```
用户："帮我买杯喜茶"
系统："好的，请填写购买地址（如喜茶XX店）和收货地址。您需要什么口味的饮品？可以指定商家或让骑手推荐"
用户："多肉葡萄，大杯少冰少糖"
系统："已记录。预估费用：饮品约29元+配送费15元，总计约44元。骑手会在购买前与您确认实际价格"
```

**用户选择帮我送服务**：
```
用户："送份文件到科技园"
系统："请填写取件地址和收件地址。文件大概多重？是否需要保价？"
用户："就几张纸，不用保价"
系统："好的。预估配送费18元，预计45分钟送达。现在为您下单吗？"
```

#### 1.2 订单信息填写规范

##### 1.2.1 必填字段说明

| 字段 | 必填性 | 填写要求 | 示例 |
|------|--------|----------|------|
| 取货地址 | 必填 | 精确到门牌号，含联系人及电话 | "XX大厦A座15楼，张三，138xxxx8888" |
| 送货地址 | 必填 | 精确到门牌号，含联系人及电话 | "YY小区3号楼2单元，李四，139xxxx6666" |
| 物品信息 | 必填 | 类型、数量、预估重量/体积 | "文件，A4信封，约200g" |
| 物品价值 | 建议填写 | 用于保价和理赔参考 | "合同文件，价值5000元" |
| 备注说明 | 选填 | 特殊要求、取货码、外观要求等 | "请轻拿轻放，易碎品" |
| 期望时效 | 必填 | 普通/特快/专人直送 | "特快，1小时内送达" |

##### 1.2.2 费用构成说明

| 费用项目 | 计算方式 | 说明 |
|----------|----------|------|
| 基础配送费 | 根据距离、重量、时段计算 | 起步价+里程费+重量费 |
| 重量附加费 | 超重部分按阶梯计费 | 通常>5kg开始计费 |
| 时段加价 | 高峰期、恶劣天气加价 | 1.2-1.5倍系数 |
| 特快服务费 | 优先配送、专人直送 | 额外加收10-30元 |
| 保价费 | 按声明价值比例收取 | 通常为声明价值的1-3% |

#### 1.3 帮我买服务特殊流程

##### 1.3.1 帮我买下单详细流程

```
用户下单 ──▶ 系统派单 ──▶ 骑手接单联系 ──▶ 确认购买需求 ──▶ 到店购买 ──▶ 拍照确认 ──▶ 支付配送
    │          │            │              │            │            │            │
    ▼          ▼            ▼              ▼            ▼            ▼            ▼
  填写商品   匹配附近      电话确认       确认商家/    选购商品      发送商品/     送达
  名称/规格  骑手          购买细节       商品/价格    垫付/预付     价格照片      结算

**【KCP】帮我买确认关键控制点**：
- 骑手必须在购买前与用户电话确认商品规格、价格上限
- 实际价格超出预估10%必须征得用户同意
- 必须提供正规购物小票

【送达时】

### 2. 骑手接单

#### 2.1 接单模式

##### 2.1.1 接单模式对比

| 模式 | 说明 | 适用场景 | 响应时效 |
|------|------|----------|----------|
| 系统派单 | 算法根据骑手位置、负载自动分配 | 标准订单 | 即时推送 |
| 骑手抢单 | 骑手主动选择订单 | 蜂鸟众包模式 | 5分钟内 |
| 蜂鸟专送 | 平台指定专职骑手 | 高价值/特殊订单 | 即时响应 |

##### 2.1.2 派单算法逻辑

```
订单生成 ──▶ 筛选可用骑手 ──▶ 计算匹配分数 ──▶ 推送订单 ──▶ 骑手响应 ──▶ 确认接单
    │            │               │              │            │
    ▼            ▼               ▼              ▼            ▼
  订单属性     距离<3km       距离权重40%    推送Top3    15秒响应
  位置/时效    在线状态       评分权重30%    骑手列表    超时重派
  服务类型     负载情况       历史权重20%                 拒绝记录
                              实时权重10%
```

#### 2.2 接单时效要求

##### 2.2.1 各阶段时效标准

| 服务类型 | 接单响应时限 | 到店/取货时限 | 配送时限 |
|----------|--------------|---------------|----------|
| 普通帮我买 | 5分钟内 | 接单后30分钟内 | 按距离预估 |
| 普通帮我送 | 5分钟内 | 接单后20分钟内 | 按距离预估 |
| 特快服务 | 3分钟内 | 接单后15分钟内 | 承诺时效内 |
| 专人直送 | 即时响应 | 立即取货 | 直达不绕路 |

**【Rule】骑手匹配拦截规则**：
- **物品禁运拦截**：订单包含违禁品（易燃易爆、管制刀具等）时，系统提示"该物品暂不支持配送，请检查物品是否符合配送要求"
- **骑手资质拦截**：高价值订单（>1000元）仅分配给评分4.8以上、完成单量>500单的骑手
- **距离拦截**：取货距离>5km的订单，系统提示"取货距离较远，可能产生额外费用，是否继续下单？"
- **负载拦截**：骑手当前负载已满（已有3单在进行中），不再向其派单

#### 2.3 骑手资质管理

##### 2.3.1 准入要求

| 审核项 | 要求 | 验证方式 |
|--------|------|----------|
| 实名认证 | 身份证信息真实有效 | 人脸识别+证件OCR |
| 健康证明 | 有效期内的健康证（餐饮配送） | 证件上传审核 |
| 无犯罪记录 | 背景审查通过 | 第三方背调 |
| 蜂鸟培训考核 | 安全服务培训合格 | 线上考试≥80分 |
| 装备要求 | 保温箱、头盔、工服 | 装备审核照片 |

##### 2.3.2 骑手评分体系

| 评分维度 | 权重 | 计算方式 |
|----------|------|----------|
| 准时率 | 30% | 准时完成单量/总单量 |
| 好评率 | 25% | 好评数/评价总数 |
| 投诉率 | 20% | 1-投诉单量/总单量 |
| 完成率 | 15% | 完成单量/接单总量 |
| 活跃度 | 10% | 在线时长/标准时长 |

### 3. 取件配送

#### 3.1 取货流程

##### 3.1.1 标准取货流程

```
到达取货点 ──▶ 联系发货人 ──▶ 核验物品 ──▶ 拍照留证 ──▶ 确认取货 ──▶ 开始配送
      │            │            │            │            │
      ▼            ▼            ▼            ▼            ▼
  系统打卡      电话/APP      外观/数量/    物品照片/     系统状态
  记录时间      通知到达      禁限品检查    取货凭证      更新为"已取货"
```

##### 3.1.2 物品核验标准

| 检查项 | 操作要求 | 异常处理 |
|--------|----------|----------|
| 外观检查 | 包装完好、无破损、无渗漏 | 拍照记录，与发货人确认 |
| 数量核对 | 与订单描述一致 | 不符时联系用户确认 |
| 禁限品检查 | 拒绝承接违禁品 | 发现违禁品拒绝取货并上报 |
| 特殊要求确认 | 温度要求、易碎标识等 | 确认保温/防震措施到位 |

**【话术】取货核验话术**：

```
骑手："您好，饿了么跑腿，我来取件"

发货人："就是合同文件"

### 4. 送达确认

|----------|----------|----------|

### 5. 异常处理

#### 5.1 订单取消

| 取消时机 | 处理规则 |
|----------|----------|
| 骑手未接单前 | 用户可免费取消 |
| 骑手已接单未取货 | 可能产生取消费用 |
| 骑手已取货 | 原则上不可取消，特殊情况协商处理 |

#### 5.2 物品损坏/丢失处理

##### 5.2.1 责任判定标准

| 场景 | 责任判定 | 判定依据 | 处理原则 |
|------|----------|----------|----------|
| 取货时已损坏 | 发货方责任 | 取货照片显示已损坏 | 拍照留证，联系发货人确认 |
| 配送途中损坏 | 骑手/平台责任 | 取货完好、送达损坏 | 按保价或实际价值赔偿 |
| 配送途中丢失 | 骑手/平台责任 | 无法提供送达凭证 | 全额赔偿 |
| 收货后发现问题 | 需举证区分责任 | 签收后24小时内举证 | 根据证据判定 |

#### 5.3 配送超时处理

| 超时类型 | 判定标准 | 处理措施 |
|----------|----------|----------|
| 接单超时 | 超过接单响应时限 | 系统自动重新派单 |
| 取货超时 | 超过到店/取货时限 | 提醒骑手，必要时改派 |
| 送达超时 | 超过承诺送达时间 | 超时赔付/优惠券补偿 |

#### 5.4 联系不上处理

| 场景 | 处理流程 |
|------|----------|
| 联系不上发货人 | 等待10分钟，上报异常，联系客服介入 |
| 联系不上收货人 | 等待10分钟，尝试备用联系方式，上报异常 |
| 地址错误/不详 | 联系用户确认，必要时取消或改派 |

#### 5.5 理赔流程

```
用户申请理赔 ──▶ 提交证据（照片、视频、价值证明）──▶ 平台审核 ──▶ 责任判定 ──▶ 赔付/拒赔
```

#### 5.6 赔付标准

| 情况 | 赔付标准 | 上限说明 |
|------|----------|----------|
| 已保价物品 | 按保价金额赔付 | 最高不超过声明价值 |
| 未保价物品 | 按实际损失赔付 | 最高不超过订单金额的10倍 |
| 部分损坏 | 按损坏比例赔付或协商修复费用 | 按实际可修复费用 |
| 完全丢失 | 全额赔付 | 受保价/赔付上限限制 |

## 评估案例

### 案例1：准时率评估

**场景**：某区域一周内完成订单1000单，其中准时送达960单，超时40单

**计算**：
- 准时率 = 960/1000 = 96%
- 评估结果：良好（95%-98%区间）

**改进建议**：
- 分析40单超时的原因分布（交通拥堵/骑手负载/天气因素）
- 针对高峰时段增加运力储备
- 优化派单算法，减少骑手绕路

### 案例2：投诉率评估

**场景**：某月完成订单5000单，收到投诉15单

**计算**：
- 投诉率 = 15/5000 = 0.3%
- 评估结果：优秀（<0.3%）

**分析**：
- 投诉类型分布：服务态度8单、物品损坏4单、配送超时3单
- 重点关注服务态度类投诉，加强骑手服务培训

### 案例3：理赔率评估

**场景**：某季度完成订单30000单，发生理赔18单

**计算**：
- 理赔率 = 18/30000 = 0.06%
- 评估结果：优秀（<0.1%）

**分析**：
- 理赔金额总计5800元，单均理赔322元
- 主要理赔原因：蛋糕损坏6单、文件丢失4单、鲜花损坏3单
- 建议加强易损品类的包装规范和配送培训

### 案例4：骑手人效评估

**场景**：某站点有活跃骑手50人，日均完成订单800单

**计算**：
- 单骑手日均完成单量 = 800/50 = 16单
- 评估结果：良好（15-20单区间）

**优化方向**：
- 分析骑手工作时段分布，优化排班
- 提升系统派单效率，减少骑手空驶
- 激励高绩效骑手，提升整体人效
