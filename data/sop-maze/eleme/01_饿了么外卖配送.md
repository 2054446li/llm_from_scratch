## 业务概述

饿了么是中国领先的本地生活服务平台，旗下外卖业务连接消费者、商家和骑手三方，提供餐饮外卖、生鲜果蔬、鲜花蛋糕等即时配送服务。

### 核心参与方

```
+-----------+      下单      +-----------+      接单      +-----------+
|  消费者   | -------------> |  饿了么平台 | -------------> |   商家    |
+-----------+                +-----------+                +-----------+
     ^                            |                            |
     |      配送完成              |      派单                  | 出餐
     |                            v                            v
     +--------------------  蜂鸟骑手  <--------------------  备餐
```

## Objective

1. **用户体验目标**：确保用户从注册到收餐的全流程顺畅，订单准时送达率 ≥ 95%
2. **商家运营目标**：帮助商家高效处理订单，出餐时间控制在承诺范围内
3. **骑手服务目标**：合理派单，保障蜂鸟骑手配送效率与安全
4. **平台质量目标**：降低客诉率，提升用户复购率和平台口碑
5. **生态建设目标**：构建用户-商家-骑手三方共赢的本地生活服务生态

### 五、配送接收

#### 5.1 收货流程

| 步骤 | 操作内容 | 注意事项 |
|------|----------|----------|
| 1 | 骑手联系用户确认收货方式 | 当面交付/放门口/放前台等 |
| 2 | 核对订单信息 | 确认商家、商品数量无误 |
| 3 | 检查餐品状态 | 查看是否有撒漏、破损 |
| 4 | 确认收货 | 点击「确认收货」或等待系统自动确认 |
| 5 | 评价订单 | 对商家、商品、配送进行评价 |

#### 5.2 收货异常处理

| 异常场景 | 处理流程 |
|----------|----------|
| 联系不上用户 | 骑手尝试多次联系 → 上报异常 → 等待用户回复/按备注处理 |
| 地址错误/不详 | 联系用户确认 → 按正确地址配送或协商处理 |
| 用户拒收 | 了解原因 → 上报平台 → 按平台指引处理 |
| 餐品损坏 | 拍照留证 → 联系用户说明 → 上报平台处理 |
| 少送/漏送 | 核对订单 → 联系商家/骑手确认 → 协商补送或退款 |

#### 5.3 自动确认规则

```
自动确认条件：
┌────────────────────────────────────────────────────────┐
│  1. 骑手点击「确认送达」后，用户未手动确认             │
│  2. 系统在一定时间后自动确认订单完成                   │
│  3. 自动确认后用户仍可在评价期内进行评价               │
└────────────────────────────────────────────────────────┘
```

## Rule层

### 系统约束

| 约束类别 | 约束项 | 规则说明 | 异常处理 |
|----------|--------|----------|----------|
| **用户侧** | 注册限制 | 同一手机号/设备限制注册数量 | 触发风控需验证身份 |
| | 地址限制 | 收货地址需在配送范围内 | 超出范围提示无法配送 |
| | 下单限制 | 新用户/异常账户可能有限制 | 联系客服解除限制 |
| **商家侧** | 接单时限 | 需在设定时间内接单 | 超时自动取消订单 |
| | 出餐时限 | 需在承诺时间内出餐 | 影响商家评分和排名 |
| | 营业状态 | 需及时更新营业/休息状态 | 避免用户无法下单 |
| **骑手侧** | 接单限制 | 同时接单数量上限 | 超出负载不再派单 |
| | 配送时限 | 需在预计时间内送达 | 影响骑手评分和收入 |
| | 服务规范 | 需遵守配送服务标准 | 违规处罚或下线 |
| **平台侧** | 支付时限 | 下单后需在规定时间内支付 | 超时未支付自动取消 |
| | 退款时限 | 退款申请需在规定时间内 | 超期可能无法退款 |
| | 评价时限 | 订单完成后评价期内可评价 | 超期自动关闭评价入口 |
| **安全侧** | 隐私保护 | 手机号虚拟化保护 | 禁止私下交易 |
| | 资金安全 | 支付风控拦截可疑交易 | 验证后放行或退款 |
| | 食品安全 | 商家需具备合法资质 | 无证商家下架处理 |

## Output Requirement

1. **订单状态实时同步**：用户、商家、骑手三端状态实时更新，关键节点推送通知
2. **异常及时通知**：配送延误、订单取消等情况主动推送通知并说明原因
3. **售后快速响应**：退款申请24小时内处理 `[需内部资料确认：时效标准]`
4. **数据记录完整**：订单全流程数据留存，便于纠纷处理和数据分析
5. **用户体验优先**：在规则允许范围内，优先保障用户权益
6. **隐私安全保护**：用户手机号虚拟化，交易数据加密存储
7. **多端一致性**：APP、小程序、网页端功能和数据保持一致

## Evaluation

### 核心评估维度

| 维度 | 指标 | 目标值 | 测量方式 |
|------|------|--------|----------|
| **用户体验** | 下单转化率 | ≥ 25% | 下单用户数/浏览商家数 |
| | 支付成功率 | ≥ 98% | 成功支付订单/提交订单 |
| | 用户满意度 | ≥ 4.7分 | 订单评价平均分 |
| **配送质量** | 准时送达率 | ≥ 95% | 准时订单/总订单 |
| | 平均配送时长 | ≤ 35分钟 | 取餐到送达平均时间 |
| | 配送投诉率 | ≤ 0.5% | 配送投诉订单/总订单 |
| **商家服务** | 商家接单率 | ≥ 98% | 接单订单/总订单 |
| | 平均出餐时长 | ≤ 20分钟 | 接单到出餐平均时间 |
| | 商家评分 | ≥ 4.5分 | 商家服务评分 |
| **售后处理** | 退款处理时效 | ≤ 24小时 | 申请到完成平均时间 |
| | 客诉解决率 | ≥ 90% | 解决客诉/总客诉 |
| | 重复投诉率 | ≤ 5% | 重复投诉用户/总投诉用户 |

### 评估周期

- **实时监控**：订单状态、配送进度、系统稳定性
- **日报**：订单量、GMV、投诉量、退款率
- **周报**：用户留存、商家活跃度、骑手效率
- **月报**：综合满意度、市场份额、竞品对比
