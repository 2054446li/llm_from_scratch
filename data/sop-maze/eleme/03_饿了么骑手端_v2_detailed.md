## Objective

本SOP旨在规范饿了么蜂鸟众包骑手端的运营流程，确保：

1. **骑手准入合规**：严格审核骑手资质，保障配送服务基础质量
2. **配送效率优化**：合理派单与路径规划，提升骑手接单效率与收入
3. **服务品质保障**：标准化配送流程，确保订单准时、安全送达
4. **骑手权益保护**：透明结算、公平申诉机制，保障骑手合法权益
5. **安全运营底线**：安全培训与监控，降低配送安全风险

## Standard Operating Procedures

### 1. 骑手注册认证流程

#### 1.1 账号注册

##### 1.1.1 注册流程

```
下载蜂鸟众包APP ──▶ 手机号注册 ──▶ 实名认证 ──▶ 上传证件 ──▶ 人脸识别 ──▶ 提交审核
      │            │              │              │              │              │
      ▼            ▼              ▼              ▼              ▼              ▼
   iOS/Android   短信验证       身份证正      身份证/      活体检测       等待1-3
   应用商店                       反面拍照      健康证等                      工作日
```

**【KCP】注册认证关键控制点**：
- 身份证必须在有效期内，且为本人持有
- 人脸识别必须通过活体检测，确保人证一致
- 健康证必须在有效期内，且为正规医疗机构出具
- 有犯罪记录或交通严重违法记录者不予通过

**【话术】注册咨询标准话术**：
```
用户："我想当饿了么骑手，需要什么条件？"
客服："您好，成为蜂鸟众包骑手需要：1）18-55周岁，身体健康；2）有效身份证；3）健康证（可在入职后补办，部分城市要求）；4）智能手机；5）电动车或自行车。注册审核通常1-3个工作日完成。"
```

#### 1.2 资质审核

##### 1.2.1 审核流程

```
资料提交 ──▶ 系统自动初审 ──▶ 人工复核 ──▶ 背景核查 ──▶ 审核结果通知 ──▶ 开通账号
    │              │              │            │              │              │
    ▼              ▼              ▼            ▼              ▼              ▼
骑手上传      OCR识别+      审核员核查      公安接口     短信+APP       可接单
证件照片      规则校验      信息真实性      验证背景       推送通知       开始配送
```

##### 1.2.2 审核标准

| 审核项 | 通过标准 | 常见驳回原因 |
|--------|----------|--------------|
| 身份证 | 有效期内，人证一致 | 过期、非本人、照片模糊 |
| 健康证 | 有效期内，正规机构 | 过期、伪造、机构不认可 |
| 人脸识别 | 活体通过，人证匹配 | 非本人、光线不足、动作不符 |
| 背景核查 | 无犯罪/严重交通违法记录 | 有犯罪记录、醉驾记录等 |

**【Rule】资质拦截规则**：
- **黑名单拦截**：在平台黑名单或有严重违规记录，系统自动拒绝"该身份信息存在违规记录，暂不支持注册"
- **年龄拦截**：未满18周岁或超过55周岁，提示"年龄不符合要求"
- **健康证拦截**：健康证过期或无效（要求健康证的城市），提示"请上传有效期内的健康证"
- **背景拦截**：有犯罪记录或严重交通违法，提示"背景审核未通过"

### 3. 接单配送

#### 3.1 接单流程

##### 3.1.1 派单模式

| 模式 | 说明 | 适用场景 |
|------|------|----------|
| 系统派单 | 算法根据位置、方向、负载自动派单 | 主要派单方式 |
| 抢单模式 | 骑手主动进入抢单大厅抢单 | 系统派单不足时 |
| 指派单 | 高价值/特殊订单指派 | 优质骑手优先 |
| 预约单 | 用户预约配送时间的订单 | 提前指派或抢单 |

##### 3.1.2 派单算法因素 `[需内部资料确认：具体权重]`

```
智能派单系统考虑因素：
┌────────────────────────────────────────────────────────┐
│  1. 骑手位置：距离商家的直线/实际距离                   │
│  2. 骑手负载：当前已接订单数量                          │
│  3. 配送方向：订单目的地与骑手当前路线的匹配度          │
│  4. 预计时间：基于历史数据的配送时长预测                │
```

##### 3.1.3 标准配送流程

```
上线接单 ──▶ 收到派单/抢单 ──▶ 确认接单 ──▶ 前往商家 ──▶ 到店取餐 ──▶ 核对商品 ──▶ 配送用户 ──▶ 送达确认
    │              │              │            │            │            │            │            │
    ▼              ▼              ▼            ▼            ▼            ▼            ▼            ▼
 设置工作      系统推送/      倒计时       导航前往      点击到店      核对数量      导航前往      用户确认
 状态在线      大厅抢单       确认接单      商家位置      确认取餐      检查包装      用户地址      订单完成
```

**【KCP】接单关键控制点**：
- 接单后必须在规定时间内到店取餐
- 取餐时必须核对商品与订单一致
- 配送途中必须保证餐品安全和温度
- 送达时必须确认用户身份或按用户要求放置

##### 3.1.4 时效标准

| 环节 | 时效要求 | 超时处理 |
|------|----------|----------|

### 4. 异常处理

#### 4.1 商家端异常

##### 4.1.1 商家出餐慢

| 场景 | 处理流程 |
|------|----------|
| 商家未出餐 | 到店后等待，超时可上报异常 |
| 上报异常 | 点击「商家出餐慢」→ 选择等待时间 → 等待系统处理 |
| 用户通知 | 系统或骑手联系用户说明情况 |
| 等待或取消 | 根据系统提示选择继续等待或取消配送 |

**【话术】商家出餐慢处理话术**：
```
骑手联系用户："您好，饿了么外卖，我在XX餐厅取餐，商家出餐稍慢，可能会晚几分钟送达，请您谅解。"
```

##### 4.1.2 餐品问题

| 问题类型 | 处理方式 |
|----------|----------|
| 餐品缺失 | 与商家核对，要求补全或联系用户确认 |
| 包装破损 | 要求商家重新包装 |
| 餐品有误 | 与商家确认，更换正确餐品 |
| 餐品变质 | 拍照留证，联系用户和平台处理 |

#### 4.2 用户端异常

##### 4.2.1 联系不上用户

| 步骤 | 操作 |
|------|------|
| 1 | 尝试拨打用户电话（至少2-3次） |
| 2 | 通过APP内消息联系 |
| 3 | 等待5-10分钟 `[需内部资料确认：具体时长]` |
| 4 | 上报异常「联系不上用户」 |
| 5 | 按系统指引处理（等待或报备后离开） |

**【话术】联系不上用户话术**：
```
骑手语音留言："您好，饿了么外卖，您的订单已送达，但联系不上您。我将餐品放在XX位置，请及时取餐。如有问题请联系我。"
```

##### 4.2.2 地址错误/不详

| 场景 | 处理流程 |
|------|----------|
| 地址有误 | 联系用户确认正确地址 |
| 地址不详 | 联系用户补充详细地址（门牌号、楼层等） |
| 超配送范围 | 上报异常，协商处理方案 |

##### 4.2.3 用户拒收

| 场景 | 处理流程 |
|------|----------|
| 了解原因 | 询问用户拒收原因（餐品问题、送错地址等） |
| 上报异常 | 点击「用户拒收」上报 |
| 按指引处理 | 联系客服或按系统提示操作 |
| 餐品处理 | 根据平台规则处理餐品（退回商家或按指引处理） |

#### 4.3 配送异常

| 异常类型 | 处理方式 |
|----------|----------|
| 餐品撒漏 | 拍照留证 → 联系用户说明 → 上报平台协商处理 |
| 交通事故 | 确保安全 → 报警处理 → 联系平台报备 → 必要时转单 |
| 车辆故障 | 上报异常 → 联系客服 → 协商转单或处理方案 |
| 天气原因 | 注意安全 → 合理延时 → 与用户沟通说明 |
| 定位异常 | 检查GPS设置 → 手动刷新位置 → 联系客服 |

**【Rule】配送拦截规则**：
- **疲劳拦截**：连续接单超过4小时，系统提示休息"您已连续配送4小时，建议休息15分钟"
- **超时预警**：配送即将超时，系统提示"订单即将超时，请加快配送"
- **异常订单拦截**：用户投诉或差评过多，该用户订单提示"该用户近期有异常记录，请谨慎接单"
- **区域限制**：未开通区域无法接单"该区域暂未开通蜂鸟众包服务"
