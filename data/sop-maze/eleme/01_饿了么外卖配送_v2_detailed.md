# 饿了么外卖配送 SOP 详细版（v2_detailed）

> **文档版本**: v2.0 详细版  
> **适用场景**: 外卖配送全流程客服/运营处理  
> **更新日期**: 2026年8月

> **声明**: 本文档基于饿了么公开规则、服务协议及行业通用标准整理，仅供参考。具体业务规则以饿了么官方最新公告为准。

---

## Objective

1. **用户体验目标**: 确保用户从注册到收餐的全流程顺畅，订单准时送达率 ≥ 95%
2. **商家运营目标**: 帮助商家高效处理订单，出餐时间控制在承诺范围内
3. **骑手服务目标**: 合理派单，保障蜂鸟骑手配送效率与安全
4. **平台质量目标**: 降低客诉率，提升用户复购率和平台口碑
5. **生态建设目标**: 构建用户-商家-骑手三方共赢的本地生活服务生态

---

## Standard Operating Procedures

### 一、用户注册登录

#### 1.1 注册流程

```
┌─────────────────────────────────────────────────────────────────┐
│                     用户注册登录流程                              │
├─────────────────────────────────────────────────────────────────┤
│                                                                 │
│  ┌──────────┐    ┌──────────┐    ┌──────────┐    ┌──────────┐  │
│  │ 1.选方式 │ -> │ 2.验身份 │ -> │ 3.设密码 │ -> │ 4.进首页 │  │
│  └──────────┘    └──────────┘    └──────────┘    └──────────┘  │
│                                                                 │
│  KCP: 手机号有效性校验、第三方授权完整性校验、定位权限获取       │
│                                                                 │
└─────────────────────────────────────────────────────────────────┘
```

| 步骤 | 操作内容 | 注意事项 | Rule层约束 |
|------|----------|----------|------------|
| 1 | 打开饿了么APP/小程序/网页 | 支持iOS、Android、支付宝、淘宝入口 | 定位失败时需手动选择 |
| 2 | 选择注册方式 | 手机号、支付宝、淘宝、微信快捷登录 | 同一设备限制注册数量，触发风控需验证身份 |
| 3 | 验证身份信息 | 手机号需短信验证；第三方需授权 | 验证码5分钟有效，超时需重新获取 |
| 4 | 设置登录密码（可选） | 可选择免密登录或设置独立密码 | 密码强度需符合安全要求（8位以上含字母数字） |
| 5 | 完成注册，进入首页 | 自动定位或提示手动选择地址 | **KCP**: 地址需在配送范围内 |

### 五、骑手配送流程

#### 5.1 派单逻辑

```
┌─────────────────────────────────────────────────────────────────┐
│                    蜂鸟智能派单系统算法逻辑                       │
├─────────────────────────────────────────────────────────────────┤
│                                                                 │
│  派单权重因子（按优先级排序）：                                   │
│                                                                 │
│  1. 骑手位置: 距离商家的直线/实际距离                            │
│  2. 骑手负载: 当前已接订单数量（通常≤5单）                       │
│  3. 配送方向: 订单目的地与骑手当前路线的匹配度                   │
│  4. 预计时间: 基于历史数据的配送时长预测                         │
│  5. 骑手评级: 服务评分、准时率等                                 │
│  6. 天气路况: 实时天气、交通拥堵情况                             │
│                                                                 │
│  Rule: 恶劣天气自动延长预计送达时间，增加骑手补贴                │
│                                                                 │
└─────────────────────────────────────────────────────────────────┘
```
