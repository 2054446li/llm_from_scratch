## 业务概述

饿了么到店餐饮业务（原「口碑」业务）是阿里巴巴本地生活服务体系的重要组成部分，为消费者提供餐厅发现、团购套餐、预订订座、优惠买单等一站式到店服务，同时为线下餐饮商家提供数字化经营解决方案。

### 核心参与方

```
+-----------+      浏览/购买     +-----------+      入驻/核销     +-----------+
|  消费者   | ----------------> |  饿了么平台 | ----------------> |   商家    |
+-----------+                   +-----------+                   +-----------+
     ^                              |                               |
     |      消费完成/评价           |      结算                      | 提供服务
     |                              v                               v
     +----------------------  交易系统  <-----------------------  确认核销
```

## Objective

1. **用户体验目标**: 帮助用户便捷发现优质餐厅，享受优惠到店服务，团购核销率 ≥ 75%
2. **商家引流目标**: 为线下商家带来精准客流，提升门店营业额 ≥ 15%
3. **平台交易目标**: 提高团购转化率，降低退款率 ≤ 12%
4. **服务质量目标**: 确保团购信息真实准确，杜绝虚假宣传，商家爽约率 ≤ 0.8%
5. **数字化目标**: 推动线下餐饮数字化，提升商家经营效率

### 一、餐厅搜索发现

#### 1.1 用户搜索流程

```
┌─────────────────────────────────────────────────────────────────┐
│                     餐厅搜索发现流程                              │
├─────────────────────────────────────────────────────────────────┤
│                                                                 │
│  ┌──────────┐    ┌──────────┐    ┌──────────┐    ┌──────────┐  │

│                                                                 │
│  KCP: LBS定位准确性、搜索结果相关性、商家信息完整性              │
│                                                                 │
└─────────────────────────────────────────────────────────────────┘
```

| 步骤 | 操作内容 | 注意事项 | Rule层约束 |
|------|----------|----------|------------|
| 1 | 打开饿了么APP/支付宝，进入「到店」频道 | 基于LBS推荐附近餐厅 | 定位失败需手动选择城市 |
| 2 | 使用搜索框输入餐厅名/菜系/商圈 | 智能联想、纠错、推荐 | **KCP**: 搜索结果需包含完整商家信息 |
| 3 | 筛选排序（距离/评分/销量/价格） | 实时计算排序结果 | 排序算法透明可解释 |
| 4 | 浏览商家详情页 | 查看团购、评价、环境等信息 | 必须展示完整使用限制 |
| 5 | 查看用户真实评价 | 过滤虚假评价，展示带图评价 | 评价真实性校验 |

#### 1.2 推荐算法逻辑

```
商家推荐排序因素:
├── 距离因素（用户与门店距离）
├── 质量因素
│   ├── 商家评分（1-5星）
│   ├── 用户评价数量
│   └── 差评率/投诉率
├── 热度因素
│   ├── 近期销量
│   ├── 收藏人数
│   └── 浏览量
├── 优惠力度
│   ├── 团购折扣率
│   ├── 代金券面额
│   └── 限时活动
└── 商家服务
    ├── 响应速度
    ├── 核销便利性
    └── 会员权益
```

#### 1.3 商家信息展示规范

| 信息项 | 展示要求 | KCP标记 |
|--------|----------|---------|
| 门店图片 | 真实环境照片，不少于5张 | 图片真实性审核 |
| 营业时间 | 精确到时段，标注节假日安排 | 营业时间准确性校验 |
| 人均消费 | 基于实际订单计算的参考价 | 价格真实性校验 |

### 三、预约订座流程

#### 3.1 在线预订流程

| 步骤 | 操作内容 | 系统处理 | KCP标记 |
|------|----------|----------|---------|
| 1 | 选择商家，点击「订座」入口 | 显示可预订时段和桌型 | 实时库存查询 |
| 2 | 选择日期、时间、人数 | 实时查询座位库存 | 时段可用性校验 |
| 3 | 选择桌型（大厅/包厢） | 展示不同桌型低消要求 | 桌型与人数匹配校验 |
| 4 | 填写联系人信息 | 验证手机号，支持代订 | 手机号有效性校验 |
| 5 | 提交预订 | 发送预订请求给商家 | 预订请求发送时间记录 |
| 6 | 等待确认 | 商家确认后短信/APP通知用户 | **KCP**: 商家确认时限15分钟 |

#### 3.2 预订状态流转

```
用户提交预订
      │
      ▼
商家收到预订通知（APP/短信/语音）
      │
      ▼
┌─────────────────────────────────────────┐
│ Rule: 核销时效拦截                      │
│ - 商家需在15分钟内确认                  │
│ - 超时未确认自动取消                    │
│ - 用户可重新预订                        │
└─────────────────────────────────────────┘
      │
      ▼
┌─────────────────────────────────────────┐
│  商家确认 → 预订成功，通知用户          │
│  商家拒绝 → 说明原因，推荐其他时段      │
│  超时未响应（15分钟）→ 系统自动取消     │
└─────────────────────────────────────────┘
```

#### 3.3 预订类型

| 预订类型 | 特点 | 适用场景 | KCP标记 |
|----------|------|----------|---------|
| 普通订座 | 仅保留座位，到店点餐 | 日常用餐 | 座位保留时长30分钟 |
| 套餐预订 | 预订+套餐预付，到店即食 | 商务宴请 | **KCP**: 套餐内容与预订绑定 |
| 包厢预订 | 私密空间，可能有低消 | 聚会宴请 | 低消金额提前告知 |
| 排队取号 | 线上取号，到店叫号 | 热门餐厅 | 叫号提醒通知 |

#### 3.4 预订变更与取消

```
用户取消预订:
├── 提前X小时取消 → 无责取消
├── 临近取消 → 可能影响信用分
└── 爽约未到 → 记录违约，限制后续预订

商家取消预订:
├── 主动取消 → 需说明原因，补偿用户
└── 不可抗力 → 协助用户改期或退款
```

#### 4.3 优惠买单流程

| 步骤 | 操作内容 | 说明 | KCP标记 |
|------|----------|------|---------|
| 1 | 用餐完毕后叫服务员结账 | 告知使用优惠买单 | 消费金额确认 |
| 2 | 打开饿了么APP扫码 | 扫描桌台二维码或商家收款码 | 扫码识别校验 |

| 4 | 选择可用优惠 | 代金券/满减/折扣自动叠加 | 最优方案自动计算 |
| 5 | 确认支付 | 完成付款，获取电子账单 | 支付成功确认 |

#### 4.4 核销异常处理

#### 7.4 商家爽约处理

##### 7.4.1 爽约定义

商家爽约包括但不限于：
- 预订成功后商家拒绝接待
- 商家临时停业未提前通知
- 到店后无法提供团购套餐内容
- 要求用户额外支付不合理费用
- 商家擅自取消已确认预订

##### 7.4.2 处理流程

```
用户投诉商家爽约
    │
    ▼

    ▼

└─────────────────────────────────────────┘
    │
    ▼
┌─────────────────────────────────────────┐
│  情况属实：                             │
│  - 为用户全额退款                       │
│  - 提供补偿（优惠券/现金红包）          │

│  - 严重情况下架商家/处罚                │

```

## Rule 层约束汇总

| 规则类别 | 规则名称 | 规则内容 | 触发时机 |
|----------|----------|----------|----------|
| 核销时效 | 商家确认时限 | 商家需在15分钟内确认预订 | 预订提交后 |
| 核销时效 | 券有效期拦截 | 过期券无法核销 | 核销时 |
| 核销时效 | 使用时段拦截 | 不在可用时段内无法核销 | 核销时 |
| 商家资质 | 商家资质拦截 | 检查商家是否具备接待能力 | 核销/预订时 |
| 退款 | 退款时效拦截 | 过期7天内可申请退款 | 退款申请时 |
| 退款 | 不可退商品拦截 | 秒杀商品不可退 | 退款申请时 |
| 爽约 | 爽约记录拦截 | 多次爽约商家限制活动 | 商家违约时 |
| 交易 | 支付超时拦截 | 支付超时15分钟释放库存 | 支付环节 |
| 交易 | 限购数量拦截 | 超出限购数量系统拦截 | 购买环节 |
| 内容 | 信息真实性拦截 | 商家信息、套餐内容必须真实 | 入驻/上架时 |
| 风控 | 反欺诈拦截 | 识别异常购买行为 | 交易全程 |

## Output Requirement

1. **信息透明**: 团购详情页清晰展示使用规则、限制条件、有效期，避免误导消费
2. **预订确认**: 预订请求15分钟内响应，超时自动提醒商家
3. **核销便捷**: 支持二维码扫码、券号输入等多种核销方式，减少用户等待时间
4. **退款高效**: 符合条件的退款申请自动处理，1-3个工作日到账
5. **投诉响应**: 商家爽约投诉24小时内处理，复杂纠纷72小时内出具结果
6. **评价真实**: 建立完善的评价审核机制，过滤虚假评价，保障参考价值
7. **数据安全**: 用户隐私信息加密存储，交易数据安全传输
