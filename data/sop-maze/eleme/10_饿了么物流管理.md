## 3. Objective（业务目标）

### 3.1 核心目标

| 目标维度 | 具体指标 | 目标值 |
|----------|----------|--------|
| 时效达标 | 准时率 | >= 95% |
| 用户体验 | 平均配送时长 | <= 30分钟 |
| 骑手效率 | 人均日单量 | >= 35单 |
| 成本控制 | 单均配送成本 | 持续优化 |
| 服务质量 | 用户满意度 | >= 4.8/5.0 |
| 异常处理 | 异常订单闭环率 | >= 98% |

### 3.2 业务价值

1. **用户体验提升**：通过智能调度和路径优化，缩短配送时间，提升用户满意度
2. **运营效率优化**：合理分配运力资源，降低空驶率，提升骑手收入
3. **成本精细化管控**：通过数据分析和预测，实现运力供需平衡
4. **风险及时响应**：建立完善的异常处理机制，保障配送服务质量

## 4. Standard Operating Procedures（标准操作流程）

### 4.1 运单管理

#### 4.1.1 运单创建
- **触发条件**：用户下单并完成支付
- **操作步骤**：
  1. 接收订单系统推送的订单数据
  2. 校验订单信息完整性（地址、商品、金额）
  3. 生成唯一运单号（规则：日期+区域码+序列号）
  4. 计算预计配送时长（基于距离、时段、天气）
  5. 写入运单数据库，状态设为"待分配"
  6. 推送至调度系统

#### 4.1.2 运单状态流转
```
待分配 → 已分配 → 骑手接单 → 到店取货 → 配送中 → 已送达 → 已完成
  │         │         │          │          │         │
  └─────────┴─────────┴──────────┴──────────┴─────────┘
                    ↓ 异常分支
              已取消 / 异常处理中 / 已转单
```

#### 4.1.3 运单查询与追踪
- 支持多维度查询：运单号、手机号、订单号、骑手ID
- 实时轨迹查询：集成地图服务，展示骑手实时位置
- 历史轨迹回放：支持72小时内轨迹回溯

#### 4.1.4 运单取消与修改
- **取消规则**：
  - 待分配状态：用户/商家可直接取消
  - 已分配未接单：自动释放运力，允许取消
  - 骑手已接单：需骑手确认或客服介入
  - 配送中：原则上不允许取消，特殊情况客服处理
- **修改规则**：
  - 地址修改：配送前可修改，重新计算配送费
  - 商品修改：需商家确认，可能影响配送时长

---

### 4.2 调度系统

#### 4.2.1 智能派单
- **派单策略**：
  1. **距离优先**：优先分配给距离商家最近的骑手
  2. **负载均衡**：考虑骑手当前订单量，避免过载
  3. **顺路优化**：分析骑手当前路径，优先顺路订单
  4. **能力匹配**：根据订单类型（重量、体积）匹配骑手运力
- **派单流程**：
  1. 订单进入派单池
  2. 筛选可用骑手（在线、空闲、区域内）
  3. 计算匹配分数（距离、负载、顺路度）
  4. 选择最优骑手推送
  5. 等待骑手响应（超时自动转派）

#### 4.2.2 抢单模式
- **适用场景**：高峰时段、特殊订单、众包运力
- **规则配置**：
  - 抢单范围：基于骑手位置划定抢单半径
  - 优先级设置：优质骑手抢单优先权
  - 防刷单机制：同一骑手连续抢单间隔限制

#### 4.2.3 调度干预
- **人工调度**：
  - 异常订单人工重新分配
  - 爆单区域紧急调派支援运力
  - 骑手突发情况订单转移
- **系统干预**：
  - 自动识别超时风险订单，提前转派
  - 动态调整派单半径应对供需变化

---

### 4.3 骑手管理

#### 4.3.1 骑手入驻
- **资料审核**：
  1. 身份信息核验（实名认证）
  2. 健康证审核（餐饮配送必需）
  3. 交通工具登记（电动车/摩托车）
  4. 培训考核（安全规范、服务标准）
- **账号开通**：审核通过后开通配送账号，配置服务区域

#### 4.3.2 骑手状态管理
| 状态 | 说明 | 可接单 |
|------|------|--------|
| 离线 | 未登录APP | 否 |
| 在线-空闲 | 登录且未达负载上限 | 是 |
| 在线-繁忙 | 订单量接近上限 | 限派 |
| 休息中 | 主动暂停接单 | 否 |
| 异常 | 定位异常/违规被限 | 否 |

#### 4.3.3 骑手考核与激励
- **考核指标**：
  - 准时率、完成率、好评率、投诉率
  - 平均配送时长、异常订单率
- **激励机制**：
  - 阶梯奖励：完成单量达标奖励
  - 时段补贴：高峰时段、恶劣天气补贴
  - 质量奖励：零投诉、高好评率奖励

#### 4.3.4 骑手培训
- **入职培训**：平台规则、安全规范、服务礼仪
- **定期培训**：新功能上线、政策更新、案例复盘
- **专项培训**：异常处理、客户沟通技巧

---

### 4.4 配送监控

#### 4.4.1 实时监控
- **监控维度**：
  - 全局运力：在线骑手数、空闲率、区域分布
  - 订单状态：各状态订单数量、滞留订单预警
  - 时效监控：即将超时订单、已超时订单
  - 骑手轨迹：实时位置、路径偏离预警
- **预警机制**：
  - 运力不足预警：区域空闲率低于阈值
  - 超时预警：订单剩余时间低于阈值
  - 异常停留预警：骑手长时间未移动

#### 4.4.2 轨迹管理
- **轨迹采集**：骑手APP定时上报GPS坐标
- **轨迹校验**：识别异常轨迹（漂移、断点）
- **轨迹应用**：配送路径优化、配送费计算依据

#### 4.4.3 服务质量监控
- **用户反馈监控**：实时收集用户评价、投诉
- **骑手行为监控**：识别违规操作（虚假签收、提前点送达）
- **商家反馈监控**：收集商家对配送服务的评价

---

### 4.5 异常处理

#### 4.5.1 异常分类
| 异常类型 | 典型场景 | 处理时效 |
|----------|----------|----------|
| 订单异常 | 商品缺货、商家闭店 | 15分钟内 |
| 配送异常 | 骑手无法联系、车辆故障 | 10分钟内 |
| 地址异常 | 地址错误、用户不在家 | 15分钟内 |
| 用户异常 | 用户拒收、要求退款 | 20分钟内 |
| 系统异常 | 定位失败、APP崩溃 | 5分钟内 |

#### 4.5.2 异常处理流程
```
异常发现 → 异常定级 → 分配处理人 → 处理执行 → 结果确认 → 闭环归档
    │          │           │           │          │
    ▼          ▼           ▼           ▼          ▼
 系统自动    P0/P1/P2    骑手/客服    转派/退款   用户确认
 人工上报    分级响应    运营人员     补送等      满意度
```

#### 4.5.3 常见异常处理方案
- **骑手无法取货**：
  1. 联系商家确认备货情况
  2. 超时可申请转派或取消
  3. 记录商家履约情况
- **用户无法联系**：
  1. 多次电话联系（至少3次）
  2. APP内消息通知
  3. 等待10分钟后报备，按流程处理
- **商品损坏/缺失**：
  1. 拍照取证
  2. 联系用户协商处理
  3. 必要时启动退款/补送流程

---

### 4.6 时效管理

#### 4.6.1 时效计算
- **基础时效**：基于距离计算基础配送时长
- **动态调整因子**：
  - 时段因子：高峰时段延长、夜间缩短
  - 天气因子：恶劣天气延长
  - 区域因子：商圈、写字楼、住宅区差异
  - 商品因子：大件、重货增加时长
- **时效承诺**：根据计算结果向用户展示预计送达时间

#### 4.6.2 时效监控
- **实时监控看板**：
  - 当前平均配送时长
  - 各区域时效达成率
  - 超时订单分布
- **预警机制**：
  - 区域平均时效超过阈值预警
  - 连续超时订单预警

#### 4.6.3 时效优化
- **策略优化**：
  - 动态调整派单半径
  - 优化骑手路径规划
  - 预派单机制（商家出餐前预分配）
- **运力调配**：
  - 高峰时段增加运力
  - 跨区支援机制

## 5. Rule层（系统约束）

### 5.1 业务规则

| 规则编号 | 规则名称 | 规则描述 | 触发条件 | 处理方式 |
|----------|----------|----------|----------|----------|
| R001 | 派单半径限制 | 派单距离不超过3公里 | 派单时 | 超出范围不纳入候选 |
| R002 | 骑手负载上限 | 同时接单不超过5单 | 派单/抢单时 | 达到上限停止派单 |
| R003 | 接单响应时限 | 骑手需在30秒内响应 | 派单推送后 | 超时自动转派 |
| R004 | 到店时限 | 接单后15分钟内到店 | 骑手接单后 | 超时预警/转派 |
| R005 | 送达时限 | 按承诺时效送达 | 配送中 | 超时记录并预警 |
| R006 | 取消时限 | 配送中订单不可随意取消 | 用户取消时 | 需客服审核 |
| R007 | 异常上报时限 | 异常需在5分钟内上报 | 发现异常时 | 超时影响骑手评分 |
| R008 | 轨迹上报频率 | 每10秒上报一次位置 | 配送过程中 | 缺失率影响考核 |

### 5.2 数据规则

| 规则编号 | 规则名称 | 规则描述 |
|----------|----------|----------|
| D001 | 运单号唯一性 | 运单号全局唯一，不可重复 |
| D002 | 状态流转合法性 | 状态变更必须符合预设流转图 |
| D003 | 时间戳完整性 | 关键节点必须记录时间戳 |
| D004 | 数据保留期限 | 运单数据保留2年，日志保留1年 |
| D005 | 敏感信息加密 | 手机号、地址等敏感信息加密存储 |

### 5.3 安全规则

| 规则编号 | 规则名称 | 规则描述 |
|----------|----------|----------|
| S001 | 接口限流 | 单IP每秒请求不超过100次 |
| S002 | 权限校验 | 敏感操作需二次身份验证 |
| S003 | 数据脱敏 | 对外展示数据需脱敏处理 |
| S004 | 操作审计 | 关键操作记录审计日志 |

  }

### 7.2 错误码定义

| 错误码 | 错误描述 | 处理建议 |
|--------|----------|----------|
| 0 | 成功 | - |
| 10001 | 运单不存在 | 检查运单号是否正确 |
| 10002 | 骑手不存在 | 检查骑手ID是否正确 |
| 10003 | 状态流转非法 | 检查当前状态和目标状态 |
| 10004 | 运力不足 | 扩大派单半径或等待 |
| 10005 | 重复操作 | 检查是否已执行过该操作 |
| 20001 | 参数错误 | 检查请求参数格式 |
| 20002 | 权限不足 | 检查操作人权限 |
| 30001 | 系统繁忙 | 稍后重试 |
| 30002 | 服务异常 | 联系技术支持 |

### 7.3 数据格式规范

- **时间格式**：ISO 8601格式，带时区（如 `2024-08-04T10:30:00+08:00`）
- **金额格式**：单位为元，保留两位小数（如 `5.00`）
- **坐标格式**：WGS84坐标系，保留6位小数
- **枚举值**：使用英文小写下划线格式（如 `food_delivery`）

### 7.4 日志输出规范

- **日志级别**：DEBUG、INFO、WARN、ERROR、FATAL
- **日志内容**：时间戳、日志级别、请求ID、类名、方法名、消息、异常堆栈
- **敏感信息**：手机号、地址等需脱敏后记录
