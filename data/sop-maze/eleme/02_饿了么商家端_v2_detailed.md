## Objective

本SOP旨在规范饿了么商家端的运营流程，确保：

1. **入驻合规**：建立标准化的商家准入审核机制，保障平台生态质量
2. **经营高效**：提供清晰的菜单管理、订单处理、营销活动操作指南
3. **履约顺畅**：确保商家-骑手-用户三方协同，提升配送体验
4. **资金安全**：规范结算对账流程，保障商家资金安全
5. **服务闭环**：建立完善的售后服务体系，处理用户投诉与纠纷

## Standard Operating Procedures

### 1. 商家入驻

#### 1.1 入驻申请

##### 1.1.1 入驻类型选择

| 入驻类型 | 适用对象 | 资质要求 | 费用标准 |
|----------|----------|----------|----------|
| 餐饮外卖 | 餐厅、小吃店、饮品店 | 营业执照+食品经营许可证 | 抽佣15-23% |
| 商超便利 | 便利店、超市 | 营业执照+食品流通许可证 | 抽佣8-12% |
| 生鲜果蔬 | 水果店、生鲜店 | 营业执照+食品经营许可证 | 抽佣10-15% |
| 医药健康 | 药店 | 营业执照+药品经营许可证 | 抽佣10-18% |
| 鲜花蛋糕 | 花店、烘焙店 | 营业执照+相关资质 | 抽佣12-18% |

##### 1.1.2 入驻申请流程

```
下载商家版APP ──▶ 注册账号 ──▶ 选择入驻类型 ──▶ 填写店铺信息 ──▶ 上传资质证照 ──▶ 提交审核
       │            │              │                │                │              │
       ▼            ▼              ▼                ▼                ▼              ▼
  iOS/Android    手机号验证    餐饮/零售/医药    店名/地址/      营业执照/      等待1-3
  应用商店                      等分类选择       联系人信息       许可证等         工作日
```

**【KCP】入驻申请关键控制点**：
- 营业执照必须在有效期内，且经营范围包含所售商品
- 食品经营许可证必须与实际经营品类一致
- 店铺地址必须与证照地址一致（或提供合法租赁证明）
- 法人身份证正反面必须清晰可辨

**【话术】入驻咨询标准话术**：
```
商家："我想在饿了么开店，需要什么条件？"
客服："您好，开店需要准备以下材料：1）营业执照原件照片；2）食品经营许可证（餐饮类）；
      3）法人身份证正反面；4）店铺门头照和店内环境照。审核通常需要1-3个工作日。"
```

**【多方对话】入驻咨询场景**：
```
商家："我想在饿了么开店，需要什么条件？"
平台客服："您好，开店需要准备以下材料：1）营业执照原件照片；2）食品经营许可证（餐饮类）；
          3）法人身份证正反面；4）店铺门头照和店内环境照。审核通常需要1-3个工作日。"

商家："我的营业执照经营范围只有餐饮服务，可以卖饮料吗？"
平台客服："餐饮服务经营范围一般可以包含饮品销售。但如果您要销售预包装食品或自制饮品，
          建议确保食品经营许可证的许可项目涵盖相关内容。"
```

#### 1.2 资质审核

##### 1.2.1 审核流程

```
资料提交 ──▶ 系统自动初审 ──▶ 人工复核 ──▶ 资质核验 ──▶ 审核结果通知 ──▶ 签约入驻
    │              │              │            │              │              │
    ▼              ▼              ▼            ▼              ▼              ▼
商家上传      OCR识别+      审核员核查      第三方接口     短信+APP       电子合同
资质照片      规则校验      信息一致性      验证真伪       推送通知       在线签署
```

##### 1.2.2 审核标准

| 审核项 | 通过标准 | 常见驳回原因 |
|--------|----------|--------------|
| 营业执照 | 有效期内，经营范围匹配 | 过期、经营范围不符、伪造 |
| 食品经营许可证 | 有效期内，许可项目匹配 | 过期、许可项目缺失、地址不符 |
| 法人身份证 | 清晰可辨，与营业执照一致 | 模糊、过期、信息不一致 |
| 店铺照片 | 真实环境，与证照地址一致 | 网图、与地址不符、环境不达标 |
| 银行信息 | 对公账户或法人个人账户 | 账户信息错误、非本人账户 |

**【Rule】资质拦截规则**：
- **黑名单拦截**：法人或店铺在平台黑名单中，系统自动拒绝入驻
- **证照过期拦截**：营业执照或许可证过期，提示"您的证照已过期，请更新后重新提交"
- **经营范围拦截**：经营范围与申请类目不符，提示"您的营业执照经营范围不包含申请类目"
- **重复入驻拦截**：同一证照已注册店铺，提示"该营业执照已注册店铺，请勿重复申请"
- **区域限制拦截**：店铺地址不在平台服务范围内，提示"该区域暂不支持入驻"

##### 1.2.3 审核时效与结果处理

| 审核环节 | 时效 | 处理方式 |
|----------|------|----------|
| 系统初审 | 即时 | OCR识别+规则校验，自动通过或转人工 |
| 人工复核 | 1-2工作日 | 审核员核查，可能要求补充材料 |
| 资质核验 | 1工作日 | 对接政府接口验证证照真伪 |
| 结果通知 | 即时 | 短信+APP推送，通过/驳回+原因 |

**【话术】审核结果通知话术**：
```
审核通过："【饿了么】恭喜您！您的店铺【XX店】已通过审核，请登录商家版APP完成签约，即可开始营业。"
审核驳回："【饿了么】您的入驻申请未通过审核，原因：食品经营许可证已过期。请更新证件后重新提交。"
```

**【多方对话】审核结果通知场景**：
```
平台（短信）："【饿了么】恭喜您！您的店铺【老张面馆】已通过审核，请登录商家版APP完成签约，
             即可开始营业。"

平台（短信）："【饿了么】您的入驻申请未通过审核，原因：食品经营许可证已过期。
             请更新证件后重新提交。"
```

### 3. 菜单管理

#### 3.1 商品上架

##### 3.1.1 商品信息录入

| 字段 | 填写要求 | 示例 |
|------|----------|------|
| 商品名称 | 清晰描述，不含违禁词 | "招牌红烧肉套餐" |
| 商品分类 | 选择对应类目 | 主食/热菜/饮品/小吃 |
| 商品图片 | 实物拍摄，清晰美观 | 白底或场景图，无水印 |
| 商品规格 | 多规格设置（如大/中/小） | 大份¥38/中份¥28/小份¥18 |
| 商品价格 | 符合市场定价，不虚假 | 原价¥38，现价¥28 |
| 商品描述 | 配料、口味、份量说明 | "五花肉500g，配米饭一份" |

##### 3.1.2 上架流程

```
进入菜单管理 ──▶ 添加商品 ──▶ 填写商品信息 ──▶ 上传图片 ──▶ 设置规格价格 ──▶ 提交审核 ──▶ 上架销售
      │              │              │              │              │              │              │
      ▼              ▼              ▼              ▼              ▼              ▼              ▼
   商家版APP      选择分类       名称/描述       主图/详情图     单规格/       系统审核       用户可见
   菜单模块                       配料信息                       多规格        合规性
```

**【KCP】商品上架关键控制点**：
- 商品图片必须为实物拍摄，禁止使用网图或过度PS
- 商品描述必须真实准确，不得虚假宣传
- 价格设置必须合理，禁止虚高原价再打折
- 特殊商品（如含酒精饮品）需标注"18岁以下请勿购买"

**【Rule】商品上架拦截规则**：
- **违禁品拦截**：涉黄、涉毒、违禁药品等，系统直接拒绝上架
- **图片违规拦截**：模糊、带水印、非实物图，提示"请上传清晰的实物图片"
- **价格异常拦截**：价格超出类目均价3倍以上，提示"价格异常，请确认后重新提交"
- **描述违规拦截**：含虚假宣传、医疗功效等，提示"描述含违规内容，请修改"

**【话术】商品咨询标准话术**：
```
用户咨询："老板，你们家的招牌牛肉面辣吗？"
商家回复："您好，我们的招牌牛肉面默认微辣，如果您不吃辣可以在下单时备注'免辣'，
          或者选择我们的清汤牛肉面。"
```

```

### 4. 订单处理

#### 4.1 接单流程

##### 4.1.1 订单流转机制

```
用户下单 ──▶ 系统派单 ──▶ 商家接单 ──▶ 备餐制作 ──▶ 打包出餐 ──▶ 骑手取餐 ──▶ 配送完成
    │           │            │            │            │            │            │
    ▼           ▼            ▼            ▼            ▼            ▼            ▼
  支付成功    自动/手动     确认接单      按单制作      核对订单      扫码取餐      用户确认
              派单模式     开始计时      倒计时提醒     贴单封装      核对商品      订单完成
```

##### 4.1.2 接单模式

| 模式 | 说明 | 适用场景 |
|------|------|----------|
| 自动接单 | 系统自动确认订单 | 订单量大、标准化出餐 |
| 手动接单 | 商家手动确认订单 | 订单量小、需要确认库存 |
| 预订单 | 用户预约时间送达 | 提前备餐、高峰分流 |

**【KCP】接单关键控制点**：
- 接单后必须在承诺出餐时间内完成备餐
- 出餐时必须核对商品与订单一致
- 打包必须符合食品安全和配送要求
- 骑手取餐时必须扫码确认

##### 4.1.3 出餐时效标准

| 品类 | 建议出餐时间 | 超时处理 |
|------|--------------|----------|
| 快餐简餐 | 10-15分钟 | 系统自动标记，影响评分 |
| 正餐炒菜 | 15-20分钟 | 骑手等待可申请补偿 |
| 烘焙蛋糕 | 按预约时间 | 提前制作，准时出餐 |
| 生鲜果蔬 | 10分钟内 | 优先处理，保证新鲜 |

**【话术】订单处理标准话术**：
```
新订单提醒："您有新订单【#123456】，请及时处理。订单内容：招牌红烧肉x1，米饭x2"
骑手到店："饿了么配送，来取123456号订单"
商家回复："好的，稍等... 餐好了，请核对一下：招牌红烧肉一份、米饭两盒"
骑手回复："对的，我扫码确认... 好了，谢谢！"
商家回复："小心慢走，注意安全！"
```

**【多方对话】订单处理场景**：
```

骑手（到店）："饿了么配送，来取123456号订单"

#### 4.2 订单异常处理

##### 4.2.1 异常类型与处理

| 异常类型 | 判定标准 | 处理流程 | 责任方 |
|----------|----------|----------|--------|
| 用户取消 | 接单前用户取消 | 自动取消，无责任 | 用户 |
| 商家拒单 | 接单后商家取消 | 需说明原因，影响评分 | 商家 |
| 缺货退单 | 接单后发现缺货 | 联系用户协商，可换货/退款 | 商家 |
| 出餐超时 | 超过承诺出餐时间 | 系统自动标记，影响评分 | 商家 |
| 餐品撒漏 | 包装不当导致 | 重新制作或退款处理 | 商家 |

**【Rule】订单拦截规则**：
- **出餐超时提醒**：超时15分钟未出餐，系统自动提醒骑手"商家出餐较慢，请耐心等待"
- **频繁拒单拦截**：单日拒单率超过10%，系统自动限制接单"您的拒单率较高，已限制自动接单功能"
- **用户投诉拦截**：收到用户投诉后，该商家订单进入人工审核"您的店铺收到用户投诉，新订单需人工审核"
- **营业状态拦截**：未开启营业状态，无法接单"店铺未营业，请先开启营业状态"

**【话术】异常处理标准话术**：
