## 业务概述

饿了么到店餐饮业务（原「口碑」业务）是阿里巴巴本地生活服务体系的重要组成部分，为消费者提供餐厅发现、团购套餐、预订订座、优惠买单等一站式到店服务，同时为线下餐饮商家提供数字化经营解决方案。

### 核心参与方

```
+-----------+      浏览/购买     +-----------+      入驻/核销     +-----------+
|  消费者   | ----------------> |  饿了么平台 | ----------------> |   商家    |
+-----------+                   +-----------+                   +-----------+
     ^                              |                               |
     |      消费完成/评价           |      结算                      | 提供服务
     |                              v                               v
     +----------------------  交易系统  <-----------------------  确认核销
```

## Objective

1. **用户体验目标**：帮助用户便捷发现优质餐厅，享受优惠到店服务
2. **商家引流目标**：为线下商家带来精准客流，提升门店营业额
3. **平台交易目标**：提高团购转化率，降低退款率，提升核销率
4. **服务质量目标**：确保团购信息真实准确，杜绝虚假宣传，保障食品安全
5. **数字化目标**：推动线下餐饮数字化，提升商家经营效率

## Standard Operating Procedures

### 一、餐厅搜索发现

#### 1.1 用户搜索流程

| 步骤 | 操作内容 | 系统处理 |
|------|----------|----------|
| 1 | 打开饿了么APP/支付宝，进入「到店」频道 | 基于LBS推荐附近餐厅 |
| 2 | 使用搜索框输入餐厅名/菜系/商圈 | 智能联想、纠错、推荐 |
| 3 | 筛选排序（距离/评分/销量/价格） | 实时计算排序结果 |
| 4 | 浏览商家详情页 | 展示团购、评价、环境等信息 |
| 5 | 查看用户真实评价 | 过滤虚假评价，展示带图评价 |

### 二、团购套餐购买

#### 2.1 团购产品类型

```
团购产品类型：
├── 套餐团购
│   ├── 固定套餐：菜品组合固定，不可更换
│   ├── 可选套餐：在指定菜品范围内选择
│   └── 阶梯套餐：2人餐/4人餐/6人餐等多规格
├── 代金券
│   ├── 全场通用券：除酒水外全场通用
│   ├── 菜品券：仅限指定菜品使用
│   ├── 满减券：满X元可用，可叠加/不可叠加
│   └── 折扣券：整单折扣（如8.8折）
├── 预订套餐
│   ├── 需提前预约，保留座位
│   ├── 节假日可能不可用或需加价
│   └── 部分含包厢服务费
└── 限时特惠
    ├── 新客专享价
    ├── 限时秒杀
    └── 会员专属价
```

#### 2.2 购买流程

| 步骤 | 操作内容 | 注意事项 |
|------|----------|----------|
| 1 | 浏览商家团购列表 | 对比不同套餐性价比 |
| 2 | 查看套餐详情 | 仔细阅读使用规则、有效期 |
| 3 | 选择套餐规格 | 注意区分：工作日/周末、午餐/晚餐 |
| 4 | 确认购买数量 | 查看限购规则（每人/每桌限用） |
| 5 | 选择支付方式 | 支持支付宝、花呗、银行卡等 |
| 6 | 完成支付 | 获取券码，同步至「我的卡包」 |

#### 2.3 购买限制说明 `[需内部资料确认：具体限制规则]`

| 限制类型 | 说明 |
|----------|------|
| 购买数量限制 | 每人限购X份，每桌限用X张 |

### 三、预约订座

#### 3.1 在线预订流程

| 步骤 | 操作内容 | 系统处理 |
|------|----------|----------|
| 1 | 选择商家，点击「订座」入口 | 显示可预订时段和桌型 |
| 2 | 选择日期、时间、人数 | 实时查询座位库存 `[需内部资料确认：库存同步机制]` |
| 3 | 选择桌型（大厅/包厢） | 展示不同桌型低消要求 |
| 4 | 填写联系人信息 | 验证手机号，支持代订 |
| 5 | 提交预订 | 发送预订请求给商家 |
| 6 | 等待确认 | 商家确认后短信/APP通知用户 |

#### 3.2 预订状态流转

```
用户提交预订
      ↓
商家收到预订通知（APP/短信/语音）
      ↓
┌─────────────────────────────────────────┐
│  商家确认 → 预订成功，通知用户          │
│  商家拒绝 → 说明原因，推荐其他时段      │
│  超时未响应（15分钟）→ 系统自动取消     │
└─────────────────────────────────────────┘
```

#### 3.3 预订类型

| 预订类型 | 特点 | 适用场景 |
|----------|------|----------|
| 普通订座 | 仅保留座位，到店点餐 | 日常用餐 |
| 套餐预订 | 预订+套餐预付，到店即食 | 商务宴请 |
| 包厢预订 | 私密空间，可能有低消 | 聚会宴请 |
| 排队取号 | 线上取号，到店叫号 | 热门餐厅 |

#### 3.4 预订变更与取消 `[需内部资料确认：具体时效规则]`

```
用户取消预订：
├── 提前X小时取消 → 无责取消

└── 爽约未到 → 记录违约，限制后续预订

商家取消预订：
```

### 四、到店消费

#### 4.1 团购券核销流程

| 步骤 | 操作内容 |
|------|----------|
| 1 | 到店后向服务员说明有饿了么团购 |
| 2 | 打开饿了么APP/支付宝，进入「我的」-「卡包」 |
| 3 | 找到对应团购券，点击「出示券码」 |
| 4 | 向服务员展示二维码或券号 |
| 5 | 商家扫码或输入密码核销 |
| 6 | 核销成功后享用服务 |

#### 4.2 商家核销操作

```
商家端核销流程：
1. 登录饿了么商家版APP/收银系统
2. 进入「验券」功能
3. 扫描用户出示的二维码
   或
   手动输入券码
4. 确认券信息（套餐内容、有效期、使用规则）
5. 点击「确认核销」
6. 打印小票或电子确认
7. 系统实时同步核销状态
```

#### 4.3 优惠买单流程

| 步骤 | 操作内容 | 说明 |
|------|----------|------|
| 1 | 用餐完毕后叫服务员结账 | 告知使用优惠买单 |
| 2 | 打开饿了么APP扫码 | 扫描桌台二维码或商家收款码 |
| 3 | 输入消费金额 | 系统自动计算优惠后金额 |
| 4 | 选择可用优惠 | 代金券/满减/折扣自动叠加 |
| 5 | 确认支付 | 完成付款，获取电子账单 |

#### 4.4 核销异常处理

| 异常情况 | 处理方式 |
|----------|----------|
| 券码无法识别 | 检查网络 → 手动输入券号 → 联系客服 |
| 券已过期 | 查看有效期 → 协商延期使用或退款 |
| 券已使用 | 查询核销记录 → 核实是否重复核销 |
| 商家无法核销 | 拍照留证 → 联系饿了么客服处理 |
| 套餐内容不符 | 与商家协商 → 差价补偿或更换 |

### 六、退款售后

#### 6.1 退款类型 `[需内部资料确认：具体退款政策]`

| 退款场景 | 退款条件 | 退款金额 |
|----------|----------|----------|
| 未消费随时退 | 券未核销，在有效期内 | 全额退款 |
| 过期自动退 | 券过期未使用 | 全额原路退回 `[需内部资料确认：是否自动退]` |
| 商家原因 | 商家停业/无法提供服务 | 全额退款 + 补偿 |
| 用户原因 | 个人原因不想去了 | 按退款规则扣除手续费/不可退 |
| 部分使用 | 套餐内部分菜品未使用 | 协商退还差价 |
| 商家爽约 | 预订成功但无法接待 | 全额退款 + 违约赔偿 |

#### 6.2 退款流程

```
用户申请退款
      ↓
选择退款原因 → 上传凭证（如需）→ 提交申请
      ↓
系统审核/商家审核
      ↓
┌─────────────────────────────────────────┐
│  符合条件 → 自动退款（1-7个工作日）     │
│  需核实 → 客服介入处理                  │
│  不符合 → 拒绝并说明原因                │
└─────────────────────────────────────────┘
```

#### 6.3 不可退款情形

- 明确标注「不可退」的特价秒杀商品
- 已核销使用的团购券
- 超过退款时限的申请 `[需内部资料确认：具体时限]`
- 用户恶意退款（系统判定）
- 已部分消费的套餐（协商处理）

#### 6.4 商家爽约处理

##### 6.4.1 爽约定义

商家爽约包括但不限于：
- 预订成功后商家拒绝接待
- 商家临时停业未提前通知
- 到店后无法提供团购套餐内容
- 要求用户额外支付不合理费用
- 商家擅自取消已确认预订

##### 6.4.2 处理流程

```
用户投诉商家爽约
      ↓
平台核实情况（联系商家、查看记录、调取证据）
      ↓
┌─────────────────────────────────────────┐
│  情况属实：                             │
│  - 为用户全额退款                       │
│  - 提供补偿（优惠券/现金红包）          │
│  - 记录商家违约行为                     │
│  - 严重情况下架商家/处罚                │
└─────────────────────────────────────────┘
```

##### 6.4.3 商家处罚措施 `[需内部资料确认：具体处罚标准]`

| 爽约次数 | 处罚措施 |
|----------|----------|
| 首次 | 警告，要求整改，扣除信用分 |
| 多次 | 降低搜索排名，限制参加活动，扣除保证金 |
| 严重/恶意 | 下架处理，终止合作，列入黑名单 |

## Output Requirement

1. **信息透明**：团购详情页清晰展示使用规则、限制条件、有效期，避免误导消费
2. **预订确认**：预订请求15分钟内响应，超时自动提醒商家 `[需内部资料确认：时效标准]`
3. **核销便捷**：支持二维码扫码、券号输入等多种核销方式，减少用户等待时间
4. **退款高效**：符合条件的退款申请自动处理，1-3个工作日到账
5. **投诉响应**：商家爽约投诉24小时内处理，复杂纠纷72小时内出具结果 `[需内部资料确认：时效标准]`
6. **评价真实**：建立完善的评价审核机制，过滤虚假评价，保障参考价值
7. **数据安全**：用户隐私信息加密存储，交易数据安全传输
