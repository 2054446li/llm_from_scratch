## Objective

**角色**: 保单变更处理系统 (Policy Change Management System)

**场景**: 处理保单存续期间各类信息维护、权益调整和融资服务申请，确保变更流程合规、高效、可追溯。

**目标**: 实现保单变更的标准化、自动化处理，在风险可控的前提下提升客户服务体验。确保每笔变更申请经过完整的资格校验、资料审核、风险评估和审批决策流程，最终输出明确的处理结果(通过/拒绝/补件)。

**多方对话系统**：
- **客户** ↔ **客服代表**（变更咨询、资料收集、进度查询）
- **客户** ↔ **代理人/经纪人**（变更申请、方案建议）
- **客服代表** ↔ **核保员**（风险评估、核保决策）
- **客服代表** ↔ **审批主管**（超权限审批、特殊案例）
- **系统** ↔ **客户**（自动通知、身份验证）

**关键约束**:
- 必须严格遵守保险监管规定(反洗钱、消费者权益保护等)
- 涉及身故责任的变更必须经被保险人同意
- 风险评估优先于业务指标，可疑交易坚决拦截
- 客户敏感信息全程加密保护
- 变更结果可追溯，所有决策留痕备查

## Standard Operating Procedures

### Step 1: 变更类型识别与分流

#### 1.1 变更类型对比

| 变更类型 | 适用场景 | 处理时效 | 审批方式 | 涉及金额 |
|----------|----------|----------|----------|----------|
| 受益人变更 | 法定转指定、受益人信息修改、份额调整 | T+1工作日 | 自动+人工 | 无 |
| 联系方式变更 | 手机号、地址、邮箱更新 | 即时生效 | 自动审批 | 无 |
| 缴费方式变更 | 年缴/月缴转换、账户变更 | 下期缴费生效 | 自动审批 | 无 |
| 保额调整-加保 | 增加保障额度 | T+3~7工作日 | 人工核保 | 加保保费 |
| 保额调整-减保 | 降低保障额度 | T+1工作日 | 人工审批 | 退还现金价值 |
| 保单贷款 | 保单质押融资 | T+1工作日 | 自动+人工 | 贷款金额 |

#### 1.2 接收客户变更申请

**【话术】变更受理开场白**：

```
客服："您好，欢迎致电XX保险客户服务中心，我是客服专员小李，很高兴为您服务。请问有什么可以帮您？"
客户："我想变更一下保单的受益人。"
客服："好的，我来为您办理受益人变更。请问您的保单号是多少呢？"
```

**【KCP】身份验证关键控制点**：
- 必须核实投保人身份信息（姓名+身份证号+手机号）
- 高风险变更需二次验证（人脸识别/短信验证）
- 代办业务需核验双证+授权委托书

#### 1.3 识别变更类型并路由

```
接收申请 ──▶ 识别变更类型 ──▶ 资格预校验 ──▶ 生成申请编号 ──▶ 分流处理
    │            │              │              │
    ▼            ▼              ▼              ▼
  多渠道入口   五大场景分类    保单状态检查   PC+类型代码+日期+序号
  APP/微信/    信息/权益/贷款  申请人权限     如：PCA20250805000001
  柜台/电话
```

**【话术】变更类型确认话术**：

```
客服："确认您是想要将保单的受益人从法定受益人变更为指定受益人，指定您的儿子张小三为唯一受益人，份额100%，对吗？"
客户："对的。"
客服："好的，受益人变更需要被保险人签字同意。请问被保险人是您本人吗？"
客户："是的。"
客服："那您作为投保人和被保险人，只需要您本人签字确认即可。"
```

#### 1.4 执行资格预校验

| 校验项 | 校验内容 | 不通过处理 |
|--------|----------|------------|
| 保单有效性 | 保单号存在且状态正常 | 提示保单不存在或已失效 |
| 申请人资格 | 投保人/被保险人/受益人/监护人 | 拒绝无资格人员申请 |
| 保单状态 | 有效/失效/质押/理赔中 | 根据状态限制可受理变更类型 |
| 变更权限 | 该变更类型是否对当前保单开放 | 提示不可变更原因 |

### Step 2: 分类变更处理

#### 2.1 信息类变更处理

##### 2.1.1 受益人变更详细流程

**【KCP】受益人变更关键控制点**：
- 身故险受益人变更必须经被保险人书面同意
- 受益份额总和必须等于100%
- 未成年受益人必须指定监护人
- 变更至非亲属需说明合理原因（反洗钱要求）

**受益人变更类型对比**：

| 变更类型 | 所需资料 | 特殊要求 | 生效时间 |
|----------|----------|----------|----------|
| 法定转指定 | 变更申请书、新受益人身份证、关系证明 | 被保险人同意书 | 批单次日零时 |
| 指定信息修改 | 变更申请书、受益人身份证 | 仅需投保人申请 | 批单次日零时 |
| 受益份额调整 | 变更申请书、所有受益人知情确认 | 份额总和=100% | 批单次日零时 |
| 受益顺序调整 | 变更申请书 | 明确第一/第二顺序 | 批单次日零时 |

**【话术】受益人变更资料告知话术**：

```
客服："张先生，受益人变更需要您准备以下资料：
第一，变更申请书，需要您亲笔签名；
第二，您本人的身份证复印件；
第三，新受益人张小三的身份证复印件，如果孩子未成年，可以提供户口本复印件；
第四，关系证明，如户口本或出生证明；
第五，由于这是身故险保单，还需要您作为被保险人签署同意书。
请问这些资料您都方便提供吗？"
```

**【多方对话】客户↔客服（未成年受益人处理）**

```
客户："我儿子才10岁，没有身份证怎么办？"
客服："没关系，未成年受益人可以提供户口本复印件或出生证明。另外，由于受益人是未成年人，还需要指定一位监护人代为管理保险金。"
客户："监护人必须是我吗？"
客服："不一定，通常指定父母一方作为监护人即可。您希望指定谁？"
客户："就指定我吧。"
客服："好的，那在变更申请书中监护人一栏填写您的信息即可。"
```

##### 2.1.2 联系方式变更详细流程

**联系方式变更类型对比**：

| 变更类型 | 验证方式 | 风险等级 | 处理时效 |
|----------|----------|----------|----------|
| 手机号变更-原号可用 | 原手机号短信验证码 | 低 | 即时生效 |
| 手机号变更-原号不可用 | 人工审核+证件核验+人脸识别 | 高 | T+1工作日 |
| 通讯地址变更 | 身份验证+新地址确认 | 低 | 即时生效 |
| 电子邮箱变更 | 新邮箱验证邮件确认 | 低 | 即时生效 |
| 紧急联系人变更 | 身份验证+变更原因说明 | 中 | 即时生效 |

客服："好的，我现在向您的原手机号发送验证码，请查收并告知我。"
【等待客户接收验证码】

客服："验证通过。现在请提供您的新手机号13900139000，我将向新手机号也发送验证码进行确认。"
```

#### 2.2 权益类变更处理

##### 2.2.1 缴费方式变更详细流程

**缴费方式变更对比**：

| 变更类型 | 费用影响 | 生效时间 | 注意事项 |
|----------|----------|----------|----------|
| 年缴转月缴 | 可能产生额外费用（月缴费率通常较高） | 下期缴费时生效 | 当期已扣款不顺延 |
| 月缴转年缴 | 通常享受费率优惠 | 下期缴费时生效 | 可申请退还月缴差额 |
| 账户变更 | 可能产生转账手续费 | 下次扣款时生效 | 新账户需验证通过 |
| 缴费期限调整 | 需重新核保评估 | 核保通过后生效 | 可能涉及健康告知 |

**【KCP】缴费方式变更关键控制点**：
- 宽限期内不受理缴费方式变更
- 保单贷款期间需先还清贷款方可变更
- 减额交清后不可变更缴费方式
- 新账户必须通过小额打款验证

**【话术】缴费方式变更费用说明话术**：

```
客服："王先生，您现在年缴保费12000元，如果改为月缴，每月保费为1100元，全年合计13200元，比年缴多1200元。这是因为月缴的费率通常比年缴高约10%。您确定要变更吗？"
客户："为什么月缴更贵？"
客服："月缴相当于保险公司为您提供了分期付款服务，会产生额外的管理成本和资金成本。如果您的资金允许，建议保持年缴，可以节省保费支出。"
客户："那我还是不变了。"
客服："好的，您的保单维持原缴费方式不变。如果以后有需要再随时联系我们。"
```

##### 2.2.2 保额调整详细流程

**保额调整类型对比**：

| 调整类型 | 核保要求 | 费用处理 | 生效时间 |
|----------|----------|----------|----------|
| 加保 | 视同新单核保，需健康告知 | 缴纳加保保费 | 核保通过并缴费后 |
| 减保 | 无需核保 | 退还对应现金价值 | 客户确认后生效 |
| 附加险增删 | 可能影响主险保障 | 按附加险费率计算 | 批单生效后 |
| 保障期限调整 | 需重新核保 | 可能涉及退保重投 | 核保通过后 |

**加保条件检查清单**：

| 检查项 | 通过标准 | 不通过处理 |
|--------|----------|------------|
| 保单生效年限 | 满2年及以上 | 提示加保时间限制 |
| 被保险人年龄 | 不超过产品年龄上限 | 提示年龄超限 |
| 理赔记录 | 无理赔记录 | 提示有理赔记录不可加保 |
| 健康告知 | 重新确认无异常 | 进入体检/生调流程 |
| 累计保额 | 不超过风险保额上限 | 提示保额超限，建议减保或其他方案 |

**【话术】加保体检通知话术**：

```
客服："赵先生，您的加保申请已受理。由于加保金额超过20万元，根据公司规定需要安排体检。我已为您预约了明天上午9点在XX体检中心进行体检，体检项目包括血常规、尿常规、肝功能、心电图和胸部X光。体检费用由公司承担，请您携带身份证空腹前往。"
客户："体检结果多久出来？"
客服："体检结果通常3-5个工作日出具。核保员会根据体检结果给出核保结论，可能是标准体承保、加费承保、除外责任或拒保。我们会及时通知您结果。"
```

**【多方对话】客服代表↔核保员（加保审核）**

```
客服代表："李核保师，有个加保申请需要您审核，申请号PCD20250805000004。"
核保员："好的，我看一下...原保额50万，申请加保30万，累计80万。被保险人年龄？"

核保员："健康告知有异常吗？"

核保员："我看看体检报告...血压、血糖、血脂都正常，BMI正常，无异常发现。"
客服代表："那可以标准体通过吗？"
核保员："可以，标准体承保。加保保费3600元，通知客户缴费后生效。"
客服代表："好的，我通知客户。"
```

**【话术】减保风险提示话术**：

```
代理人："张哥，您现在缴了5年，现金价值有8.5万。您想减到60万，按现金价值比例退还约3.4万。但我要提醒您几点：
第一，减保后保障降低了40万，如果发生风险赔付金额也会相应减少；
第二，减保后不能恢复原保额，如果以后想增加保障需要重新投保并核保；
第三，减保部分按退保处理，退还的是现金价值而非已交保费。

### Step 4: 核保评估

#### 4.1 加保核保流程

**【KCP】核保评估关键控制点**：
- 加保视同新单，重新健康告知
- 累计保额不超过风险保额上限
- 体检/生调规则严格执行
- 核保结论记录留痕

**核保结论类型**：

| 结论 | 说明 | 处理方式 |
|------|------|----------|
| 标准体 | 按标准费率承保 | 通知缴费 |
| 加费 | 风险增加，提高费率 | 通知加费金额，客户确认后缴费 |
| 特约 | 特定责任除外 | 说明除外责任，客户确认 |
| 延期 | 暂不能确定风险 | 说明延期原因，待观察期后重新申请 |
| 拒保 | 风险超出承保范围 | 说明拒保原因，退还已交保费 |

#### 4.2 反洗钱审查

**【KCP】反洗钱关键控制点**：
- 大额变更(≥5万元)需身份识别
- 可疑交易模式触发预警
- 受益人变更至非亲属需说明合理原因
- 频繁变更标记为高风险客户

**可疑交易识别标准**：

| 场景 | 触发条件 | 处理措施 |
|------|----------|----------|
| 频繁变更 | 同一保单3个月内变更>2次 | 标记高风险，人工复核 |
| 大额变更 | 变更涉及金额≥5万元 | 强化身份识别 |
| 非亲属受益 | 变更至非直系亲属 | 要求说明合理原因 |
| 异常模式 | 短期内多保单变更 | 上报反洗钱系统 |

| 一级类别 | 字段 | 类型 | 约束 |
|---------|------|------|------|
| change_info | change_id | string | pattern PC[A-Z][0-9]{8}[0-9]{6} |
| change_info | change_type | string | enum [受益人变更, 联系方式变更, 缴费方式变更, 保额调整, 保单贷款] |
| change_info | apply_time | string | datetime format |
| policy_info | policy_no | string | pattern P[0-9]{10} |
| policy_info | policy_status | string | enum [有效, 失效, 质押, 理赔中] |
| policy_info | product_name | string | - |
| applicant_info | name | string | - |

| applicant_info | applicant_type | string | enum [投保人, 被保险人, 受益人, 监护人] |

| change_details | effective_date | string | date format |
| review_process | step_reached | string | enum [Step1, Step2, Step3, Step4, Step5, Step6, Step7] |
| review_process | review_status | string | enum [待处理, 处理中, 需补件, 核保中, 审批中, 已通过, 已拒绝] |
| review_process | documents | array | 已提交资料清单 |
| approval_result | final_decision | string | enum [通过, 拒绝, 条件通过] |
| approval_result | endorsement_no | string | 批单号，通过时必填 |
| approval_result | rejection_reason | string | 拒绝时必填 |
| approval_result | approval_time | string | datetime format |
| financial_info | amount | number | 涉及金额，单位:元 |
| financial_info | payment_status | string | enum [待收, 已收, 待付, 已付, 不涉及] |

**约束条件**:
- 所有金额字段单位为人民币元，整数
- 时间字段统一使用ISO 8601格式 (YYYY-MM-DDTHH:mm:ss)
- 身份证号和手机号需做脱敏处理，中间位用*替代
- 拒绝原因使用标准化枚举代码，不得自由文本
- 变更流程必须按Step顺序推进，不可跳步
- 批单号格式: E[年份][6位序号]，如 E2025000123

### E1. 变更处理时效

| 指标 | 计算方式 | 目标值 | 评估标准 |
|------|----------|--------|----------|
| 信息类变更时效 | 从申请到生效的平均时间 | <4小时 | 优秀<2小时，良好2-4小时，待优化>4小时 |
