## 4. 详细操作流程 (Detailed Procedures)

### 4.1 一级：众筹模式咨询 [KCP:All or Nothing规则]

#### 4.1.1 二级：众筹模式解释

**Rule层约束：**
- RULE-CR-001: [KCP:All or Nothing规则] 必须100%达成目标金额才算成功
- RULE-CR-002: 支持是预售行为，非即时交易
- RULE-CR-003: 存在项目失败、延期、与描述不符等风险
- RULE-CR-004: 支持后不可更改档位，需退款后重新支持

**4.1.1.1 三级：All or Nothing规则详解**

**4.1.1.1.1 四级：规则定义**
```
项目必须在规定时间内达到或超过目标金额才算成功
否则视为失败，全额退款给支持者
```

**4.1.1.1.2 四级：示例说明**
```
案例：某项目目标金额10万元，众筹期30天

情况1：30天内筹集到12万元 → 众筹成功，进入生产发货
情况2：30天内筹集到8万元 → 众筹失败，全额退款
情况3：30天内筹集到10万元整 → 众筹成功，刚好达标
```

**4.1.1.2 三级：众筹vs普通购物对比**

| 维度 | 众筹 | 普通购物 |
|------|------|---------|
| 交易时机 | 先付款后生产 | 现货交易 |
| 发货时间 | 项目成功后按承诺时间 | 下单后48小时内 |
| 失败风险 | 可能失败退款 | 无 |
| 延期风险 | 存在可能性 | 一般无 |
| 独特性 | 创意新品首发 | 常规商品 |
| 价格 | 早鸟价优惠 | 市场价 |
| 等待周期 | 较长（1-6个月） | 短（3-7天） |

### 4.2 一级：支持下单流程

#### 4.2.1 二级：项目浏览引导

**4.2.1.1 三级：项目状态确认**

**4.2.1.1.1 四级：项目状态类型**
| 状态 | 说明 | 用户操作 |
|------|------|---------|
| 预热中 | 即将开始众筹 | 可设置提醒 |
| 众筹中 | 正在进行 | 可选择档位支持 |
| 已成功 | 达到目标金额 | 可能还能追加支持 |
| 已失败 | 未达目标 | 等待退款 |
| 已结束 | 众筹期结束 | 查看结果 |

**4.2.1.2 三级：回报档位说明**

**4.2.1.2.1 四级：档位选择要点**
- 每个档位对应不同回报内容
- 支持后不可更改档位
- 可同时支持多个档位（生成独立订单）
- 早鸟档通常限量且价格优惠

**多方对话示例：**
```
[用户] "我选错回报档位了，可以改吗？"
[客服] "【Rule-CR-004】抱歉，支持后不可更改档位。

【解决方案】
1. 申请退款当前支持订单
2. 等待退款到账（1-15个工作日）
3. 重新选择正确档位支持

【特别提醒】
• 退款期间该项目可能仍在众筹中
• 如项目即将结束，建议先重新支持正确档位，再申请退款
• 避免退款后项目已结束无法支持

请问您需要我协助您申请退款吗？"
```

### 4.3 一级：众筹成功处理 [KCP:众筹成功判定]

#### 4.3.1 二级：成功判定标准

**Rule层约束：**
- RULE-CR-008: [KCP:众筹成功判定] 众筹截止时间到达时，已筹金额 >= 目标金额
- RULE-CR-009: 发起人需在承诺时间内发货
- RULE-CR-010: 发货后用户需在淘宝确认收货

**4.3.1.1 三级：成功后续流程**

| 阶段 | 客服工作 | 用户通知 |
|-----|---------|---------|
| 成功确认 | 系统标记项目成功，冻结资金转入发起人账户 | 发送成功通知短信/站内信 |
| 生产阶段 | 监督发起人按承诺执行 | 提醒用户关注项目动态更新 |
| 发货阶段 | 确认发起人按约定时间发货 | 通知用户物流信息 |
| 确认收货 | 处理收货相关问题 | 提醒用户确认收货并评价 |

**多方对话示例：**
```
[用户] "项目成功了接下来会发生什么？"
[客服] "【KCP:众筹成功判定】恭喜！项目众筹成功，后续流程如下：

【成功后续流程】
1. 【资金结算】平台将支持款项结算给发起人（扣除平台服务费）
2. 【生产阶段】发起人按承诺开始生产/采购
   • 建议您关注项目动态，了解生产进度
   • 发起人应定期更新项目进展
3. 【发货阶段】发起人按承诺时间发货
   • 【Rule-CR-009】必须在承诺发货时间内发货

4. 【确认收货】收到商品后在淘宝确认收货
   • 确认收货后支持流程完成

【注意事项】
• 如发起人逾期未发货，您可发起维权
• 收到商品后如有质量问题，按淘宝售后规则处理
• 建议保留项目页面截图，作为承诺凭证

请问还有什么需要了解的吗？"
```

### 4.5 一级：项目延期处理 [KCP:项目延期]

#### 4.5.1 二级：延期类型判断

**Rule层约束：**
- RULE-CR-014: [KCP:项目延期] 超过承诺发货时间未发货即构成延期
- RULE-CR-015: 发起人应提前公告延期原因和新发货时间
- RULE-CR-016: 用户可选择等待或申请退款

**4.5.1.1 三级：延期类型**

| 类型 | 说明 | 处理方式 |
|-----|------|---------|
| 发起人主动延期 | 因生产原因申请延期发货 | 需提前公告并获得用户理解 |
| 逾期未发货 | 超过承诺时间未发货 | 用户可发起维权投诉 |

**4.5.1.2 三级：延期处理流程**

**4.5.1.2.1 四级：用户咨询延期**
1. 查询项目最新动态更新
2. 告知延期原因和预计新发货时间
3. 提供等待或退款的选择

**4.5.1.2.2 四级：延期维权处理**
1. 确认是否超过承诺发货时间
2. 协助用户发起退款申请
3. 协调发起人沟通解决方案
4. 记录发起人延期次数（影响信用评级）

**多方对话示例：**
```
[用户] "我支持的项目说好了上个月发货，现在都延期了，怎么办？"
[客服] "【KCP:项目延期】非常抱歉给您带来不便，我来帮您查询一下该项目的具体情况。

【查询结果】
项目状态：众筹成功
承诺发货时间：[具体日期]
当前状态：已延期

【处理方案】
1. 查看发起人是否有发布延期公告及说明
2. 如您愿意等待，可关注项目动态获取最新进展
3. 如您希望退款，因项目已成功，需联系发起人协商
4. 【Rule-CR-014】如发起人失联或拒绝处理，可发起维权投诉

【维权路径】
我的淘宝 → 我的众筹 → 对应订单 → 申请维权

【补偿说明】
根据延期时长，您可协商：
• 延期补偿（如额外赠品、优惠券）
• 部分退款
• 全额退款

请问您希望如何处理？我可以协助您联系发起人。"
```

### 4.6 一级：退款申请处理 [KCP:退款类型判断]

#### 4.6.1 二级：退款类型对照

**Rule层约束：**
- RULE-CR-017: [KCP:退款类型判断] 需先判断退款类型再处理
- RULE-CR-018: 众筹失败退款系统自动处理
- RULE-CR-019: 项目成功后退款需与发起人协商
- RULE-CR-020: 退款纠纷可平台介入仲裁

**4.6.1.1 三级：退款类型表**

| 场景 | 退款条件 | 处理时效 | 处理方式 |
|-----|---------|---------|---------|
| 众筹失败自动退款 | 系统自动处理 | 1-15个工作日 | 自动原路退回 |
| 项目取消 | 发起人主动取消 | 全额退款 | 系统自动处理 |
| 未发货退款 | 项目成功但未发货 | 联系发起人协商 | 发起人审核 |
| 发货前退款 | 特殊原因申请 | 发起人审核 | 协商处理 |
| 质量问题退货 | 收货后质量问题 | 按淘宝售后规则 | 维权处理 |

**4.6.1.2 三级：退款处理流程**

**4.6.1.2.1 四级：众筹失败退款**
- 告知系统自动处理
