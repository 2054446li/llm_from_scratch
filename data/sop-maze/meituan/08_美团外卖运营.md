## 业务概述

美团外卖运营是商家在美团外卖平台开展餐饮外卖业务的全流程管理，涵盖店铺入驻、商品管理、订单处理、配送管理、售后服务等核心环节。

### 核心参与方

```
+-----------+      入驻/运营    +-----------+      接单/出餐    +-----------+
|   商家    | ---------------> |  美团平台  | <-------------> |   用户    |
+-----------+                  +-----------+                 +-----------+
       ^                            |                             |
       |      结算/对账             |      派单                   | 下单
       |                            v                             v
       +--------------------  骑手配送员  <-------------------- 支付
```

## Objective

1. **商家入驻目标**：完成资质审核与店铺开通，入驻流程 ≤ 3个工作日
2. **商品管理目标**：菜单配置完整度 ≥ 95%，商品信息准确无误
3. **订单履约目标**：接单率 ≥ 98%，出餐时效符合平台承诺
4. **用户满意度目标**：店铺评分 ≥ 4.5分，差评率 ≤ 2%
5. **营收增长目标**：通过营销活动提升订单量和客单价

## Standard Operating Procedures

### 一、商家入驻流程

#### 1.1 入驻申请

| 步骤 | 操作内容 | 注意事项 |
|------|----------|----------|
| 1 | 登录美团外卖商家版APP或官网，点击「我要开店」 | 需准备手机号、身份证 |
| 2 | 选择经营品类（正餐/快餐/饮品/甜品等） | 品类决定后续费率和规则 |
| 3 | 填写店铺基本信息（店名、地址、联系人） | 店名需符合命名规范 |
| 4 | 上传资质证件（营业执照、食品经营许可证等） | 证件需在有效期内 |
| 5 | 提交审核，等待平台审核 | 通常1-3个工作日 `[需内部资料确认]` |

#### 1.2 资质要求

```
必备资质清单：
├── 主体资质
│   ├── 营业执照（企业/个体户）
│   ├── 法人/经营者身份证
│   └── 银行开户许可证/银行卡
├── 经营资质
│   ├── 食品经营许可证（餐饮类）
│   ├── 餐饮服务许可证（部分地区）
│   └── 健康证（从业人员）
└── 特殊资质（如适用）
    ├── 特许经营备案（加盟品牌）
    ├── 商标注册证（品牌商家）
    └── 进口食品相关证明
```

#### 1.3 合同签署与费用

| 费用类型 | 说明 | 参考标准 `[需内部资料确认]` |
|----------|------|---------------------------|
| 平台服务费 | 按订单金额比例收取 | 5%-8%（因品类而异） |
| 配送服务费 | 使用美团配送的费用 | 每单固定费用或比例 |
| 推广费用 | 竞价排名、广告位等 | 按点击/曝光计费 |
| 保证金 | 履约保证 | 1000-5000元不等 |

### 二、店铺装修与配置

#### 2.1 店铺信息设置

| 配置项 | 内容要求 | 最佳实践 |
|--------|----------|----------|
| 店铺头像 | 清晰LOGO或门店照片 | 建议使用品牌LOGO |
| 店铺公告 | 营业时间、特色介绍 | 突出卖点，定期更新 |
| 店铺海报 | 活动海报、新品推荐 | 高清图片，吸引点击 |
| 营业时间 | 准确的营业时间段 | 与实际出餐能力匹配 |
| 联系电话 | 可接通的客服电话 | 确保高峰期有人接听 |

#### 2.2 配送设置

```
配送方式选择：
┌────────────────────────────────────────────────────────┐
│  1. 美团专送：平台统一配送，覆盖范围广，配送质量稳定    │
│  2. 美团众包：灵活配送，适合订单波动大的商家            │
│  3. 商家自配：自行安排配送，适合有自有配送团队的商家    │
│  4. 混合配送：根据距离/时段选择不同配送方式             │
└────────────────────────────────────────────────────────┘

配送范围设置：
├── 建议配送半径：3-5公里（根据出餐时效）
├── 分区定价：不同距离设置不同配送费
└── 特殊区域：避开无法配送的区域（如封闭小区）
```

### 三、菜单配置与管理

#### 3.1 商品上架流程

| 步骤 | 操作内容 | 注意事项 |
|------|----------|----------|
| 1 | 创建商品分类（如主食/小吃/饮品） | 分类清晰，便于用户浏览 |
| 2 | 添加商品信息（名称、价格、图片） | 图片需清晰美观 |
| 3 | 设置商品规格（大/中/小份等） | 规格命名统一规范 |
| 4 | 配置商品属性（口味/配料等） | 属性选项完整 |
| 5 | 设置库存和可售时间 | 避免超卖 |

#### 3.2 商品信息规范

```
商品信息结构：
├── 基础信息
│   ├── 商品名称（简洁明了，突出特色）
│   ├── 商品图片（白底或场景图，尺寸规范）
│   ├── 商品描述（配料、口味、分量说明）
│   └── 商品标签（新品/热销/招牌等）
├── 价格信息
│   ├── 原价（划线价）
│   ├── 现价（实际售价）
│   ├── 打包费（如适用）
│   └── 会员价/活动价
└── 销售设置
    ├── 库存数量
    ├── 可售时间段
    ├── 起售份数
    └── 限购数量
```

#### 3.3 菜单优化策略

| 策略 | 说明 | 效果 |
|------|------|------|
| 引流款 | 设置1-2款低价爆款商品 | 吸引流量，提升转化 |
| 利润款 | 主推高毛利商品 | 保证整体利润 |
| 套餐组合 | 搭配销售，提升客单价 | 增加单笔订单金额 |
| 新品测试 | 定期上新，测试市场反应 | 保持新鲜感 |

### 四、营销活动管理

#### 4.1 活动类型概览

```
营销活动体系：
┌────────────────────────────────────────────────────────┐
│  满减活动：满X元减Y元，提升客单价                       │
│  折扣活动：指定商品X折，清库存或推新品                  │
│  新客立减：首次下单优惠，拉新转化                       │
│  满赠活动：满X元赠Y商品，提升满意度                     │
│  会员活动：会员专享价，提升复购                         │
│  神券/红包：平台补贴活动，增加曝光                      │
│  竞价推广：提升店铺排名，增加流量                       │
└────────────────────────────────────────────────────────┘
```

#### 4.2 活动配置流程

| 步骤 | 操作内容 | 注意事项 |
|------|----------|----------|
| 1 | 进入「营销活动」页面，选择活动类型 | 根据运营目标选择 |
| 2 | 设置活动规则（门槛、优惠力度） | 计算成本，确保利润 |
| 3 | 选择参与商品/全店参与 | 引流款建议全店参与 |
| 4 | 设置活动时间 | 避开已有大促重叠 |
| 5 | 提交审核，等待生效 | 提前规划，避免临时调整 |

#### 4.3 活动效果监控

| 指标 | 说明 | 健康值参考 |
|------|------|----------|
| 活动曝光量 | 活动被用户看到的次数 | 环比提升 ≥ 20% |
| 活动转化率 | 曝光到下单的转化比例 | ≥ 8% |
| 活动ROI | 投入产出比 | ≥ 1:3 |
| 客单价变化 | 活动期间客单价 | 较日常提升 ≥ 10% |

### 五、订单处理流程

#### 5.1 接单操作

| 场景 | 操作流程 | 结果 |
|------|----------|------|
| 正常接单 | 收到订单推送 → 查看订单详情 → 点击「接单」 | 订单状态变为「待出餐」 |
| 自动接单 | 开启自动接单功能，系统自动确认 | 无需手动操作 `[需内部资料确认]` |
| 拒单 | 点击「拒单」 → 选择原因 → 提交 | 订单取消，可能影响店铺评分 |

#### 5.2 出餐管理

```
出餐时效标准 `[需内部资料确认]`：
┌────────────────────────────────────────────────────────┐
│  快餐类：接单后 10-15 分钟完成出餐                     │
│  正餐类：接单后 20-30 分钟完成出餐                     │
│  烘焙类：按预约时间提前准备                            │
│  饮品类：接单后 5-10 分钟完成出餐                      │
└────────────────────────────────────────────────────────┘

出餐流程：
1. 接单确认 → 2. 打印小票 → 3. 制作餐品 → 4. 打包核对 → 5. 点击「出餐完成」
```

#### 5.3 订单异常处理

| 异常情况 | 处理方式 |
|----------|----------|
| 商品售罄 | 立即标记售罄，联系用户协商换货或退款 |
| 备餐延迟 | 提前联系用户说明情况，申请延长配送时间 |
| 订单错误 | 发现配错餐，立即联系骑手追回或重新制作 |
| 用户备注特殊要求 | 仔细查看备注，无法满足时主动联系用户 |

### 六、配送管理

#### 6.1 配送状态跟踪

| 阶段 | 商家操作 | 状态说明 |
|------|----------|----------|
| 待分配 | 等待系统派单 | 出餐完成后进入此状态 |
| 待骑手接单 | 骑手抢单中 | 通常1-3分钟 `[需内部资料确认]` |
| 骑手已接单 | 等待骑手到店 | 可查看骑手位置和预计到达时间 |
| 骑手到店 | 核对订单，交付餐品 | 核对订单号、商品数量 |
| 配送中 | 无需操作 | 用户可查看实时位置 |
| 已送达 | 订单完成 | 等待用户评价 |

#### 6.2 配送异常处理

```
配送异常处理流程：

骑手未按时到店
      ↓
查看骑手位置 → 主动联系骑手确认情况
      ↓
┌─────────────────────────────────────────┐
│  骑手延误：联系用户说明，申请延长配送时间  │
│  骑手取消：联系平台重新派单               │
│  无骑手接单：联系平台客服协助             │
└─────────────────────────────────────────┘
```

|----------|----------|
| 好评 | 及时回复感谢，维护客户关系 |
| 中评 | 了解原因，针对性改进，礼貌回复 |

#### 7.2 退款处理

```
退款类型及处理：
┌────────────────────────────────────────────────────────┐
│  用户申请退款                                          │
│       ↓                                                │
│  商家接单前：自动同意，款项原路退回                     │
│  商家已接单：商家审核 → 同意/拒绝                       │
│  骑手已取餐：协商部分退款或拒绝                         │
│  已送达：根据原因判断是否同意                           │
└────────────────────────────────────────────────────────┘

常见退款原因：
├── 商家原因：缺货、出餐慢、餐品质量问题 → 建议同意退款
├── 配送原因：配送超时、餐品损坏 → 协商处理
├── 用户原因：下错单、改变主意 → 视情况处理
└── 其他原因：根据实际情况判断
```

### 八、数据运营

#### 8.1 核心数据指标

```
经营数据看板：
├── 流量指标
│   ├── 曝光人数：看到店铺的用户数
│   ├── 进店转化率：曝光到进店的比例

│   ├── 订单量：有效订单数量
│   ├── 交易额：订单总金额
│   ├── 客单价：平均每单金额
│   └── 实收金额：扣除平台费用后的收入
├── 服务指标
│   ├── 店铺评分：用户综合评分
│   ├── 差评率：差评订单占比
│   ├── 投诉率：投诉订单占比
│   └── 退单率：退款订单占比
└── 效率指标
    ├── 平均出餐时长
    ├── 接单率
    └── 准时率
```

#### 8.2 数据分析与优化

| 数据异常 | 可能原因 | 优化建议 |
|----------|----------|----------|
| 曝光高、转化低 | 菜单吸引力不足、价格偏高 | 优化商品图片、调整定价 |
| 转化高、复购低 | 口味/服务体验不佳 | 提升餐品质量、改善包装 |
| 差评集中在配送 | 出餐慢导致配送超时 | 优化出餐流程 |
| 差评集中在口味 | 餐品质量不稳定 | 标准化制作流程 |

## Rule 约束

### 服务时效约束

| 服务环节 | 时效要求 | 超时后果 |
|----------|----------|----------|
| 资质审核 | ≤ 3个工作日 `[需内部资料确认]` | 入驻延迟 |
| 接单响应 | ≤ 5分钟 `[需内部资料确认]` | 自动取消，影响评分 |
| 出餐完成 | 按承诺时间 | 配送超时，用户投诉 |
| 退款审核 | ≤ 24小时 `[需内部资料确认]` | 平台介入，强制退款 |
| 投诉响应 | ≤ 2小时 `[需内部资料确认]` | 平台处罚，降权 |

### 配送时限约束

| 配送方式 | 承诺时效 `[需内部资料确认]` | 覆盖范围 |
|----------|---------------------------|----------|
| 美团专送 | 30-45分钟 | 3-5公里 |
| 美团众包 | 40-60分钟 | 5-8公里 |
| 商家自配 | 自定义 | 自定义 |

### 退款规则约束

| 退款场景 | 退款规则 | 责任方 |
|----------|----------|--------|
| 商家未接单 | 自动全额退款 | 无责 |
| 商家超时未出餐 | 用户可申请全额退款 | 商家责任 |
| 商品缺货 | 部分或全额退款 | 商家责任 |
| 餐品质量问题 | 全额退款+补偿 | 商家责任 |
| 配送超时（准时宝） | 按比例赔付 | 平台/骑手责任 |
| 用户原因取消 | 视情况扣除部分费用 | 用户责任 |

### 示例3：营销活动报名
```
商家：我想参加满减活动，怎么设置？
系统：参加满减活动步骤如下：
      1. 进入「营销活动」-「满减活动」
      2. 点击「创建活动」，设置满减门槛（如满30减5）
      3. 选择参与商品或全店参与
      4. 设置活动时间
      5. 提交审核
      温馨提示：建议设置多档满减（如30-5、50-10、100-20），引导用户提升客单价。
```

### 示例4：订单处理
```
商家：有个订单我接不了，怎么取消？
系统：如需取消订单，请在商家APP中：
      1. 进入「订单管理」，找到该订单
      2. 点击「拒单」按钮
      3. 选择拒单原因（如商品售罄、设备故障等）
      4. 提交后订单将自动取消，款项原路退回用户
      注意：频繁拒单会影响店铺评分和排名，建议提前设置商品库存避免超卖。
```

### 示例5：退款处理
```
商家：用户申请退款，我已经出餐了怎么办？
系统：已出餐订单的退款处理建议：
      1. 先查看退款原因
      2. 联系用户沟通，了解具体情况
      3. 如餐品无问题，可协商拒绝退款或部分退款
      4. 如同意退款，联系骑手追回餐品（如骑手未送达）
      5. 在APP中处理退款申请
      建议保留出餐凭证，以便平台介入时提供证据。
```

### 示例6：配送问题
```
商家：骑手一直没来取餐，怎么办？
系统：骑手未到店取餐的处理方式：
      1. 在订单详情查看骑手位置和预计到达时间
      2. 如已超时，点击「联系骑手」沟通情况
      3. 如联系不上或骑手取消，系统会自动重新派单
      4. 长时间无骑手接单，可联系平台客服协助
      建议：出餐前关注骑手接单状态，避免餐品做好后长时间等待。
```
