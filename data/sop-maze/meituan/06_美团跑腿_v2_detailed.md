## Objective

本SOP旨在规范美团跑腿同城即时配送服务的运营流程，确保：

1. **响应速度**：用户下单后快速匹配骑手，缩短等待时间
2. **服务品质**：保障物品安全、准时送达
3. **服务多样**：支持帮买、帮送、帮取、代办等多种服务场景
4. **风险管控**：完善物品损坏/丢失处理、安全保障机制

## Standard Operating Procedures

### 1. 下单发单

#### 1.1 服务类型选择

##### 1.1.1 服务类型定义

| 服务类型 | 说明 | 典型场景 | 预估时效 |
|----------|------|----------|----------|
| 帮买 | 骑手代用户购买商品 | 代购餐饮、超市商品、药品等 | 45-90分钟 |
| 帮送 | 骑手将物品从A地送至B地 | 文件传递、礼品配送、商务急件 | 30-60分钟 |
| 帮取 | 骑手代为取回物品 | 取快递、取钥匙、取证件 | 30-60分钟 |
| 代办 | 骑手代为办理简单事务 | 排队、缴费、简单手续 | 按任务复杂度 |

##### 1.1.2 下单流程

```
选择服务类型 ──▶ 填写取/送地址 ──▶ 描述物品/需求 ──▶ 选择配送时效 ──▶ 确认支付
      │              │                  │              │              │
      ▼              ▼                  ▼              ▼              ▼
  帮买/帮送/     精确到门牌号       物品类型/价值    普通/加急/     预估费用确认
  帮取/代办      联系人及电话       特殊要求说明     专人直送       支付方式选择
```

#### 1.2 订单信息填写规范

##### 1.2.1 必填字段说明

| 字段 | 必填性 | 填写要求 | 示例 |
|------|--------|----------|------|
| 取货地址 | 必填 | 精确到门牌号，含联系人及电话 | "XX大厦A座15楼，张三，138xxxx8888" |
| 送货地址 | 必填 | 精确到门牌号，含联系人及电话 | "YY小区3号楼2单元，李四，139xxxx6666" |
| 物品信息 | 必填 | 类型、数量、预估重量/体积 | "文件，A4信封，约200g" |
| 物品价值 | 建议填写 | 用于保价和理赔参考 | "合同文件，价值5000元" |
| 备注说明 | 选填 | 特殊要求、取货码、外观要求等 | "请轻拿轻放，易碎品" |
| 期望时效 | 必填 | 普通/加急/专人直送 | "加急，1小时内送达" |

**【话术】下单引导话术**：

**用户选择帮买服务**：
```
用户："帮我买杯咖啡"
系统："好的，请填写购买地址（如星巴克XX店）和收货地址。您需要什么口味的咖啡？可以指定商家或让骑手推荐"
用户："星巴克拿铁，大杯热的"
系统："已记录。预估费用：咖啡约35元+配送费15元，总计约50元。骑手会在购买前与您确认实际价格"
```

**用户选择帮送服务**：
```
用户："送份文件到国贸"
系统："请填写取件地址和收件地址。文件大概多重？是否需要保价？"
用户："就几张纸，不用保价"
系统："好的。预估配送费18元，预计45分钟送达。现在为您下单吗？"
```

##### 1.2.2 费用构成说明

| 费用项目 | 计算方式 | 说明 |
|----------|----------|------|
| 基础配送费 | 根据距离、重量、时段计算 | 起步价+里程费+重量费 |
| 重量附加费 | 超重部分按阶梯计费 | 通常>5kg开始计费 |
| 时段加价 | 高峰期、恶劣天气加价 | 1.2-1.5倍系数 |
| 加急服务费 | 优先配送、专人直送 | 额外加收10-30元 |
| 保价费 | 按声明价值比例收取 | 通常为声明价值的1-3% |

#### 1.3 帮买服务特殊流程

##### 1.3.1 帮买下单详细流程

```
用户下单 ──▶ 系统派单 ──▶ 骑手接单联系 ──▶ 确认购买需求 ──▶ 到店购买 ──▶ 拍照确认 ──▶ 支付配送
    │          │            │              │            │            │            │
    ▼          ▼            ▼              ▼            ▼            ▼            ▼
  填写商品   匹配附近      电话确认       确认商家/    选购商品      发送商品/     送达
  名称/规格  骑手          购买细节       商品/价格    垫付/预付     价格照片      结算
```

**【KCP】帮买确认关键控制点**：
- 骑手必须在购买前与用户电话确认商品规格、价格上限
- 实际价格超出预估10%必须征得用户同意
- 必须提供正规购物小票

**【多方对话】帮买服务典型对话**：

```
【骑手接单后】
骑手："您好，美团跑腿，我是您的骑手王师傅。您是要买一杯星巴克拿铁大杯热的是吗？"
用户："对的"
骑手："好的，我现在过去买。请问您有指定的门店吗？还是就近购买？"
用户："就近买就行"

【到店购买时】
骑手："您好，我到星巴克了。大杯热拿铁37元，需要加什么吗？"
用户："不用了，就这个"
骑手："好的，我这就买。小票我拍照发您，和咖啡一起送过去"

【送达时】
骑手："您好，您的咖啡到了。这是小票，一共37元咖啡+15元配送费，您确认一下"
用户："好的，没问题"
骑手："麻烦您在APP上确认收货，感谢您的使用"
```

### 2. 骑手接单

#### 2.1 接单模式

##### 2.1.1 接单模式对比

| 模式 | 说明 | 适用场景 | 响应时效 |
|------|------|----------|----------|
| 系统派单 | 算法根据位置、负载自动分配 | 标准订单 | 即时推送 |
| 骑手抢单 | 骑手主动选择订单 | 众包模式、特殊订单 | 5分钟内 |
| 指派骑手 | 平台指定优质骑手 | 高价值/特殊订单 | 即时响应 |

##### 2.1.2 派单算法逻辑

```
订单生成 ──▶ 筛选可用骑手 ──▶ 计算匹配分数 ──▶ 推送订单 ──▶ 骑手响应 ──▶ 确认接单
    │            │               │              │            │
    ▼            ▼               ▼              ▼            ▼
  订单属性     距离<3km       距离权重40%    推送Top3    15秒响应
  位置/时效    在线状态       评分权重30%    骑手列表    超时重派
  服务类型     负载情况       历史权重20%                 拒绝记录
                              实时权重10%
```

#### 2.2 接单时效要求

##### 2.2.1 各阶段时效标准

| 服务类型 | 接单响应时限 | 到店/取货时限 | 配送时限 |
|----------|--------------|---------------|----------|
| 普通帮买 | 5分钟内 | 接单后30分钟内 | 按距离预估 |
| 普通帮送 | 5分钟内 | 接单后20分钟内 | 按距离预估 |
| 加急服务 | 3分钟内 | 接单后15分钟内 | 承诺时效内 |
| 专人直送 | 即时响应 | 立即取货 | 直达不绕路 |

**【Rule】骑手匹配拦截规则**：
- **物品禁运拦截**：订单包含违禁品（易燃易爆、管制刀具等）时，系统提示"该物品暂不支持配送，请检查物品是否符合配送要求"
- **骑手资质拦截**：高价值订单（>1000元）仅分配给评分4.8以上、完成单量>500单的骑手
- **距离拦截**：取货距离>5km的订单，系统提示"取货距离较远，可能产生额外费用，是否继续下单？"
- **负载拦截**：骑手当前负载已满（已有3单在进行中），不再向其派单

#### 2.3 骑手资质管理

##### 2.3.1 准入要求

| 审核项 | 要求 | 验证方式 |
|--------|------|----------|
| 实名认证 | 身份证信息真实有效 | 人脸识别+证件OCR |
| 健康证明 | 有效期内的健康证（餐饮配送） | 证件上传审核 |
| 无犯罪记录 | 背景审查通过 | 第三方背调 |
| 培训考核 | 安全服务培训合格 | 线上考试≥80分 |
| 装备要求 | 保温箱、头盔、工服 | 装备审核照片 |

##### 2.3.2 骑手评分体系

| 评分维度 | 权重 | 计算方式 |
|----------|------|----------|
| 准时率 | 30% | 准时完成单量/总单量 |
| 好评率 | 25% | 好评数/评价总数 |
| 投诉率 | 20% | 1-投诉单量/总单量 |
| 完成率 | 15% | 完成单量/接单总量 |
| 活跃度 | 10% | 在线时长/标准时长 |

### 3. 物品取送

#### 3.1 取货流程

##### 3.1.1 标准取货流程

```
到达取货点 ──▶ 联系发货人 ──▶ 核验物品 ──▶ 拍照留证 ──▶ 确认取货 ──▶ 开始配送
      │            │            │            │            │
      ▼            ▼            ▼            ▼            ▼
  系统打卡      电话/APP      外观/数量/    物品照片/     系统状态
  记录时间      通知到达      禁限品检查    取货凭证      更新为"已取货"
```

##### 3.1.2 物品核验标准

| 检查项 | 操作要求 | 异常处理 |
|--------|----------|----------|
| 外观检查 | 包装完好、无破损、无渗漏 | 拍照记录，与发货人确认 |
| 数量核对 | 与订单描述一致 | 不符时联系用户确认 |
| 禁限品检查 | 拒绝承接违禁品 | 发现违禁品拒绝取货并上报 |
| 特殊要求确认 | 温度要求、易碎标识等 | 确认保温/防震措施到位 |

**【话术】取货核验话术**：

```
骑手："您好，美团跑腿，我来取件"
发货人："好的，这是要送的文件"
骑手："我检查一下... 外包装完好，是A4信封一份。请问里面是什么？需要确认一下是否符合配送要求"
发货人："就是合同文件"
骑手："好的，我拍个照留证。麻烦您在APP上确认一下已交接，或者我确认也可以"
```

#### 3.2 配送途中规范

##### 3.2.1 配送过程管理

| 环节 | 要求 | 系统监控 |
|------|------|----------|
| 路线规划 | 按系统推荐路线，特殊情况可调整 | GPS轨迹记录 |
| 时效监控 | 实时更新配送进度 | 超时预警 |
| 异常上报 | 交通堵塞、车辆故障等及时上报 | 异常标记 |
| 物品保管 | 妥善放置，防止损坏、丢失 | 用户可查看实时位置 |

##### 3.2.2 异常处理流程

```
发现异常 ──▶ 立即上报 ──▶ 联系用户 ──▶ 协商解决方案 ──▶ 执行处理 ──▶ 记录完结
    │          │            │              │            │
    ▼          ▼            ▼              ▼            ▼
  交通堵塞   APP一键上报    说明情况       改派/延期/    系统记录
  车辆故障   客服介入       预计影响       取消          责任判定
```

### 4. 帮买帮送

#### 4.1 帮买服务流程

##### 4.1.1 全流程节点

| 步骤 | 骑手操作 | 用户配合 | 系统支持 |
|------|----------|----------|----------|
| 1 | 接单后联系用户确认需求 | 保持电话畅通 | 提供虚拟号码 |
| 2 | 前往指定商家购买 | 可指定商家或让骑手推荐 | 推荐附近商家 |
| 3 | 购买时拍照确认商品/价格 | 及时确认或调整 | 实时消息推送 |
| 4 | 垫付或用户预付 | 确认支付方式 | 垫付额度管理 |
| 5 | 配送至收货地址 | 准备接收 | 实时位置追踪 |

##### 4.1.2 帮买费用处理

| 场景 | 处理方式 | 用户确认 |
|------|----------|----------|
| 实际价格=预估价格 | 正常结算 | 无需额外确认 |
| 实际价格<预估价格 | 按实际结算，差额退回 | 自动处理 |
| 实际价格>预估价格（<10%） | 按实际结算 | 系统提示价格差异 |
| 实际价格>预估价格（>10%） | 必须用户确认 | 电话/APP确认 |
| 缺货替换 | 等值替换或退款 | 用户同意替换方案 |

#### 4.2 帮送服务要点

##### 4.2.1 不同场景服务标准

| 场景 | 特殊要求 | 注意事项 |
|------|----------|----------|
| 文件急送 | 优先配送，确保准时 | 防水防潮，不可折叠 |
| 餐饮配送 | 保温/保冷，注意时效 | 检查包装密封性 |
| 生鲜配送 | 冷链运输，优先处理 | 检查保鲜状态 |
| 贵重物品 | 保价配送，当面签收 | 核对身份信息 |
| 蛋糕/易碎品 | 平稳配送，防震防压 | 提醒用户检查 |

### 5. 损坏/丢失处理

#### 5.1 损坏/丢失场景判定

##### 5.1.1 责任判定标准

| 场景 | 责任判定 | 判定依据 | 处理原则 |
|------|----------|----------|----------|
| 取货时已损坏 | 发货方责任 | 取货照片显示已损坏 | 拍照留证，联系发货人确认 |
| 配送途中损坏 | 骑手/平台责任 | 取货完好、送达损坏 | 按保价或实际价值赔偿 |
| 配送途中丢失 | 骑手/平台责任 | 无法提供送达凭证 | 全额赔偿 |
| 收货后发现问题 | 需举证区分责任 | 签收后24小时内举证 | 根据证据判定 |

#### 5.2 理赔流程

##### 5.2.1 标准理赔流程

```
用户申请理赔 ──▶ 提交证据 ──▶ 平台审核 ──▶ 责任判定 ──▶ 赔付/拒赔 ──▶ 用户确认
      │              │            │            │            │
      ▼              ▼            ▼            ▼            ▼
  APP一键申请    照片/视频/      1-3工作日     按责任方      原路退回/
  或客服电话     价值证明        完成审核      赔付标准      余额退款
```

##### 5.2.2 赔付标准

| 情况 | 赔付标准 | 上限说明 |
|------|----------|----------|
| 已保价物品 | 按保价金额赔付 | 最高不超过声明价值 |
| 未保价物品 | 按实际损失赔付 | 最高不超过订单金额的10倍 |
| 部分损坏 | 按损坏比例赔付或协商修复费用 | 按实际可修复费用 |
| 完全丢失 | 全额赔付 | 受保价/赔付上限限制 |

**【话术】理赔处理话术**：

```
用户："骑手把我蛋糕弄坏了"
客服："非常抱歉给您带来不好的体验。请您上传一下蛋糕损坏的照片，以及购买小票或价值证明，我立即为您登记理赔"
用户："已经上传了，蛋糕是268元买的"
客服："看到了，蛋糕侧面确实有严重变形。请问您下单时是否选择了保价服务？"
用户："保了300元"
客服："好的，您选择了保价300元，蛋糕价值268元，在保价范围内。理赔申请已审核通过，退款268元将在1-3个工作日原路退回，请注意查收"
```

#### 5.3 免责情形

| 情形 | 说明 | 举证要求 |
|------|------|----------|
| 不可抗力 | 自然灾害、政府行为等 | 官方公告/证明 |
| 物品本身质量问题 | 发货时已存在缺陷 | 发货方确认 |
| 用户提供的地址/联系方式错误 | 导致无法送达 | 订单信息截图 |
| 用户指定的特殊配送方式 | 导致损坏风险 | 用户备注/聊天记录 |

### R1. 物品禁运拦截

| 规则ID | 规则名称 | 触发条件 | 拦截动作 | 提示信息 |
