# 美团买菜 SOP 详细版（v2_detailed）

> **文档版本**: v2.0 详细版  
> **适用场景**: 美团买菜（小象超市）即时零售全流程客服/运营处理  
> **更新日期**: 2026年8月

---

## Objective

1. **时效目标**: 订单30分钟内送达率 ≥ 95%
2. **品质目标**: 生鲜商品新鲜度达标，客诉率 ≤ 1%
3. **库存目标**: 缺货率 ≤ 3%，缺货及时通知用户
4. **体验目标**: 售后问题30分钟内响应处理，极速退款覆盖率 ≥ 90%

---

## Standard Operating Procedures

### 一、选购下单流程

#### 1.1 用户端操作流程

```
┌─────────────────────────────────────────────────────────────────┐
│                     选购下单操作流程                              │
├─────────────────────────────────────────────────────────────────┤
│                                                                 │
│  ┌──────────┐    ┌──────────┐    ┌──────────┐    ┌──────────┐  │
│  │1.浏览商品│ -> │2.加入购物车│ -> │3.选择时段│ -> │4.确认支付│  │
│  └──────────┘    └──────────┘    └──────────┘    └──────────┘  │
│                                                                 │
│  KCP: 商品规格确认、配送地址准确性、配送时段选择                 │
│                                                                 │
└─────────────────────────────────────────────────────────────────┘
```

| 步骤 | 操作内容 | 注意事项 | Rule层约束 |
|------|----------|----------|------------|
| 1 | 打开美团APP/小象超市APP | 自动定位附近前置仓 | **Rule**: 配送范围拦截 - 超出范围提示「不在配送范围」 |
| 2 | 浏览商品分类或搜索 | 生鲜商品库存实时变化 | 库存为0商品标记「补货中」 |
| 3 | 选择商品规格、数量，加入购物车 | 注意商品重量/个数规格 | **KCP**: 生鲜商品重量预估 |
| 4 | 进入购物车，确认商品 | 查看小计金额、优惠 | 库存变化实时校验 |
| 5 | 选择配送时间段 | 可选「立即配送」或预约时段 | **KCP**: 时段运力校验 |
| 6 | 确认收货地址 | 确认是否在配送范围内 | **Rule**: 配送范围拦截 |
| 7 | 选择支付方式，完成支付 | 支持多种支付方式 | 支付超时15分钟释放库存 |

### 二、分拣打包流程

#### 2.1 订单分配

```
用户下单成功
    │
    ▼
┌─────────────────────────────────────────┐
│ Rule: 配送范围拦截                      │
│ - 校验地址是否在配送范围内              │
│ - 分配最近前置仓                        │
│ - 超出范围：订单无法提交                │
└─────────────────────────────────────────┘
    │
    ▼
系统根据配送地址分配最近前置仓
    │
    ▼
订单进入拣货队列（按配送时段排序）
    │
    ▼
分配拣货员
```

#### 2.2 拣货流程

| 步骤 | 操作内容 | 系统支持 | KCP标记 |
|------|----------|----------|---------|
| 1 | 拣货员接收订单任务 | PDA/APP推送 | 任务分配时间记录 |
| 2 | 按最优路径拣货 | 系统规划拣货路线 | 拣货效率监控 |
| 3 | 扫码核对商品 | 扫描商品条码确认 | **KCP**: 商品准确性校验 |
| 4 | 生鲜称重 | 实际称重，系统计算差价 | **KCP**: 重量准确性 |
| 5 | 缺货处理 | 标记缺货，系统触发通知 | **KCP**: 缺货及时标记 |
| 6 | 完成拣货，提交复核 | 打包台接收 | 拣货完成时间记录 |

#### 2.3 打包复核

```
拣货完成
    │
    ▼
复核员核对商品（品种、数量、质量）
    │
    ▼
┌─────────────────────────────────────────┐
│  核对无误 → 按规范打包                  │
│  发现问题 → 退回重新拣货                │
│  商品瑕疵 → 更换商品                    │
└─────────────────────────────────────────┘
    │
    ▼
粘贴订单标签，放置配送区
    │
    ▼
等待骑手取货
```

#### 2.4 打包规范

| 商品类型 | 打包要求 | Rule层约束 |
|----------|----------|------------|
| 冷冻食品 | 保温袋+冰袋，单独包装 | 冷冻商品必须冷链 |
| 生鲜水产 | 防水袋+冰袋，防止渗漏 | 活鲜需充氧包装 |
| 易碎商品 | 气泡膜包裹，标识易碎 | 易碎标识必须清晰 |
| 重物商品 | 底部放置，轻物在上 | 承重限制5kg/袋 |
| 化学品 | 单独密封，与食品隔离 | 严格隔离要求 |

### 三、即时配送流程

#### 3.1 骑手取货

| 步骤 | 操作内容 | KCP标记 |
|------|----------|---------|
| 1 | 骑手接收配送任务 | 任务分配时间 |
| 2 | 到达前置仓，扫码取货 | 到店时间记录 |
| 3 | 核对订单号、商品数量 | **KCP**: 商品数量核对 |
| 4 | 检查商品包装完整性 | 包装检查记录 |
| 5 | 装车，按路线配送 | 配送开始时间 |

#### 3.2 配送时效管理

```
┌─────────────────────────────────────────────────────────────────┐
│                    时效控制节点                                  │
├─────────────────────────────────────────────────────────────────┤
│                                                                 │
│  下单至拣货开始：≤ 5分钟                                        │
│  拣货完成时间：≤ 15分钟                                         │
│  骑手取货时间：≤ 5分钟                                          │
│  配送途中时间：≤ 15分钟（3公里内）                              │
│  ─────────────────────────                                      │
│  总时效目标：≤ 30-45分钟                                        │
│                                                                 │
│  Rule: 超时自动触发补偿                                         │
│  - 超时10分钟：发送优惠券                                       │
│  - 超时20分钟：自动退款+补偿                                    │
│  - 超时30分钟：全额退款+补偿                                    │
│                                                                 │
└─────────────────────────────────────────────────────────────────┘
```

#### 3.3 配送异常处理

| 异常情况 | 处理流程 | Rule层约束 |
|----------|----------|------------|
| 联系不上用户 | 多次联系 → 上报异常 → 等待/按备注放置 | 联系3次，间隔2分钟 |
| 地址错误 | 联系用户确认 → 协商处理/退回前置仓 | 地址错误15分钟内解决 |
| 商品破损 | 拍照留证 → 联系客服 → 协商处理 | 破损商品带回 |
| 用户拒收 | 了解原因 → 上报平台 → 商品退回 | 拒收原因记录 |

### 四、缺货处理

#### 4.1 缺货发现时机

| 时机 | 处理方式 | Rule层约束 |
|------|----------|------------|
| 下单时缺货 | 商品标记「缺货」，无法加入购物车 | 实时库存校验 |
| 拣货时缺货 | 系统推送缺货通知给用户 | **Rule**: 缺货15分钟内通知用户 |
| 配送前发现 | 联系用户协商换货/退款 | 配送前必须解决 |

#### 4.2 缺货处理流程

```
拣货员发现缺货
    │
    ▼
系统标记缺货商品
    │
    ▼
自动推送通知给用户（APP推送/短信）
    │
    ▼
┌─────────────────────────────────────────┐
│  方案1：用户选择替换商品（等价/补差价） │
│  方案2：缺货商品退款，其余商品继续配送  │
│  方案3：整单取消，全额退款              │
│  用户未响应 → 按默认方案处理            │
└─────────────────────────────────────────┘
```

#### 4.3 缺货自动替换规则

```
┌─────────────────────────────────────────────────────────────────┐
│                    缺货自动替换规则                              │
├─────────────────────────────────────────────────────────────────┤
│                                                                 │
│  Rule: 缺货自动替换                                               │
│  - 用户开启「缺货自动替换」功能                                   │
│  - 系统根据商品相似度自动推荐替代品                               │
│  - 替代品价格不高于原商品                                         │
│  - 如替代品价格更高，差价由平台承担                               │
│  - 用户可在订单详情页查看替换记录                                 │
│                                                                 │
│  替换优先级：                                                     │
│  1. 同品牌同规格不同口味                                          │
│  2. 同品牌不同规格（重量相近）                                    │
│  3. 不同品牌同品类（评分相近）                                    │
│  4. 不同品牌同品类（价格相近）                                    │
│                                                                 │
│  不替换商品：                                                     │
│  - 用户明确标注「不接受替换」                                     │
│  - 药品、婴幼儿食品等特殊商品                                     │
│                                                                 │
└─────────────────────────────────────────────────────────────────┘
```

### 五、生鲜售后

#### 5.1 售后场景

| 场景 | 描述 | 举证要求 | Rule层约束 |
|------|------|----------|------------|
| 商品变质 | 生鲜不新鲜、有异味 | 照片/视频 | **Rule**: 生鲜24小时内可申请售后 |
| 商品损坏 | 挤压破损、包装破裂 | 照片 | 签收时检查 |
| 重量不足 | 实际重量低于标注 | 称重照片 | 称重差异>10%可申诉 |
| 商品错发 | 收到非订单商品 | 照片 | 错发商品可保留 |
| 品质不符 | 与描述/图片不符 | 照片 | 描述不符可退款 |

#### 5.2 售后流程

```
用户申请售后
    │
    ▼
选择售后原因 → 上传凭证 → 提交申请
    │
    ▼
系统/客服审核
    │
    ▼
┌─────────────────────────────────────────┐
│  审核通过 → 退款/补发/补偿              │
│  需补充凭证 → 通知用户补充              │
│  审核不通过 → 说明原因                  │
└─────────────────────────────────────────┘
```

#### 5.3 售后政策

| 商品类型 | 售后时效 | 退款方式 | Rule层约束 |
|----------|----------|----------|------------|
| 生鲜商品 | 签收后24小时内 | 按比例/全额退款 | 24小时后不可申请 |
| 普通商品 | 签收后7天内 | 退货退款/仅退款 | 7天后不可申请 |
| 质量问题 | 优先退款，无需退货 | 极速退款 | 信用良好用户即时到账 |

### 六、极速退款

#### 6.1 极速退款条件

| 条件 | 说明 | Rule层约束 |
|------|------|------------|
| 用户信用 | 美团账号信用良好，无恶意退款记录 | 信用分≥80分 |
| 订单金额 | 单笔订单金额在200元以内 | 超出金额需审核 |
| 售后类型 | 质量问题、缺货等明确责任方 | 用户原因不适用 |
| 历史记录 | 近期退款率不超过20% | 退款率过高需审核 |

#### 6.2 极速退款流程

```
用户提交退款申请
    │
    ▼
系统判断是否符合极速退款条件
    │
    ▼
┌─────────────────────────────────────────┐
│  符合条件 → 即时退款到账，无需审核      │
│  不符合 → 进入人工审核流程              │
└─────────────────────────────────────────┘
```

#### 6.3 退款时效

| 支付方式 | 极速退款时效 | 普通退款时效 |
|----------|--------------|--------------|
| 美团余额 | 即时 | 即时 |
| 微信/支付宝 | 即时 | 1-3个工作日 |
| 银行卡 | 1-3个工作日 | 3-15个工作日 |

## Rule 层约束汇总

| 规则类别 | 规则名称 | 规则内容 | 触发时机 |
|----------|----------|----------|----------|
| 配送范围 | 配送范围拦截 | 超出前置仓配送范围无法下单 | 下单时 |
| 时效 | 缺货通知时限 | 缺货15分钟内通知用户 | 拣货缺货时 |
| 时效 | 配送时效 | 30-45分钟送达，超时补偿 | 配送过程中 |
| 缺货 | 缺货自动替换 | 用户开启后系统自动推荐替代品 | 缺货时 |
| 售后 | 生鲜售后时效 | 生鲜24小时内可申请售后 | 售后申请时 |
| 退款 | 极速退款条件 | 信用良好、金额≤200元、质量问题 | 退款申请时 |
