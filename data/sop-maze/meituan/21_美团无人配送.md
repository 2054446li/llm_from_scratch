## Objective

1. **用户体验目标**: 提供便捷、透明的无人配送服务，确保用户能够顺利完成下单、取货全流程
2. **安全运营目标**: 建立多重安全防护机制，确保无人设备运行安全，事故率控制在0.1%以下
3. **高效履约目标**: 保障配送时效，无人机配送3公里内平均时效<25分钟，无人车配送5公里内平均时效<35分钟
4. **人机协作目标**: 建立完善的远程监控与人工介入机制，人工接管率控制在5%以内
5. **合规运营目标**: 满足空域管理、道路测试等监管要求，确保合法合规运营

## Standard Operating Procedures

### 一、无人配送区域与站点查询

#### 1.1 服务区域查询

##### 1.1.1 查询方式

| 查询渠道 | 操作方式 | 返回信息 |
|----------|----------|----------|
| APP首页 | 点击「无人配送」入口 | 当前定位是否支持无人配送 |
| 地址选择页 | 输入/选择收货地址 | 该地址是否在服务范围内 |
| 地图模式 | 查看附近站点分布 | 起降点/停靠点位置、距离、状态 |
| 客服咨询 | 人工/智能客服查询 | 服务覆盖范围说明 |

##### 1.1.2 区域判定逻辑

```
用户发起查询
    │
    ▼
┌─────────────────────────────────────────┐
│ 地址解析 → 经纬度转换 → 区域匹配        │
└─────────────────────────────────────────┘
    │
    ▼
┌─────────────────────────────────────────┐
│ Rule: 服务范围拦截                      │
│ - 地址在无人机配送范围？→ 显示无人机选项 │
│ - 地址在无人车配送范围？→ 显示无人车选项 │
│ - 地址不在任何范围？→ 提示「当前区域暂未开通」│
└─────────────────────────────────────────┘
    │
    ▼
返回查询结果 + 可用配送方式 + 最近站点信息
```

**【KCP】区域查询关键控制点**:
- 必须精确匹配到具体起降点/停靠点（用户需到指定位置取货）
- 无人机配送范围：直线距离3公里内，需有空域许可
- 无人车配送范围：道路距离5公里内，需在路测许可区域
- 实时校验站点可用状态（是否满负荷、是否维护中）

#### 1.2 站点信息展示

##### 1.2.1 站点类型

| 站点类型 | 适用设备 | 服务场景 | 取货方式 |
|----------|----------|----------|----------|
| 无人机起降点 | 无人机 | 社区、商圈、写字楼 | 起降点自提 |
| 无人车停靠点 | 无人车 | 社区门口、写字楼停车场 | 停靠点自提 |
| 智能配送柜 | 无人机/无人车 | 社区、园区 | 扫码/取货码开柜 |
| 商户专用点 | 无人机/无人车 | 大型商户、商圈 | 商家协助装载 |

### 三、订单调度与自动装载

#### 3.1 智能调度系统

##### 3.1.1 调度流程

```
订单支付成功
    │
    ▼
┌─────────────────────────────────────────┐
│ Rule: 订单有效性拦截                    │
│ - 商品重量是否超限？→ 超限转人工配送    │
│ - 商品体积是否超限？→ 超限转人工配送    │
│ - 站点是否可用？→ 不可用转其他站点或人工│
│ - 空域/路权是否开放？→ 不开放转人工     │
└─────────────────────────────────────────┘
    │
    ▼
订单进入调度池 → 智能匹配设备
    │
    ▼
┌─────────────────────────────────────────┐
│ 调度因子（优先级排序）：                 │
│ 1. 设备距离商家/起点的远近              │
│ 2. 设备电量状态（需满足往返+冗余）      │
│ 3. 设备载重匹配度                       │
│ 4. 当前任务负载                         │
│ 5. 预计完成时效                         │
└─────────────────────────────────────────┘
    │
    ▼
任务派发至指定设备 → 设备确认接单
```

##### 3.1.2 设备匹配规则

| 匹配条件 | 无人机要求 | 无人车要求 |
|----------|------------|------------|
| 电量要求 | ≥30%（满足往返+20%冗余） | ≥20%（满足单程+返站） |
| 载重要求 | 订单重量≤3kg | 订单重量≤100kg |
| 距离要求 | 直线距离≤3km | 道路距离≤5km |
| 空域/路权 | 航线空域开放 | 道路在许可范围内 |
| 设备状态 | 待机中 | 待机中 |

**【Rule】调度拦截规则**:
- **电量拦截**：设备电量不满足任务需求时，禁止派单
- **载重拦截**：订单商品超过设备额定载重时，自动转人工配送
- **空域拦截**：空域管制时段，无人机任务暂停或转人工
- **路权拦截**：超出路测许可区域，无人车禁止通行

#### 3.2 自动装载流程

##### 3.2.1 商家装载流程

```
设备到达商家/起点
    │
    ▼
系统自动通知商家：「无人配送设备已到达，请准备装载」
    │
    ▼
商家操作：
┌─────────────────────────────────────────┐
│ 1. 扫码核验订单信息                     │
│ 2. 核对商品与订单一致性                 │
│ 3. 检查包装完好性                       │
│ 4. 将商品放入设备货舱                   │
│ 5. 确认装载完成，关闭舱门               │
└─────────────────────────────────────────┘
    │
    ▼
系统检测：
┌─────────────────────────────────────────┐
│ Rule: 装载校验拦截                      │
│ - 舱门是否关闭？→ 未关闭提示重新关闭    │
│ - 重量是否合规？→ 超重拒载              │
│ - 装载是否超时？→ 超5分钟上报运维       │
└─────────────────────────────────────────┘
    │
    ▼
装载完成 → 设备开始配送
```

##### 3.2.2 装载异常处理

| 异常类型 | 判定标准 | 处理流程 | 通知方式 |
|----------|----------|----------|----------|
| 商品不符 | 扫码与订单不一致 | 拒载，通知商家重新配货 | APP推送+语音播报 |
| 超重 | 实际重量>额定载重 | 拒载，建议分批或转人工 | APP推送 |
| 包装破损 | 外包装明显破损 | 拒载，要求更换包装 | APP推送+电话 |
| 装载超时 | 超过5分钟未完成 | 自动上报运维介入 | 运维系统告警 |
| 舱门未关 | 系统检测舱门开启 | 语音提醒重新关闭 | 设备语音播报 |

**【话术】装载环节标准话术**（设备语音播报）:
- 到达通知：「美团无人配送已到达，请准备装载商品」
- 扫码提示：「请扫描订单条码确认装载」
- 装载完成：「商品装载完成，舱门已关闭，即将开始配送」
- 异常提醒：「检测到舱门未完全关闭，请重新检查」

### 四、配送执行与路径规划

#### 4.1 无人机配送流程

##### 4.1.1 航路规划

```
起点（商家/起降点）
    │
    ▼
┌─────────────────────────────────────────┐
│ 航路规划系统：                           │
│ • 计算最优航线（距离最短/时间最短）      │
│ • 避开禁飞区、限飞区、人口密集区         │
│ • 设置备用航线和紧急降落点               │
│ • 飞行高度：30-100米                     │
└─────────────────────────────────────────┘
    │
    ▼
起飞 → 按规划航线飞行 → 到达目标起降点
```

##### 4.1.2 飞行监控

| 监控维度 | 监控指标 | 告警阈值 | 响应动作 |
|----------|----------|----------|----------|
| 位置监控 | GPS坐标 | 偏离航线>10m | 自动修正/告警 |
| 电量监控 | 剩余电量 | <20% | 提示返航 |
| 通信监控 | 信号强度 | <2格 | 切换备用链路 |
| 环境监测 | 风速 | >8m/s | 减速/备降 |
| 高度监控 | 飞行高度 | <10m或>120m | 强制调整 |

**【KCP】无人机配送关键控制点**:
- 航线必须避开禁飞区、限飞区、人口密集区
- 单程飞行距离不超过设备续航能力的70%
- 设置至少1个备用降落点和1个紧急降落点
- 飞行高度保持在30-100米之间

#### 4.2 无人车配送流程

##### 4.2.1 路径规划

```
起点（商家/停靠点）
    │
    ▼
┌─────────────────────────────────────────┐
│ 路径规划系统：                           │
│ • 优先选择非机动车道、封闭园区道路       │
│ • 避开施工路段、拥堵路段                 │
│ • 规划斑马线/天桥过街点                  │
│ • 速度限制：园区≤20km/h，人行道≤5km/h   │
└─────────────────────────────────────────┘
    │
    ▼
出发 → 按规划路径行驶 → 到达目标停靠点
```

##### 4.2.2 行驶监控

| 监控维度 | 监控指标 | 告警阈值 | 响应动作 |
|----------|----------|----------|----------|
| 位置监控 | GPS坐标 | 偏离路径>5m | 重新规划 |
| 电量监控 | 剩余电量 | <15% | 寻找充电桩 |
| 速度监控 | 行驶速度 | 超限速20% | 强制减速 |
| 障碍物 | 前方距离 | <3m | 减速/停车 |
| 人员接近 | 周围距离 | <1m | 停车+语音提示 |

**【Rule】安全拦截规则**:
- **距离拦截**：无人机与障碍物距离<5m时，强制悬停并上报
- **高度拦截**：无人机飞行高度<10m或>120m时，强制调整高度
- **速度拦截**：无人车速度超过限速20%时，强制减速
- **人员接近拦截**：检测到人员靠近无人车<1m时，停车并语音提示

### 五、到达交付与取货码获取

#### 5.1 到达通知流程

##### 5.1.1 无人机到达交付

```

    │
    ▼

    │
    ▼

┌─────────────────────────────────────────┐
│ 1. 解锁货舱门                           │
│ 2. 生成/确认取货码                      │
│ 3. 拍照留证                             │
│ 4. 发送取货通知给用户                   │
└─────────────────────────────────────────┘
    │
    ▼
用户收到通知 → 前往起降点取货
```

### 六、异常处理

#### 6.1 无法送达异常

##### 6.1.1 异常类型与判定

| 异常类型 | 判定标准 | 常见原因 |
|----------|----------|----------|
| 用户未取货 | 到达后30分钟未取货 | 用户忘记、不方便取货 |
| 取货码失效 | 超过有效期 | 用户未及时查看通知 |
| 站点被占 | 起降点/停靠点被占用 | 其他车辆/人员占用 |
| 地址错误 | 用户选择站点与实际不符 | 用户选错站点 |

##### 6.1.2 处理流程

```
无法送达异常触发
    │
    ▼
系统尝试联系用户（APP推送+短信+电话）
    │
    ▼
┌─────────────────────────────────────────┐
│ 用户响应？                              │
│ ├─ 是 → 根据情况处理（延时/改地址）     │
│ └─ 否 → 继续下一步                      │
└─────────────────────────────────────────┘
    │
    ▼
等待10分钟 → 仍无响应
    │
    ▼
启动任务转移：
┌─────────────────────────────────────────┐
│ 方案A：转人工骑手配送至用户地址         │
│ 方案B：商品退回商家，订单取消退款       │
│ 方案C：暂存站点，联系用户协商取货时间   │
└─────────────────────────────────────────┘
    │
    ▼
设备返航/继续下一任务
```

**【话术】无法送达通知话术**:
- 首次提醒：「您的订单已送达XX站点，取货码123456，请尽快取货」
- 二次提醒：「您的订单已等待15分钟，取货码即将过期，请尽快取货」
- 最终通知：「因超时未取货，您的订单已转为骑手配送，预计XX分钟后送达」

#### 6.2 设备故障异常

##### 6.2.1 故障类型与响应

| 故障类型 | 判定标准 | 自动响应 | 人工介入 |
|----------|----------|----------|----------|
| 电量不足 | 剩余<15% | 强制返航 | 监控员确认 |
| GPS丢失 | 信号丢失>10s | 视觉导航/悬停 | 远程接管 |
| 通信中断 | 失联>30s | 按预设航线飞行 | 启动搜救 |
| 机械故障 | 电机/传感器异常 | 迫降/停靠程序 | 现场运维 |
| 系统死机 | 无响应>1min | 自动重启 | 人工重启 |

##### 6.2.2 故障处理流程

```
故障检测
    │
    ▼
系统评估故障等级：
┌─────────────────────────────────────────┐
│ P1-紧急：安全风险，需立即处置           │
│ P2-重要：影响配送，需尽快处置           │
│ P3-一般：可稍后处理                     │
└─────────────────────────────────────────┘
    │
    ▼
自动处置 + 通知监控员
    │
    ▼
┌─────────────────────────────────────────┐
│ 可自动恢复？                            │
│ ├─ 是 → 自动处置后继续任务              │
│ └─ 否 → 人工介入                        │
└─────────────────────────────────────────┘
    │
    ▼
人工接管/现场运维处置
    │
    ▼
任务转移（转人工配送或取消）→ 设备回收检修
```

**【话术】故障通知话术**:
- 配送延迟：「非常抱歉，您的订单因设备临时故障配送有所延迟，已安排人工骑手接单，预计XX分钟后送达」

- 订单取消：「因设备故障无法完成配送，您的订单已取消，款项将原路退回，补偿5元红包」
