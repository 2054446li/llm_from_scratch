## 业务概述

美团外卖是中国领先的即时配送平台，连接消费者、商家和骑手三方，提供餐饮外卖、生鲜果蔬、药品等即时配送服务。

### 核心参与方

```
+-----------+      下单      +-----------+      接单      +-----------+
|  消费者   | -------------> |  美团平台  | -------------> |   商家    |
+-----------+                +-----------+                +-----------+
     ^                            |                            |
     |      配送完成              |      派单                  | 出餐
     |                            v                            v
     +--------------------  骑手配送员  <--------------------  备餐
```

## Objective

1. **用户体验目标**：确保用户从下单到收餐的全流程顺畅，订单准时送达率 ≥ 95%
2. **商家运营目标**：帮助商家高效处理订单，出餐时间控制在承诺范围内
3. **骑手服务目标**：合理派单，保障骑手配送效率与安全
4. **平台质量目标**：降低客诉率，提升用户复购率和平台口碑

## Standard Operating Procedures

### 一、下单流程

#### 1.1 用户端操作流程

| 步骤 | 操作内容 | 注意事项 |
|------|----------|----------|
| 1 | 打开美团APP/小程序，进入外卖频道 | 自动定位或手动选择配送地址 |
| 2 | 浏览商家列表，选择目标商家 | 可筛选：距离、评分、销量、配送费等 |
| 3 | 选择商品，加入购物车 | 注意商品规格、口味选择 |
| 4 | 确认订单信息 | 核对地址、电话、配送时间 |
| 5 | 选择支付方式，完成支付 | 支持微信、支付宝、银行卡等 |
| 6 | 等待商家接单 | 超时未接单自动取消退款 |

#### 1.2 订单信息要素

```
订单信息结构：
├── 配送信息
│   ├── 收货地址（精确到门牌号）
│   ├── 联系人姓名
│   ├── 联系电话
│   └── 配送时间要求（立即/预约）
├── 商品信息
│   ├── 商品名称、规格、数量
│   ├── 单价、小计
│   └── 特殊要求（少辣/免葱等）
├── 费用明细
│   ├── 商品总价
│   ├── 配送费
│   ├── 包装费
│   ├── 优惠抵扣
│   └── 实付金额
└── 增值服务
    ├── 准时宝（延时赔付）
    ├── 号码保护
    └── 备注信息
```

#### 1.3 平台处理逻辑

1. **订单生成**：支付成功后，订单状态变为「待商家接单」
2. **消息推送**：向商家推送新订单通知（APP推送/语音播报/打印机）
3. **接单时限**：商家需在设定时间内接单，超时自动取消 `[需内部资料确认：具体时限]`
4. **自动接单**：部分商家开启自动接单功能，支付成功即自动确认

### 二、商家接单流程

#### 2.1 接单操作

| 场景 | 操作流程 | 结果 |
|------|----------|------|
| 正常接单 | 商家APP收到推送 → 点击「接单」 → 开始备餐 | 订单状态变为「商家已接单」 |
| 自动接单 | 系统自动确认，商家直接备餐 | 无需手动操作 |
| 拒单 | 商家点击「拒单」 → 选择原因 → 提交 | 订单取消，款项原路退回 `[需内部资料确认：拒单规则]` |

#### 2.2 备餐管理

1. **出餐时间预估**：商家设置预计出餐时间（通常15-30分钟）
2. **出餐上报**：餐品制作完成后，点击「出餐完成」
3. **骑手取餐**：骑手到店后核对订单，取走餐品

#### 2.3 商家异常处理

| 异常情况 | 处理方式 |
|----------|----------|
| 商品售罄 | 及时标记售罄，联系用户协商换货或退款 |
| 备餐延迟 | 提前联系用户说明情况，申请延长配送时间 |
| 订单错误 | 发现配错餐，立即联系骑手追回或重新制作 |

### 三、骑手配送流程

#### 3.1 派单逻辑 `[需内部资料确认：具体算法参数]`

```
智能派单系统考虑因素：
┌────────────────────────────────────────────────────────┐
│  1. 骑手位置：距离商家的直线/实际距离                   │
│  2. 骑手负载：当前已接订单数量                          │
│  3. 配送方向：订单目的地与骑手当前路线的匹配度          │
│  4. 预计时间：基于历史数据的配送时长预测                │
│  5. 骑手评级：服务评分、准时率等                        │
│  6. 天气路况：实时天气、交通拥堵情况                    │
└────────────────────────────────────────────────────────┘
```

#### 3.2 配送流程

| 阶段 | 骑手操作 | 用户端显示 |
|------|----------|------------|
| 派单 | 系统派单 → 骑手抢单/系统指派 | 「骑手正在赶往商家」 |
| 到店 | 到达商家 → 点击「我已到店」 → 取餐核对 | 「骑手已到店」 |
| 取餐 | 核对订单号、餐品数量 → 点击「确认取餐」 | 「骑手已取餐，正赶往目的地」 |
| 配送中 | 按导航路线配送 | 实时显示骑手位置、预计送达时间 |
| 送达 | 到达地址 → 联系用户 → 点击「确认送达」 | 「订单已完成」 |

#### 3.3 配送异常处理

| 异常场景 | 处理流程 |
|----------|----------|
| 联系不上用户 | 尝试多次联系 → 上报异常 → 等待用户回复/按用户备注处理 |
| 地址错误/不详 | 联系用户确认 → 按正确地址配送或协商处理 |
| 用户拒收 | 了解原因 → 上报平台 → 按平台指引处理 |
| 餐品损坏 | 拍照留证 → 联系用户说明 → 上报平台处理 |

### 四、准时宝服务

#### 4.1 服务说明

准时宝是美团外卖提供的配送时效保障服务，用户下单时可选择购买。

#### 4.2 赔付规则 `[需内部资料确认：具体赔付标准]`

| 延时情况 | 赔付标准（示例） |
|----------|------------------|
| 超时 10-20 分钟 | 赔付订单金额 × 10% |
| 超时 20-30 分钟 | 赔付订单金额 × 30% |
| 超时 30 分钟以上 | 赔付订单金额 × 50% 或全额 |

#### 4.3 赔付流程

```
1. 订单超时送达
        ↓
2. 系统自动识别超时（或用户申诉）
        ↓
3. 核实配送时间记录
        ↓
4. 符合赔付条件 → 自动发放赔付金（红包/现金）
        ↓
5. 用户收到赔付通知
```

#### 4.4 免责情形

- 用户要求延迟配送
- 不可抗力（恶劣天气、交通管制等）
- 用户提供的地址/电话错误导致延误
- 商家出餐严重延迟 `[需内部资料确认：具体免责条款]`

### 五、餐损处理

#### 5.1 餐损类型

| 类型 | 描述 | 责任方 |
|------|------|--------|
| 撒漏 | 汤类、饮料等洒出 | 骑手/商家（包装问题） |
| 变形 | 餐盒挤压变形 | 骑手 |
| 错送 | 送错餐品 | 骑手/商家 |
| 丢失 | 餐品遗失 | 骑手 |
| 变质 | 餐品质量问题 | 商家 |

#### 5.2 处理流程

```
用户发现餐损
      ↓
拍照留证 → 在APP内申请售后
      ↓
平台审核（结合骑手/商家反馈）
      ↓
┌─────────────┬─────────────┬─────────────┐
│  商家责任    │  骑手责任    │  用户原因    │
└─────────────┴─────────────┴─────────────┘
      ↓             ↓             ↓
  商家退款/     平台先行赔付    协商处理/
  重新配送      后向骑手追偿    不予退款
```

### 六、退款售后

#### 6.1 退款类型

| 退款场景 | 退款原因 | 处理时效 |
|----------|----------|----------|
| 商家未接单 | 超时未接单自动取消 | 即时原路退回 |
| 用户取消 | 下单后改变主意 | 商家接单前可全额退 `[需内部资料确认：取消费规则]` |
| 商家取消 | 商家原因无法出餐 | 全额退款 + 补偿（如有） |
| 缺货退款 | 商品售罄 | 部分或全额退款 |
| 质量问题 | 餐品变质、异物等 | 全额退款 + 赔偿协商 |

#### 6.2 退款流程

```
用户申请退款
      ↓
选择退款原因 → 上传凭证（如有）
      ↓
┌─────────────────────────────────────────┐
│  商家接单前：自动退款                    │
│  商家已接单：需商家/平台审核             │
└─────────────────────────────────────────┘
      ↓
审核通过 → 退款原路返回（1-7个工作日）
      ↓
用户收到退款
```

#### 6.3 售后申诉

- 对退款结果有异议，可联系美团客服介入
- 客服核实情况后进行最终判定

---

### 七、异常处理

#### 7.1 送错餐处理

```
发现送错餐
      ↓
保留餐品原状 → 拍照 → 联系骑手/客服
      ↓
┌─────────────────────────────────────────┐
│  方案A：骑手取回错送餐，送达正确餐品     │
│  方案B：用户自行处理错送餐，平台退款     │
│  方案C：协商补差价换购                   │
└─────────────────────────────────────────┘
```

#### 7.2 撒漏/破损处理

| 严重程度 | 处理方式 |
|----------|----------|
| 轻微撒漏（可食用） | 协商小额补偿红包 |
| 严重撒漏（无法食用） | 全额退款或重新配送 |
| 包装破损但餐品完好 | 视情况补偿 |

#### 7.3 少送/漏送处理

```
1. 核对订单与实物
2. 拍照记录
3. 联系商家/骑手确认
4. 处理方案：
   - 补送漏送商品
   - 漏送商品退款
   - 整单退款（严重情况）
```
