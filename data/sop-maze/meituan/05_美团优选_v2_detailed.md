## Objective

本SOP旨在规范美团优选社区团购业务的运营流程，确保：

1. **用户体验**：提供便捷、高效的社区团购购物体验
2. **履约质量**：保障"次日达"配送时效和商品品质
3. **团长服务**：建立标准化的团长管理和服务体系
4. **售后保障**：完善缺货、质量问题等售后处理机制

## Standard Operating Procedures

### 1. 下单流程

#### 1.1 用户端操作

##### 1.1.1 入口选择

| 入口 | 操作路径 | 适用场景 |
|------|----------|----------|
| 美团APP | 首页 → 美团优选 | 已安装美团APP用户 |
| 微信小程序 | 搜索"美团优选" | 快速访问，无需下载 |
| 团长分享链接 | 点击团长分享的商品/活动链接 | 老用户推荐 |

##### 1.1.2 自提点选择流程

```
用户定位/手动选择地址 ──▶ 系统推荐附近自提点 ──▶ 查看自提点详情 ──▶ 确认选择
         │                      │                      │
         ▼                      ▼                      ▼
    获取用户位置           显示距离/评分/营业状态    团长信息/历史评价
```

**【KCP】自提点选择关键控制点**：
- 必须选择距离用户收货地址3公里内的自提点
- 自提点营业状态必须为"营业中"
- 团长评分低于3.5分的自提点需提示用户谨慎选择

##### 1.1.3 商品浏览与加购

| 步骤 | 操作内容 | 关键要点 |
|------|----------|----------|
| 1 | 浏览商品分类/搜索商品 | 查看商品详情、评价、销量 |
| 2 | 选择规格/数量 | 注意库存状态、限购数量 |
| 3 | 加入购物车 | 可跨店加购，统一结算 |
| 4 | 查看截单时间 | 通常当日22:00截单，次日达 |

**【Rule】下单拦截规则**：
- **自提点范围拦截**：收货地址超出自提点服务范围（>3公里）时，系统提示"该自提点暂不支持配送至您的地址，请重新选择"
- **截单时间拦截**：超过当日22:00后，系统提示"今日已截单，现在下单将于后天送达"或自动切换至次日订单
- **库存不足拦截**：加购商品库存不足时，提示"商品库存不足，已为您调整至最大可购买数量"

##### 1.1.4 订单确认与支付

```
进入购物车 ──▶ 勾选商品 ──▶ 确认订单信息 ──▶ 选择优惠券 ──▶ 提交订单 ──▶ 支付
                │              │                  │              │
                ▼              ▼                  ▼              ▼
           核对商品清单    确认自提点/收货人    可用优惠券列表    支付方式选择
```

**【话术】支付环节标准话术**：
- 支付前："订单提交成功，请在30分钟内完成支付，超时订单将自动取消"
- 支付成功："支付成功！您的订单将于明日16:00前送达【XX自提点】，取货码将在到货后通过短信和APP通知您"

#### 1.2 系统处理流程

##### 1.2.1 订单流转机制

```
用户下单 ──▶ 订单聚合 ──▶ 供应商接单 ──▶ 商品备货 ──▶ 物流揽收 ──▶ 中心仓分拣 ──▶ 网格仓配送 ──▶ 团长签收
    │           │            │            │            │            │            │            │
    ▼           ▼            ▼            ▼            ▼            ▼            ▼            ▼
  实时确认   按区域/商品聚合  供应商确认   打包贴标     装车发运     按线路分拣   按团长配送   清点入库
```

##### 1.2.2 关键时效节点

| 节点 | 时间要求 | 超时处理 |
|------|----------|----------|
| 支付时限 | 下单后30分钟内 | 自动取消订单 |
| 供应商确认 | 00:00前完成 | 触发缺货流程 |
| 中心仓收货 | 06:00-08:00 | 延迟预警 |
| 团长签收 | 16:00前 | 自动触发延迟补偿 |

### 2. 次日达配送

#### 2.1 配送流程

##### 2.1.1 全链路时效标准

| 环节 | 时间节点 | 操作内容 | 责任方 |
|------|----------|----------|--------|
| 供应商发货 | 00:00-06:00 | 商品打包、贴标、装车 | 供应商 |
| 中心仓收货 | 06:00-08:00 | 质检、分拣、按线路集货 | 中心仓 |
| 网格仓配送 | 08:00-14:00 | 按线路配送至各团长点 | 网格仓 |
| 团长签收 | 14:00-16:00 | 清点、入库、系统确认 | 团长 |
| 用户通知 | 16:00-16:30 | 发送取货通知（短信+APP） | 系统自动 |

##### 2.1.2 配送时效承诺

**【KCP】次日达履约关键控制点**：
- 标准时效：当日22:00前下单，次日16:00前送达自提点
- 生鲜商品：优先配送，确保12:00前送达
- 延迟补偿：超时送达自动发放优惠券补偿（满20减5元）

#### 2.2 物流异常处理

##### 2.2.1 异常类型与处理

| 异常类型 | 判定标准 | 处理流程 | 用户通知 |
|----------|----------|----------|----------|
| 配送延迟 | 超过16:00未送达 | 系统自动标记+补偿发放 | "您的订单配送有所延迟，已为您发放5元优惠券" |
| 商品破损 | 外包装破损/渗漏 | 拍照留证+退回重发/退款 | "您的订单中部分商品在运输中受损，已为您安排退款" |
| 缺货 | 供应商无法供货 | 系统自动退款+通知 | "您购买的XX商品暂时缺货，款项已原路退回" |
| 错发 | 商品与订单不符 | 核实后补发/退款 | "经核实您的订单存在错发情况，正在为您处理" |

### 3. 自提点提货

#### 3.1 提货流程

##### 3.1.1 标准提货流程

```
用户收到到货通知 ──▶ 前往自提点 ──▶ 出示取货码/手机号 ──▶ 团长核验 ──▶ 领取商品 ──▶ 确认收货
         │                │                  │                │            │            │
         ▼                ▼                  ▼                ▼            ▼            ▼
    短信+APP推送      查看营业时间        4-6位数字码      系统核对订单    清点商品     订单完成
```

##### 3.1.2 取货方式

| 方式 | 操作说明 | 适用场景 | 验证方式 |
|------|----------|----------|----------|
| 取货码取货 | 提供4-6位数字验证码 | 标准流程 | 团长在系统中输入验证 |
| 扫码取货 | 扫描订单二维码 | 手机操作便捷 | 系统自动核销 |
| 手机号取货 | 提供下单手机号后四位 | 忘带手机时 | 团长人工核对 |
| 团长代查 | 团长根据姓名/手机号查询 | 特殊情况 | 人工核实身份 |

**【话术】提货环节标准话术**：

**用户到达自提点**：
```
用户："我来取货"
团长："您好，请提供取货码或下单手机号后四位"
用户："取货码是123456"
团长："好的，稍等... 确认是张三的订单，共5件商品，请清点一下"
```

**商品清点**：
```
团长："您的商品都在这里了：苹果1袋、牛奶1箱、鸡蛋1盒、青菜2份，请检查一下"
用户："好的，没问题"
团长："麻烦您在APP上点击确认收货，或者我帮您确认？"
```

#### 3.2 提货时效管理

##### 3.2.1 提货时限规则

| 商品类型 | 建议提货时间 | 超期处理 |
|----------|--------------|----------|
| 常温商品 | 到货后48小时内 | 第3天自动确认收货 |
| 冷藏商品 | 到货后24小时内 | 团长提醒用户尽快提取 |
| 冷冻商品 | 到货后12小时内 | 团长必须电话通知用户 |
| 生鲜商品 | 当天提取 | 次日开始品质下降，建议当日提取 |

**【Rule】提货时效拦截规则**：
- **超期未提预警**：常温商品超24小时未提，系统自动发送提醒短信
- **超期处理**：生鲜商品超48小时未提，团长可按售后流程处理（退回/销毁）
- **自动确认**：常温商品到货后72小时自动确认收货

### 5. 售后处理

#### 5.1 售后类型与判定

##### 5.1.1 售后类型定义

| 类型 | 定义 | 举证要求 | 处理时限 |
|------|------|----------|----------|
| 商品质量问题 | 破损、变质、过期、与描述不符 | 照片/视频 | 24小时内 |
| 缺货/少货 | 订单商品未送达或数量不足 | 订单截图、收货照片 | 24小时内 |
| 错发商品 | 收到非订单内商品 | 商品照片、订单截图 | 24小时内 |
| 未收到货 | 订单显示已送达但未提取 | 与团长核实 | 24小时内 |

**【Rule】售后时效拦截规则**：
- **超期拦截**：订单确认收货超过72小时后，生鲜类商品不再支持售后
- **超期拦截**：订单确认收货超过7天后，常温商品不再支持售后
- **异常拦截**：同一用户同一商品频繁售后（月超5次），触发风控审核

##### 5.1.2 售后申请入口

| 入口 | 路径 | 适用场景 |
|------|------|----------|
| 订单详情页 | 我的订单 → 选择订单 → 申请售后 | 标准流程 |
| 团长协助 | 联系团长 → 团长代提交 | 老年人/操作困难 |
| 客服入口 | 我的 → 客服中心 → 售后申请 | 复杂问题 |

#### 5.2 售后处理流程

##### 5.2.1 标准处理流程

```
用户申请售后 ──▶ 团长/系统初审 ──▶ 平台审核 ──▶ 处理执行 ──▶ 用户确认 ──▶ 完结
      │              │              │            │            │
      ▼              ▼              ▼            ▼            ▼
  选择类型/     简单问题自动通过   复杂问题人工   退款/补货/    满意度
  上传凭证      复杂问题转人工     核实判定       补偿发放      评价
```

##### 5.2.2 退款标准

| 情况 | 退款标准 | 到账时效 |
|------|----------|----------|
| 全额退款 | 商品严重质量问题、完全未送达、错发 | 审核通过后1-3个工作日 |
| 部分退款 | 商品轻微瑕疵、重量不足、部分破损 | 审核通过后1-3个工作日 |
| 补货重发 | 缺货商品用户同意等待 | 次日配送 |
| 优惠券补偿 | 小额问题、用户满意度维护 | 即时到账 |

**【话术】售后处理标准话术**：

**用户申请售后**：
```
用户："我买的鸡蛋破了3个"

用户："退款吧"
客服："好的，退款申请已提交，预计1-3个工作日原路退回您的支付账户，请注意查收"
```

#### 5.3 缺货补差

##### 5.3.1 缺货场景处理

| 场景 | 处理方式 | 用户通知 | 补偿标准 |
|------|----------|----------|----------|
| 下单后供应商缺货 | 系统自动退款+短信通知 | "您购买的XX商品缺货，款项已退回" | 3元无门槛券 |
| 配送中损耗 | 全额退款或次日补送 | "您的XX商品在配送中受损，已安排退款" | 5元无门槛券 |
| 规格替换 | 经用户同意后更换等值商品 | "XX商品暂时缺货，可替换为YY商品，是否同意？" | 差价多退少不补 |

##### 5.3.2 补差规则

```
缺货发现 ──▶ 系统判定 ──▶ 用户通知 ──▶ 处理执行 ──▶ 补偿发放
    │          │            │            │            │
    ▼          ▼            ▼            ▼            ▼
供应商/    全额/部分      短信+APP      自动退款/    优惠券
物流反馈   缺货判定       推送通知      人工确认      自动发放
```

**【KCP】缺货处理关键控制点**：
- 缺货必须在用户提货前发现并通知
- 退款必须在24小时内完成
- 缺货率超过5%的商品触发供应商整改
