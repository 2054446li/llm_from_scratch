## Objective

本SOP旨在规范美团闪购商家端的运营流程，确保：

1. **入驻合规**：建立标准化的商家准入审核机制，保障平台生态质量
2. **商品丰富**：提供清晰的商品上架、分类管理、价格设置操作指南
3. **库存精准**：确保库存数据实时同步，避免超卖或缺货
4. **履约高效**：确保商家-骑手-用户三方协同，实现30分钟送达
5. **服务闭环**：建立完善的售后服务体系，处理用户投诉与纠纷
6. **资金安全**：规范结算对账流程，保障商家资金安全

## Standard Operating Procedures

### 1. 入驻开店

#### 1.1 入驻申请

##### 1.1.1 入驻类型选择

| 入驻类型 | 适用对象 | 资质要求 | 费用标准 |
|----------|----------|----------|----------|
| 品牌连锁 | 连锁超市、便利店品牌 | 营业执照+品牌授权 | 抽佣8-15% |
| 前置仓 | 纯线上仓储配送 | 营业执照+食品经营许可证 | 抽佣10-18% |
| 闪电仓 | 24小时线上超市 | 营业执照+相关许可 | 抽佣10-20% |
| 便利店 | 社区便利店 | 营业执照+食品流通许可证 | 抽佣8-15% |
| 生鲜果蔬 | 水果店、生鲜店 | 营业执照+食品经营许可证 | 抽佣10-18% |
| 鲜花礼品 | 花店、礼品店 | 营业执照+相关资质 | 抽佣15-20% |
| 母婴用品 | 母婴店 | 营业执照+相关资质 | 抽佣12-18% |
| 宠物用品 | 宠物店 | 营业执照+相关资质 | 抽佣10-15% |

##### 1.1.2 入驻申请流程

```
下载商家版APP ──▶ 注册账号 ──▶ 选择入驻类型 ──▶ 填写店铺信息 ──▶ 上传资质证照 ──▶ 提交审核
       │            │              │                │                │              │
       ▼            ▼              ▼                ▼                ▼              ▼
  iOS/Android    手机号验证    前置仓/闪电仓    店名/地址/      营业执照/      等待1-3
  应用商店                      /便利店等        联系人信息       许可证等         工作日
                                分类选择
```

**【KCP】入驻申请关键控制点**：
- 营业执照必须在有效期内，且经营范围包含所售商品
- 食品经营许可证必须与实际经营品类一致
- 店铺地址必须与证照地址一致（或提供合法租赁证明）
- 法人身份证正反面必须清晰可辨
- 前置仓/闪电仓需提供仓储场地租赁合同

**【话术】入驻咨询标准话术**：
```
商家："我想在美团闪购开店，需要什么条件？"
客服："您好，美团闪购开店需要准备以下材料：1）营业执照原件照片；2）食品经营许可证（如涉及食品）；3）法人身份证正反面；4）店铺门头照和店内环境照；5）仓储场地证明（前置仓/闪电仓）。审核通常需要1-3个工作日。"
```

#### 1.2 资质审核

##### 1.2.1 审核流程

```
资料提交 ──▶ 系统自动初审 ──▶ 人工复核 ──▶ 资质核验 ──▶ 审核结果通知 ──▶ 签约入驻
    │              │              │            │              │              │
    ▼              ▼              ▼            ▼              ▼              ▼
商家上传      OCR识别+      审核员核查      第三方接口     短信+APP       电子合同
资质照片      规则校验      信息一致性      验证真伪       推送通知       在线签署
```

##### 1.2.2 审核标准

| 审核项 | 通过标准 | 常见驳回原因 |
|--------|----------|--------------|
| 营业执照 | 有效期内，经营范围匹配 | 过期、经营范围不符、伪造 |
| 食品经营许可证 | 有效期内，许可项目匹配 | 过期、许可项目缺失、地址不符 |
| 法人身份证 | 清晰可辨，与营业执照一致 | 模糊、过期、信息不一致 |
| 店铺照片 | 真实环境，与证照地址一致 | 网图、与地址不符、环境不达标 |
| 仓储证明 | 场地合法，面积符合要求 | 合同过期、面积不足、用途不符 |
| 银行信息 | 对公账户或法人个人账户 | 账户信息错误、非本人账户 |

**【Rule】资质拦截规则**：
- **黑名单拦截**：法人或店铺在平台黑名单中，系统自动拒绝入驻
- **重复入驻拦截**：同一证照已注册店铺，提示"该营业执照已注册，请勿重复申请"
- **区域限制拦截**：店铺地址不在平台服务范围内，提示"该区域暂不支持入驻"
- **类目限制拦截**：特殊类目（如母婴、医药）需额外资质，缺失时提示"该类目需要特殊资质，请联系客户经理"

##### 1.2.3 审核时效与结果处理

| 审核环节 | 时效 | 处理方式 |
|----------|------|----------|
| 系统初审 | 即时 | OCR识别+规则校验，自动通过或转人工 |
| 人工复核 | 1-2工作日 | 审核员核查，可能要求补充材料 |
| 资质核验 | 1工作日 | 对接政府接口验证证照真伪 |
| 结果通知 | 即时 | 短信+APP推送，通过/驳回+原因 |

**【话术】审核结果通知话术**：
```
审核通过："恭喜您！您的店铺【XX便利店】已通过审核，请登录商家版APP完成签约，即可开始营业。"
审核驳回："您的入驻申请未通过审核，原因：食品经营许可证经营范围不包含乳制品销售。请更新证件后重新提交。"
```

### 2. 商品管理

#### 2.1 商品上架

##### 2.1.1 商品信息录入

| 字段 | 填写要求 | 示例 |
|------|----------|------|
| 商品名称 | 清晰描述，不含违禁词 | "可口可乐330ml罐装" |
| 商品分类 | 选择对应类目 | 饮料/碳酸饮料/可口可乐 |
| 商品图片 | 实物拍摄，清晰美观 | 白底或场景图，无水印 |
| 商品规格 | 多规格设置（如单瓶/整箱） | 单瓶¥3.5/整箱¥42 |
| 商品价格 | 符合市场定价，不虚假 | 原价¥4，现价¥3.5 |
| 商品描述 | 规格、保质期、存储条件 | "330ml/罐，保质期12个月" |
| 条形码 | 商品标准条码 | EAN-13条码 |
| 重量/体积 | 用于运费计算 | 0.33kg/罐 |

##### 2.1.2 上架流程

```
进入商品管理 ──▶ 添加商品 ──▶ 填写商品信息 ──▶ 上传图片 ──▶ 设置规格价格 ──▶ 提交审核 ──▶ 上架销售
      │              │              │              │              │              │              │
      ▼              ▼              ▼              ▼              ▼              ▼              ▼
   商家版APP      选择分类       名称/描述       主图/详情图     单规格/       系统审核       用户可见
   商品模块                       配料信息                       多规格        合规性
```

**【KCP】商品上架关键控制点**：
- 商品图片必须为实物拍摄，禁止使用网图或过度PS
- 商品描述必须真实准确，不得虚假宣传
- 价格设置必须合理，禁止虚高原价再打折
- 保质期必须清晰标注，临期商品需特别说明
- 生鲜商品需标注"实际称重，多退少补"

**【Rule】商品上架拦截规则**：
- **违禁品拦截**：涉黄、涉毒、违禁药品等，系统直接拒绝上架
- **图片违规拦截**：模糊、带水印、非实物图，提示"请上传清晰的实物图片"
- **价格异常拦截**：价格超出类目均价3倍以上，提示"价格异常，请确认后重新提交"
- **描述违规拦截**：含虚假宣传、医疗功效等，提示"描述含违规内容，请修改"
- **临期商品拦截**：保质期剩余不足30天的商品，提示"临期商品需标注保质期"

### 3. 库存管理

#### 3.1 库存设置

##### 3.1.1 库存管理功能

| 功能 | 操作说明 | 适用场景 |
|------|----------|----------|
| 设置库存 | 设置商品可售数量 | 限量商品、仓库容量有限 |
| 自动沽清 | 库存为0时自动下架 | 避免超卖 |
| 手动沽清 | 临时下架某商品 | 临时缺货、商品问题 |
| 库存预警 | 库存低于阈值时提醒 | 及时补货 |
| 多仓库存 | 多仓库分别管理库存 | 前置仓/闪电仓模式 |

##### 3.1.2 库存同步机制

```
用户下单 ──▶ 系统扣减库存 ──▶ 订单取消 ──▶ 库存回滚
    │              │              │
    ▼              ▼              ▼
  实时校验      锁定库存       释放库存
  防止超卖      15分钟         重新可售
```

**【KCP】库存管理关键控制点**：
- 库存数据必须实时同步，避免超卖
- 设置合理的库存预警阈值，及时补货
- 多仓模式下需分别管理各仓库库存
- 生鲜商品需考虑损耗率，预留安全库存

**【话术】库存不足提醒话术**：
```
商家："今天的牛奶快卖完了"
系统通知："您的商品【蒙牛纯牛奶250ml】库存仅剩10件，请及时补充库存或设置沽清。"
```

#### 3.2 缺货处理

##### 3.2.1 缺货发现时机

| 时机 | 处理方式 |
|------|----------|
| 用户下单时缺货 | 商品标记"缺货"，无法加入购物车 |
| 拣货时缺货 | 系统推送缺货通知给用户 |
| 配送前发现 | 联系用户协商换货/退款 |

##### 3.2.2 缺货处理流程

```
拣货员发现缺货
      ↓
系统标记缺货商品
      ↓
自动推送通知给用户（APP推送/短信）
      ↓
┌─────────────────────────────────────────┐
│  方案1：用户选择替换商品（等价/补差价） │
│  方案2：缺货商品退款，其余商品继续配送  │
│  方案3：整单取消，全额退款              │
│  用户未响应 → 按默认方案处理            │
└─────────────────────────────────────────┘
```

**【话术】缺货沟通话术**：
```
商家："您好，您订单中的可口可乐330ml暂时缺货，可以换成百事可乐同规格吗？价格相同。"
用户："可以"
商家："好的，已为您更换，订单继续配送。"
```

### 4. 订单处理

#### 4.1 接单流程

##### 4.1.1 订单流转机制

```
用户下单 ──▶ 系统派单 ──▶ 商家接单 ──▶ 拣货打包 ──▶ 骑手取货 ──▶ 配送完成
    │           │            │            │            │            │
    ▼           ▼            ▼            ▼            ▼            ▼
  支付成功    自动/手动     确认接单      按单拣货      扫码取货      用户确认
              派单模式     开始计时      打包复核      核对商品      订单完成
```

##### 4.1.2 接单模式

| 模式 | 说明 | 适用场景 |
|------|------|----------|
| 自动接单 | 系统自动确认订单 | 订单量大、标准化拣货 |
| 手动接单 | 商家手动确认订单 | 订单量小、需要确认库存 |
| 预订单 | 用户预约时间送达 | 提前备货、高峰分流 |

**【KCP】接单关键控制点**：
- 接单后必须在承诺拣货时间内完成拣货打包
- 拣货时必须核对商品与订单一致
- 打包必须符合商品特性（生鲜保温、易碎防护等）
- 骑手取货时必须扫码确认

##### 4.1.3 拣货时效标准

| 品类 | 建议拣货时间 | 超时处理 |
|------|--------------|----------|
| 快消品 | 5-10分钟 | 系统自动标记，影响评分 |
| 生鲜果蔬 | 8-15分钟 | 优先处理，保证新鲜 |
| 综合订单 | 10-15分钟 | 影响配送时效 |

**【话术】订单处理标准话术**：
```
新订单提醒："您有新订单【#SG123456】，请及时处理。订单内容：可口可乐x6，薯片x2，牛奶x1"
骑手到店："美团闪购配送，来取SG123456号订单" 商家："好的，稍等... 订单齐了，请核对一下"
```

#### 4.2 拣货打包

##### 4.2.1 拣货流程

| 步骤 | 操作内容 | 系统支持 |
|------|----------|----------|
| 1 | 拣货员接收订单任务 | PDA/APP推送 |
| 2 | 按最优路径拣货 | 系统规划拣货路线 |
| 3 | 扫码核对商品 | 扫描商品条码确认 |
| 4 | 生鲜称重 | 实际称重，系统计算差价 |
| 5 | 缺货处理 | 标记缺货，系统触发通知 |
| 6 | 完成拣货，提交复核 | 打包台接收 |

##### 4.2.2 打包规范

| 商品类型 | 打包要求 |
|----------|----------|
| 冷冻食品 | 保温袋+冰袋，单独包装 |
| 生鲜水产 | 防水袋+冰袋，防止渗漏 |
| 易碎商品 | 气泡膜包裹，标识易碎 |
| 重物商品 | 底部放置，轻物在上 |
| 化学品 | 单独密封，与食品隔离 |
| 鲜花 | 保湿包装，防挤压 |

**【KCP】打包关键控制点**：
- 核对商品品种、数量与订单一致
- 检查商品保质期，拒绝临期/过期商品
- 按商品特性选择合适包装材料
- 粘贴订单标签，标注配送信息

#### 4.3 订单异常处理

##### 4.3.1 异常类型与处理

| 异常类型 | 判定标准 | 处理流程 | 责任方 |
|----------|----------|----------|--------|
| 用户取消 | 接单前用户取消 | 自动取消，无责任 | 用户 |
| 商家拒单 | 接单后商家取消 | 需说明原因，影响评分 | 商家 |
| 缺货退单 | 接单后发现缺货 | 联系用户协商，可换货/退款 | 商家 |

| 商品破损 | 打包不当导致 | 重新打包或退款处理 | 商家 |

**【Rule】订单拦截规则**：
- **拣货超时拦截**：超时15分钟未完成拣货，系统自动提醒骑手"商家拣货较慢，请耐心等待"
- **频繁拒单拦截**：单日拒单率超过10%，系统自动限制接单"您的拒单率较高，已限制自动接单功能"
- **用户投诉拦截**：收到用户投诉后，该商家订单进入人工审核"您的店铺收到用户投诉，新订单需人工审核"

### 8. 结算对账

#### 8.1 结算规则

##### 8.1.1 结算周期与方式

| 结算类型 | 周期 | 到账方式 | 适用商家 |
|----------|------|----------|----------|
| T+1结算 | 订单完成后次日 | 自动打款到绑定账户 | 优质商家 |
| T+3结算 | 订单完成后3日 | 自动打款 | 普通商家 |
| 周结算 | 每周固定日期 | 批量打款 | 小额商家 |
| 月结算 | 每月固定日期 | 批量打款 | 特殊类目 |

##### 8.1.2 费用构成

```
订单实付金额
    │
    ├──▶ 平台抽佣（8-20%，按类目）
    │
    ├──▶ 配送费（用户支付部分归平台，商家承担部分扣除）
    │
    ├──▶ 营销费用（活动补贴、推广费用）
    │
    └──▶ 商家实收金额（到账金额）
```

**【KCP】结算关键控制点**：
- 订单完成后才能进入结算周期
- 退款订单会扣除相应金额
- 违规处罚会扣除相应罚款
- 对账差异需在3个工作日内提出

#### 8.2 对账流程

##### 8.2.1 对账操作

```

      │              │                │              │              │
      ▼              ▼                ▼              ▼              ▼
   商家版APP       按日/周/月      Excel/CSV      逐笔核对       差异申诉
   财务模块        查看流水        格式下载       订单金额       3日内有效
```

**【Rule】资金结算拦截规则**：
- **账户异常拦截**：绑定银行卡信息错误，资金无法到账，提示"请检查银行卡信息"
- **违规冻结拦截**：店铺存在违规未处理，结算资金冻结"您的店铺存在违规事项，资金暂冻结"
- **争议订单拦截**：订单存在售后争议，该订单金额暂缓结算"订单存在争议，金额暂缓结算"

**【话术】结算咨询话术**：
```
商家："昨天的钱怎么还没到账？"
客服："您昨天的订单还在T+1结算周期中，预计明天上午10点前到账。您可以查看财务中心的【预计到账】模块查看具体明细。"
```
