## 业务概述

美团买菜（品牌升级为「小象超市」）是美团旗下的即时零售业务，主打「30分钟快送超市」，提供生鲜果蔬、肉禽蛋奶、粮油副食、日用百货等商品的即时配送服务。

### 核心参与方

```
+-----------+      选购下单      +-----------+      履约配送      +-----------+
|  消费者   | -----------------> |  美团平台  | -----------------> |  前置仓/   |
+-----------+                    +-----------+                    |  闪电仓    |
     ^                               |                            +-----------+
     |      收货/售后                |                                  |
     |                               |      库存管理                     | 分拣打包
     +-----------------------  运营系统  <-------------------------  商品出库
```

## Objective

1. **时效目标**：订单30分钟内送达率 ≥ 95% `[需内部资料确认：具体时效标准]`
2. **品质目标**：生鲜商品新鲜度达标，客诉率 ≤ 1%
3. **库存目标**：缺货率 ≤ 3%，缺货及时通知用户
4. **体验目标**：售后问题30分钟内响应处理

## Standard Operating Procedures

### 一、选购下单流程

#### 1.1 用户端操作流程

| 步骤 | 操作内容 | 注意事项 |
|------|----------|----------|
| 1 | 打开美团APP/小象超市APP | 自动定位附近前置仓 |
| 2 | 浏览商品分类或搜索 | 生鲜商品库存实时变化 |
| 3 | 选择商品规格、数量，加入购物车 | 注意商品重量/个数规格 |
| 4 | 进入购物车，确认商品 | 查看小计金额、优惠 |
| 5 | 选择配送时间段 | 可选「立即配送」或预约时段 |
| 6 | 确认收货地址 | 确认是否在配送范围内 |
| 7 | 选择支付方式，完成支付 | 支持多种支付方式 |

│   ├── 中午时段：11:00-13:00
│   ├── 下午时段：13:00-17:00
│   ├── 晚间时段：17:00-20:00

### 二、分拣打包流程

#### 2.1 订单分配

```
用户下单成功
      ↓
系统根据配送地址分配最近前置仓
      ↓
订单进入拣货队列（按配送时段排序）
      ↓
分配拣货员 `[需内部资料确认：分配逻辑]`
```

#### 2.2 拣货流程

| 步骤 | 操作内容 | 系统支持 |
|------|----------|----------|
| 1 | 拣货员接收订单任务 | PDA/APP推送 |
| 2 | 按最优路径拣货 | 系统规划拣货路线 |
| 3 | 扫码核对商品 | 扫描商品条码确认 |
| 4 | 生鲜称重 | 实际称重，系统计算差价 |
| 5 | 缺货处理 | 标记缺货，系统触发通知 |
| 6 | 完成拣货，提交复核 | 打包台接收 |

#### 2.3 打包复核

```
拣货完成
      ↓
复核员核对商品（品种、数量、质量）
      ↓
┌─────────────────────────────────────────┐
│  核对无误 → 按规范打包                  │
│  发现问题 → 退回重新拣货                │
│  商品瑕疵 → 更换商品                    │
└─────────────────────────────────────────┘
      ↓
粘贴订单标签，放置配送区
      ↓
等待骑手取货
```

#### 2.4 打包规范 `[需内部资料确认：具体规范标准]`

| 商品类型 | 打包要求 |
|----------|----------|
| 冷冻食品 | 保温袋+冰袋，单独包装 |
| 生鲜水产 | 防水袋+冰袋，防止渗漏 |
| 易碎商品 | 气泡膜包裹，标识易碎 |
| 重物商品 | 底部放置，轻物在上 |
| 化学品 | 单独密封，与食品隔离 |

### 三、即时配送流程

#### 3.1 骑手取货

| 步骤 | 操作内容 |
|------|----------|
| 1 | 骑手接收配送任务 |
| 2 | 到达前置仓，扫码取货 |
| 3 | 核对订单号、商品数量 |
| 4 | 检查商品包装完整性 |
| 5 | 装车，按路线配送 |

#### 3.2 配送时效管理 `[需内部资料确认：具体时效标准]`

```
时效控制节点：
├── 下单至拣货开始：≤ 5分钟
├── 拣货完成时间：≤ 15分钟
├── 骑手取货时间：≤ 5分钟
├── 配送途中时间：≤ 15分钟（3公里内）
└── 总时效目标：≤ 30-45分钟
```

#### 3.3 配送异常处理

| 异常情况 | 处理流程 |
|----------|----------|
| 联系不上用户 | 多次联系 → 上报异常 → 等待/按备注放置 |
| 地址错误 | 联系用户确认 → 协商处理/退回前置仓 |
| 商品破损 | 拍照留证 → 联系客服 → 协商处理 |
| 用户拒收 | 了解原因 → 上报平台 → 商品退回 |

---

### 四、缺货处理

#### 4.1 缺货发现时机

| 时机 | 处理方式 |
|------|----------|
| 下单时缺货 | 商品标记「缺货」，无法加入购物车 |
| 拣货时缺货 | 系统推送缺货通知给用户 |
| 配送前发现 | 联系用户协商换货/退款 |

#### 4.2 缺货处理流程

```
拣货员发现缺货
      ↓
系统标记缺货商品
      ↓
自动推送通知给用户（APP推送/短信）
      ↓
┌─────────────────────────────────────────┐
│  方案1：用户选择替换商品（等价/补差价） │
│  方案2：缺货商品退款，其余商品继续配送  │
│  方案3：整单取消，全额退款              │
│  用户未响应 → 按默认方案处理 `[需内部资料确认：默认规则]` │
└─────────────────────────────────────────┘
```

#### 4.3 缺货补偿 `[需内部资料确认：补偿标准]`

| 缺货情况 | 补偿措施 |
|----------|----------|
| 单商品缺货 | 该商品退款 + 优惠券补偿 |
| 多商品缺货 | 退款 + 额外优惠券/红包 |
| 整单缺货 | 全额退款 + 补偿 |

### 五、生鲜售后

#### 5.1 售后场景

| 场景 | 描述 | 举证要求 |
|------|------|----------|
| 商品变质 | 生鲜不新鲜、有异味 | 照片/视频 |
| 商品损坏 | 挤压破损、包装破裂 | 照片 |
| 重量不足 | 实际重量低于标注 | 称重照片 |
| 商品错发 | 收到非订单商品 | 照片 |
| 品质不符 | 与描述/图片不符 | 照片 |

#### 5.2 售后流程

```
用户申请售后
      ↓
选择售后原因 → 上传凭证 → 提交申请
      ↓
系统/客服审核
      ↓
┌─────────────────────────────────────────┐
│  审核通过 → 退款/补发/补偿              │
│  需补充凭证 → 通知用户补充              │
│  审核不通过 → 说明原因                  │
└─────────────────────────────────────────┘
```

#### 5.3 售后政策 `[需内部资料确认：具体售后标准]`

| 商品类型 | 售后时效 | 退款方式 |
|----------|----------|----------|
| 生鲜商品 | 签收后24小时内 | 按比例/全额退款 |
| 普通商品 | 签收后7天内 | 退货退款/仅退款 |
| 质量问题 | 优先退款，无需退货 | 极速退款 |
