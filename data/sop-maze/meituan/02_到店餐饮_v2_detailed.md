# 美团到店餐饮 SOP 详细版（v2_detailed）

> **文档版本**: v2.0 详细版  
> **适用场景**: 到店餐饮团购全流程客服/运营处理  
> **更新日期**: 2026年8月

---

## Objective

1. **用户体验目标**: 帮助用户便捷发现、购买、使用到店服务，团购核销率 ≥ 80%
2. **商家引流目标**: 为线下商家带来精准客流，提升翻台率 ≥ 20%
3. **平台交易目标**: 提高团购转化率，降低退款率 ≤ 10%
4. **服务质量目标**: 确保团购信息真实准确，杜绝虚假宣传，商家爽约率 ≤ 0.5%

---

## Standard Operating Procedures

### 一、团购购买流程

#### 1.1 用户端操作流程

```
┌─────────────────────────────────────────────────────────────────┐
│                     团购购买操作流程                              │
├─────────────────────────────────────────────────────────────────┤
│                                                                 │
│  ┌──────────┐    ┌──────────┐    ┌──────────┐    ┌──────────┐  │
│  │1.浏览商家│ -> │2.查看套餐│ -> │3.确认规则│ -> │4.完成支付│  │
│  └──────────┘    └──────────┘    └──────────┘    └──────────┘  │
│                                                                 │
│  KCP: 使用规则确认、有效期确认、限制条件确认                     │
│                                                                 │
└─────────────────────────────────────────────────────────────────┘
```

| 步骤 | 操作内容 | 注意事项 | Rule层约束 |
|------|----------|----------|------------|
| 1 | 打开美团APP，进入「美食」频道 | 可按位置、菜系、价格筛选 | 定位失败需手动选择城市 |
| 2 | 浏览商家及团购套餐 | 查看套餐详情、使用规则、用户评价 | **KCP**: 必须展示完整使用限制 |
| 3 | 选择套餐规格（如有） | 注意区分：工作日/周末、午餐/晚餐等 | 不可选规格标记售罄 |
| 4 | 确认购买数量 | 部分套餐限购，注意查看 | 超出限购数量无法提交 |
| 5 | 选择支付方式，完成支付 | 支持多种支付方式 | 支付超时15分钟释放库存 |
| 6 | 获取团购券码 | 券码发送至APP「我的订单」和短信 | 券码即时生效 |

#### 1.3 购买限制说明

| 限制类型 | 说明 | Rule层约束 |
|----------|------|------------|
| 购买数量限制 | 每人限购X份，每桌限用X张 | 超出限购数量系统拦截 |
| 使用时间限制 | 工作日/周末、午餐/晚餐时段 | 不在可用时段内无法核销 |
| 使用日期限制 | 节假日不可用/仅限特定日期 | 节假日系统自动标记不可用 |
| 叠加使用限制 | 是否可与其他优惠同享 | 不可叠加时系统自动计算最优方案 |
| 预约要求 | 是否需要提前电话预约 | 需预约套餐未预约无法核销 |

### 二、预约订座流程

#### 2.1 在线预订

| 步骤 | 操作内容 | 系统处理 | KCP标记 |
|------|----------|----------|---------|
| 1 | 选择商家，点击「订座」 | 显示可预订时段和桌型 | 实时库存查询 |
| 2 | 选择日期、时间、人数 | 实时查询座位库存 | 时段可用性校验 |
| 3 | 填写联系人信息 | 验证手机号 | 手机号有效性校验 |
| 4 | 提交预订 | 发送预订请求给商家 | 预订请求发送时间记录 |
| 5 | 等待确认 | 商家确认后通知用户 | **KCP**: 商家确认时限30分钟 |

#### 2.2 预订状态流转

```
用户提交预订

│ - 商家需在30分钟内确认                  │
│ - 超时未确认自动取消                    │
│ - 用户可重新预订                        │
└─────────────────────────────────────────┘
    │
    ▼
┌─────────────────────────────────────────┐
│  商家确认 → 预订成功，通知用户          │
│  商家拒绝 → 说明原因，推荐其他时段      │
│  超时未响应 → 系统自动取消              │

```

### 三、到店核销流程

#### 3.1 用户到店

| 步骤 | 操作内容 | KCP标记 |
|------|----------|---------|
| 1 | 到店后向服务员说明有美团团购 | 到店时间记录 |
| 2 | 打开美团APP，进入「我的」-「订单」 | 券码有效性校验 |
| 3 | 找到对应团购券，点击「出示券码」 | 券码状态检查 |
| 4 | 向服务员展示二维码或券号 | **KCP**: 券码清晰可识别 |
| 5 | 等待商家扫码/输入密码核销 | 核销时间记录 |
| 6 | 核销成功后享用服务 | 核销成功确认 |

#### 3.2 商家核销操作

```
商家端核销流程：
    │
    ▼
登录美团商家版APP
    │
    ▼
进入「验券」功能
    │
    ▼
┌─────────────────────────────────────────┐
│ 方式1: 扫描用户出示的二维码             │
│ 方式2: 手动输入12位券码                 │
└─────────────────────────────────────────┘
    │
    ▼
确认券信息（套餐内容、有效期）
    │
    ▼
┌─────────────────────────────────────────┐
│ Rule: 核销时效拦截                      │
│ - 检查券是否在有效期内                  │
│ - 检查券是否已使用                      │
│ - 检查使用时段限制                      │
│ - 检查商家资质（是否可核销）            │
└─────────────────────────────────────────┘
    │
    ▼
点击「确认核销」
    │
    ▼
打印小票或电子确认
```

#### 3.3 核销异常处理

| 异常情况 | 处理流程 | Rule层约束 | 话术 |
|----------|----------|------------|------|
| 券码无法识别 | 检查网络 → 手动输入券号 → 联系客服 | 网络异常30秒内重试 | "网络稍慢，我手动输入券号为您核销" |
| 券已过期 | 查看有效期 → 协商延期使用或退款 | 过期7天内可申请延期 | "券已过期，为您申请延期使用或全额退款" |
| 券已使用 | 查询核销记录 → 核实是否重复核销 | 已使用券无法再次核销 | "该券已使用，查询记录显示XX时间已核销" |
| 商家无法核销 | 拍照留证 → 联系美团客服处理 | 商家系统故障需30分钟内解决 | "系统故障，为您联系客服协助处理" |

### 五、退款规则

#### 5.1 退款类型

| 退款场景 | 退款条件 | 退款金额 | Rule层约束 |
|----------|----------|----------|------------|
| 未消费随时退 | 券未核销，在有效期内 | 全额退款 | 有效期内自动退款 |
| 过期自动退 | 券过期未使用 | 全额原路退回 | 过期7天内自动发起 |
| 商家原因 | 商家停业/无法提供服务 | 全额退款 + 补偿 | 商家责任需补偿 |
| 用户原因 | 个人原因不想去了 | 按退款规则扣除手续费/不可退 | 秒杀商品不可退 |
| 部分使用 | 套餐内部分菜品未使用 | 协商退还差价 | 需商家确认 |

#### 5.2 退款流程

```
用户申请退款
    │
    ▼
选择退款原因 → 提交申请
    │
    ▼
┌─────────────────────────────────────────┐
│ Rule: 退款时效拦截                      │
│                                         │
│ 未消费随时退：自动审核通过              │
│ 已过期：自动审核通过                    │
│ 商家原因：需客服核实                    │
│ 部分使用：需商家确认                    │
│ 秒杀商品：不可退（特殊情况申诉）        │
└─────────────────────────────────────────┘
    │
    ▼
┌─────────────────────────────────────────┐
│  符合条件 → 自动退款（1-7个工作日）     │
│  需核实 → 客服介入处理                  │
│  不符合 → 拒绝并说明原因                │
└─────────────────────────────────────────┘
```

### 六、商家爽约处理

#### 6.1 爽约定义

商家爽约包括但不限于：
- 预订成功后商家拒绝接待
- 商家临时停业未提前通知
- 到店后无法提供团购套餐内容
- 要求用户额外支付不合理费用

#### 6.2 处理流程

```
用户投诉商家爽约
```

#### 6.3 商家处罚措施

| 爽约次数 | 处罚措施 | Rule层约束 |
|----------|----------|------------|
| 首次 | 警告，要求整改 | 记录违约行为 |
| 多次（3个月内≥2次） | 降低搜索排名，限制参加活动 | 7天内限制活动报名 |
| 严重/恶意 | 下架处理，终止合作 | 永久下架，终止合作 |

## Rule 层约束汇总

| 规则类别 | 规则名称 | 规则内容 | 触发时机 |
|----------|----------|----------|----------|
| 核销时效 | 商家确认时限 | 商家需在30分钟内确认预订 | 预订提交后 |
| 核销时效 | 券有效期拦截 | 过期券无法核销 | 核销时 |
| 核销时效 | 使用时段拦截 | 不在可用时段内无法核销 | 核销时 |
| 商家资质 | 商家资质拦截 | 检查商家是否具备接待能力 | 核销/预订时 |
| 退款 | 退款时效拦截 | 过期7天内可申请退款 | 退款申请时 |
| 退款 | 不可退商品拦截 | 秒杀商品不可退 | 退款申请时 |
| 爽约 | 爽约记录拦截 | 多次爽约商家限制活动 | 商家违约时 |
