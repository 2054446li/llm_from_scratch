# 美团闪购商家端 SOP（v2 详细版）

> **文档版本**: v2.0 详细版  
> **适用场景**: 美团闪购商家端即时零售全流程运营/客服处理  
> **更新日期**: 2026年8月

---

## Objective

1. **入驻合规目标**: 资质审核通过率 ≥ 70%，平均审核时长 < 2天
2. **商品管理目标**: 商品信息完整率 ≥ 95%，商品审核通过率 ≥ 90%
3. **库存管理目标**: 库存准确率 ≥ 98%，缺货率 ≤ 3%，超卖率 < 0.5%
4. **履约时效目标**: 接单率 ≥ 98%，拣货准时率 ≥ 95%，30分钟送达率 ≥ 90%
5. **服务体验目标**: 售后响应时效 < 2小时，售后满意度 ≥ 90%，投诉率 < 1%
6. **经营健康目标**: 店铺评分 > 4.5分，月活跃商家率 > 80%，商家留存率 > 85%

---

#### 1.2 入驻申请流程

| 步骤 | 操作内容 | 注意事项 | Rule层约束 |
|------|----------|----------|------------|
| 1 | 下载商家版APP（iOS/Android） | 官方应用商店下载 | **Rule**: 非官方渠道下载拦截 |
| 2 | 注册账号，手机号验证 | 使用法人或负责人手机号 | 手机号实名认证 |
| 3 | 选择入驻类型 | 根据实际经营模式选择 | **KCP**: 类型与资质匹配校验 |
| 4 | 填写店铺信息 | 店名/地址/联系人信息 | 地址与证照地址一致性校验 |
| 5 | 上传资质证照 | 营业执照/许可证/身份证 | **Rule**: OCR识别+规则校验 |
| 6 | 提交审核 | 等待1-3个工作日 | 系统自动初审+人工复核 |

**【KCP】入驻申请关键控制点**:
- 营业执照必须在有效期内，且经营范围包含所售商品
- 食品经营许可证必须与实际经营品类一致
- 店铺地址必须与证照地址一致（或提供合法租赁证明）
- 法人身份证正反面必须清晰可辨
- 前置仓/闪电仓需提供仓储场地租赁合同

**【话术】入驻咨询标准话术**:
```
商家："我想在美团闪购开店，需要什么条件？"
客服："您好，美团闪购开店需要准备以下材料：
      1）营业执照原件照片
      2）食品经营许可证（如涉及食品）
      3）法人身份证正反面
      4）店铺门头照和店内环境照
      5）仓储场地证明（前置仓/闪电仓）
      审核通常需要1-3个工作日。"
```

#### 1.3 资质审核流程

```
资料提交
    │
    ▼
┌─────────────────────────────────────────┐
│ Rule: 系统自动初审                      │
│ - OCR识别证照信息                       │
│ - 规则校验（有效期/经营范围）           │
│ - 黑名单比对                            │
│ - 重复入驻检测                          │
└─────────────────────────────────────────┘
    │
    ▼
人工复核（审核员核查信息一致性）
    │
    ▼
资质核验（对接政府接口验证证照真伪）
    │
    ▼
审核结果通知（短信+APP推送）
    │
    ▼
签约入驻（电子合同在线签署）
```

| 审核项 | 通过标准 | 常见驳回原因 | Rule层约束 |
|--------|----------|--------------|------------|
| 营业执照 | 有效期内，经营范围匹配 | 过期、经营范围不符、伪造 | **Rule**: 证照过期拦截 |
| 食品经营许可证 | 有效期内，许可项目匹配 | 过期、许可项目缺失、地址不符 | **Rule**: 经营范围拦截 |
| 法人身份证 | 清晰可辨，与营业执照一致 | 模糊、过期、信息不一致 | OCR识别校验 |
| 店铺照片 | 真实环境，与证照地址一致 | 网图、与地址不符、环境不达标 | 人工审核 |
| 仓储证明 | 场地合法，面积符合要求 | 合同过期、面积不足、用途不符 | 前置仓/闪电仓必审 |
| 银行信息 | 对公账户或法人个人账户 | 账户信息错误、非本人账户 | 银行卡验证 |

**【话术】审核结果通知话术**:
```
审核通过：
"恭喜您！您的店铺【XX便利店】已通过审核，请登录商家版APP完成签约，即可开始营业。"

审核驳回：
"您的入驻申请未通过审核，原因：食品经营许可证经营范围不包含乳制品销售。
请更新证件后重新提交，如有疑问请联系客户经理。"
```

### 二、商品管理流程

#### 2.1 商品上架流程

```
┌─────────────────────────────────────────────────────────────────┐
│                     商品上架操作流程                              │
├─────────────────────────────────────────────────────────────────┤
│                                                                 │
│  ┌──────────┐    ┌──────────┐    ┌──────────┐    ┌──────────┐  │
│  │1.添加商品│ -> │2.填写信息│ -> │3.上传图片│ -> │4.提交审核│  │
│  └──────────┘    └──────────┘    └──────────┘    └──────────┘  │
│                                                                 │
│  KCP: 商品信息准确性、图片合规性、价格合理性                     │
│                                                                 │
└─────────────────────────────────────────────────────────────────┘
```

| 字段 | 填写要求 | 示例 | Rule层约束 |
|------|----------|------|------------|
| 商品名称 | 清晰描述，不含违禁词 | "可口可乐330ml罐装" | **Rule**: 违禁词拦截 |
| 商品分类 | 选择对应类目 | 饮料/碳酸饮料/可口可乐 | 类目匹配校验 |
| 商品图片 | 实物拍摄，清晰美观 | 白底或场景图，无水印 | **Rule**: 图片违规拦截 |
| 商品规格 | 多规格设置 | 单瓶¥3.5/整箱¥42 | 规格价格逻辑校验 |
| 商品价格 | 符合市场定价 | 原价¥4，现价¥3.5 | **Rule**: 价格异常拦截 |
| 商品描述 | 规格、保质期、存储条件 | "330ml/罐，保质期12个月" | 描述合规校验 |
| 条形码 | 商品标准条码 | EAN-13条码 | 条码有效性校验 |
| 重量/体积 | 用于运费计算 | 0.33kg/罐 | 重量合理性校验 |

**【KCP】商品上架关键控制点**:
- 商品图片必须为实物拍摄，禁止使用网图或过度PS
- 商品描述必须真实准确，不得虚假宣传
- 价格设置必须合理，禁止虚高原价再打折
- 保质期必须清晰标注，临期商品需特别说明
- 生鲜商品需标注"实际称重，多退少补"

**【话术】商品上架咨询话术**:
```
商家："我要怎么上架商品？"
客服："您可以登录商家版APP，进入【商品管理】-【添加商品】，按提示填写：
      1）商品名称和分类
      2）上传清晰的实物图片
      3）设置价格和库存
      4）填写商品描述
      提交后系统会自动审核，通常几分钟内完成。"
```

### 三、库存管理流程

#### 3.1 库存设置与同步

```
用户下单
    │
    ▼
┌─────────────────────────────────────────┐
│ Rule: 实时库存校验                      │
│ - 校验库存是否充足                      │
│ - 库存不足：提示"库存不足"              │
│ - 库存充足：锁定库存15分钟              │
└─────────────────────────────────────────┘
    │
    ▼
系统扣减库存（锁定状态）
    │
    ▼
┌─────────────────────────────────────────┐
│ 订单完成 → 确认扣减                     │
│ 订单取消 → 库存回滚                     │
│ 支付超时 → 自动释放库存                 │
└─────────────────────────────────────────┘
```

| 功能 | 操作说明 | 适用场景 | Rule层约束 |
|------|----------|----------|------------|
| 设置库存 | 设置商品可售数量 | 限量商品、仓库容量有限 | 库存≥0校验 |
| 自动沽清 | 库存为0时自动下架 | 避免超卖 | **Rule**: 超卖拦截 |
| 手动沽清 | 临时下架某商品 | 临时缺货、商品问题 | 即时生效 |
| 库存预警 | 库存低于阈值时提醒 | 及时补货 | 预警阈值可配置 |
| 多仓库存 | 多仓库分别管理库存 | 前置仓/闪电仓模式 | 分仓库存独立 |

**【KCP】库存管理关键控制点**:
- 库存数据必须实时同步，避免超卖
- 设置合理的库存预警阈值，及时补货
- 多仓模式下需分别管理各仓库库存
- 生鲜商品需考虑损耗率，预留安全库存

**【话术】库存不足提醒话术**:
```
系统通知：
"您的商品【蒙牛纯牛奶250ml】库存仅剩10件，请及时补充库存或设置沽清。"

商家咨询：
商家："今天的牛奶快卖完了，怎么设置库存？"
客服："您可以在商品管理中找到该商品，点击【修改库存】，
      将库存数量改为实际剩余数量。如果已经售罄，可以开启【自动沽清】，
      商品会自动下架，避免用户下单后无法发货。"
```

#### 3.2 缺货处理流程

| 时机 | 处理方式 | Rule层约束 |
|------|----------|------------|
| 用户下单时缺货 | 商品标记"缺货"，无法加入购物车 | 实时库存校验 |
| 拣货时缺货 | 系统推送缺货通知给用户 | **Rule**: 缺货15分钟内通知用户 |
| 配送前发现 | 联系用户协商换货/退款 | 配送前必须解决 |

```
拣货员发现缺货
    │
    ▼
系统标记缺货商品
    │
    ▼
自动推送通知给用户（APP推送/短信）
    │
    ▼
┌─────────────────────────────────────────┐
│  方案1：用户选择替换商品（等价/补差价） │
│  方案2：缺货商品退款，其余商品继续配送  │
│  方案3：整单取消，全额退款              │
│  用户未响应 → 按默认方案处理            │
└─────────────────────────────────────────┘
```

**【话术】缺货沟通话术**:
```
商家："您好，您订单中的可口可乐330ml暂时缺货，
      可以换成百事可乐同规格吗？价格相同。"
用户："可以"
商家："好的，已为您更换，订单继续配送。"
```

| 环节 | 操作内容 | 时效要求 | Rule层约束 |
|------|----------|----------|------------|
| 用户下单 | 支付成功，系统派单 | 即时 | 支付超时15分钟释放库存 |
| 商家接单 | 确认接单，开始计时 | ≤ 2分钟 | **Rule**: 超时自动接单/拒单 |
| 拣货打包 | 按单拣货，打包复核 | 快消品5-10分钟，生鲜8-15分钟 | **Rule**: 拣货超时提醒 |
| 骑手取货 | 扫码取货，核对商品 | ≤ 5分钟 | 取货扫码确认 |
| 配送途中 | 按路线配送 | ≤ 15分钟（3公里内） | **Rule**: 配送时效监控 |
| 订单完成 | 用户确认收货 | 即时 | 自动结算触发 |

#### 4.2 接单模式

| 模式 | 说明 | 适用场景 | Rule层约束 |
|------|------|----------|------------|
| 自动接单 | 系统自动确认订单 | 订单量大、标准化拣货 | 默认开启 |
| 手动接单 | 商家手动确认订单 | 订单量小、需要确认库存 | 超时自动转自动接单 |
| 预订单 | 用户预约时间送达 | 提前备货、高峰分流 | 按预约时间触发拣货 |

**【KCP】接单关键控制点**:
- 接单后必须在承诺拣货时间内完成拣货打包
- 拣货时必须核对商品与订单一致
- 打包必须符合商品特性（生鲜保温、易碎防护等）
- 骑手取货时必须扫码确认

**【话术】订单处理标准话术**:

预计拣货时间：10分钟"

骑手到店：

#### 4.3 拣货打包规范

| 步骤 | 操作内容 | 系统支持 | KCP标记 |
|------|----------|----------|---------|
| 1 | 拣货员接收订单任务 | PDA/APP推送 | 任务分配时间记录 |
| 2 | 按最优路径拣货 | 系统规划拣货路线 | 拣货效率监控 |
| 3 | 扫码核对商品 | 扫描商品条码确认 | **KCP**: 商品准确性校验 |
| 4 | 生鲜称重 | 实际称重，系统计算差价 | **KCP**: 重量准确性 |
| 5 | 缺货处理 | 标记缺货，系统触发通知 | **KCP**: 缺货及时标记 |
| 6 | 完成拣货，提交复核 | 打包台接收 | 拣货完成时间记录 |

| 商品类型 | 打包要求 | Rule层约束 |
|----------|----------|------------|
| 冷冻食品 | 保温袋+冰袋，单独包装 | 冷冻商品必须冷链 |
| 生鲜水产 | 防水袋+冰袋，防止渗漏 | 活鲜需充氧包装 |
| 易碎商品 | 气泡膜包裹，标识易碎 | 易碎标识必须清晰 |
| 重物商品 | 底部放置，轻物在上 | 承重限制5kg/袋 |
| 化学品 | 单独密封，与食品隔离 | 严格隔离要求 |
| 鲜花 | 保湿包装，防挤压 | 鲜花保鲜处理 |

**【KCP】打包关键控制点**:
- 核对商品品种、数量与订单一致
- 检查商品保质期，拒绝临期/过期商品
- 按商品特性选择合适包装材料
- 粘贴订单标签，标注配送信息

#### 4.4 订单异常处理

| 异常类型 | 判定标准 | 处理流程 | 责任方 |
|----------|----------|----------|--------|
| 用户取消 | 接单前用户取消 | 自动取消，无责任 | 用户 |
| 商家拒单 | 接单后商家取消 | 需说明原因，影响评分 | 商家 |
| 缺货退单 | 接单后发现缺货 | 联系用户协商，可换货/退款 | 商家 |
| 拣货超时 | 超过承诺拣货时间 | 系统自动标记，影响评分 | 商家 |
| 商品破损 | 打包不当导致 | 重新打包或退款处理 | 商家 |

**【Rule】订单拦截规则**:
- **拣货超时拦截**: 超时15分钟未完成拣货，系统自动提醒骑手"商家拣货较慢，请耐心等待"
- **频繁拒单拦截**: 单日拒单率超过10%，系统自动限制接单"您的拒单率较高，已限制自动接单功能"
- **用户投诉拦截**: 收到用户投诉后，该商家订单进入人工审核"您的店铺收到用户投诉，新订单需人工审核"

### 八、结算对账流程

#### 8.1 结算规则

| 结算类型 | 周期 | 到账方式 | 适用商家 |
|----------|------|----------|----------|
| T+1结算 | 订单完成后次日 | 自动打款到绑定账户 | 优质商家 |
| T+3结算 | 订单完成后3日 | 自动打款 | 普通商家 |
| 周结算 | 每周固定日期 | 批量打款 | 小额商家 |
| 月结算 | 每月固定日期 | 批量打款 | 特殊类目 |

```
订单实付金额
    │
    ├──▶ 平台抽佣（8-20%，按类目）
    │
    ├──▶ 配送费（用户支付部分归平台，商家承担部分扣除）
    │
    ├──▶ 营销费用（活动补贴、推广费用）
    │
    └──▶ 商家实收金额（到账金额）
```

**【KCP】结算关键控制点**:
- 订单完成后才能进入结算周期
- 退款订单会扣除相应金额
- 违规处罚会扣除相应罚款
- 对账差异需在3个工作日内提出

#### 8.2 对账流程

```
进入财务中心
    │
    ▼
查看账单明细（按日/周/月查看流水）
    │
    ▼
下载对账单（Excel/CSV格式下载）
    │
    ▼
核对订单（逐笔核对订单金额）
    │
    ▼
┌─────────────────────────────────────────┐
│  核对无误 → 确认                        │
│  发现差异 → 差异申诉（3日内有效）       │
└─────────────────────────────────────────┘
```

**【话术】结算咨询话术**:
```
商家："昨天的钱怎么还没到账？"
客服："您昨天的订单还在T+1结算周期中，预计明天上午10点前到账。
      您可以查看财务中心的【预计到账】模块查看具体明细。"
```

        1）营业执照

        3）仓储场地租赁合同（面积建议100平米以上）

        请问您有合适的场地吗？

平台客服：好的，那您可以在商家版APP提交入驻申请，审核通常1-3个工作日。
        闪电仓的抽佣比例是10-18%，具体根据您的商品类目确定。
