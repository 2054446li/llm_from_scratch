## Objective

本SOP旨在规范美团众包骑手端的运营流程，确保：

1. **骑手准入合规**：严格审核骑手资质，保障配送服务基础质量
2. **配送效率优化**：合理派单与路径规划，提升骑手接单效率与收入
3. **服务品质保障**：标准化配送流程，确保订单准时、安全送达
4. **骑手权益保护**：透明结算、公平申诉机制，保障骑手合法权益
5. **安全运营底线**：安全培训与监控，降低配送安全风险

## Standard Operating Procedures

### 1. 骑手注册认证流程

#### 1.1 账号注册

| 步骤 | 操作内容 | 注意事项 |
|------|----------|----------|
| 1 | 下载美团众包APP | 支持iOS/Android系统 |
| 2 | 手机号注册 | 需使用本人实名手机号 |
| 3 | 设置登录密码 | 建议设置安全强度较高的密码 |
| 4 | 完善个人信息 | 填写真实姓名、身份证号等 |

#### 1.2 实名认证

##### 1.2.1 认证材料准备

| 材料类型 | 要求 | 说明 |
|----------|------|------|
| 身份证 | 二代身份证原件 | 正反面清晰照片 |
| 人脸识别 | 实时活体检测 | 确保本人操作 |
| 银行卡 | 本人名下借记卡 | 用于收入结算 |

##### 1.2.2 认证流程

```
上传身份证照片 ──▶ 人脸识别验证 ──▶ 绑定银行卡 ──▶ 等待审核 ──▶ 认证通过
```

#### 1.3 健康证上传

| 项目 | 要求 |
|------|------|
| 适用地区 | 部分城市要求（如北京、上海等）`[需内部资料确认]` |
| 办理地点 | 当地疾控中心或指定体检机构 |
| 有效期 | 通常为1年 |
| 上传要求 | 清晰照片，信息完整可见 |

#### 1.4 培训与考试

##### 1.4.1 培训内容

| 模块 | 内容要点 |
|------|----------|
| 平台规则 | 接单规则、服务规范、奖惩制度 |
| 配送流程 | 取餐标准、配送规范、送达要求 |
| 安全知识 | 交通安全、食品安全、人身安全 |
| 异常处理 | 常见问题处理、申诉流程 |

##### 1.4.2 考试要求

| 项目 | 要求 |
|------|------|
| 考试形式 | 在线答题 |
| 合格标准 | 通常为80分及以上 `[需内部资料确认]` |
| 补考机会 | 未通过可重新学习后补考 |

### 2. 接单流程

#### 2.1 上线准备

##### 2.1.1 上线前检查

| 检查项 | 要求 |
|--------|------|
| 装备检查 | 配送箱、头盔、手机支架、充电宝 |
| 电量检查 | 手机电量充足（建议80%以上） |
| 网络检查 | 确保网络畅通 |
| 定位检查 | GPS定位正常 |

##### 2.1.2 装备要求

| 装备 | 说明 | 是否强制 |
|------|------|----------|
| 配送箱 | 保温箱，确保餐品温度 | 是 |
| 头盔 | 骑行安全必备 | 是 |
| 工作服 | 美团众包马甲/工服 | 部分地区要求 `[需内部资料确认]` |
| 手机支架 | 方便导航和接单 | 建议配备 |

#### 2.2 派单机制

##### 2.2.1 派单模式

| 模式 | 说明 | 适用场景 |
|------|------|----------|
| 系统派单 | 算法根据位置、方向、负载自动派单 | 主要派单方式 |
| 抢单模式 | 骑手主动抢单大厅抢单 | 系统派单不足时 |
| 指派单 | 高价值/特殊订单指派 | 优质骑手优先 |

##### 2.2.2 派单算法因素 `[需内部资料确认：具体权重]`

```
智能派单系统考虑因素：
┌────────────────────────────────────────────────────────┐
│  1. 骑手位置：距离商家的直线/实际距离                   │
│  2. 骑手负载：当前已接订单数量                          │
│  3. 配送方向：订单目的地与骑手当前路线的匹配度          │
│  4. 预计时间：基于历史数据的配送时长预测                │
│  5. 骑手评级：服务评分、准时率、投诉率等                │
│  6. 拒单率：历史拒单情况                                │
│  7. 天气路况：实时天气、交通拥堵情况                    │
└────────────────────────────────────────────────────────┘
```

#### 2.3 接单操作

##### 2.3.1 接单流程

| 阶段 | 操作 | 说明 |
|------|------|------|
| 收到派单 | 语音播报+弹窗提醒 | 需在限定时间内响应 |
| 查看订单 | 查看商家、用户位置、预计收入 | 评估是否接单 |
| 确认接单 | 点击「确认接单」 | 接单后需按时完成 |
| 拒单操作 | 点击「拒绝」并选择原因 | 频繁拒单影响派单优先级 |

##### 2.3.2 接单时限 `[需内部资料确认：具体秒数]`

| 操作 | 时限要求 |
|------|----------|
| 接单响应 | 通常15-30秒 |
| 到店时限 | 接单后需在规定时间内到店 |
| 送达时限 | 按订单要求时间送达 |

### 3. 配送流程

#### 3.1 到店取餐

##### 3.1.1 到店操作

| 步骤 | 操作内容 | 注意事项 |
|------|----------|----------|
| 1 | 到达商家后点击「我已到店」 | 确保在商家规定范围内 |
| 2 | 核对订单信息 | 订单号、商品名称、数量 |
| 3 | 检查餐品包装 | 确认包装完好、无破损 |
| 4 | 确认取餐 | 点击「确认取餐」，开始配送 |

##### 3.1.2 取餐核对清单

```
取餐核对项：
├── 订单信息核对
│   ├── 订单号一致
│   ├── 商家名称正确
│   └── 商品数量无误
├── 餐品状态检查
│   ├── 包装完好无破损
│   ├── 封口贴完整
│   └── 冷热分离（如有需要）
└── 特殊物品确认
    ├── 餐具是否配备
    ├── 发票是否随餐
    └── 备注要求是否满足
```

#### 3.2 配送途中

##### 3.2.1 配送规范

| 环节 | 标准要求 |
|------|----------|
| 路线规划 | 使用平台导航或自主选择最优路线 |
| 交通安全 | 遵守交通规则，不闯红灯、不逆行 |
| 餐品保护 | 平稳骑行，避免餐品撒漏 |
| 保温措施 | 餐品放入保温箱，保持温度 |

##### 3.2.2 配送中状态更新

| 状态 | 说明 |
|------|------|
| 已取餐 | 取餐后系统显示「骑手已取餐」 |
| 配送中 | 实时显示骑手位置 |
| 即将到达 | 距离用户一定距离时触发 `[需内部资料确认：具体距离]` |

#### 3.3 送达确认

##### 3.3.1 送达操作

| 步骤 | 操作内容 | 注意事项 |
|------|----------|----------|
| 1 | 到达用户地址 | 核对地址准确性 |
| 2 | 联系用户 | 电话或APP内联系 |
| 3 | 交付餐品 | 核对用户身份（手机尾号） |
| 4 | 点击「确认送达」 | 完成订单配送 |

##### 3.3.2 交付方式

| 方式 | 场景 | 操作要求 |
|------|------|----------|
| 当面交付 | 用户在场 | 核对信息后交付 |
| 放置指定位置 | 用户要求 | 拍照留证，通过APP告知用户 |
| 代收点交付 | 用户指定 | 确认代收点信息，拍照留证 |

### 4. 异常处理

#### 4.1 商家端异常

##### 4.1.1 商家出餐慢

| 场景 | 处理流程 |
|------|----------|
| 商家未出餐 | 到店后等待，超时可上报异常 |
| 上报异常 | 点击「商家出餐慢」→ 等待系统处理 |
| 用户通知 | 系统或骑手联系用户说明情况 |
| 等待或取消 | 根据系统提示选择继续等待或取消 |

##### 4.1.2 餐品问题

| 问题类型 | 处理方式 |
|----------|----------|
| 餐品缺失 | 与商家核对，要求补全 |
| 包装破损 | 要求商家重新包装 |
| 餐品有误 | 与商家确认，更换正确餐品 |

#### 4.2 用户端异常

##### 4.2.1 联系不上用户

| 步骤 | 操作 |
|------|------|
| 1 | 尝试拨打用户电话（至少2-3次） |
| 2 | 通过APP内消息联系 |
| 3 | 等待5-10分钟 `[需内部资料确认：具体时长]` |
| 4 | 上报异常「联系不上用户」 |
| 5 | 按系统指引处理（等待或报备后离开） |

##### 4.2.2 地址错误/不详

| 场景 | 处理流程 |
|------|----------|
| 地址有误 | 联系用户确认正确地址 |
| 地址不详 | 联系用户补充详细地址 |
| 超配送范围 | 上报异常，协商处理方案 |

##### 4.2.3 用户拒收

| 场景 | 处理流程 |
|------|----------|
| 了解原因 | 询问用户拒收原因 |
| 上报异常 | 点击「用户拒收」上报 |
| 按指引处理 | 联系客服或按系统提示操作 |
| 餐品处理 | 根据平台规则处理餐品 |

#### 4.3 配送异常

| 异常类型 | 处理方式 |
|----------|----------|
| 餐品撒漏 | 拍照留证 → 联系用户说明 → 上报平台 |
| 交通事故 | 确保安全 → 报警处理 → 联系平台报备 |
| 车辆故障 | 上报异常 → 联系客服 → 协商转单或处理 |
| 天气原因 | 注意安全 → 合理延时 → 与用户沟通 |

## Rule层（系统约束）

### 平台规则约束

| 规则类别 | 约束内容 | 违规后果 |
|----------|----------|----------|
| 准入规则 | 必须完成实名认证、培训考试通过方可接单 | 无法接单 |
| 装备规则 | 必须配备配送箱、头盔等基本装备 | 警告/限制接单 |
| 接单规则 | 接单后需按时完成，不得随意取消 | 扣款/降低派单优先级 |
| 时效规则 | 需在规定时间内到店、送达 | 超时扣款/扣分 |
| 服务规则 | 服务态度良好，不得与用户冲突 | 投诉成立扣款/封号 |
| 安全规则 | 遵守交通规则，不得危险驾驶 | 警告/封号处理 |
| 诚信规则 | 不得虚假配送、刷单等 | 封号/追究法律责任 |

## Evaluation（评估维度）

### 骑手侧评估指标

| 指标 | 计算方式 | 目标值 `[需内部资料确认]` |
|------|----------|---------------------------|
| 准时送达率 | 准时送达订单数 / 总完成订单数 | ≥ 95% |
| 订单完成率 | 完成订单数 / 接单总数 | ≥ 98% |
| 用户好评率 | 好评订单数 / 评价订单总数 | ≥ 90% |
| 投诉率 | 被投诉订单数 / 完成订单总数 | ≤ 1% |
| 平均配送时长 | 总配送时长 / 完成订单数 | ≤ 30分钟 |
| 日活跃骑手数 | 每日上线接单骑手数量 | 按城市目标 |
| 骑手留存率 | 持续接单骑手占比 | ≥ 70% |

### 平台侧评估指标

| 指标 | 说明 |
|------|------|
| 运力满足率 | 订单需求与骑手供给的匹配程度 |
| 平均派单距离 | 骑手到商家的平均距离 |
| 骑手人均收入 | 骑手平均日/月收入 |
| 安全事故率 | 配送过程中安全事故发生比例 |
| 申诉处理时效 | 骑手申诉的平均处理时间 |
| 申诉通过率 | 申诉成立并撤销处罚的比例 |
