# 美团外卖配送 SOP 详细版（v2_detailed）

> **文档版本**: v2.0 详细版  
> **适用场景**: 外卖配送全流程客服/运营处理  
> **更新日期**: 2026年8月

---

## Objective

1. **用户体验目标**: 确保用户从下单到收餐的全流程顺畅，订单准时送达率 ≥ 95%
2. **商家运营目标**: 帮助商家高效处理订单，出餐时间控制在承诺范围内
3. **骑手服务目标**: 合理派单，保障骑手配送效率与安全
4. **平台质量目标**: 降低客诉率，提升用户复购率和平台口碑

---

## Standard Operating Procedures

### 一、下单流程

#### 1.1 用户端操作流程

```
┌─────────────────────────────────────────────────────────────────┐
│                     用户下单操作流程                              │
├─────────────────────────────────────────────────────────────────┤
│                                                                 │
│  ┌──────────┐    ┌──────────┐    ┌──────────┐    ┌──────────┐  │
│  │ 1.选商品 │ -> │ 2.填地址 │ -> │ 3.选支付 │ -> │ 4.等接单 │  │
│  └──────────┘    └──────────┘    └──────────┘    └──────────┘  │
│                                                                 │
│  KCP: 地址准确性校验、配送范围校验、支付方式可用性校验           │
│                                                                 │
└─────────────────────────────────────────────────────────────────┘
```

| 步骤 | 操作内容 | 注意事项 | Rule层约束 |
|------|----------|----------|------------|
| 1 | 打开美团APP/小程序，进入外卖频道 | 自动定位或手动选择配送地址 | 定位失败时需手动选择 |
| 2 | 浏览商家列表，选择目标商家 | 可筛选：距离、评分、销量、配送费等 | 超出配送范围商家不展示 |
| 3 | 选择商品，加入购物车 | 注意商品规格、口味选择 | 售罄商品标记不可选 |
| 4 | 确认订单信息 | 核对地址、电话、配送时间 | **KCP**: 地址精确到门牌号 |
| 5 | 选择支付方式，完成支付 | 支持微信、支付宝、银行卡等 | 支付超时15分钟自动取消 |
| 6 | 等待商家接单 | 超时未接单自动取消退款 | 接单时限：商家设置（通常5-15分钟） |

### 二、商家接单流程

#### 2.1 接单操作

| 场景 | 操作流程 | 结果 | 话术示例 |
|------|----------|------|----------|
| 正常接单 | 商家APP收到推送 → 点击「接单」 → 开始备餐 | 订单状态变为「商家已接单」 | 「您有新的美团外卖订单，请及时处理」 |
| 自动接单 | 系统自动确认，商家直接备餐 | 无需手动操作 | 「已开启自动接单，订单直接进入备餐流程」 |
| 拒单 | 商家点击「拒单」 → 选择原因 → 提交 | 订单取消，款项原路退回 | 「商家因【商品售罄】取消订单，款项已退回」 |

```
    │

└─────────────────────────────────────────┘
    │
    ▼

    │
    ▼

    │
    ▼

```

#### 2.4 商家异常处理

| 异常情况 | 处理流程 | Rule层约束 | 话术 |
|----------|----------|------------|------|
| 商品售罄 | 及时标记售罄，联系用户协商换货或退款 | 售罄商品15分钟内必须标记 | 「您订单中的【商品名】已售罄，可更换为【替代商品】或申请退款」 |
| 备餐延迟 | 提前联系用户说明情况，申请延长配送时间 | 延迟超过15分钟必须通知用户 | 「商家因【原因】备餐稍有延迟，预计延迟XX分钟，您可选择等待或取消订单」 |
| 订单错误 | 发现配错餐，立即联系骑手追回或重新制作 | 出餐后30分钟内可拦截 | 「非常抱歉配餐有误，正在为您重新制作，预计XX分钟送达」 |

### 三、骑手配送流程

#### 3.1 派单逻辑

```
┌─────────────────────────────────────────────────────────────────┐
│                    智能派单系统算法逻辑                          │
├─────────────────────────────────────────────────────────────────┤
│                                                                 │
│  派单权重因子（按优先级排序）：                                   │
│                                                                 │
│  1. 骑手位置: 距离商家的直线/实际距离                            │
│  2. 骑手负载: 当前已接订单数量（通常≤5单）                       │
│  3. 配送方向: 订单目的地与骑手当前路线的匹配度                   │
│  4. 预计时间: 基于历史数据的配送时长预测                         │
│  5. 骑手评级: 服务评分、准时率等                                 │
│  6. 天气路况: 实时天气、交通拥堵情况                             │
│                                                                 │
│  Rule: 恶劣天气自动延长预计送达时间，增加骑手补贴                │
│                                                                 │
└─────────────────────────────────────────────────────────────────┘
```

#### 3.2 配送流程

| 阶段 | 骑手操作 | 用户端显示 | KCP标记 |
|------|----------|------------|---------|
| 派单 | 系统派单 → 骑手抢单/系统指派 | 「骑手正在赶往商家」 | 派单响应时间≤30秒 |
| 到店 | 到达商家 → 点击「我已到店」 → 取餐核对 | 「骑手已到店」 | 到店时间记录 |
| 取餐 | 核对订单号、餐品数量 → 点击「确认取餐」 | 「骑手已取餐，正赶往目的地」 | 取餐时间戳 |
| 配送中 | 按导航路线配送 | 实时显示骑手位置、预计送达时间 | GPS轨迹记录 |
| 送达 | 到达地址 → 联系用户 → 点击「确认送达」 | 「订单已完成」 | 送达时间确认 |

### 四、准时宝服务

#### 4.1 服务说明

准时宝是美团外卖提供的配送时效保障服务，用户下单时可选择购买。

#### 4.2 赔付规则

| 延时情况 | 赔付标准 | Rule层约束 |
|----------|----------|------------|
| 超时 10-20 分钟 | 赔付订单金额 × 10% | 系统自动识别，无需申请 |
| 超时 20-30 分钟 | 赔付订单金额 × 30% | 赔付上限20元 |
| 超时 30 分钟以上 | 赔付订单金额 × 50% 或全额 | 赔付上限50元 |

#### 4.3 赔付流程

```
订单超时送达
    │
    ▼
┌─────────────────────────────────────────┐
│ Rule: 配送时效拦截                      │
│ - 系统实时计算预计送达时间              │
│ - 超时自动标记                          │
└─────────────────────────────────────────┘
    │
    ▼
系统自动识别超时（或用户申诉）
    │
    ▼
核实配送时间记录（骑手取餐时间 - 送达时间）
    │
    ▼
┌─────────────────────────────────────────┐
│ Rule: 免责情形排除                      │
│ - 用户要求延迟配送：排除                │
│ - 不可抗力（恶劣天气、交通管制）：排除  │
│ - 用户地址/电话错误导致延误：排除       │
│ - 商家出餐严重延迟（>30分钟）：排除     │
└─────────────────────────────────────────┘
    │
    ▼
符合赔付条件 → 自动发放赔付金（红包/现金）
    │
    ▼
用户收到赔付通知
```

#### 4.4 准时宝多方对话示例

```
【场景：用户咨询准时宝赔付】

用户: "我的外卖超时了，买了准时宝怎么赔付？"
客服: "为您查看订单...订单超时28分钟，符合准时宝赔付条件"
      "根据规则，超时20-30分钟赔付订单金额的30%，即6元"
      "赔付红包已发放至您的账户，可在『我的-红包』中查看"
用户: "不是说超时30分钟以上全额赔付吗？"
客服: "您的订单超时28分钟，属于20-30分钟档"
      "如超时达到30分钟，将按50%或全额赔付"
      "当前赔付金额6元已发放，如后续继续超时，将按更高档位补差"
```

### 五、餐损处理

### 六、退款售后

#### 6.1 退款类型

| 退款场景 | 退款原因 | 处理时效 | Rule层约束 |
|----------|----------|----------|------------|
| 商家未接单 | 超时未接单自动取消 | 即时原路退回 | 接单超时自动触发 |
| 用户取消 | 下单后改变主意 | 商家接单前可全额退 | 商家接单后需协商 |
| 商家取消 | 商家原因无法出餐 | 全额退款 + 补偿 | 商家取消需说明原因 |
| 缺货退款 | 商品售罄 | 部分或全额退款 | 15分钟内通知用户 |
| 质量问题 | 餐品变质、异物等 | 全额退款 + 赔偿协商 | 需照片凭证 |

#### 6.2 退款流程

```
用户申请退款
    │
    ▼
选择退款原因 → 上传凭证（如有）
    │
    ▼
┌─────────────────────────────────────────┐
│ Rule: 退款时效拦截                      │
│                                         │
│ 商家接单前：自动退款                    │
│ 商家已接单：需商家/平台审核             │

└─────────────────────────────────────────┘
    │
    ▼
审核通过 → 退款原路返回（1-7个工作日）
    │
    ▼
用户收到退款
```

#### 7.1 送错餐处理

```
发现送错餐
    │
    ▼
保留餐品原状 → 拍照 → 联系骑手/客服
    │
    ▼
┌─────────────────────────────────────────┐
│ Rule: 异常订单拦截                      │

│ - 必须保留餐品原状                      │
│ - 提供照片凭证                          │
└─────────────────────────────────────────┘
    │
    ▼
┌─────────────────────────────────────────┐
│  方案A：骑手取回错送餐，送达正确餐品    │
│  方案B：用户自行处理错送餐，平台退款    │
│  方案C：协商补差价换购                  │
└─────────────────────────────────────────┘
```

#### 7.2 撒漏/破损处理

| 严重程度 | 处理方式 | 话术 |
|----------|----------|------|
| 轻微撒漏（可食用） | 协商小额补偿红包 | 「餐品轻微撒漏但不影响食用，为您申请3元补偿红包」 |
| 严重撒漏（无法食用） | 全额退款或重新配送 | 「餐品严重撒漏无法食用，为您全额退款或重新配送」 |
| 包装破损但餐品完好 | 视情况补偿 | 「包装有破损但餐品完好，为您申请2元补偿红包」 |

#### 7.3 少送/漏送处理

```
1. 核对订单与实物
2. 拍照记录
3. 联系商家/骑手确认
4. 处理方案：
   - 补送漏送商品
   - 漏送商品退款
   - 整单退款（严重情况）
```

## Rule 层约束汇总

| 规则类别 | 规则名称 | 规则内容 | 触发时机 |
|----------|----------|----------|----------|
| 配送时效 | 配送范围拦截 | 超出商家配送范围的地址无法下单 | 下单时 |
| 配送时效 | 地址有效性拦截 | 模糊地址需用户确认 | 下单时 |
| 配送时效 | 接单时限拦截 | 商家超时未接单自动取消 | 商家接单阶段 |
| 配送时效 | 出餐时限拦截 | 商家出餐超时触发预警 | 备餐阶段 |
| 异常订单 | 售后时效拦截 | 24小时内可申请售后 | 售后申请 |
| 异常订单 | 凭证要求拦截 | 必须提供照片凭证 | 售后申请 |
| 准时宝 | 免责情形排除 | 排除不可抗力等免责情况 | 赔付判定 |
| 退款 | 退款时效拦截 | 不同阶段不同退款规则 | 退款申请 |
