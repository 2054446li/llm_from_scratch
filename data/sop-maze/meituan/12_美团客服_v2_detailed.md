## Objective

本文档旨在规范美团客服服务体系的标准操作流程，确保用户问题能够得到及时、专业、有效的解决，同时建立完善的投诉处理和纠纷仲裁机制。适用于所有美团客服相关服务场景。

**核心目标：**
- 提供多渠道、便捷的客户服务入口
- 快速准确识别和分类用户问题
- 智能与人工服务高效协同
- 建立公平的投诉处理和纠纷仲裁机制
- 持续优化服务质量，提升用户满意度

## Standard Operating Procedures

### 1. 问题分类

#### 1.1 一级分类
##### 1.1.1 分类说明
| 分类代码 | 分类名称 | 占比估算 | 处理时效 |
|---------|---------|---------|---------|
| A | 订单问题 | 35% | 即时-24h |
| B | 退款售后 | 25% | 即时-72h |
| C | 账户安全 | 10% | 即时-48h |
| D | 活动规则 | 12% | 即时 |
| E | 商家纠纷 | 13% | 24h-7d |
| F | 平台功能 | 5% | 即时-48h |

##### 1.1.2 分类路由规则
```
用户输入 → 意图识别 → 一级分类 → 二级分类 → 技能组匹配 → 客服分配
```

#### 1.2 二级分类（订单问题示例）
| 二级分类 | 具体问题 | 处理优先级 |
|---------|---------|-----------|
| A1-配送问题 | 超时未送达、配送地址错误 | P0-紧急 |
| A2-商品问题 | 商品缺失、错发、质量问题 | P0-紧急 |
| A3-订单修改 | 地址修改、商品增减、取消订单 | P1-高 |
| A4-骑手问题 | 态度问题、配送损坏 | P1-高 |
| A5-发票问题 | 发票开具、发票内容修改 | P2-中 |

#### 1.3 问题分级标准
| 优先级 | 定义 | 响应时效 | 处理时效 | 升级条件 |
|-------|------|---------|---------|---------|
| P0-紧急 | 影响用户安全/重大财产损失 | 5分钟 | 2小时 | 自动升级 |
| P1-高 | 影响用户核心体验 | 15分钟 | 24小时 | 超时升级 |
| P2-中 | 一般性问题 | 30分钟 | 48小时 | 投诉升级 |
| P3-低 | 咨询建议类 | 2小时 | 72小时 | 不自动升级 |

### 2. 智能客服

#### 2.1 智能客服能力
| 能力类型 | 功能说明 | 覆盖场景 |
|---------|---------|---------|
| 意图识别 | 理解用户问题类型 | 全场景 |
| 知识问答 | 基于知识库回答问题 | 规则咨询 |
| 订单查询 | 关联用户订单信息 | 订单相关 |
| 自助办理 | 引导用户自助操作 | 标准流程 |
| 智能推荐 | 推荐解决方案 | 问题处理 |

#### 2.2 智能客服流程
```
用户输入 ──▶ 意图识别 ──▶ 知识匹配 ──▶ 方案输出
                │              │
                ▼              ▼
           置信度低        无匹配知识
                │              │
                └──────┬───────┘
                       ▼
                  转人工客服
```

#### 2.3 智能客服转人工条件
| 转人工场景 | 触发条件 |
|-----------|---------|
| 意图不明 | 连续3次无法识别用户意图 |
| 知识缺失 | 问题不在知识库范围内 |
| 用户要求 | 用户明确要求人工服务 |
| 情绪识别 | 检测到用户负面情绪 |
| 复杂问题 | 涉及多系统/多部门协调 |
| 投诉升级 | 用户对智能客服处理不满 |

#### 2.4 自助服务功能
| 功能模块 | 自助内容 | 适用场景 |
|---------|---------|---------|
| 订单管理 | 取消订单、修改地址、催单 | 订单处理中 |
| 退款申请 | 发起退款、查看进度 | 售后场景 |
| 发票管理 | 申请发票、重开发票 | 发票相关 |
| 账户管理 | 修改信息、安全设置 | 账户相关 |
| 红包查询 | 查看红包、使用规则 | 优惠相关 |

### 3. 人工接入

#### 3.1 人工客服渠道
| 渠道 | 服务时间 | 平均等待 | 适用场景 |
|-----|---------|---------|---------|
| 在线客服 | 7×24小时 | 2-5分钟 | 一般问题 |
| 电话客服 | 7×24小时 | 3-8分钟 | 紧急/复杂问题 |
| 视频客服 | 9:00-21:00 | 预约制 | 需要可视化场景 |
| 专属客服 | 工作日 | 即时 | 高价值用户 |

#### 3.2 人工接入流程
```
用户请求 ──▶ 排队等待 ──▶ 客服分配 ──▶ 问题沟通 ──▶ 方案处理 ──▶ 服务结束
                │            │            │            │
                ▼            ▼            ▼            ▼
            队列状态      技能匹配      知识推荐      满意度评价
            预计等待      历史关联      权限判断      工单归档
```

#### 3.3 客服分配策略
| 分配维度 | 策略说明 |
|---------|---------|
| 技能匹配 | 根据问题类型分配对应技能组 |
| 负载均衡 | 优先分配给当前负载低的客服 |
| 历史关联 | 优先分配给服务过该用户的客服 |
| 语言匹配 | 匹配用户使用的语言/方言 |
| 优先级 | VIP用户优先接入 |

#### 3.4 客服处理规范
| 环节 | 规范要求 |
|-----|---------|
| 开场白 | 问候语+工号+询问需求 |
| 问题确认 | 复述问题+确认理解 |
| 方案提供 | 清晰说明+操作指引 |
| 处理执行 | 即时处理/建单跟进 |
| 结束语 | 确认解决+满意度引导 |

### 4. 投诉处理

#### 4.1 投诉类型
| 投诉类型 | 定义 | 处理部门 |
|---------|------|---------|
| 服务投诉 | 对客服服务不满 | 客服质检 |
| 商家投诉 | 对商家服务/商品不满 | 商家管理 |
| 配送投诉 | 对配送服务不满 | 配送管理 |
| 平台投诉 | 对平台规则/功能不满 | 产品运营 |
| 费用投诉 | 对收费有异议 | 财务/客服 |

#### 4.2 投诉处理流程
```
投诉受理 ──▶ 分级定责 ──▶ 调查核实 ──▶ 方案制定 ──▶ 沟通确认 ──▶ 执行闭环
    │          │          │          │          │
    ▼          ▼          ▼          ▼          ▼
  24h内     责任判定    证据收集    补偿方案    用户确认
  响应      系统标记    多方核实    审批流程    结果反馈
```

#### 4.3 投诉分级处理
| 投诉级别 | 判定标准 | 处理时效 | 审批层级 |
|---------|---------|---------|---------|
| 一般投诉 | 普通用户首次投诉 | 48小时 | 客服主管 |
| 重要投诉 | VIP用户/多次投诉 | 24小时 | 部门经理 |
| 重大投诉 | 媒体关注/监管部门转办 | 12小时 | 高管 |
| 危机投诉 | 群体性/安全事件 | 即时 | 危机小组 |

#### 4.4 投诉补偿标准
| 投诉类型 | 轻微 | 一般 | 严重 |
|---------|------|------|------|
| 配送延迟 | 红包¥5 | 红包¥10 | 红包¥20+免单 |
| 商品问题 | 退款+红包¥5 | 退款+红包¥10 | 退款+红包¥30 |
| 服务态度 | 红包¥5 | 红包¥10 | 红包¥20+道歉 |
| 平台故障 | 红包¥5 | 红包¥10 | 根据损失协商 |

### 5. 纠纷仲裁

#### 5.1 纠纷类型
| 纠纷类型 | 涉及方 | 常见场景 |
|---------|--------|---------|
| 用户-商家 | 买卖双方 | 商品质量、服务不符 |
| 用户-骑手 | 配送双方 | 配送损坏、态度问题 |
| 用户-平台 | 服务双方 | 规则理解、费用争议 |
| 商家-平台 | 合作双方 | 费用结算、规则处罚 |

#### 5.2 仲裁流程
```
纠纷申请 ──▶ 材料收集 ──▶ 双方举证 ──▶ 仲裁判定 ──▶ 结果执行 ──▶ 申诉渠道
    │          │          │          │          │
    ▼          ▼          ▼          ▼          ▼
  7天内      订单信息    用户凭证    规则依据    自动执行
  提出申请   沟通记录    商家凭证    公平原则    或人工确认
```

#### 5.3 举证责任
| 纠纷场景 | 用户举证 | 商家/骑手举证 | 平台责任 |
|---------|---------|--------------|---------|
| 商品质量问题 | 商品照片/视频 | 出货凭证 | 协调判定 |
| 未收到货 | 订单信息 | 配送凭证 | 核实配送 |
| 服务态度 | 描述/录音 | 服务记录 | 综合判定 |
| 费用争议 | 支付记录 | 计费依据 | 核对系统 |

#### 5.4 仲裁原则
| 原则 | 说明 |
|-----|------|
| 公平公正 | 基于事实和规则，不偏袒任何一方 |
| 举证责任 | 谁主张谁举证，无法举证承担不利后果 |
| 保护弱势 | 在证据对等时，适当保护消费者 |
| 效率优先 | 复杂纠纷先解决主要争议 |
| 终局性 | 仲裁结果具有约束力，特殊情形可申诉 |

#### 5.5 仲裁结果
| 结果类型 | 适用场景 | 执行方式 |
|---------|---------|---------|
| 支持用户 | 用户举证充分 | 退款/补偿/处罚商家 |
| 支持商家 | 商家举证充分 | 维持交易/驳回用户 |
| 双方有责 | 各有过错 | 按比例承担责任 |
| 无法判定 | 证据不足 | 平台兜底/协商解决 |

## Rule 层（拦截与约束）

### Rule 1: 恶意投诉拦截
| 拦截条件 | 拦截动作 | 提示话术 |
|---------|---------|---------|
| 同一问题24小时内投诉>3次 | 合并处理 | "您的问题已在处理中，请勿重复提交" |
| 虚假证据/恶意索赔 | 标记警告 | "检测到异常投诉行为，请如实描述问题" |
| 辱骂/威胁客服 | 限制服务 | "检测到不当言论，客服服务将受限" |
| 职业投诉人识别 | 特殊处理 | "您的问题将转交专人处理" |

### Rule 2: 重复投诉合并
| 拦截条件 | 拦截动作 | 提示话术 |
|---------|---------|---------|
| 同一订单重复投诉 | 合并工单 | "该订单已有投诉在处理中，我们将合并处理" |
| 相似问题7天内重复 | 关联历史 | "检测到历史相似问题，为您关联处理" |
| 已解决再次投诉 | 核实原因 | "该问题已标记解决，请说明再次反馈的原因" |

### Rule 3: 敏感词拦截
| 拦截条件 | 拦截动作 | 提示话术 |
|---------|---------|---------|
| 涉及政治敏感词 | 屏蔽并警告 | "发言包含不当内容，请文明沟通" |
| 涉及个人隐私 | 脱敏处理 | "为保护隐私，相关信息已脱敏" |
| 涉及违法犯罪 | 转交风控 | "检测到敏感信息，将转交相关部门" |

### Rule 4: 升级规则拦截
| 拦截条件 | 拦截动作 | 提示话术 |
|---------|---------|---------|
| P0问题未在5分钟响应 | 自动升级 | "问题已升级至高级客服处理" |
| 用户要求升级 | 评估后升级 | "您的问题已提交主管审核" |
| 客服权限不足 | 主动升级 | "该问题需要更高级别权限，为您升级" |

## 标准话术库

### 场景1：智能客服入口
**系统**："您好！我是美团智能助手。请选择您要咨询的问题类型：1.订单问题 2.账户问题 3.活动问题 4.商家问题 5.直接转人工客服"

### 场景2：转人工服务
**系统**："此类问题需要人工客服为您处理。当前排队人数：3人，预计等待：2分钟。您可以先描述问题，客服接入后立即处理。"

### 场景3：问题确认
**客服**："您好，工号9527为您服务。了解到您的问题是【外卖配送超时】，订单号【XXXXXX】，对吗？"

### 场景4：方案提供
**客服**："为您查询到订单当前状态：配送中，骑手距离您500米，预计10分钟送达。因已超时15分钟，已为您申请¥5补偿红包。"

### 场景5：投诉受理
**客服**："非常抱歉给您带来不好的体验。已记录您的投诉，将在24小时内核实处理。处理结果将短信通知您。为您申请¥10红包补偿，是否接受？"

### 场景6：纠纷仲裁
**客服**："了解到您与商家存在退款纠纷。您可以申请平台仲裁，需要提供：1.退货商品照片 2.快递单号 3.沟通记录。仲裁将在3个工作日内完成。"
