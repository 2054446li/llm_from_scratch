## 3. Objective（业务目标）

### 3.1 核心目标

| 目标维度 | 具体指标 | 目标值 |
|----------|----------|--------|
| 时效达标 | 次日达达成率 | >= 95% |
| 时效达标 | 当日达达成率 | >= 98% |
| 用户体验 | 平均配送时长 | 同城 <= 24小时 |
| 服务质量 | 用户满意度 | >= 4.8/5.0 |
| 异常处理 | 异常订单闭环率 | >= 98% |
| 成本控制 | 单均配送成本 | 持续优化 |
| 覆盖范围 | 配送覆盖区县 | >= 99% |

### 3.2 业务价值

1. **时效保障**：通过智能路由规划和运力调度，确保时效承诺兑现
2. **服务体验**：提供上门揽收、预约配送、代收货款等增值服务
3. **成本控制**：优化仓储布局和运输路线，降低物流成本
4. **异常响应**：建立完善的异常处理机制，保障客户权益

## 4. Standard Operating Procedures（标准操作流程）

### 4.1 揽收流程

#### 4.1.1 寄件下单
- **触发条件**：用户提交寄件请求
- **操作步骤**：
  1. 用户填写寄件信息（收发地址、物品信息）
  2. 系统解析地址并计算运费
  3. 用户选择服务类型（标准快递/特快/冷链等）
  4. 系统分配就近揽收网点/快递员
  5. 生成运单号并推送揽收任务

#### 4.1.2 上门揽收
- **操作步骤**：
  1. 快递员接收揽收任务
  2. 联系用户确认上门时间
  3. 上门验视物品（实名认证、违禁品检查）
  4. 称重计费、包装贴单
  5. 系统更新运单状态为"已揽收"

#### 4.1.3 网点自寄
- **操作步骤**：
  1. 用户携带物品至就近网点
  2. 网点工作人员验视物品
  3. 填写运单信息、称重计费
  4. 打印面单、包装交接
  5. 系统更新运单状态

### 4.2 运输流程

#### 4.2.1 入库分拣
- **操作步骤**：
  1. 揽收包裹送至分拣中心
  2. 扫描入库、称重复核
  3. 智能分拣系统按目的地分拣
  4. 装车发运至下一节点

#### 4.2.2 干线运输
- **运输方式**：
  - 航空运输：长距离、时效要求高
  - 陆运：中短距离、大宗货物
  - 铁路运输：特定线路、大宗货物
- **监控要点**：
  - 车辆GPS实时追踪
  - 运输时效监控
  - 异常路况预警

#### 4.2.3 中转分拨
- **操作步骤**：
  1. 到达中转场扫描卸车
  2. 二次分拣至末端网点
  3. 装车配送至目的地

### 4.3 配送流程

#### 4.3.1 末端入库
- **操作步骤**：
  1. 包裹到达末端配送站
  2. 扫描入库、分拣至快递员
  3. 系统推送配送任务

#### 4.3.2 配送排班
- **派单策略**：
  1. 按区域划分配送范围
  2. 智能路径规划
  3. 考虑客户预约时间
  4. 优先级排序（时效承诺）

#### 4.3.3 末端配送
- **操作步骤**：
  1. 快递员装车出发
  2. 按路线依次配送
  3. 联系客户确认收货
  4. 完成签收、上传回单

### 4.4 异常处理流程

#### 4.4.1 异常分类

| 异常类型 | 典型场景 | 处理时效 |
|----------|----------|----------|
| 揽收异常 | 客户不在家、地址错误 | 2小时内 |
| 运输异常 | 包裹破损、丢失 | 4小时内 |
| 配送异常 | 客户拒收、联系不上 | 2小时内 |
| 签收异常 | 代收纠纷、包裹损坏 | 24小时内 |
| 系统异常 | 轨迹缺失、状态错误 | 1小时内 |

#### 4.4.2 异常处理流程

```
异常发现 → 异常定级 → 分配处理人 → 处理执行 → 结果确认 → 闭环归档
    │          │           │           │          │
    ▼          ▼           ▼           ▼          ▼
 系统自动    P0/P1/P2    快递员/客服  转派/退回   客户确认
 人工上报    分级响应    运营人员     理赔等      满意度
```

#### 4.4.3 常见异常处理方案

- **客户不在家**：
  1. 电话联系确认再次配送时间
  2. 放置指定位置（客户授权）
  3. 转交驿站/快递柜
  4. 带回网点次日再配

- **包裹破损**：
  1. 拍照取证
  2. 联系客户协商处理
  3. 启动理赔流程（如需）
  4. 记录责任方

- **客户拒收**：
  1. 确认拒收原因
  2. 按退回流程处理
  3. 通知发件人
  4. 更新系统状态

### 4.5 客户签收流程

#### 4.5.1 签收方式

| 签收方式 | 适用场景 | 操作要求 |
|----------|----------|----------|
| 本人签收 | 普通包裹 | 核验身份、签字确认 |
| 代收签收 | 客户授权代收 | 记录代收人信息 |
| 快递柜签收 | 自提场景 | 投递后系统推送取件码 |
| 驿站签收 | 代收点场景 | 扫描入库、客户自提 |
| 拍照签收 | 特殊场景 | 拍照留证、系统记录 |

#### 4.5.2 签收确认
- **操作步骤**：
  1. 核验收件人身份
  2. 确认包裹完好
  3. 客户签字或电子确认
  4. 上传签收凭证
  5. 系统更新状态为"已签收"

## 5. Rule层（系统约束）

### 5.1 时效承诺规则

| 服务类型 | 时效承诺 | 适用范围 |
|----------|----------|----------|
| 当日达 | 当日24:00前送达 | 同城、指定城市 |
| 次日达 | 次日24:00前送达 | 全国主要城市 |
| 隔日达 | 第三日24:00前送达 | 偏远地区 |
| 定时达 | 客户指定时间段 | 支持区域 |
| 冷链达 | 按温控要求时效 | 生鲜医药 |

### 5.2 配送范围规则

| 区域类型 | 配送范围 | 时效标准 |
|----------|----------|----------|
| 一线城市 | 全境覆盖 | 次日达为主 |
| 二线城市 | 主城区+郊区 | 次日达/隔日达 |
| 三四线城市 | 城区覆盖 | 隔日达为主 |
| 乡镇农村 | 镇级覆盖 | 3-5日达 |
| 偏远地区 | 有限覆盖 | 按实际时效 |

### 5.3 赔偿标准规则

| 异常类型 | 赔偿标准 | 最高赔偿 |
|----------|----------|----------|
| 延误赔偿 | 运费退还+一定比例补偿 | 按服务协议 |
| 丢失赔偿 | 保价金额或实际价值 | 最高保价金额 |
| 破损赔偿 | 按破损程度协商 | 实际损失金额 |
| 错发赔偿 | 重新配送+补偿 | 按服务协议 |

### 5.4 业务规则

| 规则编号 | 规则名称 | 规则描述 | 触发条件 | 处理方式 |
|----------|----------|----------|----------|----------|
| R001 | 揽收时效 | 下单后2小时内联系客户 | 下单后 | 超时预警 |
| R002 | 配送时效 | 按承诺时效完成配送 | 配送中 | 超时预警/补偿 |
| R003 | 签收时效 | 到达网点后24小时内完成配送 | 到达网点 | 超时预警 |
| R004 | 异常上报 | 异常需在30分钟内上报 | 发现异常 | 超时影响考核 |
| R005 | 客户联系 | 配送前需电话联系客户 | 配送前 | 强制要求 |
| R006 | 签收确认 | 必须获取签收凭证 | 签收时 | 系统校验 |
| R007 | 轨迹上报 | 关键节点必须扫描上传 | 流转节点 | 系统校验 |
| R008 | 实名验视 | 揽收必须实名验视 | 揽收时 | 强制要求 |

### 5.5 数据规则

| 规则编号 | 规则名称 | 规则描述 |
|----------|----------|----------|
| D001 | 运单号唯一性 | 运单号全局唯一，不可重复 |
| D002 | 状态流转合法性 | 状态变更必须符合预设流转图 |
| D003 | 时间戳完整性 | 关键节点必须记录时间戳 |
| D004 | 数据保留期限 | 运单数据保留2年，日志保留1年 |
| D005 | 敏感信息加密 | 手机号、地址等敏感信息加密存储 |

## 8. Output Requirement（输出规范）

### 8.1 接口响应规范

#### 成功响应

```json
{
  "code": 0,
  "message": "success",
  "request_id": "REQ202408040001",
  "timestamp": "2024-08-04T10:30:00+08:00",
  "data": {}
}
```

#### 错误响应

```json
{
  "code": 10001,
  "message": "运单不存在",
  "request_id": "REQ202408040001",
  "timestamp": "2024-08-04T10:30:00+08:00",
  "error_detail": {
    "error_type": "business_error",
    "waybill_no": "JD1234567890"
  }
}
```

### 8.2 错误码定义

| 错误码 | 错误描述 | 处理建议 |
|--------|----------|----------|
| 0 | 成功 | - |
| 10001 | 运单不存在 | 检查运单号是否正确 |
| 10002 | 运单号格式错误 | 检查运单号格式 |
| 10003 | 状态流转非法 | 检查当前状态和目标状态 |
| 10004 | 运力不足 | 扩大派单半径或等待 |
| 10005 | 重复操作 | 检查是否已执行过该操作 |
| 20001 | 参数错误 | 检查请求参数格式 |
| 20002 | 权限不足 | 检查操作人权限 |
| 30001 | 系统繁忙 | 稍后重试 |
| 30002 | 服务异常 | 联系技术支持 |

### 8.3 数据格式规范

- **时间格式**：ISO 8601格式，带时区（如 `2024-08-04T10:30:00+08:00`）
- **金额格式**：单位为元，保留两位小数（如 `25.00`）
- **坐标格式**：WGS84坐标系，保留6位小数
- **枚举值**：使用英文小写下划线格式（如 `standard_express`）
