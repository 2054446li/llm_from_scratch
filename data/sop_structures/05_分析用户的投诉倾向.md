## SOP: 分析用户的投诉倾向
分析用户的投诉倾向 —— 以第三人称视角解析客服-用户对话，判断用户投诉倾向(预投诉/已投诉/未投诉)、投诉部门及关键句（classification 族）。

### Objective

**角色**：打判专家（第三人称视角的分析者）

**场景**：客观解析客服和用户之间的对话，判断用户投诉倾向是预投诉、已投诉还是未投诉

**目标**：识别客服/用户角色，提取投诉相关关键信息（仅外部对公司投诉），按决策规则输出 result、Complaint Department、Key sentence

**关键约束**：
- 仅提取向**外部**投诉公司的相关部分（非公司内部客服/管理）
- 多意图混杂取最严重(已投诉>预投诉>未投诉)
- 投诉部门必须明确具体(笼统表述不算预投诉)
- 若无可选部门归类或属未投诉 → Department=[其他]

### Standard Operating Procedures

#### Step 1: 对话内容分析
- **Step 1.1**: 识别角色
  - 客服: 使用官方语言、提供帮助(如"您好，我是本次为您服务的客服小美_xxx")
  - 用户: 描述问题、表达不满
- **Step 1.2**: 提取关键信息
  - 逐句找投诉相关关键词(投诉/12315/消费者协会等)
  - 区分是否针对公司的外部投诉；若不是 → 视为未投诉
  - 提取用户表示将要/已经向具体外部部门投诉公司的关键句子
  - 若无 → Key sentence="无"

#### Step 2: 输出结果
- **Step 2.1**: 匹配决策规则
  - 预投诉: 将要向具体外部部门投诉(政府/媒体/平台)
  - 已投诉: 已经向具体外部部门投诉(或表示已向外部投诉)
  - 未投诉: 未提及外部投诉意图，或仅投诉公司/内部
- **Step 2.2**: 多意图混杂取最严重(已投诉>预投诉>未投诉)
- **Step 2.3**: 输出 Complaint Department(21项枚举之一, 多部门用、分隔, 无法归类/未投诉→其他)
- **Step 2.4**: 输出 Key sentence(将要+已经都提取, 多句用、分隔, 无→"无")
- **Step 2.5**: 双重检查准确性与符合对话实际情况

### Output Requirement

**JSON Schema**（Draft-07，顶层 required=[result, Complaint Department, Key sentence]，additionalProperties=False）:

| 字段 | 类型 | 约束 |
|------|------|------|
| result | string | enum [预投诉, 已投诉, 未投诉] |
| Complaint Department | array of string | enum 21项之一, uniqueItems, minItems 0 |
| Key sentence | string | 关键句子(多句用、分隔), 无则"无" |

**Complaint Department 枚举**（21项）:
- 政府: 工商局, 市场监督管理局, 食药监, 运管局, 网信办, 工信部, 税务局, 公安局, 法院
- 媒体: 电视台, 报社, 新闻记者, 朋友圈, 抖音, 快手, 小红书, 微博
- 平台: 12315, 12345市长热线, 黑猫投诉
- 社会组织: 消费者协会
- 其他

**约束条件**：
- 仅外部对公司投诉计入预投诉/已投诉
- 多意图取最严重(已投诉>预投诉>未投诉)
- 投诉部门必须明确具体(笼统不算)
- 无法归类/属未投诉 → Department=["其他"]
- Key sentence 无则"无"；将要+已经都提取，多句用、分隔
- additionalProperties=False
