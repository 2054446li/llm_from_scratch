## 一、GRPO：去掉 Critic 的 RL 算法 ★ 重点记录

### 1.1 动机

PPO 需要一个与策略模型同等规模的 **value（critic）网络**来估计优势 $A_t$，在 LLM 上显存与算力开销巨大，且 value 估计本身难训。GRPO 的核心思想：**用"组内采样的相对好坏"替代 value 网络**。

### 1.2 算法

对每个问题 $q$，用旧策略 $\pi_{\theta_{old}}$ 采样一**组** $G$ 个输出 $\{o_1,\dots,o_G\}$，对每个输出打分得 $\{r_1,\dots,r_G\}$，优势用**组内归一化**得到：

$$A_i = \frac{r_i - \text{mean}(\{r_1,\dots,r_G\})}{\text{std}(\{r_1,\dots,r_G\})}$$

目标函数（带裁剪 + KL 约束）：

$$\mathcal{J}_{GRPO}(\theta) = \mathbb{E}\Big[\frac{1}{G}\sum_{i=1}^{G}\Big(\min\big(\rho_i A_i,\ \text{clip}(\rho_i, 1-\epsilon, 1+\epsilon)A_i\big) - \beta\, D_{KL}(\pi_\theta \| \pi_{ref})\Big)\Big]$$

其中重要性比 $\rho_i = \dfrac{\pi_\theta(o_i|q)}{\pi_{\theta_{old}}(o_i|q)}$。

**与 PPO 对比**

| 维度 | PPO | GRPO |
|------|-----|------|
| 优势估计 | GAE，需 value 网络 | 组内归一化，无需 value 网络 |
| 额外模型 | critic（≈策略同规模） | 无 |
| 显存/算力 | 高 | 显著降低 |
| KL 约束 | 常加在奖励里 | 直接作为正则项加在 loss |
| 适用前提 | 通用 | 每题可多次采样、可批量打分 |

**后训练关联**：GRPO 去掉 critic 让 RL 显存预算几乎全部留给策略模型与 rollout，是把 RL 规模化到 671B 基座的关键工程前提；组采样天然契合"每题多次 rollout + 规则打分"的推理任务。

## 二、R1-Zero：纯 RL 无 SFT 冷启动 ★ 核心结论

### 2.1 设定

直接在 **V3-Base** 上做 RL，**不经过任何 SFT**。模板极简：要求模型先在 `<think>...</think>` 内写推理过程，再在 `<answer>...</answer>` 内给答案，不对推理内容做任何人为约束。

### 2.2 奖励设计（规则化，刻意不用神经 RM）

- **准确率奖励**：数学题答案可用规则校验（如要求放进 `\boxed{}`）、代码题用编译器/测试用例判定；
- **格式奖励**：是否把思考过程正确包进 `<think>` 标签。

**为什么不用神经奖励模型**：作者明确指出大规模 RL 中神经 RM 易被 **reward hacking**，且重训 RM 需额外资源、使 pipeline 复杂化。规则奖励虽"粗"，但**不可被钻空子**，是 R1-Zero 成立的前提。

### 2.3 自我进化与 "aha moment"

随训练步数增加：
- **思考长度持续自发增长**（模型自己学会"想更久"，非人为设定）；
- 自发涌现**反思、验证、回溯**等行为，反思类词（wait / verify / check）频率上升数倍；
- 出现 "aha moment"：模型在推理中途自我纠错、重新评估解法。

**结论**：推理能力可以**纯靠 RL 的结果奖励"激励"出来，而非靠 SFT"教"出来**——这是本文最重要的论点。

### 2.4 R1-Zero 的缺陷

可读性差、**语言混杂**（中英混用）。这直接催生了 R1 的多阶段设计。

## 三、DeepSeek-R1：多阶段 SFT + RL Pipeline ★ 重点记录

### 阶段① 冷启动 SFT

收集**数千条**高质量长 CoT 数据（few-shot 提示 R1-Zero 生成 + 人工后处理整理可读格式）先做一轮 SFT。目的：给后续 RL 一个**可读、稳定的起点**，避免 R1-Zero 早期的不稳定与语言混杂。

### 阶段② 推理导向 RL

在冷启动模型上做 GRPO，奖励 = 规则准确率奖励 + **语言一致性奖励**。

- **语言一致性奖励** = CoT 中目标语言词所占比例。作者坦言它会**轻微损害推理性能**，但显著改善可读性、对齐人类偏好——这是一次**主动的对齐 vs. 性能权衡**。

### 阶段③ 拒绝采样 + SFT

用阶段②收敛的模型做**拒绝采样**生成新 SFT 数据：
- **推理数据约 60 万条**：对每题多次采样，只保留答案正确的轨迹（部分用 V3 做生成式判定），过滤语言混杂/超长/乱码；
- **非推理数据约 20 万条**：写作、事实问答、自我认知、翻译等，复用 V3 的 SFT 数据与 pipeline。

合并约 **80 万条**，**从 V3-Base 重新 SFT 2 个 epoch**（注意：是回到 Base 重训，不是在阶段②模型上继续）。

### 阶段④ 全场景 RL（对齐）

第二轮 RL，覆盖推理 + 通用场景，奖励分两类：
- **推理任务**：继续用**规则奖励**；
- **通用任务**：引入**模型化偏好奖励**——helpful 与 safety 奖励模型（细节见第五节）。

**为什么模型奖励只在最后引入**：把神经 RM 推迟到推理能力已稳固之后，最大限度压缩它被 reward hacking 的窗口；推理阶段始终靠不可钻空子的规则奖励。

## 四、蒸馏 vs. 小模型直接 RL ★ 核心结论

### 4.1 做法

用训练好的 **R1 生成的 80 万条数据**，直接对 Qwen/Llama 系列小模型做 **SFT（不做 RL）**，得到 DeepSeek-R1-Distill 系列。

### 4.2 关键对照实验

作者在 **Qwen-32B-Base** 上做对照：
- **Qwen-32B-Zero**：在该 32B 基座上**直接做 >10K 步大规模 RL**；
- **R1-Distill-Qwen-32B**：仅用 R1 数据做蒸馏 SFT。

结果：**蒸馏版在所有基准上显著优于直接 RL 版**。

### 4.3 两条结论（原文 G.1 / F.2）

1. **把强模型蒸馏进小模型，效果极好**；而小模型若想靠自身大规模 RL 达到同等水平，需要**巨量算力，且可能仍达不到蒸馏的效果**。
2. **蒸馏经济且有效，但要突破智能上界，仍需更强的基座 + 更大规模的 RL**。

**后训练关联**：这给出了一条清晰的产线分工——**用最强基座跑 RL 造"推理数据工厂"，再用蒸馏把能力低成本铺到各尺寸**。这正是 V3 笔记里"R1 蒸馏"那一环的来源。

### 4.4 base checkpoint 的重要性（G.1）

早期在 7B dense 和 16B MoE 小模型上做 RL **始终失败**：响应变长后倾向重复、无法有效利用长 CoT 提升准确率。换到 32B / 230B MoE / 671B MoE 后才出现实质增益。**结论：RL from scratch 的有效性高度依赖基座容量**，验证"纯 RL"主张时必须用足够大、足够表达力的模型。

## 五、奖励模型设计（全场景 RL 阶段）

| 类型 | Helpful RM | Safety RM |
|------|-----------|-----------|
| 训练形式 | pairwise（偏好对） | point-wise（逐条打分） |
| 数据规模 | 约 6.6 万偏好对 | 约 10.6 万提示 |
| 目标 | 提升回答有用性，只评最终摘要不干扰推理 | 识别不安全输出 |

**验证器（verifier）的重要性（G.1）**：规则奖励（RM）与"用 LLM 对照 ground-truth 判对错"是缓解 reward hacking 的两类稳健机制；LLM 判定对**有明确简短答案**的任务很有效，但对开放式生成/长文写作**泛化有限**——这正是这类任务必须保留 SFT、不能纯 RL 的原因。

## 六、失败尝试（G.2）—— 给后训练工程师的负面经验

### 6.1 过程奖励模型（PRM）被放弃

三大问题：① 通用推理中**难以明确定义细粒度步骤**；② 判断中间步骤是否正确很难（自动标注不准、人工标注难规模化）；③ 一旦引入模型化 PRM **必然带来 reward hacking**，且重训 RM 增加资源与 pipeline 复杂度。结论：PRM 在对 top-N 重排或引导搜索时有用，但在大规模 RL 里**收益不抵开销**。

### 6.2 MCTS 被放弃

借鉴 AlphaGo/AlphaZero 用 MCTS 扩展 test-time 计算。失败原因：① token 生成的**搜索空间指数级大**（远比围棋复杂），设节点扩展上限又易陷局部最优；② **细粒度 value 模型极难训练**，而 value 质量直接决定搜索质量，导致难以自我迭代提升。结论：MCTS 配预训练 value 模型能改善推理，但**靠自搜索迭代提升仍是重大挑战**。

**后训练关联**：这两条共同支撑了本文的主线选择——**outcome-based（结果导向）规则奖励 + GRPO**，而非 process-based（过程导向）的 PRM/MCTS 路线。

## 七、关键启示（Key Findings 汇总，G.1）

1. **基座容量是前提**：纯 RL 激发推理要求足够大的基座，小模型 RL from scratch 易失败。
2. **验证器质量决定 R1-Zero 成败**：规则奖励 + LLM 对照判定是抗 reward hacking 的核心。
3. **SFT 与 RL 不可偏废**：RL 负责探索人类标注覆盖不到的长链推理；SFT 负责奖励信号难定义的开放任务（写作、开放问答）。纯 RL 易 reward hacking，纯 SFT 无法探索出新策略。

---

## 八、对后训练工作的可迁移要点

- **奖励能用规则就别用神经网络**：推理类任务优先规则奖励（可校验答案 + 格式），把神经 RM 推迟到对齐末期，压缩 reward hacking 窗口。
- **GRPO 是 LLM RL 的实用默认**：去掉 critic、组内归一化优势，显存预算让给策略与 rollout。
- **多阶段交替 SFT/RL**：冷启动 SFT 稳起点 → 推理 RL → 拒绝采样自蒸馏 SFT → 全场景对齐 RL。
- **能力迁移走蒸馏而非小模型 RL**：用最强模型造数据，SFT 铺到各尺寸，经济且效果更好。
- **对齐要主动权衡**：语言一致性奖励等会轻微牺牲性能换可读性/偏好对齐，需有意识地做取舍。
