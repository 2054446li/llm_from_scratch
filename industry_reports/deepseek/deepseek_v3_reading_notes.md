## 整体 Pipeline

```
预训练基座（14.8T tokens，4K 上下文，FP8 训练）
   │  ① YaRN 两阶段长上下文扩展（4K→32K→128K，各 1000 步）
   ▼
DeepSeek-V3 Base  ★ 最强开源基座
   │  ② SFT（1.5M 实例，2 epoch，lr 5e-6→1e-6，样本掩码隔离）
   │     ├─ 推理数据：内部 R1 + 领域 expert model 生成 → 拒绝采样提纯
   │     └─ 非推理数据：V2.5 生成 + 人工核验
   ▼
DeepSeek-V3 Chat (SFT)
   │  ③ RL（GRPO，规则 RM + 模型 RM，多领域 prompt）
   ▼
DeepSeek-V3  ★  Arena-Hard 85.5 / AlpacaEval 2.0 70.0
```

## 一、负载均衡（Load Balancing）★ 重点记录

### 1.1 为什么需要负载均衡

MoE 模型若专家负载不均衡会导致两个问题：
- **路由崩溃（routing collapse）**：少数专家被反复选中，其余专家几乎不被训练；
- 在专家并行（EP）场景下**降低计算效率**（热门专家所在 GPU 成为瓶颈）。

传统方案靠**辅助损失（auxiliary loss）**强制均衡，但辅助损失过大会**损害模型性能**——这正是 V3 要解决的痛点。

### 1.2 无辅助损失均衡（Auxiliary-Loss-Free）★ V3 核心创新

**核心思想**：为每个专家引入一个**偏置项 $b_i$**，只用于路由选择（top-K），不进入门控加权、不进入梯度。

$$g'_{i,t} = \begin{cases} s_{i,t}, & s_{i,t} + b_i \in \text{Topk}(\{s_{j,t}+b_j \mid 1\le j\le N_r\}, K_r) \\ 0, & \text{otherwise} \end{cases}$$

关键点：
- **偏置 $b_i$ 只影响"选哪些专家"**，最终与 FFN 输出相乘的门控值仍由原始亲和度 $s_{i,t}$ 导出；
- 每步结束动态调整：**专家过载 → $b_i$ 减 $\gamma$；专家欠载 → $b_i$ 加 $\gamma$**（$\gamma$ 为偏置更新速度）；
- V3 设置：$\gamma$ 前 14.3T tokens 取 0.001，最后 500B tokens 取 0.0。

**为什么优于辅助损失**：均衡这个"工程目标"不再混进损失函数 → 语言建模梯度不被污染 → 在保住均衡的同时不牺牲模型质量。消融实验（§4.5.2，表5）证明它在多数基准上一致优于纯辅助损失方法。

### 1.3 互补的序列级均衡损失（兜底）

仍保留一个**极小权重**的序列级辅助损失，仅防单条序列内部极端失衡：

$$\mathcal{L}_{\text{Bal}} = \alpha \sum_{i=1}^{N_r} f_i P_i$$

其中 $f_i$ 是专家 $i$ 在该序列被选中的频率，$P_i$ 是其平均亲和度，$\alpha=0.0001$（极小）。

### 1.4 批级 vs 序列级均衡 ★ 关键认知（§4.5.3）

两者本质都是"统计专家被选频率、惩罚不均"，**唯一区别是统计范围**：

| 方法 | 统计范围 | 实现方式 | 对专家专门化 | 对模型质量 |
|------|----------|----------|--------------|------------|
| 序列级辅助损失 | 单条序列 | 损失项（进梯度） | **抑制**（强制每序列内均衡） | 略受损 |
| 批级辅助损失 | 整个批次 | 损失项（进梯度） | 允许 | 较好 |
| **无辅助损失（V3）** | 整个批次 | 偏置 $b_i$（不进梯度） | 允许 | **最好** |

- **序列级约束太强**：哪怕一条全是数学的序列，也被强迫把 token 摊给非数学专家 → 抑制专门化；
- **批级更灵活**：只要整批平均均衡即可，单序列可不均衡 → 允许专家按领域专门化（图9 证实：Wikipedia/Github/数学 激活的专家明显不同）；
- **无辅助损失属于批级思路的"无梯度污染"实现**。
- 验证损失对比：序列级 2.258 / 无辅助损失 2.253 / 批级辅助损失 2.253（1B MoE），后两者持平且优于序列级。

### 1.5 节点受限路由 + 不丢 token

- **节点受限路由**：每个 token 最多发往 $M=4$ 个节点（按各节点专家亲和度之和的 top-$K_r/M$ 选），降低跨节点通信，逼近完全计算-通信重叠；
- **不丢 token（No Token-Dropping）**：因均衡有效，训练与推理**全程不丢 token**。

> **与后训练的关联**：不丢 token 保证了**训练-推理一致性**——这是 on-policy RL 正确性的前提。若推理丢 token 而训练不丢，策略分布偏移会破坏 RL 的 on-policy 假设。

## 二、MTP 多 token 预测（Multi-Token Prediction）★ V3 亮点

**核心**：把每个位置的预测范围从"下一个 token"扩展到"多个未来 token"。两点好处：① **致密化训练信号**（densify training signals），提升数据效率；② 可能让模型**预先规划表示**，更好预测未来。

与 Gloeckle et al. (2024) 的区别：后者用**独立输出头并行**预测；V3 用 **$D$ 个顺序模块**预测，并在每个深度**保持完整因果链**。

### 2.1 ★ 必须区分：训练阶段 vs 推理阶段

| | 训练阶段 | 推理阶段 |
|---|----------|----------|
| MTP 模块 | **参与**，提供额外监督信号 | **直接丢弃**，主模型独立工作 |
| 作用 | 致密训练信号 → 训出更强主模型 | 主模型正常单 token 解码 |
| 可选复用 | — | 复用 MTP 模块做**推测解码**加速 |

### 2.2 训练阶段机制

第 $k$ 个 MTP 模块：把上一深度表示与未来 token 嵌入拼接、投影、过 Transformer 块、经共享输出头出分布：

$$h_i'^k = M_k\,[\,\text{RMSNorm}(h_i^{k-1})\,;\,\text{RMSNorm}(\text{Emb}(t_{i+k}))\,]$$
$$h_{1:T-k}^k = \text{TRM}_k(h_{1:T-k}'^k), \qquad P_{i+k+1}^k = \text{OutHead}(h_i^k)$$

每深度交叉熵损失，加权进总损失：
$$\mathcal{L}_{\text{MTP}} = \frac{\lambda}{D}\sum_{k=1}^{D}\mathcal{L}_{\text{MTP}}^k$$

- 嵌入层与输出头**与主模型共享**（DualPipe 把最浅层和最深层放同一 PP rank，物理共享省显存）；
- V3 设置：**$D=1$**（只多预测 1 个未来 token）；$\lambda$ 前 10T tokens 取 0.3，其余 4.8T 取 0.1。

### 2.3 消融证据（§4.5.1，表4）

- 两种规模（15.7B / 228.7B）上，MTP 在绝大多数基准一致提升（如大规模 HumanEval 44.5→53.7）；
- **关键**：推理时丢弃 MTP 模块，故两个对比模型**推理成本完全相同** → MTP 提升是"免费的"。

### 2.4 推理评估（§5.4.3）

- V3 通过 MTP 预测接下来 2 个 token；
- 第二个 token 的**接受率 85%~90%**；
- 结合推测解码，解码速度提升 **1.8× TPS**。

> **与后训练关联**：训练侧 MTP 训出更强基座；推理侧复用为推测解码加速 RL rollout 吞吐。

## 三、后训练（Post-Training）★★ 本笔记核心

### 3.1 SFT（§5.1）

数据集 **1.5M 实例**，跨多领域，每领域定制构造方法。

**推理数据（数学/代码/逻辑）—— R1 蒸馏 pipeline ★**

核心流程（"专家模型作数据工厂"）：
```
种子数据(题目 + 可验证奖励)        ← 注意：只有题目+对错信号，没有现成回答
      │  喂 RL（这种形态喂不进 SFT）
      ▼
领域 expert model（SFT+RL 训出，会推理，准确率高但啰嗦）
      │  采样多个回答 + 拒绝采样（用规则/答案验证筛掉错的）
      ▼
高质量 (问题, 正确回答) 配对        ← 这才是 V3 能用的 SFT 数据
      │  提纯（控长度、改格式）
      ▼
SFT 训练 V3
```

- 每个实例生成两类样本：`<problem, original response>` 和 `<system prompt, problem, R1 response>`；
- 系统提示引导产出带反思/验证机制的回答；RL 阶段用高温采样融合 R1 模式；
- R1 数据准确率高但**过度思考、格式差、冗长** → 需要这套提纯流程平衡准确率与简洁性。

**非推理数据**：用 V2.5 生成 + 人工核验。

**SFT 设置**：2 epoch，lr 余弦衰减 5e-6→1e-6，样本打包但用**样本掩码**隔离互不可见。

### 3.2 奖励模型（§5.2.1）★

**规则化 RM（Rule-Based）**：能用规则验证的题（数学放 `\boxed{}`、代码用编译器测试用例）→ **抗操纵、抗 reward hacking**，可靠性最高。

**模型 RM（Model-Based）**：自由形式答案 / 无确定答案时用。从 V3 SFT 检查点训练。
- ★ **偏好数据不仅给最终奖励，还包含通往奖励的 CoT** → 缓解 reward hacking（详见疑问解答 Q2）。

### 3.3 GRPO（§5.2.2）★

**去掉 critic（价值模型）**，用组内奖励均值当 baseline，省一半显存/算力。

对每个问题 $q$ 从旧策略采样一组 $\{o_1,...,o_G\}$，优化：

$$\mathcal{J}_{\text{GRPO}}(\theta) = \mathbb{E}\Big[\tfrac{1}{G}\sum_{i=1}^{G}\big(\min(r_i A_i,\ \text{clip}(r_i, 1-\epsilon, 1+\epsilon)A_i) - \beta\,\mathbb{D}_{KL}(\pi_\theta\|\pi_{ref})\big)\Big]$$

其中概率比 $r_i = \dfrac{\pi_\theta(o_i|q)}{\pi_{\theta_{old}}(o_i|q)}$，优势由组内奖励标准化（z-score）：

$$A_i = \frac{r_i - \text{mean}(\{r_1,...,r_G\})}{\text{std}(\{r_1,...,r_G\})}$$

- 回答好于组内平均 → 正优势 → 提升概率；差于平均 → 压低；
- clip 限制单步幅度，KL 项把策略拉回参考模型防跑偏；
- 对 MoE + 长序列 RL 友好：去 critic 大幅降显存，与 MLA 缩小 KV、不丢 token 一起构成高效 RL 三支柱。

### 3.4 评测亮点（§5.3）

- **Arena-Hard**：对 GPT-4-0314 胜率 >86%，**首个开源破 85%（85.5）**；
- **AlpacaEval 2.0**：70.0，比 V2.5-0905 高 20%；
- **V3 作生成式 RM**（RewardBench）：与 GPT-4o/Claude-3.5 最佳版持平，配合**投票**增强 → 用于 self-feedback。

### 3.5 讨论要点（§5.4）

- **R1 蒸馏权衡（表9）**：蒸馏提升性能但**大幅增加回答长度**（MATH-500 长度 769→1510）→ 需精选设置平衡准确率与效率；
- **Self-Rewarding**：通用领域难构造奖励时，用**宪法 AI + V3 自身投票评估**作反馈源，自我提升；
- **MTP 推理评估**：见 §二.4。

## 四、对后训练工程师的 takeaway

1. **数据形态决定训练方式**：题目+可验证奖励只能喂 RL；要做 SFT 必须先经 expert model + 拒绝采样转成 (问题,回答) 配对。expert model 是数据工厂，不是浪费的中间步。
2. **规则化奖励优先**：可验证就用规则（抗 hacking）；不可验证才用模型 RM，且让 RM 带 CoT 打分提升稳健性。
3. **GRPO 去 critic** 是 MoE 大模型做 RL 的关键省显存手段。
4. **蒸馏有长度税**：长 CoT 蒸馏提升能力但拉长输出，需主动控制。
5. **训练-推理一致性**（不丢 token）是 on-policy RL 正确性前提；MTP/MLA 等系统设计直接影响 RL rollout 吞吐。

## 五、疑问解答

### Q1：MTP 机制（已理解，列为亮点）
见 §二。关键是区分训练（模块参与，致密信号）与推理（丢弃模块，或复用为推测解码 1.8× 加速），$D=1$。

### Q2：带 CoT 的偏好数据为什么缓解 reward hacking？
reward hacking 指模型钻 RM 空子（如靠"长度/符号/自信语气"骗高分）。
- **只给最终奖励**：RM 只学"长得像好回答"的表面特征 → 易被表面模式欺骗；
- **奖励+CoT**：强迫 RM 打分前先生成判断理由（哪步推理错、答案是否真匹配）→ 奖励锚定可解释依据而非表面模式 → 模型靠表面把戏 hack 不动，因为 RM 会实际检查内容。
- 与规则化 RM 同思路：规则化用客观事实抗 hack；模型 RM 无客观事实时用"强制讲理"逼近稳健性。

### Q3：既然有数据训 expert model，为什么不直接训目标模型？
关键：那批数据是**"题目+可验证奖励"形态，只能驱动 RL、喂不进 SFT**（RL 无标准回答文本，只有对错信号）。
- expert 经 RL 后才能稳定产出正确解法 → 采样+拒绝采样才**第一次**得到 (问题,正确回答) 配对 → 这才是 SFT 数据；
- 绕道 expert 的好处：① 隔离 RL 不稳定/hacking 风险（牺牲小模型，V3 只收干净数据）；② 数据可控（筛长度/格式）；③ 分而治之（各领域专精 expert 避免互相干扰）；④ 把"RL 试错探索出的能力"固化成"可模仿示范"，V3 用 SFT 高效继承，不必重走昂贵探索。
- 本质：expert model 是把"奖励形态数据"转换+放大成"示范形态数据"的数据工厂。
