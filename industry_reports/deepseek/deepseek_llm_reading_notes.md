## 模型架构

基于 LLaMA 架构的变体：

| 组件 | 选择 | 说明 |
|------|------|------|
| 整体结构 | Decoder-only Transformer | 自回归语言模型 |
| 归一化 | Pre-Norm + RMSNorm | 归一化在 Attention/FFN 之前 |
| FFN 激活 | SwiGLU | 中间维度 8/3 × d_model（而非标准 4×） |
| 位置编码 | RoPE (Rotary Position Embedding) | 相对位置编码 |
| 注意力 | 7B: MHA; 67B: GQA (8 KV heads) | GQA 降低推理KV缓存 |
| 上下文长度 | 4096 | - |

**架构独特设计：**

| 参数量 | 层数 | d_model | 注意力头 | KV头 |
|--------|------|---------|---------|------|
| 7B | 30 | 4096 | 32 | 32 |
| 67B | 95 | 8192 | 64 | 8 |

- **选择加深（95层）而非加宽FFN**：与同规模模型不同，DeepSeek 在使用 GQA 省下的参数量上选择增加层数而非扩大 FFN 中间维度，追求更好的性能
- 层数设计便于流水线并行分区

## 预训练（简述）

- **数据**：2T tokens，中英双语，三阶段处理（去重→过滤→重混合）
- **分词器**：BBPE，词表 102400
- **优化器**：AdamW（β₁=0.9, β₂=0.95, wd=0.1）
- **学习率**：多步调度器（warmup 2000步 → 80% tokens处降至31.6% → 90%处降至10%）
- **基础设施**：HAI-LLM框架，bf16训练 + fp32梯度累积

## 后训练 / 对齐（重点）

### 数据构成

| 类型 | 数量 | 分布 |
|------|------|------|
| 有用性数据 | 120万条 | 通用语言 31.2% / 数学 46.6% / 代码 22.2% |
| 安全性数据 | 30万条 | 覆盖各种敏感话题 |
| **总计** | **~150万条** | 中英双语 |

### SFT 阶段

| 配置 | 7B | 67B |
|------|-----|------|
| 学习率 | 1e-5 | 5e-6 |
| Epoch | 4 | 2 |
| 过拟合情况 | 轻微 | 严重（因此减少epoch） |

**关键发现：**

1. **重复率（Repetition Ratio）问题**：数学SFT数据增加→重复率上升（从正常到2.0%）
   - **重复率定义**：收集3868条中英文prompt让模型生成回复，统计"无法正常终止、陷入无限重复某段文本"的回复比例（重复回复数/总回复数）
   - 原因：数学数据中推理步骤结构相似（如"设x=...，则..."反复出现），小模型无法理解推理逻辑，只学到表面重复模式，生成时陷入循环
   - 解决方案：两阶段微调 或 DPO，均能保持分数同时降低重复率

2. **两阶段微调策略**（7B模型）：
   - Stage 1：全量数据（含数学/代码），重复率2.0%
   - Stage 2：仅对话数据，重复率降至1.4%，代码/数学分数不降
   - 67B 不需要 Stage 2（一阶段后重复率已<1%）

3. **SFT 的本质认知**：
   - SFT **不学习推理能力**，只学习推理路径的正确格式（CoT格式）
   - SFT 的价值 = 让 0-shot chat 达到 few-shot base 的水平
   - SFT **不改变知识量**，知识任务上的小幅波动不代表知识获取或丢失

4. **性能变化规律**：
   - 提升大：数学（GSM8K +45.6）、代码（HumanEval +31.1）— 基座模型欠拟合的领域
   - 下降：完形填空类（HellaSwag -8.3）— 纯语言模型天然更擅长
   - 不变：知识类（MMLU、TriviaQA）

### DPO 阶段

| 配置 | 值 |
|------|-----|
| 学习率 | 5e-6 |
| Batch size | 512 |
| Epoch | 1 |
| 调度器 | warmup + 余弦衰减 |

**偏好数据构建：**

- 有用性偏好数据：多语言提示（创意写作、问答、指令遵循等）→ DeepSeek Chat 生成候选回复
- 无害性偏好数据：类似操作
- **注意**：用自身模型生成候选回复（on-policy思路）

**DPO 效果：**

- ✅ 增强开放式生成能力（MT-Bench: 8.35 → 8.76）
- ✅ 几乎所有 AlignBench 维度都有提升
- ⚪ 标准基准测试无明显差异（不伤害基础能力）

### 安全对齐

- 20人多学科专家团队构建安全分类体系
- 5大类安全评估：歧视偏见、侵权、知识产权、违法行为、其他
- 注重攻击多样性：诱导、角色扮演、多轮对话、预设立场
- 总计 2400 道安全测试题
- 结果：Do-Not-Answer 得分 97.8（高于 ChatGPT 97.7 和 GPT-4 96.5）

### 后训练关键工程经验

| 发现 | 详情 | 启示 |
|------|------|------|
| 多选题数据是毒药 | 加入2000万MC数据，C-Eval 47→71.3，但生成式评估无提升 | 基准过拟合，不追求 |
| 预训练加指令≈SFT加指令 | 预训练最后10%加500万指令数据，效果等同SFT阶段加入 | 没必要污染预训练 |
| System Prompt 对小模型有害 | 7B加prompt后MT-Bench微降，67B则明显提升 | 小模型无法理解prompt意图 |
| 模型越大SFT越要小心 | 67B过拟合更严重，需要更小lr和更少epoch | 大模型后训练需更保守 |
| DPO可替代Stage2去重复 | DPO能同时解决重复问题和提升对话质量 | DPO一石二鸟 |

## 疑问解答

### Q1: 持续训练的复用率指的是什么？

**回答：** 指的是在进行持续训练（continual training）时，之前训练阶段的计算成果可以被直接复用的比例。

具体到 DeepSeek LLM 的多步学习率调度器：
- 调度器将训练分为三阶段（80%/10%/10%），学习率在各阶段内保持恒定或线性变化
- 当需要扩展训练数据量时（如从1T扩展到2T），第一阶段（80%）的训练可以直接复用，只需从第一阶段结束点继续训练
- **复用率 = 可直接复用的训练token数 / 总训练token数**，在此设计下约为80%

相比之下，余弦调度器的学习率持续平滑衰减，如果要扩展训练规模，必须从头重新训练（因为学习率曲线形状改变了），复用率为0%。

### Q2: 为什么要使用多步学习率调度器？

**回答：** 核心原因是**便于持续训练（continual training）**，体现长期主义（longtermism）。

具体优势：
1. **可复用性**：扩展数据时无需从头训练，直接从第一阶段末尾续训，节省80%计算
2. **性能等价**：论文图1(a)证明，多步调度器最终loss与余弦调度器一致
3. **灵活性**：可以根据需要调整各阶段比例（图1(b)显示不同比例的影响很小）

余弦调度器的问题：
- 学习率从最大值平滑衰减到接近0，整个曲线形状由总步数决定
- 如果事后想多训一些数据，要么从头重训，要么在已经很小的学习率上续训（效果差）
- 对于一个"长期主义"的项目，数据会不断迭代升级，余弦调度器不够灵活

### Q3: 为什么预训练使用的学习率通常比后训练大？

**回答：** 本质原因是三个阶段的优化目标和约束不同：

1. **搜索空间尺度**：预训练从随机初始化出发需大步快速移动；后训练从好的起点出发仅需局部微调
2. **数据量与容错**：预训练万亿级token提供强纠错能力；SFT/DPO数据量小，大学习率易过拟合
3. **灾难性遗忘**：后训练学习率过大会破坏预训练获得的知识表示

DeepSeek 论文的实证佐证：
- 67B的SFT学习率（5e-6）比预训练（3.2e-4）小64倍
- 67B只训练2 epoch就过拟合，而预训练可以遍历2T tokens
- DPO学习率与SFT相同（5e-6），但只训1 epoch

## 对后训练工程师的关键启示

1. **数据配比很重要**：数学46.6%的SFT数据占比值得注意，但要警惕重复率问题
2. **大模型后训练要保守**：更小的学习率、更少的epoch、更早停止
3. **DPO是轻量有效的对齐手段**：1 epoch、简单实现、提升开放式生成同时不伤基础能力
4. **不要追求benchmark**：多选题数据能刷分但无实际意义，要关注生成式评估
5. **分阶段微调解决质量冲突**：数学/代码能力 vs 对话流畅度的矛盾可通过两阶段SFT解决
6. **偏好数据用on-policy生成**：用自身模型生成候选回复构建偏好对
7. **安全对齐贯穿全程**：预训练→SFT→DPO每个阶段都纳入安全考量
