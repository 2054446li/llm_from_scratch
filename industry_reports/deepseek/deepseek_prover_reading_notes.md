## 整体 Pipeline（核心，必须吃透）

```
自然语言数学题 869,659 条（网络爬取，外部种子）
   │  ① 自动形式化（Autoformalization）          ← 冷启动靠 MMA 数据集微调
   ▼
形式化命题（query，模型自产）
   │  ② 质量过滤：CoT 打分 + 假设拒绝（证 False）  → 712,073 条
   ▼
高质量形式化命题
   │  ③ 命题证明：并行证「原命题 P」与「否命题 ¬P」（response，模型自产）
   │     ↓
   │  ④ Lean 4 验证器裁定对错（可验证奖励 0/1）—— 只留通过的「定理-证明」对
   ▼
合成数据（形式化命题 + 正确证明）
   │  ⑤ 回灌微调 DeepSeek-Prover
   ▼
更强的 DeepSeek-Prover  ──→ 回到 ①，迭代直到收益饱和
```

**一句话本质**：7B 模型**自己出题（query）、自己答题（response）**，由 **Lean 验证器机器判分**，只学做对的，循环自举。这就是后训练里 **RFT（Rejection sampling Fine-Tuning）+ 迭代** 的范式，把"奖励模型"换成了"确定性形式化验证器"。

## 一、Approach 拆解

### 1.1 自动形式化（§3.1）—— 自训练链路的入口

- **种子**：网络爬取 869,659 条自然语言数学题，侧重**代数与数论**（条件明确、目标清晰的题更易形式化）。
- **冷启动**：DeepSeekMath-Base 起初不会"自然语言 → Lean 命题"。用 **MMA 数据集**（Jiang et al. 2023）微调——MMA 是 mathlib 里现成的形式化命题，由 GPT-4 **反向回译**成自然语言。
- **关键点**：MMA 构造方向是「形式化 → 自然语言」（反向），而模型要学的是「自然语言 → 形式化」（正向）。用反向配对数据训练正向翻译，是 autoformalization 的常见低成本造数据手法。
- 冷启动之后，"出题"能力即由模型自身承担 → query 自产。

### 1.2 质量过滤（§3.2）—— 数据清洗本身也是可验证任务 ★

自动形式化的命题有两类毛病：

| 问题 | 表现 | 解法 |
|------|------|------|
| 过于简单 | 命题平凡无训练价值 | **模型 CoT 自打分**，分 excellent/good/above average/fair/poor，剔除 fair+poor |
| 假设不自洽 | 假设为假 → 结论"空洞为真"，数学上无意义 | **假设拒绝**：把结论换成 `False` 让模型去证，若证出 → 假设矛盾 → 剔除 |

> **后训练意义**：假设拒绝是"用模型+验证器自动剔除噪声样本"的范例。类比 RLHF，就是自动过滤 reward hacking / 标注错误样本，而非靠人工或启发式规则。**数据清洗也可以被构造成一个可验证的生成任务。**

### 1.3 命题证明（§3.3）—— 否命题并行的双重收益 ★

- 模型自产的命题中**至少 20% 是错的**（即便过滤后），暴力证明会浪费大量算力。
- 解法：对每条命题，**并行**搜索 `Γ ⊢ P` 和 `Γ ⊢ ¬P`，任一方先证出即停，同时判定另一方不可证。每路最多 k 次尝试。
- **双重收益**：
  1. **效率**：快速丢弃不可证命题，不必等到 timeout。
  2. **数据增强**：原命题没被正确形式化时，否命题的证明同样能进训练集。

### 1.4 迭代增强（§3.4）—— 自举不崩塌的前提

- 每轮用新生成数据微调 → 更新模型 → 用于下一轮自动形式化与证明。
- 模型逐轮变强 → 产出的"定理-证明"对质量逐轮提高，直到收益饱和。
- **不崩塌的关键**：response 对错由 **Lean 验证器**裁定（外部、确定性、0/1），而非模型自评。可验证奖励比奖励模型可靠 → self-training 不退化。

## 二、实验与消融（§4）—— 自训练有效性的证据

**主结果（表 1）**：miniF2F-test 上 DeepSeek-Prover 整证 46.3%（pass@64）、累计 52.0%，碾压 GPT-4（23.0%）；pass@k 随 k 增大持续涨（48.8%→50.0% @8192→65536）→ **test-time scaling**，多采样+验证器筛选换取更高成功率。

四个消融，对应四个"有效性"：

| 消融 | 结论 | 数字 |
|------|------|------|
| 4.3.1 大规模自动形式化 | 自产数据 >> 仅用 mathlib | test 42.6% vs 31.2% vs 27.5%（baseline） |
| 4.3.2 命题打分 | 高分数据训练更优 | 高分比低分高 **4.5%**（test 42.6% vs 38.1%） |
| 4.3.3 **迭代增强** ★ | 逐轮单调提升，自举有效 | iter0→4: test **34.0% → 46.3%** |
| 4.3.4 数据规模 | 性能随数据指数增长而提升 | 1k→8M: test 24.18% → 40.16% |

> **后训练 takeaway**：
> - 4.3.3 是"采样→验证器过滤→回灌"循环不崩塌、且单调自我提升的**直接证据**——前提是有可靠的可验证奖励（Lean）。
> - 4.3.4 呼应"合成数据 scaling law"：有可靠自动裁判时，瓶颈不在标注成本，而在采样与计算预算。

## 三、案例研究（§5）

- **5.1 成功证明**：3×3 余弦矩阵行列式为 0，正确翻译为 `Matrix.det ![...] = 0`。
- **5.2 不自洽假设**：模型把"D²=154 对所有非零 a,b,c 成立"错误地形式化为全称假设，随后**自己用反例证出 `False`**，暴露假设矛盾，并给出修正版（把 D 定义为具体行列式）。→ 体现"自动裁判可纠错"。

## 四、对后训练工程师的 takeaway

1. **这是一条标准 RFT + 迭代自举流水线**：种子 → 模型生成 query → 模型生成 response → 验证器过滤 → 回灌再训。把 Lean 验证器换成奖励模型/规则奖励，就是 RLHF/RLAIF 里的 RFT。
2. **可验证奖励（verifiable reward）是 self-training 不崩塌的核心**。确定性 0/1 裁判比奖励模型可靠，这正是后来 **RLVR（RL with Verifiable Rewards，如 GRPO 在数学/代码）** 的雏形。
3. **query 与 response 全部由待训 7B 模型自产**，不蒸馏更强外部模型——"自己造数据喂自己"，但靠外部锚点（网络种子 + Lean 裁判）防退化。
4. **数据清洗可被构造成可验证生成任务**（假设拒绝 = 证 False），减少对人工/启发式规则的依赖。
5. **test-time scaling**：多次采样 + 验证器筛选 = 更高 pass@k，与 RL/推理阶段"采样—验证"范式一脉相承。
6. **脉络定位**：本文（V1）→ DeepSeek-Prover-V1.5（加 RL/GRPO + MCTS）→ DeepSeek-R1（规则化可验证奖励做 RL 激发推理）。理解 V1 有助于把握"为什么可验证奖励是 reasoning model 后训练的关键拼图"。

## 疑问解答（本次阅读积累的疑问）

### Q：合成数据（query + response）是否都由"待训练的模型"自己合成？

**是的，核心循环里 query 和 response 都由 DeepSeek-Prover（正在被训练的模型）自产**，但要分清"外部种子/裁判"与"模型自产"两层：

| 数据成分 | 角色 | 由谁产生 | 待训模型自产？ |
|---|---|---|---|
| 自然语言数学题（869,659） | 最原始种子 | 网络爬取 | ✗ 外部 |
| 初始 autoformalization 能力 | 冷启动 | MMA 数据集（GPT-4 回译 mathlib） | ✗ 外部 |
| 形式化命题（query） | 训练样本的"题" | **DeepSeek-Prover 自动形式化** | ✓ |
| 证明（response） | 训练样本的"答案" | **DeepSeek-Prover 生成** | ✓ |
| 质量打分 / 假设拒绝 | 数据清洗 | **DeepSeek-Prover**（CoT + 证 False） | ✓ |
| 正确性标签 | 监督信号 | **Lean 4 验证器** | ✗ 外部裁判 |

**结论**：query + response 均由待训模型自产，但由**外部 Lean 验证器把关正确性**——"自己出题、自己答题、机器判分、留对的再学"。两个外部锚点（网络种子冷启动 + 可验证奖励裁判）防止 self-training 崩塌。
