## 一、DeepSeek 稀疏注意力（DSA）★ 架构核心

### 1.1 两个组件

DSA = **闪电索引器（lightning indexer）** + **细粒度 token 选择机制**。

**闪电索引器**：算查询 token $\mathbf{h}_t$ 与在前 token $\mathbf{h}_s$ 的索引分数

$$I_{t,s} = \sum_{j=1}^{H^I} w_{t,j}^I \cdot \mathrm{ReLU}\!\left( \mathbf{q}_{t,j}^I \cdot \mathbf{k}_s^I \right)$$

- $\mathbf{q}_{t,j}^I$、权重 $w_{t,j}^I$ 由 $\mathbf{h}_t$ 导出；$\mathbf{k}_s^I$ 由 $\mathbf{h}_s$ 导出（MQA 式共享，无头下标）
- 用 ReLU（非 softmax）+ FP8 + 头少维度小 → 极高吞吐

**细粒度 token 选择**：只取 top-k 索引分数对应的键值条目，主注意力只在这批稀疏条目上算

$$\mathbf{u}_t = \mathrm{Attn}\!\left( \mathbf{h}_t,\ \left\{ \mathbf{c}_s \mid I_{t,s} \in \mathrm{Top\text{-}k}(I_{t,:}) \right\} \right)$$

### 1.2 在 MLA 之下实例化

从 V3.1-Terminus 持续训练，故 DSA 基于 MLA 实现。kernel 层面每个 KV 条目须在同查询多头间共享 → 用 MLA 的 **MQA 模式**，每个潜在向量在该查询所有头间共享。

### 1.3 复杂度理解 ★（对话推导核心）

**系统有两笔账，不能混：**

$$\text{总成本} = \underbrace{O(N^2 \cdot d_{\text{idx}})}_{\text{索引器打分}} + \underbrace{O(N \cdot k \cdot d_{\text{main}})}_{\text{主注意力}}$$

一行公式概括 DSA 效率：

$$\underbrace{a \cdot N^2}_{\text{原始}} \quad\longrightarrow\quad \underbrace{b \cdot N^2}_{\text{索引器}} + \underbrace{a \cdot N k}_{\text{主注意力}}, \qquad b < a,\ k < N$$

- **第一项 $b \cdot N^2$**：索引器仍是 $N^2$，但常数从 $a$ 砍到 $b$（头少、维度小、FP8、只打分不聚合 value、ReLU 免规约）。这是「便宜的 $N^2$」，**没有降阶**。
- **第二项 $a \cdot Nk$**：主注意力保留大常数 $a$，但把一个 $N$ 换成 $k$（只对 top-k 算 $QK^\top$ 和 $\text{scores}\cdot V$ 两个大矩阵乘）。**这才是论文声称的 $O(N^2)\to O(Nk)$**。

**何时划算**（解不等式 $a N^2 > b N^2 + a N k$）：

$$N > \frac{a\,k}{a - b} \quad\Rightarrow\quad N \text{ 足够大（长上下文）必然划算}$$

短序列时 $b N^2$ 平方项可能吃亏，故 §2.3 短序列专门用 masked MHA 模式模拟 DSA。

**具体数值（128K，粗估）**：主注意力 $d_{\text{main}} \approx 128 \text{ 头} \times 576 \approx 73728$，$k = 2048$；索引器 $d_{\text{idx}}$ 量级仅几百~千且 FP8。
- 索引器 vs 原打分：省几十倍常数（仍 $N^2$）
- 主注意力 $N^2 \to N k$：省 $L/k = 131072/2048 \approx \mathbf{64}$ 倍，且降阶（$L$ 越大越赚）

### 1.4 为什么必须独立建索引器（对话关键理解）★

**你的直觉「在 MLA 低维下算 q·k 选 top-k」为何不成立：**

1. **MLA 压的是 KV 存储，不是打分维度**。真实注意力打分是 $128 \text{ 头} \times 576 \text{ 维} \times L^2$——正是 attention 的大头，一点不便宜。
2. **用真实 $\mathbf{q}\cdot\mathbf{k}$ 选 top-k = 白省**：$QK^\top$ 全量算完钱已付，选 top-k 只能省下第二个矩阵乘（$\text{scores}\cdot V$），最多省一半。DSA 要用廉价索引器让**两个大矩阵乘都只碰 top-k**。
3. **多头给不出单一选择分数**：主注意力每 $(t,s)$ 有 $H$ 个分数，选 token 需统一标量；索引器对头加权求和成一个 $I_{t,s}$，天生为选择服务。

### 1.5 索引器多头的作用

目标分布 $p_{t,:}$ 是主注意力 128 头分数之和。单个 $\mathrm{ReLU}(\mathbf{q}\cdot\mathbf{k})$ 只表达一种关系；多头加权求和 = 小型分段线性函数，用「任一头命中即重要」的并集逼近多头 teacher。单头会欠拟合。

### 1.6 误差容忍度不对称 ★（解开「轻模型拟合重模型」的张力）

不是「算数值比选 top-k 难」，而是两件事**容错度不同**：

| | 选择（selection） | 输出（value 聚合） |
|---|---|---|
| 需求 | 高召回：top-k **包含**重要 token 即可 | 高精度：直接进残差流影响 LM loss |
| 容错 | 高（排序错在不重要 token 无所谓） | 低（误差传播损害质量） |
| 对应 | 廉价索引器（维度小） | 昂贵 MLA（维度大、全精度） |

**索引器学的是 $\mathrm{argsort}(\text{attention})$，不是 $\text{attention}\cdot V$** —— 预测「关注落点」远比算出加权和容易。且有安全网：即便 top-k 略偏，主注意力随后在选中集合上算**精确 softmax**，只要召回够高，输出精度不受损。

### 1.7 训练：知识蒸馏视角

```
训练时：MLA 稠密注意力 = teacher（只跑 1000 步/2.1B token，算得起），出真值分布 p
        索引器 = student，KL 对齐"MLA 会关注哪里"
推理时：不再算稠密注意力，直接用学好的廉价索引器预测 top-k，永久省钱
```

- **稠密预热**（式3）：$\mathcal{L}^I = \sum_t \mathbb{D}_{\mathrm{KL}}\!\left( p_{t,:} \,\|\, \mathrm{Softmax}(I_{t,:}) \right)$，$p_{t,:}$ 为主注意力全头分数求和后 L1 归一化，lr $=10^{-3}$
- **稀疏训练**（式4）：只在选中集合 $\mathcal{S}_t$ 上对齐 $\mathcal{L}^I = \sum_t \mathbb{D}_{\mathrm{KL}}\!\left( p_{t,\mathcal{S}_t} \,\|\, \mathrm{Softmax}(I_{t,\mathcal{S}_t}) \right)$，lr $=7.3\times10^{-6}$，$k=2048$；**索引器输入 detach**，索引器只受 $\mathcal{L}^I$、主模型只受 LM loss

### 1.8 与后训练的关联

DSA 把核心注意力 $O(L^2)\to O(Lk)$，直接压低长上下文 **RL rollout 吞吐成本**，是「后训练算力 >预训练 10%」这种规模化 RL 得以成立的前提。detach + KL 对齐是在不破坏原模型行为下植入稀疏，保障训练-推理一致性。

## 三、后训练（Post-Training）★★ 本笔记核心

### 3.1 专家蒸馏 + 混合 RL 是这一代核心范式 ★

> **原文结论·忠实翻译（两条核心，务必保留原意）**
>
> **① 关于专家蒸馏**：「对每类任务，我们首先开发一个专门用于该特定领域的专家模型（specialist），所有专家模型都从同一个预训练好的 DeepSeek-V3.2 基础检查点微调而来……一旦专家模型准备就绪，就用它们为最终检查点生成领域专属数据。实验结果表明：**在蒸馏数据上训练出的模型，其性能仅略低于各领域的专家模型，而这一性能差距会在后续的强化学习训练中被有效消除。**」
>
> **② 关于单阶段混合 RL**：「对 DeepSeek-V3.2，与 DeepSeek-V3.2-Exp 一样，我们把推理、智能体、人类对齐三类训练合并进单一 RL 阶段。**这种做法在多样领域间有效平衡了性能，同时规避了多阶段训练范式常见的灾难性遗忘问题。**」（即：先训推理再训通用/对齐的多阶段做法会让后阶段把已练好的推理能力练丢，故本版合并为一个阶段一起训。）

- **专家蒸馏的有效性结论**：在蒸馏数据上训练的模型性能**仅略低于**各领域 specialist，差距会在**后续混合 RL 中被有效抹平**。
  - 范式：6 领域（数学 / 编程 / 通用逻辑推理 / 通用 agent / agent 编程 / agent 搜索，均支持 thinking 与 non-thinking）各用大规模 RL 训 specialist → specialist 为最终检查点生成领域数据（蒸馏）→ 统一混合 RL 补齐差距。
  - thinking 与 non-thinking 数据由**不同模型**生成。
  - 意义：避免直接在通用模型上多领域 RL 相互干扰；蒸馏损失的少量能力由最后 RL 找回。

- **单阶段混合 RL 的取舍**：推理 + agent + 人类对齐塞进**单一 RL 阶段**。
  - 多阶段 RL 易致后阶段把前阶段能力练丢（**灾难性遗忘**）；单阶段混合用统一优化把各能力一起保住。
  - **混合奖励体系**：可验证任务（推理/agent）用规则化结果奖励 + 长度惩罚 + 语言一致性奖励；开放任务（通用）用带 rubric 的生成式奖励模型。
  - 仍用 **GRPO** 作 RL 算法。

### 3.2 扩展 GRPO 的四项稳定性技巧（§3.1）★

共同主题：处理「训练-推理 / 新旧策略不一致」的离策略问题。

1. **无偏 KL 估计** — 用重要性采样比率修正 K3 估计器在离策略下的偏差，消除系统误差。K3 在 π_θ≪π_ref 时梯度爆炸；无偏版稳定收敛。数学等可验证领域可**弱化甚至省略** KL。详见 [[13_unbiased_kl_estimate]]。
2. **离策略序列掩码** — 二值掩码 $M_{i,t}$：**仅对「负优势 $\hat{A}_{i,t}<0$ 且策略分歧 $\frac{1}{|o_i|}\sum_t \log\frac{\pi_{\text{old}}}{\pi_\theta} > \delta$」**的序列丢弃梯度。直觉：模型从自己的错误学最多，但高度离策略的负样本会带偏优化。只砍负样本，不砍正样本。
3. **保持路由（Keep Routing）** — MoE 训练时强制采用推理采样时的专家路由路径，保证「采样的网络 = 被更新的网络」，避免激活参数子空间突变。自 V3-0324 起采用。
4. **保持采样掩码（Keep Sampling Mask）** — 把 top-p/top-k 截断掩码从采样侧复制到训练侧，保证 π_old 与 π_θ 动作空间一致，维护重要性采样正确性与语言一致性。

#### 3.2.1 深入：离策略序列掩码为什么这么设计 ★★

**升级内容**：标准 GRPO 里一个 group 采出的 $G$ 条序列不分好坏全部参与梯度更新。V3.2 加了一个二值门 $M_{i,t}$，对**同时满足两个条件**的序列丢弃梯度：

$$\text{条件1（负优势）：}\ \hat{A}_{i,t} < 0 \qquad \text{条件2（高度离策略）：}\ \frac{1}{|o_i|}\sum_{t=1}^{|o_i|} \log\frac{\pi_{\text{old}}}{\pi_\theta} > \delta$$

即：**只有既是"坏样本"、又"离当前策略很远"的序列才被掩掉**。正样本一律保留；离策略程度低的负样本也保留。

**问题从哪来——GRPO 名义 on-policy、实际 off-policy**：

1. **训练-推理框架不一致**：rollout 用推理引擎（不同 kernel / 量化 / 并行），训练用训练框架，二者对同一序列算出的概率天然有偏差。
2. **一批数据多步复用**：采一次样、更新多个 minibatch，越到后面 $\pi_\theta$ 离 $\pi_{\text{old}}$ 越远。
3. **混合 RL + 长序列**：agent 轨迹动辄几万 token，逐 token 的 $\pi_{\text{old}}/\pi_\theta$ 偏差沿序列累积放大。

条件2 里的平均对数比率就是每条序列的「离策略程度」——越大越"陌生"（当前策略越不会再生成它）。

**核心：为什么只砍「负优势 × 高离策略」这一格**（2×2 取舍）：

| | 低离策略 | 高离策略 |
|---|---|---|
| **正优势** | 保留（有用信号） | 保留（模型自己能到达的好路径，探索最有价值） |
| **负优势** | 保留（从自己真会犯的错误学） | **★丢弃★**（有害） |

- **负 × 高离策略为何有害**：负优势的梯度方向是「**压低**这条序列概率」，但它在当前 $\pi_\theta$ 下概率本已趋零（几乎不会再生成）。对一个模型早已不产生的样本继续用大梯度纠正，等于**惩罚一个不存在的行为**；且此时重要性比率 $\rho = \pi_\theta/\pi_{\text{old}}$ 数值不稳，方差极大、方向可疑，**把优化带偏**。一句话：模型从「自己真会犯的错」学得最多，对「自己早就不犯的错」还拼命纠正纯属噪声甚至反伤。
- **正样本为何不砍（哪怕高离策略）**：正优势是「**上拉**概率」，一条高离策略的正样本意味着「有好路径当前策略走得还不够」，正是探索里最宝贵的信号，砍掉等于自断探索。且**上拉比下压对离策略更鲁棒**——上拉是把低概率往模型能力范围内带；下压一个趋零概率则容易数值失控。

**与另外三项的关系**：四项技巧是同一主题的四个侧面，都在治「名义 on-policy、实际 off-policy」。无偏 KL 与序列掩码是**事后修正梯度**（KL 项 / 优势项），保持路由与保持采样掩码是**事前减小分歧**（网络 / 动作空间对齐）。序列掩码是其中最"外科手术式"的一刀：不动框架，只在梯度层面精准切掉最脏的那一格。详见 [[13_unbiased_kl_estimate]]、[[9_grpo]]。

**一句话**：给负优势样本加一道**离策略熔断**——坏样本里只学「你自己真会犯的错」，对「你早就不犯的错」直接免疫；因为压低趋零概率的重要性比率会爆方差、带偏优化，而正样本的上拉信号对离策略鲁棒，故一律保留。

## 四、评估（§4）

### 4.1 主结果（表2）
- 推理任务追平 GPT-5-high，略逊 Gemini-3.0-Pro；相比 K2-Thinking 用**更少输出 token** 达可比分数。
- 提升归因于 **RL 训练算力增加（>预训练 10% 且持续提升）** → 印证「开源落后主因是后训练算力不足，而非方法差距」。
- 本文 V3.2 受**长度约束奖励模型**限制，移除后性能进一步提升（见 Speciale）。
- **域外泛化**：MCP 等环境 RL 训练时从未见过，仍有提升 → 证明学到的是通用推理-工具协同策略。
- 副作用：**冗余自我验证**致轨迹过长撑爆 128K（奖励过优化现象）。

### 4.2 DeepSeek-V3.2-Speciale（表3-4）
- 用**更多推理 token** 超越 Gemini-3.0-Pro（多基准最高）。
- 无针对性训练即达金牌：**IMO 35/42、CMO 102/126、IOI 492/600、ICPC WF 10/12**（整合 DeepSeekMath-V2 强化证明）。
- 代价：**token 效率显著低于 Gemini**（如 CodeForces 77k vs 22k）。官方版收紧 token 约束换效率。
- **本质是「性能 vs token 效率」的奖励取舍实验**：长度惩罚这一奖励项直接调节「推理深度 ↔ 部署成本」的天平。

### 4.3 合成 agent 任务消融（表5 / 图5）★
- **难度足够**：50 个合成实例上 V3.2-Exp 仅 12%，前沿闭源最高 62% → 难，RL 信号浓。
- **泛化验证**：仅在合成通用 agent 数据上做 RL（非思考模式），就能泛化到 τ²/MCP 等**训练未见**基准；只练 code+search 的 Exp 反而不行。
- 结论：**agent 能力泛化来自训练任务的「多样性 + 可验证难度」，而非特定环境数据量** → 指导 RL 数据配比。

### 4.4 搜索 agent 的上下文管理（图6）★
- 128K 仍会被 agent 工作流撑爆（约 20%+ 用例超限），token 用量 >80% 时触发管理。
- 三策略：**Summary**（摘要溢出轨迹重启，步数扩到 364，得 60.2 但效率低）、**Discard-75%**（丢前 75% 工具历史）、**Discard-all**（清空所有工具历史，简单却得 67.6，接近并行 scaling 且步数更少）。
- 对比基线 **Parallel-fewest-step**（采 N 条选最短）。
- 洞见：上下文管理 = **串行 test-time scaling**，与并行采样并列；旧工具历史大多用完即弃（对照 3.2.1 思考要留）。

## 五、对后训练工程师的 takeaway

1. **专家蒸馏 + 单阶段混合 RL**：分领域练强 → 蒸馏汇总 → 统一 RL 补齐，兼顾专精与防遗忘。蒸馏差距可被 RL 抹平。
2. **离策略稳定性是 scale RL 的命门**：无偏 KL、离策略序列掩码、保持路由、保持采样掩码——全在处理「名义 on-policy、实际 off-policy」，核心是训练-推理一致性。
3. **可验证奖励可弱化 KL**：数学等有客观信号的领域，KL 可弱化甚至去掉以充分探索。
4. **难解易验证是 agent RL 数据合成的灵魂**：契合 RL「客观奖励 + 高探索难度」；自提任务+自写验证器闭环 = 自动生产 RL 课程。
5. **长度惩罚是性能↔成本的调节旋钮**：Speciale vs 官方版清晰展示放宽/收紧长度惩罚如何调节推理深度与部署成本。
6. **agent 泛化靠任务多样性而非环境数据量**：域外泛化 + 合成消融共同证明。
7. **上下文管理 = 串行 test-time scaling**：agent 超长轨迹可用 Discard-all 等腾空间续跑，性价比高。
8. **DSA 服务后训练**：核心注意力 O(L²)→O(Lk) 降低长上下文 RL rollout 吞吐成本。

## 六、疑问解答（对话沉淀）

### Q1：闪电索引器仍是 $N\times N$，复杂度没降？
是。索引器保留 $O(L^2)$（论文明确承认），但常数极小（头少、维度小、FP8、只打分不聚合 value、ReLU 免规约）。降阶发生在**主注意力** $O(L^2)\to O(Lk)$。用「便宜的 $N^2$」换掉「昂贵的 $N^2$」。见 §1.3。

### Q2：为何不直接用 $\mathbf{q}\cdot\mathbf{k}$ 结果选 top-k，非要建索引器？
鸡生蛋：拿到全部真实 $\mathbf{q}\cdot\mathbf{k}$ = 已付最贵的 $QK^\top$ 钱，选 top-k 只能省一半（$\text{scores}\cdot V$）。DSA 要让**两个大矩阵乘都只碰 top-k**，故需独立廉价打分器。且 MLA 压的是 KV 存储不是打分维度，真实打分不便宜；多头也给不出单一选择分数。见 §1.4。

### Q3：MQA 共享是否省 num_head 倍计算量？
**纠正**：MQA 省的是 **key 投影 + KV 显存/带宽**，不是点积 FLOPs（每头仍各算一次点积）。索引器相对主注意力省的是「只打分不聚合 value + 小维度 + FP8 + ReLU」的叠加，不是单一 num_head 倍。见 §1.6。

### Q4：softmax 比 ReLU 慢多少？
逐元素约 5~10×（exp 走 SFU + 行内 max/sum 规约 + 除法 vs 单个 max）。但激活只是 $O(N^2)$ 小项，注意力大头是两个 $O(N^2 d)$ 矩阵乘。ReLU 真正价值在**免规约 + FP8 友好**，让廉价 $N^2$ 打分跑满吞吐。

### Q5：轻 index 拟合重 MLA 是否矛盾？
不矛盾，是**知识蒸馏 + 摊销**。选择是高容错任务（top-k 含重要 token 即可），输出是低容错任务（进残差流）。索引器学的是 $\mathrm{argsort}(\text{attention})$ 而非 $\text{attention}\cdot V$，预测关注落点远比算加权和易；且主注意力在选中集合上算**精确 softmax 兜底**。训练时付一次钱教会代理，推理永久省钱。见 §1.6-1.7。

### Q6：3.2 冷启动的背景与目的？
RL 需先有种子轨迹才能启动（目标行为概率为 0 则无梯度）。纯推理数据与纯 agent 数据都产不出「思考+工具交织」轨迹。冷启动用 system prompt 诱导模型**偶尔**产出该轨迹，把概率从 0 抬到非零，为 3.2.3 大规模 RL 点火。见 §3.3。
