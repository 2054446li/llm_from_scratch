# Qwen 系列模型架构分析

> 阿里通义千问的技术设计选择与多语言优化。

---

## 核心架构特点

### Qwen 系列演进

| 版本 | 参数规模 | 主要改进 |
|-----|--------|--------|
| Qwen-1 | 7B, 14B, 72B | 基础版本，中文优化 |
| Qwen-1.5 | 0.5B-72B | 更多尺寸，性能提升 |
| Qwen-2 | 0.5B-72B | 架构优化，推理加速 |

### 架构选择

1. **位置编码**：RoPE + ALiBi
   - RoPE：主要位置编码
   - ALiBi：补充性偏置
   - 好处：长文本能力强

2. **Attention 机制**：GQA (Grouped-Query Attention)
   - 推理 KV 缓存减少 4-8 倍
   - 保持模型质量

3. **归一化**：RMSNorm
   - 比 LayerNorm 更快
   - 数值更稳定

4. **激活函数**：GELU
   - 平滑且表现好

## 多语言优化

### Token 化策略

**SentencePiece 的优化**：
- 词表大小：151,936（比 Llama 的 32,000 大得多）
- 设计理由：支持多语言

**多语言特性**：
- 中文：充分覆盖常用字符
- 英文：完整覆盖
- 代码：特殊 token 处理
- 其他语言：足够覆盖

### 训练数据组成

预估（未官方公开）：
- 英文：30-40%
- 中文：30-40%
- 代码：10-15%
- 其他语言：10-20%

### 性能表现

多语言基准：
- 英文任务：与 Llama 相当
- 中文任务：明显优于国际模型
- 代码任务：强势（充分的代码数据）
- 长文本：好（特别是中文）

---

## 推理优化

### Flash Attention 支持

- 完整支持 Flash Attention v2
- 推理加速 2-3 倍
- 内存节省显著

### 量化方案

1. **GPTQ 量化**
   - INT4/INT8 量化
   - 保持较好精度

2. **AWQ 量化**
   - 权重量化
   - 低秩激活保护

3. **bfloat16**
   - 原生支持
   - 无精度损失

| 英文 | 相当 | 相当 |

## 关键学习点

1. **多语言不是额外成本**：充分的语言特定数据投入

2. **词表大小的权衡**：151K 词表虽然参数多，但多语言收益值得

3. **推理优化的组合**：GQA + Flash Attention + 量化的协同

4. **开源生态**：完全开源，社区应用案例多
